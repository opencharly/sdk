# 0.2026272.1813 — fix(loaderkit)!: scope candy-version arbitration + notice PER BOX, INFO not WARNING (#735)

## Summary

The candy-version resolver arbitrated a bare ref **globally**. `spec`'s per-box scope (merged
`opencharly/spec#186`, tag `v0.2026272.1512`) made the SCOPE available; this PR makes `sdk`'s
`loaderkit` USE it, so arbitration + the diagnostic are **per box**:

1. **Scope = one box.** A bare ref's versions are arbitrated within `(scope, bareRef)`, never
   across boxes. The `referrers` map carries SCOPE labels alongside the `(repo, tag)` fetch
   coordinate; the fetch set stays **global by design** (one clone per `(repo, tag)`), the
   *candidate* merge is what is scoped.
2. **Across boxes** → differing versions are **NOT a conflict** → **silent**.
3. **Within one box**, differing versions → the **newest REFERENCED** version wins, recorded as
   **INFO** (resolvable) — never WARNING, and never the newest *remote* tag.
4. **ONE unified diagnostic path** — the existing sink carries the level (`spec.DiagLevel`,
   merged in `spec#186`); no parallel advisory API.

Root cause, evidence, and the formal 8-step RCA: `opencharly/charly#735`. This is the `sdk` leg
of the `spec` → `sdk` → `charly` chain.

**This clears `#733`'s zero-warnings gate**, since the ~1602 advisories were spurious cross-box
"conflicts" — independent boxes are not a conflict.
