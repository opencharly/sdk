# 0.2026288.1404 — fix(candywalk): never read a prose template as a ref — `marketplace generate|drift` cannot run while this stands

## Summary

`remoteRefRe`'s character classes excluded whitespace, quotes, `]`, `}` and `#` — but not `<` or `>`.
So the notation our own documentation uses to *describe* a ref:

```
@github.com/opencharly/<kind>-<name>:<tag>
```

matched like any other. It parsed into a repo path (`opencharly/<kind>-<name>`) plus a version
(`<tag>`), reached the resolver, and was handed to `git ls-remote` as a URL.

**The measured consequence, which is why this is more than a tidy-up:** `charly marketplace generate`
and `charly marketplace drift` both die in `collect entities` before reading a single entity, so no
corpus in the org can be regenerated while this stands. The only file in the marketplace checkout
carrying that shape is a CHANGELOG, i.e. prose:

```
$ grep -rl -m1 '<kind>-<name>' <marketplace checkout>
./CHANGELOG/2026.240.0810.md
```

The fix adds the two characters to both classes. `<` and `>` occur in no repository name and no
version — they exist only in placeholders — so every real ref keeps working, including the branch and
SHA forms that the comment above the pattern records as the reason a `:v…` anchor was dropped. That
comment is why this fix is the character class and **not** the anchor.

## How tested

Proven three ways on the committed tree, and the negative arm reproduces the production failure
character for character:

```
1. with the fix        → ok
2. pattern reverted    → --- FAIL: TestCollectRefs_IgnoresProseTemplates
                         collectRefs returned the prose template
                         "@github.com/opencharly/<kind>-<name>:<tag>`" — it is fetched as if it were a repository
3. restored, full arm  → go test ./... rc=0 (19 packages ok)
                         gofmt -l . → empty      go vet ./... → rc=0
                         golangci-lint run ./... → 0 issues (v2.13.2, the CI pin)
                         GOOS=linux CGO_ENABLED=0 go build ./... → amd64 ok, arm64 ok, arm ok, 386 ok
```

Note the stray backtick in the failing token: the real error printed exactly the same thing, because
the CHANGELOG quotes the notation in backticks and the ref class does not stop at one. The fixture
reproduces the trigger rather than a cleaned-up version of it — and it single-quotes the real refs
beside it, as the sibling fixture does, because `'` *is* a delimiter the class stops at.

The test covers both directions: the placeholder must not be returned, and the real refs on the
surrounding lines — one tag, one **branch** — must still come through.
