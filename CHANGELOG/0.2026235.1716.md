# 0.2026235.1716 — feat(loaderkit): root-level remote candy name derivation (the candy de-submodule cutover)

## Summary

The candy de-submodule cutover's **root-level remote candy support** (sdk-side): a standalone candy repo's manifest lives at the repo ROOT, so the bare ref IS the repo path (no `/candy/<name>` sub-path). `ScanRemoteCandy` now:

1. treats a ref that equals the repo path as an **empty sub-path** (the manifest at the repo root — the previous `TrimPrefix` left the full ref as the sub-path and the scan looked for `repoDir/github.com/opencharly/ripgrep`), and
2. derives the candy name from the **repo's own name** (`path.Base(repoPath)`) when the sub-path is empty.

The sub-path form (a candy library inside a repo — the pre-cutover shape) is unchanged.
