# 0.2026236.1958 — feat(buildkit): hasPrefix template func + unified install body both-venue render test

## Summary

Supports the spec#50 R3 cutover (one venue-agnostic `install` body per format, venue applied at render):
- `TemplateFuncs` gains `hasPrefix` (alongside the existing `hasSuffix`): the pac install body branches a repo `key:` that is a published key FILE URL (`curl -fsSL <url> | pacman-key --add` + lsign by extracted fingerprint — the deterministic, keyserver-free mechanism every other format uses) from a keyserver fingerprint (`pacman-key --recv-keys`). A VM guest cannot always reach the keyservers the fingerprint form depends on (observed live in check-cachyos-vm deploy-add: `gpg: keyserver receive failed`).
- `TestUnifiedInstallBodyRendersBothVenues` proves the R3 shape end to end: one venue-agnostic install body renders as plain shell for the host venue and as a BuildKit `RUN {{cacheMounts}}` for the container venue.
- `TestPacUnifiedInstallKeyBranchUsesHasPrefix` is the FAILING-WITHOUT-FIX coverage for the changed func: it renders the pac key branch with an http(s) URL (must take curl + pacman-key --add) and with a fingerprint (must take recv-keys). Without `hasPrefix` the template errors `function "hasPrefix" not defined` (verified by temporarily removing the func).
- spec pin bumped to v0.2026232.521-0.20260824192047-0c29ab15816d (spec#50, the `PhaseTemplates.install` cell).
