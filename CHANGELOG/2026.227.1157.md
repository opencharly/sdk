# 2026.227.1157 — `ai.opencharly.box` carries the box's LEAF name, not the namespace-qualified key

The render half of the stale-artifact certification fix (the resolver half is
`spec`; the call sites are the superproject).

## The defect

`buildBakedMetadata` set `meta.Box = boxName`, where `boxName` is the Generator's
`Boxes` map KEY. For a box reached through an `import:` namespace that key is
QUALIFIED — `fedora.fedora-nonfree`. The image REF is not: `buildkit.ResolveBox`
descends into the namespace and resolves the box under its leaf name, so
`FullTag` reads `ghcr.io/opencharly/fedora-nonfree:<tag>`. The image was
therefore labelled with a name no ref of it ever carries.

Measured on 2026-08-15: `ghcr.io/opencharly/fedora-nonfree:2026.227.0836` carried
`ai.opencharly.box=fedora.fedora-nonfree`, while
`ghcr.io/opencharly/fedora-nonfree:2026.216.1908` (built when the box was named
unqualified) carried `fedora-nonfree`.

Every consumer keys the label and the ref name together, so they must agree:

- `spec/container.ResolveLocalImage`'s label family is exactly
  `img.Labels[LabelBox] == <short>`, and the election discards the name family
  wholesale when the label family is non-empty. A namespaced build was thus
  invisible to a resolve of its own image name, and an older bare-labelled image
  won — which is how `charly check box fedora-nonfree` came to certify a stale
  artifact and report all-green.
- `candy/plugin-clean`'s retention groups by the same label, so one box's builds
  split into two `keep_images` groups depending on how the box was named at build
  time.

## The fix

`meta.Box = spec.LeafName(boxName)` in `deploykit.buildBakedMetadata`, and the
same in the data-image label block in `deploykit.generate.go`. `spec.LeafName` is
the codebase's existing namespace stripper — the same one `ResolveShellImageRef`'s
callers already use to build a ref name — so the label is derived exactly the way
the ref is. Unqualified keys (every non-imported box, and every synthesized
intermediate) are unchanged.

`kit` re-exports the new resolver surface (`ResolveBuiltImageRef`,
`ResolveLocalImage`, `LocalImageResolution`, `ErrStaleLocalImage`) so the plugin
call sites keep their `kit.X` spelling.

## Coverage

`deploykit/baked_box_label_test.go` — `TestBuildBakedMetadata_BoxLabelIsLeafName`
asserts the emitted label equals the trailing repo segment of the ref that same
build produces, for a namespace-qualified map key, and that an unqualified key is
unchanged. Fails on the pre-fix body (emits `fedora.fedora-nonfree`).

R8, live: after the fix, `charly box build fedora.fedora-nonfree` from the
superproject emits `ai.opencharly.box=fedora-nonfree`, read back with
`charly box labels`.
