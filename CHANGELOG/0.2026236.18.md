# 0.2026236.18 — fix(loaderkit): root-level remote bare dep must not be enqueued as a sibling (fix-point mirror of #160)

## Summary

The batch-1 candy cutover (charly#385) revealed a second sibling-ref fabrication site in the remote-candy fetch fix-point. The #160 fix guarded `QualifyRemoteSiblingDeps` (the scan-time `.Resolved` qualification), but `ScanCandyFromLocal`'s fix-point **enqueue leg** independently fabricates the same wrong sibling ref for a root-level remote candy:

```go
// before
return enqueue(dl.RepoPath, dl.Version, dl.RepoPath+"/"+sc.View.SubPathPrefix+dep.Raw)
// with SubPathPrefix "" → github.com/opencharly/layer-cuda/nvidia for a bare "nvidia" dep
```

The next fix-point round then scans that fabricated ref against the repo at the tag and fails the resolve with `remote candy github.com/opencharly/layer-cuda/nvidia not found at .../layer-cuda@v2026.235.2110/nvidia` — the exact `charly check run check-marketplace` bed failure at the charly#385 head.

**The fix** (34edc0d): mirror the `#160` skip in the enqueue leg — a root-level remote candy (SubPathPrefix `""`) has NO siblings, so a plain-name dep is left to resolve against the scan set (the local library or another downloaded remote). The pre-cutover sub-path form (`SubPathPrefix "candy/"`) keeps the same-repo sibling enqueue unchanged.

**The negative control** (24f20df): `TestScanCandyFromLocal_SubPathBareDepStillEnqueued` holds the candy-library form to its existing sibling enqueue, so the skip cannot degenerate into "drop all plain-name deps of remote candies".
