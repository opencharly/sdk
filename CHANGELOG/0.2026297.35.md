# 0.2026297.35 — fix(candywalk): admit charly's BARE repo-root ref as a corpus source, keep the pre-cutover subpath form refused

## Summary

`candywalk.acceptedRef` refused `github.com/opencharly/charly` **outright**, so the corpus could never
read `charly` as a source: three skills (`go`, `go-quality`, `plugin`) authored in `charly` beside the
code they document were unreachable, and a fourth (`charly-version`) had no authority but `pod-charly-core`'s
retired copy (`opencharly/sdk#468`; `opencharly/opencharly#600` §8 decides it).

The refusal is **correct for the one form it was written for** — `@github.com/opencharly/charly/candy/<name>`,
the pre-cutover IN-REPO ref that resolves to the LOCAL charly checkout's candy dir (the local FS walk
already surfaces that) and that the box submodule repos' own cutover sweeps (`87a2fcd`, `#167`,
2026-08-25) — and **obsolete for the BARE repo-root form** now blocked, the shape
`opencharly/opencharly`, `spec` and `sdk` are already pinned as, and the shape `charly` began authoring
its skills in on **2026-10-23** (`092f82e4`, charly#1047) — after the refusal existed. Keyed on
`RepoPath` alone, the predicate could not tell the two apart; `spec.ParsedRef.SubPath` already carries
the distinction.

The change is that one predicate, in the single home both readers share:

```go
if pr.RepoPath == "" {
    return ""
}
// The pre-cutover IN-REPO charly form is still refused: … The BARE repo-root form is a CORPUS SOURCE …
if pr.RepoPath == "github.com/opencharly/charly" && pr.SubPath != "" {
    return ""
}
```

Per file:

- **`candywalk/candywalk.go`** — the skip narrowed to the SUBPATH form (`+32/−13` in the file: **4 added
  code lines, 1 removed**, the other 28 added and 12 removed lines being comments); and the three
  comments that stated the old rule corrected in the SAME change (R5): `collectRefs`' doc block (which
  said refs INTO charly are "skipped" full stop — it now states the subpath reason AND the repo-root
  admission), `acceptedRef`'s own comment, and `parseRemoteRef`'s, which claimed `collectRefs` "skips
  `RepoPath == github.com/opencharly/charly`". No comment still claims a blanket refusal.
- **`candywalk/candywalk_refs_charly_repo_root_test.go`** (new) — two arms with the control that fails:
  the collector admits the bare repo-root ref while BOTH spellings of the pre-cutover subpath form
  (versioned and versionless) stay refused beside an untouched sibling ref; and the walk-level arm —
  a refs list declaring the bare ref has the fetched ROOT manifest walked and exactly 4 `skill:` nodes
  unioned in with `Dir: "."` and the fetched tree as `SourceRoot`.

**What this PR does NOT do, and it is deliberate:** it does not run the real `charly marketplace generate`
— that is the CONSUMER leg (`marketplace` refs PR, producer-first after this merges and tags), and its
arm is the with/without-pin corpus diff. It also does not touch the local-root asymmetry measured while
deciding this (`collectEntitiesWithRemote` reads a repo's ROOT `charly.yml` only on the FETCHED path);
that is `opencharly/sdk#469`, filed with the measurement, not absorbed here.
