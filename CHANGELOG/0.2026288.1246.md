# 0.2026288.1246 — feat(candywalk): read a skill's prose from its .agents/skills file

## Summary

**Leg L2** of the `.agents/skills` relocation (`opencharly/opencharly#496`, the `agents-skills-relocation` ledger): the **shared reader** for a skill's prose, in the kit both generators consume.

A skill's body is moving out of its `skill:` entity into the file the repository owns:

```
<tree>/<name>/SKILL.md                 frontmatter (name + description) + the markdown body
<tree>/<name>/references/<stem>.md     no frontmatter, by contract
```

where `<tree>` is the tree the owning candy declares (`skills:`, default `.agents/skills`) and `<name>` is the skill id — the **directory** name. The entity keeps the routing metadata (`family`/`owner`/`triggers`), and the github ref that fetched the repo is the version of record.

This adds `candywalk`'s reader for that file: `AgentsSkillsDir`, `SkillFile`, `SkillReferenceFile`, `ReadSkillFile` and `ReadSkillTree`, plus the two-key frontmatter parse and the generator-marker strip:

```
$ git show HEAD:candywalk/skillfile.go | grep -nE '^(const|func|type) '
36:const (
53:type SkillReferenceFile struct {
59:type SkillFile struct {
85:func ReadSkillFile(treeDir, name string) (*SkillFile, error) {
125:func ReadSkillTree(treeDir string) (map[string]*SkillFile, error) {
152:func readSkillReferences(dir string) ([]SkillReferenceFile, error) {
187:func splitFrontmatter(s string) (front, body string) {
201:func stripGeneratedHeader(body string) string {
```

**It lives in the kit, not in either generator, because both need it** — `candy/plugin-marketplace` (which synthesizes the corpus from these files) and `candy/plugin-docs` (which renders them). It is the docs projection's own `readSkill`, lifted: same fence split, same two-key frontmatter, same marker strip, same stem-sorted references. Its two deliberate properties are the ones a round trip needs:

- **the marker is stripped either way**, so a file read from the published corpus (marker-bearing) and a file authored bare in a repo read back to the *same* prose — which is what makes `extract` → read → emit byte-exact;
- **`Content` is returned verbatim, not trimmed**, because the corpus emitter writes `TrimSuffix(content, "\n") + "\n"`, so the body as-authored is the body to re-emit.

**One fix over the copy it is lifted from**, and it is why `plugin-docs` converges onto this reader in L5: the fence split **keeps the newline that precedes the closing `---`**, without which a `description: |` (keep) block scalar reads back one newline shorter and the next emit silently rewrites the indicator as `|-`.
