# 0.2026269.958 — fix(checkkit): SnapshotCheckEnv must carry CandyDirs — the committed-APK fixture anchor (v2)

## Summary

Fixes the committed-APK fixture anchor on the **plugin→host wire leg**. Every relative `apk:` check step in a live bed failed with:

```
verb "adb": committed APK "./tests/data/ApiDemos-debug.apk": candy "github.com/opencharly/pod-android-emulator-layer" is absent from the source scan (0 candies scanned) — cannot anchor the fixture
```

**Root cause.** `checkkit.SnapshotCheckEnv` (`checkkit/checkkit.go:136`) builds the wire `spec.CheckEnv` the plugin sends back to the host for a nested out-of-process verb dispatch, but it omitted `CandyDirs`. The runner HAS the map (`kit.Runner.CandyDirs()`) and the plugin-check live arms populate it (`live_gather.go` ← `candyDirsFromEnvelope(rp)`); the host→plugin snapshot already carries it (`charly/charly/provider_checkenv.go:44`). Only this one direction dropped it, so the host's `resolveCheckApk` (`spec/checkhost/apk.go:63-68`) saw `len(candyDirs) == 0`.

**This is a regression from the R3 `checkkit` one-home cutover, not a schema effect.** plugin-check's previous LOCAL snapshot set `ce.CandyDirs = kr.CandyDirs()`; the cutover replaced it with `checkkit.SnapshotCheckEnv`, which did not carry the field over.

**The 2-file diff:** `checkkit/checkkit.go` (+1 — add `CandyDirs: kr.CandyDirs()` to the snapshot literal); `checkkit/checkkit_test.go` (+21 — the regression test). Head `3cf5c3b` (the fix + a merge of current `main`; the merge carries no source change, so the change under review is still the one line + its guard).
