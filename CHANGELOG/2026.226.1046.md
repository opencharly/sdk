# 2026.226.1046 — `vmshared.QemuAlive`: one QEMU liveness predicate, hardened

The QEMU liveness probe existed in THREE places in the consumer repo, all
answering "is the VM recorded in `<stateDir>/qemu.pid` running?" and none
agreeing on the answer: inline in `charly vm start`, inline in `charly vm
list`'s state scan, and — weakest of the three — in `candy/plugin-preempt`'s
holder probe, the arbiter that decides whether a preemptible GPU-holder VM may
be preempted. This adds the single predicate they now share.

`QemuAlive` belongs in `sdk/vmshared` because it has consumers in more than one
module and the module already owns this class — `VmStateRoot` resolves the state
dir it reads, and `RenderQemuArgv` emits the very argv it matches against.

**It also asserts more than any of the three copies did.** A bare `Signal(0)`
probe reports a recycled PID as "running". Narrowing that with a
`/proc/<pid>/cmdline` substring match on `qemu-system` is still not enough: a
PID reused by a DIFFERENT VM's qemu satisfies it. The consequences are real in
both directions — `vm start` would treat a stopped VM as running and no-op
instead of starting it, and the preempt arbiter would treat a departed holder
as live and refuse to reclaim its GPU.

`QemuAlive` therefore matches `-pidfile <stateDir>/qemu.pid` as ADJACENT
NUL-separated argv fields, which `RenderQemuArgv` always appends, so a live
process is confirmed to be the qemu started for THAT state dir. The comparison
is whole-field rather than substring, so a longer path sharing the same prefix
does not match. `qemu_liveness_test.go` tables the discriminating cases,
including the recycled-onto-another-VM case the substring check accepted and
the prefix case a naive `Contains` would accept.
