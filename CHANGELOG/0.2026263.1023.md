# 0.2026263.1023 — feat(llmkit): surface finish_reason + usage; type the empty-completion and stall errors

## Summary

The shared `llmkit` OpenAI-compatible client **drops two pieces of data the
provider sends** and reports two failure classes as untyped strings. Both make an
RCA of a slow/failed eval impossible, and both block a caller from acting
deterministically on the failure.

This PR surfaces the data and types the errors:

1. **`Message.FinishReason` + `Message.Usage` are now surfaced.** The SDK
   accumulator already receives the provider's `finish_reason` and `usage`
   (including `completion_tokens_details.reasoning_tokens`), but `Chat` discarded
   them. Without them a caller cannot tell a TRUNCATED turn (`finish_reason:
   length`) from a natural stop, nor see the reasoning-token count that makes an
   unbounded reasoning generation measurable.
2. **`include_usage` is requested by default** (in `normalize()`, the one
   chokepoint every Config passes through), so the token split arrives.
3. **Two typed errors replace two string-formatted ones:**
   `*EmptyCompletionError` (carries `ReasoningBytes` + `FinishReason`) and
   `*StallError` (carries the idle bound + content/reasoning/tool counters). A
   caller classifies via `errors.As`, not by matching a library's wording, and can
   treat a deterministic empty completion as NON-retryable.

**Why this matters (measured).** On the real validator context the engine sent no
generation bound; `deepseek-v4.1-flash` (a reasoning model) produced ~200–260 KB
of reasoning, exhausted the output budget, and returned an empty completion — which
the old code reported as a bare string and the caller then blind-retried 3×
(13 minutes, no verdict). With `finish_reason` surfaced and the error typed, the
caller can fail hard immediately instead of re-running a doomed request.

**Fail-without-it (measured):** reverting the `FinishReason`/`Usage` population
makes `TestChat_SurfacesFinishReasonAndUsage` fail (`FinishReason = ""`); reverting
`*StallError` back to a plain `fmt.Errorf` makes
`TestChat_IdleWatchdogBoundsAStall` fail (`stall must be *StallError, got
*errors.errorString`); and the `EmptyCompletionError` test asserts the typed error
carries `finish_reason=length` and a non-zero reasoning byte count.
