# 0.2026287.1311 — feat(deploykit): deliver the microVM shape — a rootfs and a kernel in one VM box

## Summary

Teaches `deploykit`'s VM-box emitter to deliver the **microVM shape**: two artefacts in one box — a raw/ext4 **rootfs** and the **kernel** booted with it — and records the in-image layout it wrote. Closes #379, and is the consumer half of the contract that landed as `opencharly/spec#229` (umbrella ledger WI-3).

The shape is not hypothetical: a microVM's root drive is a **file** the VMM attaches, produced on a device-less host by `mke2fs -t ext4 -d <tree> <file>` (measured as ledger probe **P3**), and the kernel is a **separate** file. `EmitVmBoxAt` wrapped exactly one file from one directory, so a reader had nothing to find a second artefact by.

**One implementation, two shapes (R2).** `EmitVmBox` and `EmitVmBoxAt` keep their signatures and behaviour as thin wrappers over `emitVmBoxArtifacts`; there is no second render path. The build context is the artefacts' **own directory** when they share one — exactly today's behaviour, where the disk is never copied because buildah streams it into the layer — and otherwise a staged context in which a qcow2 overlay is flattened and every other artefact is **hardlinked** (a byte copy only when the filesystem refuses the link, `EXDEV`), so a multi-gigabyte rootfs is still not copied.

**The layout record cannot lie.** `EmitVmBoxMicroVM` builds against a copy of the caller's metadata carrying the layout, and writes that layout back to the caller **only after the build succeeds**. A failed emit leaves the metadata untouched, so a label can never describe a box that was not built — and there is a gate for exactly that.

**Two findings fixed in this change rather than deferred (R1):**

1. The repo's lint gate flagged my own tree: `misspell` on a word in a new comment (reworded), and `unparam` — `requireUsableEngine`'s `engine` parameter is always `"podman"` in this package. Measured discriminator before classifying it: **clean `main` reports `0 issues`** (with the cache cleared), and this change's added call surfaces it. It is dead surface, so it is **removed, not suppressed** (R3 forbids the `//nolint` route); a parameter returns with the second engine, not for a hypothetical one.
2. `AGENTS.md` told a reader to bump the contract's `#SchemaVersion` — a stamp the contract module **deleted** (`spec` `CHANGELOG/0.2026270.938.md`). Corrected in this change (R4), because a contradicted instruction is a defect in the artifact a reader trusts.

**One CI finding, and the two steps it took to resolve it** — both measured, neither guessed:

1. The live e2e failed on the CI runner while passing locally, and its own message said only
   `podman create: exit status 125`, because the helper used `.Output()` and threw the engine's
   stderr away. A failing test that hides its cause is the same defect class as an unsubstantiated
   claim: the evidence is discarded where it is produced. Capturing it made the next run name the
   cause in one line.
2. The cause: `Error: no command or entrypoint provided, and no CMD or ENTRYPOINT from image`. A
   `FROM scratch` image that only COPYs artefacts carries no CMD, and a runner whose podman enforces
   the image config refuses to create a container from it — while `create` executes nothing, so the
   command it demands is inert. One helper (`createContainer`) now owns that step, supplies the
   placeholder, keeps the engine's output on failure, and is used by **both** e2e tests: the
   pre-existing overlay e2e carried the same latent defect, shielded only by the `qemu-img` skip
   above its own create.
