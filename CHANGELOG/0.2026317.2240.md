# 0.2026317.2240 — feat(deploykit): write the plugin manifest through the ONE shared serializer

## Summary

A plugin tree — baked into an image by `EmitBakedPlugins`, or delivered at a venue by a `class:step` — is read by **one** reader, so its `<leaf>.providers` manifest must have exactly one spelling. `sdk/deploykit`'s bake carried its own `strings.Join(providers, "\n") + "\n"` and its own `".providers"` literal; the delivered-tree format that `opencharly/charly#1131` needs would have made that a **third** copy of one format, which is the R2 class this cutover keeps finding.

So this leg deletes the copy and calls the shared serializer that `opencharly/spec#313` (tagged `v0.2026317.2143`) put beside the constant that names it:

- `deploykit/bake_plugins.go` — `spec.PluginManifest(...)`, `spec.PluginManifestName(...)`, `spec.ManifestSuffix`, `spec.ManifestMode`, and the matching `COPY … .providers … .providers` line rendered from the same suffix.
- **The empty-provider case is UNCHANGED, and deliberately so.** The enclosing `len(providers) > 0` guard is what decides whether a manifest exists at all, so `spec.PluginManifest` only ever renders bytes. (Round 1 added a refusal inside that guard, where it could never execute — dead code, deleted in round 2. Turning the empty case into an error would be a POLICY change with its own blast radius, and it does not belong in a leg whose whole point is "same bytes, one function".)
- `go.mod`/`go.sum` — adopt `github.com/opencharly/spec v0.2026317.2143`.

`deploykit/bake_plugins_manifest_bytes_test.go` is the leg's whole point: it asserts the staged manifest **byte-for-byte against a literal**, its mode, and the emitted `COPY` line — so "the repoint changes nothing" is verified instead of assumed. It covers the POPULATED path, which is the only path this leg changes; the empty case is not exercised because it is not touched.

**Round 2** deleted the dead refusal branch and dropped its claim from this body. What remains is a repoint with byte-for-byte equivalence — the tier below says exactly that.
