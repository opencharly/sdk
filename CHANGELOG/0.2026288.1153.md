# 0.2026288.1153 — docs(exitcode): delete the duplicate exit-code table and point at the canonical one

## Summary

This module's re-export file carried a **second copy** of the check-command exit-code convention — the table that says what process exit codes `charly check` returns — while its own docstring says the convention is *"single-sourced here so both the HOST … and candy/plugin-check reference ONE contract"*. **The two copies had already diverged.** The canonical one (`github.com/opencharly/spec/exitcode`) and this one both said 3 meant only *"the bed was SKIPPED (a required host prerequisite — e.g. a GPU — is absent)"*, but the code now reaches 3 by a second route: a check mode whose plan resolution comes back **EMPTY** is a SKIP rather than a pass (`opencharly/plugin-check#110`, fixed in `opencharly/plugin-check#114`), so a reader of this copy learned a narrower contract than the code implements.

This is a **comment-only** change: the duplicated table is deleted and the constants keep their alias form, with the canonical statement named as the place to read. That is the R2 fix rather than a re-wording — a second statement of a contract is a second contract, and the divergence above is the evidence, not the argument. The canonical table itself now names both routes to 3 (sibling PR to `opencharly/spec`), so the pair reads as one change: **the contract states it once, and the re-export points at it**.
