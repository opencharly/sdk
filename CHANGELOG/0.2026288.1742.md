# 0.2026288.1742 — fix(candywalk): decide ref acceptance by shape, not by an instance-shaped constant

## Summary

`remoteRefRe` found prose and handed it to the resolver. Two earlier fixes each excluded one shape — `#406` removed `<` and `>`, `#409` imposed a two-character minimum — and each was derived from a single observed instance. The third instance broke both: `v2026.xxx.yyyy` is four characters longer than that minimum. **So instead of a fourth constant, this splits finding from deciding.**

```go
if len(v) > 1 && v[0] == 'v' && v[1] >= '0' && v[1] <= '9' {
    return calVerRe.MatchString(v)      // a version CLAIMING the tag namespace must be tag-shaped
}
if plainCalShapeRe.MatchString(v) {     // the same rule one `v` to the left: `2026.xxx.yyyy`
    return plainCalRe.MatchString(v)
}
return branchRe.MatchString(v) || shaRe.MatchString(v)
```

Three arms, and the second exists because my own fixture caught the gap on the first run. A version claiming `v<digit>` must be CalVer; a token claiming CalVer *shape* must be CalVer; anything else is accepted only as a lowercase branch (≥2 characters, so a lone `v` dies) or a commit SHA. **The allowlist is what decides** — a character class can only guess, and `vTAG` is four characters, so no length constant could ever have reached it.

**One more defect, found by the A/B rather than by a reviewer.** The negative run printed the captured token with a **trailing backtick**: a real ref written in markdown backticks keeps the delimiter, and the validator would then silently drop it. That is precisely the `sdk#322` failure mode this repo already paid for: a fail-closed pattern dropping a real mutable ref with no error. The backtick now sits in the scanner's delimiter set beside `'` and `"`, and a test pins that a backticked real ref is collected **clean**.
