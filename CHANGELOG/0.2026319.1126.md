# 0.2026319.1126 — feat(loaderkit): entity validation resolves the AUTHORED body through the gates

## Summary

`ValidateEntityCUE` resolved the kind's def from the **base table** (`cueKindDef`). For a kind whose authored body moved into a plugin, that entry is whatever keeper remained — for `vm` it is `#ResolvedVm`, the **post-default envelope**, where `autostart`, `firmware` and `backend` are all required. An authored document can never satisfy it:

```
expected CUE to ACCEPT "vm libvirt modeled field accepted", but it failed:
  t.yml:vm: autostart: field is required but not present
```

`ValidateEntityCUEWithGates` resolves `kindDefFor(kind, gates)` instead — the same resolution the defaults fill uses — so the authored `#Vm` validates authored fixtures. The 3-argument `ValidateEntityCUE` delegates with `nil` gates, so its production caller (`plugin-loader`) is unchanged and every existing caller keeps its behaviour.

With this and `spec#328`'s authored/wire split, charly's `TestCueTightening_RejectsAndAccepts` **and** the six `TestApplyCueDefaults_*` tests all pass — measured on a charly checkout carrying the wave.

This is the second consumer of `opencharly/opencharly#1048`'s authored-vs-wire distinction: the gate path was fixed by `spec#328` + the host's fill; this is the validation path.
