# 0.2026287.726 — feat(loaderkit): the cluster resolver carries the kubeconfig file beside the context

## Summary

A `cluster: <profile>` resolved to ONE string — the kubeconfig context name. A cluster template
addresses a per-cluster kubeconfig FILE (`#ResolvedKubernetes.kubeconfig`, opencharly/spec#221,
tagged `v0.2026287.638`), and a context name cannot select that file, so every consumer of this
helper was structurally unable to honour what the template declared. On an externally-managed
cluster that is exactly the case that matters: the ambient `$KUBECONFIG` / `~/.kube/config` names
some other cluster.

`ResolveClusterViaExecutor` now returns the resolved kind:kubernetes template itself — the
kubeconfig file, the context inside it, and the opaque cluster model — and
`ResolveClusterContextViaExecutor` stays the thin wrapper over it, so every existing caller keeps
its exact contract. One implementation, two views (R2).

Miss and failure semantics are preserved bit for bit: `(nil, nil)` for a legitimate miss (the
project declares no such entity), and a loud error naming the cluster otherwise — the asymmetry
`opencharly/plugin-kube#15` depends on (a resolve FAILURE must never be read as "no cluster
profile"). The existing arms' tests are unchanged and still pass; the new tests pin the same
asymmetry from the full view's side, plus the file riding through beside the context and both
views agreeing, so no caller can behave differently based on which it was written against.

Pins: `spec` v0.2026280.2244 → **v0.2026287.638** (a merged, tagged ref — Policy B).

**Round 1 (head `8079e14`)** answers the validator's round-0 verdict, which was fair:
* the "How tested" evidence was headed with the **base** SHA `2f4014b` — captured before the commit,
  by construction — so it could not be attributed to the changed tree, and the same SHA also
  appeared in the R6 line as `origin/main`, which read as a contradiction. The root fix is in the
  **control**: the gate is now run on the COMMITTED tree (commit → gate → paste → push) and pasted

* the non-blocking R7 note is closed too: the exported `ResolveClusterViaExecutor` had no direct
  call in the diff, so it is now called directly and its nil-executor arm pinned
  (`TestResolveClusterViaExecutorIsTheExportedContract`).
