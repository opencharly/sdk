# 0.2026242.1913 — feat(kit): add the mise detection-builder to BuilderResolve (distro-agnostic stage)

## Summary

Adds the **mise** detection-builder to the shared `sdk/kit.BuilderResolve` (R3 — the ONE render the four detection-builders already use). The mise stage is **distro-agnostic by construction**:

- `FROM {{.BuilderRef}}` — the host-computed builder box (distro-appropriate, e.g. fedora-builder or cachyos-builder); the toolchain (curl+tar) comes from the builder image.
- `{{.InstallCmd}}` — the install command from the embedded `builder: mise:` vocabulary's `install_command`.
- `{{.CopySrc}}/{{.Manifest}}`, `{{.UID}}`/`{{.GID}}`/`{{.Home}}`, `{{.CacheMountsOwned}}` — all from the host's `BuilderResolveInput`.
- The only fixed paths are mise's OWN conventions: the binary at `/usr/local/bin/mise` (the release tarball's layout) and the Home-based data dir (the CopyArtifacts copy the stage's Home, exactly like the pixi builder's `~/.pixi`).

**No hard-coded distro names, package managers, or install paths** — distro knowledge stays in the host's vocabulary (the boundary law: a builder template never names a distro).

**Named version pin (R4):** the pinned mise release is the named `miseVersion` const (`v2026.8.14`), rendered into the download URL via the `miseStageData` wrapper — not a magic literal in the template. Bump deliberately (mise releases weekly); the tarball naming is Go-style arch (x64/arm64) with a `-musl` suffix for musl libc bases.

**Musl-aware download (RCA of the alpine bed failure):** mise publishes glibc builds (`mise-<ver>-linux-<arch>.tar.gz`) AND musl builds (`mise-<ver>-linux-<arch>-musl.tar.gz`). The stage probes for the musl loader (`/lib/ld-musl-*.so.1`) and appends the `-musl` suffix on musl bases — the glibc binary cannot exec on a musl image (missing `/lib64/ld-linux-*`), which the shell reports as `mise: not found` (the check-mise-alpine bed failure).

**Companion deploykit change:** `BoxNeedsBuilder` recognizes the mise detection files (`mise.toml`/`.tool-versions`) so a candy shipping either makes the image need its builder box as a build dependency (the build-graph ordering fix).
