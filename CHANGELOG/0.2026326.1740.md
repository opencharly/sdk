# 0.2026326.1740 — docs(skills): a Claude Code install record is not matched by its path, and update output is not the confirmation

## Summary

Head `6829d1558ba689bfe6c8a8e04b982b0551270d72`. This PR corrects two false claims in `/charly-internals:skills` (`.agents/skills/skills/SKILL.md`, "The corpus must actually LOAD"). It relates to opencharly/opencharly#1227, whose documentation half this session claimed.

1. **"A `settings.json` listing a plugin whose install record belongs to a different project … loads NONE of its skills."** This is false where one repository has several project-scope records, from another clone or a linked or removed worktree. On the host recorded in #1227, a session in the umbrella clone loaded the copy of a second clone's record (`/tmp/umb`, `36609ed9b9ae`), not its own (`cfb7c91b2a47`). The text now says a record is not matched to a session by its exact path. It keeps the measured half: with no record, or one whose `installPath` is gone, nothing loads.
2. **`updated from <old> to <new>` "is the confirmation to look for".** This is false for the same reason. `claude plugin update --scope project`, run from the clone, printed `already at the latest version (66b236ff9727)` and had moved a removed worktree's record, while the clone's own record stayed at `cfb7c91b2a47`. The text now names the fresh-session probe as the confirmation.

The claim-keyed sweep of the umbrella and this repo is pasted below under *How tested*. Neither retired phrase occurs in either tree; the only copy left is the generated marketplace projection of this file, which the next corpus refresh regenerates. `scripts/bootstrap.sh`'s comments about "a record for this project" and `update` moving "an existing record" remain true as written, so they are unchanged.
