# 0.2026275.653 — fix(loaderkit)!: key the derived repo view on the resolved COMMIT — a mutable (@main/branch) ref always re-checks upstream

## Summary

Key the derived **repo view** on the pristine export's **resolved commit**, so a view of a
**mutable / untagged** ref (the default branch, any branch) is re-derived the moment upstream
advances — instead of being reused on the mere presence of the view marker. Fixes `opencharly/sdk#327`.

## RCA

`DeriveRepoView` (`loaderkit/refs_collect.go`) returned `viewPath` as soon as the
`.charly-view-ok` marker existed, and the view path was keyed only on the consumer's compiled
schema/loader identity:

```
reshapeViewPath    = cachePath + ".view." + sha256(spec module ver ‖ sdk module ver)[:16]
marker content     = that identity string            (NO commit)
reuse condition    = "the marker file exists"        (:114-118, re-entry :120-124, locked :136-138)
```

The repo's own commit is **not** an input. The pristine export's freshness IS checked
(`spec/refs` `repoCacheFresh`, re-clone + `.ref` sidecar), and `EnsureRepoDownloaded` correctly
forces it for a mutable ref — but `DeriveRepoView` never read `.ref`, so the **view** stayed
frozen at whatever the ref resolved to the first time.

**Measured:** a bed resolved a bare `@github.com/opencharly/plugin-kube` (→ `main`) and executed
`~/.cache/charly/repos/github.com/opencharly/plugin-kube@main.view.60d7c987d88e7c61/candy/plugin-kube`:

```
$ cat …/plugin-kube@main.ref
{"version":2,"commit":"5b1e0b891a77ad39aeb1b7ede1398bef4887dbad"}   # NEW upstream commit
$ grep sdk …/plugin-kube@main.view.60d7c987d88e7c61/candy/plugin-kube/go.mod
        github.com/opencharly/sdk v0.2026268.1823                    # PRE-merge  (stale view)
$ grep -c 'node.Version' …/main.view.60d7c987d88e7c61/candy/plugin-kube/deploy.go
2                                                                    # the OLD field still present
```

The tagged view `v2026.275.0411.view.…`, materialized today, was correct. So an UNTAGGED ref
served pre-advance content with **no error and no warning**.

## Change

This is the ONE content-addressed path already in the codebase — `cache.Entry.Components`
("valid iff these equal the caller's current set", `spec/cache/cache.go:91-93`) — applied to the
view, the last bespoke cache that used "the marker exists" instead of a content-validity check.

- `repoViewResolvedCommit(cachePath)` — the pristine export's resolved commit
  (`refs.ReadRepoCacheProvenance`), or `""` when unknown.
- `repoViewMarkerContent(cachePath)` — a fresh view's marker now carries that **commit** (or the
  identity when no provenance exists).
- `repoViewReusable(viewPath, cachePath)` — a view is reused ONLY when its marker's commit equals
  the pristine export's CURRENT commit. Immutable tags (no moving commit) keep the identity stamp
  and reuse unchanged; a legacy identity-stamped view re-derives exactly once (the same
  self-healing migration `refs.repoCacheFresh` uses for provenance-less exports).

`DeriveRepoView` now calls `repoViewReusable` at all three prior `os.Stat` sites.
