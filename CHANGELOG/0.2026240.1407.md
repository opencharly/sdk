# 0.2026240.1407 — fix(loaderkit): a repo-root @github ref to a project repo provides its candy/ dir

## Summary

Fixes the Phase-0 distro sweep blocker: a repo-root @github ref (`@github.com/opencharly/charly:v...`) to a PROJECT repo — whose root charly.yml is a project file (version/repo/import/discover + entity nodes), not a candy manifest — previously failed with 'unrecognized candy manifest shape' because ScanRemoteCandy tried to parse the project root as a single candy.

This is the 'charly.yml is everything at once' contract: a repo-root ref must provide EVERY candy the repo owns. The fix scans the repo's candy/ dir and returns all candies keyed by their bare ref (github.com/org/repo/candy/<name>), the same surface the project loader's discover: path provides for a local checkout. A root-level standalone candy repo (manifest at the repo root) still resolves via the normal path.
