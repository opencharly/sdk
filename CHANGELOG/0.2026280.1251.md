# 0.2026280.1251 — fix(loaderkit): terminate a cyclic namespace graph on the materialized wire

## Summary

`MarshalMaterialized` serialized a materialized `spec.UnifiedFile` as `materializedEnvelope{UF: uf}`, and `spec.UnifiedFile.Namespaces` is JSON-serialized (it carries only `yaml:"-"`). The graph it holds is **cyclic by design**: `MaterializeLoadedProject` reference-mounts the SAME `*UnifiedFile` pointer to break cycles and preserve diamonds ("the intentional main↔cachyos mutual import"), and this package's own `capturePluginKindsSeen` documents that cycle. `encoding/json` therefore rejects the marshal:

```
json: unsupported value: encountered a cycle via map[string]*spec.UnifiedFile
```

That made `charly box validate` / `charly task <name>` fail on any project whose import graph contains such a cycle — opencharly/opencharly#330.

The codec now carries the namespace tree **flat**: one `materializedNamespace` per PATH, each `File` a shallow copy with its own `Namespaces` cleared — exactly as the same envelope already carries `PluginKinds` by path. Every path a finite walk reaches survives (diamond and multi-alias mounts included); a genuine back-edge truncates, which is exactly the set `UnifiedFile.collectBeds` enumerates (it returns the instant it re-enters a namespace already on the current path). `UnmarshalMaterialized` rebuilds the tree from the flat levels.

The materialized-tree cache key already includes the sdk module version (`loader_identity`), so the wire-format change re-keys every entry and no stale payload is served.
