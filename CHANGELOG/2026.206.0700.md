# 2026.206.0700 — Cutover 1 sdk contract leg: deploy/build/check-cone envelope extensions

The sdk producer leg of the superproject's **Cutover 1** ("plugins-for-everything,
part 1 — all cones' UNBLOCKED capability moves + banked core reduction"). These
are the contract changes the charly-side plugin moves consume; the charly
consumer leg repoints its gitlink to the merged commit.

## Deploy cone

- **`#DeployTraits.bracketed_lifecycle` (new field).** A substrate declares whether
  its Start/Stop lifecycle needs the Q1 resource-arbiter bracket as DECLARED data
  (P9), instead of the host inferring it from `lifecycleStartPlanHooks` map
  presence. `plugin-substrate` sets it true for `pod`, false for every other
  substrate. The charly consumer derives the bracket signal from
  `deployTraitsFor(word).BracketedLifecycle` — the boundary-law-correct source
  (the per-word hook map stays purely the host-side opts-marshaling mechanism).
- **`ProvidedCapability` proto encode carries `bracketed_lifecycle`.** The
  hand-written `ProvidedCapability → pb.DeployTraits` encode block (`schema.go`)
  now copies the new field, so it survives the provider round-trip (in-proc AND
  grpc). Without this the field was silently dropped and
  `deployTraitsFor(word).BracketedLifecycle` was always false at runtime —
  the regression the check-pod bed caught.
- **`AndroidEntityResolution` drops its google-play credential fields
  (`schema/seam.cue`).** `candy/plugin-adb` now resolves the apkeep google-play
  credentials itself via a direct peer `InvokeProvider(verb:credential)` call —
  the same peer-to-peer pattern `candy/plugin-vm` already uses for
  `verb:arbiter`/`verb:gpu`/`verb:egress` — instead of the host pre-resolving them
  behind the `deploy-entity-resolve` seam.

## Build cone

- **`#BuildResolveBox` extended for candy-side privileged bootstrap
  (`schema/buildwire.cue`).** Carries the fields `candy/plugin-build` needs to run
  the privileged builder-bootstrap step itself, part of the build-cone move out of
  charly core.

## Check cone

- **`kit.StampCharlyBin` / `kit.NewRuntimeCheckVarResolver` (new helpers).** Shared
  `CHARLY_BIN` stamping + runtime check-var resolution the `candy/plugin-check`
  moves delegate to, deduped out of charly core (R3).

No `#SchemaVersion` bump — every change here is a WIRE / helper contract change
(proto/spec/kit), not an authored-config ingress schema change, so no migration
entry is required. `task wire:gen` regeneration is a no-op (reproducible).
