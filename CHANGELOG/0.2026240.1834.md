# 0.2026240.1834 — refactor(ovmf): read the distro family from the distro vocabulary

## Summary

The consumer leg of `opencharly/spec#61`.

`ovmfDistroAliases` parsed an `ovmf_distro_aliases:` directive out of the consumer's embedded
`charly.yml`. It now reads **`spec.DistroOvmfFamilies`**, generated from `#Distros[id].ovmf_family` —
the same vocabulary that already supplies each distro's `format`, `ssh_unit` and `init`.

Three things follow.

**The hand-maintained table is gone.** It lived in two byte-identical copies — charly's `charly.yml`
and plugin-vm's `build_defaults.yml` — that had to be edited together, and editing only one was
silent. Deleting those copies is the next leg; this is what makes them unread.

**A startup panic goes with it.**

```go
if len(doc.OvmfDistroAliases) == 0 {
    panic("ovmf: embedded charly.yml has no ovmf_distro_aliases: directive")
}
```

A consumer embedding a defaults file without that directive **crashed** — even though degrading was
the *designed* behaviour for an unknown distro (union the families). The generated table cannot be
absent, so the panic has nothing to guard.

**`cachyos` gains a family it never had.** The alias table predated the distro, so a CachyOS host
fell through to the union — and that is the host the cstream VM beds run on.

## Preserved deliberately

An unlisted distro still has **no entry**, which is what selects the all-families union rather than
pinning it to a wrong firmware layout. Asserted, not assumed:

```go
if fam, ok := got["nixos"]; ok {
    t.Errorf("an unknown distro resolved to %q; the union fallback is gone", fam)
}
```

## How tested

```
$ go test ./...        (no failures)
$ golangci-lint run
0 issues.
```

`TestOvmfDistroAliasesComeFromTheDistroVocabulary` checks every mapping the old table carried
survives, that the unknown-distro gap survives, and that `cachyos` is new.

`TestOvmfCandidatesUseTheFamily` goes further and checks the mapping is actually **consumed** — a
family that resolves but selects no candidates would be worse than no entry:

- `cachyos` and `arch` yield the **same** candidates, which is what sharing a family buys;
- an unknown distro yields **more** candidates than any single family, i.e. the union fallback is
  really the union.

That test also makes the candidate path testable for the first time. It reaches `ovmfPathTable`,
which needs the `UnmarshalEmbeddedDefaults` hook — nil in a bare unit test, so the first run
segfaulted. The test now supplies a minimal `ovmf_paths` fixture.

Worth noting: that hook used to be needed for **both** halves of the lookup. Only the path data
depends on an embedded file now.
