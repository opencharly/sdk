# 0.2026321.1237 — feat(deploykit): deliver a use: secret: entry as a FILE step at realize

## Summary

**The first producer of a `FileStep` — and the mechanism was already there.**

DESIGN.md:2983 says *"there is no `get`: a value reaches a consumer as a `secret:` need, never as text"*, and D-SEC-1 (:2511) says a secret *"never enters the store, artifacts, labels, IR, state or output"*. Today that is violated by `deploykit.InjectSecretsIntoPlans`, which puts VALUES into `OpStep.Op.Env` so the heredoc renderer emits `export KEY=value`.

This compiles each `use: secret:` entry into a **file delivery** instead:

```go
&FileStep{Source: src, Dest: dst, Mode: 0o600, CandyName: layer.GetName()}
```

and `kit/walk.go`'s `walkFile` — which already ships — does the rest:

```go
content, err := os.ReadFile(step.Source)                                  // the OPERATOR HOST, at realize
exec.PutFile(ctx, step.Dest, content, mode, isSystem(step.Scope))        // the VENUE
```

**The IR carries only the two paths.** The value never enters the plan, the ledger, a log or an artifact, so D-SEC-1 holds **by construction rather than by care** — and because `PutFile` is one method of the substrate-neutral `DeployExecutor` with every deploy target out-of-process on that same walk, **one compiled step serves local, pod and vm.**

### Nothing produced a `FileStep` before this — measured, and it changed the proof

```console
$ for r in spec sdk charly; do echo "$r: $(git -C $r grep -c 'FileStep{' origin/main -- '*.go')"; done
spec:   1     → spec/install_step_view.go:200 -- the WIRE DECODER, not an emitter
sdk:    0
charly: 3     → all *_test.go fixtures
$ grep -rln 'FileStep{' .worktrees/*/plugin-*/ --include='*.go'
(none)
```

So `kit.walkFile` has never been driven by a compiled plan in this tree. **That is why the R7 proof below is at PLAN level — "a compiled step actually lands in the plan, before the candy's own steps" — and not merely "the compiler returns the right struct."** A struct assertion would have proved nothing about whether the step reaches the plan at all.

### The four decisions, and where each is visible

| decision | where |
|---|---|
| **Position** after `extract`, before the candy's own op steps | slot **2.8** in `install_build.go`, so a task that reads `dst` finds it in place |
| **Sorted by entry NAME** | so the plan is reproducible; the sort is one of the two planted failures below |
| **Mode `0o600`** | a secret delivered world-readable is not delivered |
| **Compile-time `optional`** | skip when optional-and-unreadable, error naming candy+entry when required-and-unreadable, error when `src`/`dst` is absent |

**And an unreachable `use:` block is an ERROR, not a silent skip.** `ErrUseBlockUnreachable` wraps, so `errors.Is` classifies it; the message names the offending Go type and points at `NewSpecCandyModel`; and `var _ secretUseCarrier = (*specCandyAdapter)(nil)` pins the one production implementation **at compile time**. A silent skip on a secret delivery is the worst possible failure — the deployment starts without the key it needs and reports success. `TestCompileSecretSteps_UnreachableUseBlockIsAnError` proves the miss with a struct that embeds the reader interface (every method, no accessor).

**The residual race is named in the code comment rather than hidden**: the source is `stat`ed at compile and read at realize, so an optional entry whose file vanishes in between fails at realize instead of being skipped. That is `spec#363` — `FileStep` has no `optional`, so the tolerance is decided one step early. It does not block the delivery, and the issue asks for the shape that would remove the second authority.

### Producer-first, and the deletion that is NOT this module's

`go.mod` bumps `github.com/opencharly/spec` `v0.2026320.2307` → **`v0.2026321.1215`**, the merge that made `CandyUse.Secret` a real map. Producer first, consumer second.

**`deploykit.InjectSecretsIntoPlans` is untouched, deliberately.** Its only caller is the out-of-tree `candy/plugin-deploy-pod` overlay (`git -C sdk grep -rn 'InjectSecretsIntoPlans' origin/main` → one definition, zero in-module callers; the call site is `charly/.build/_candy/plugin-deploy-pod.v2026.274.2042/overlay.go:88`). Deleting it here would break that plugin at its next pin bump. **That deletion is the plugin's cutover leg, not this module's** — producer-first, exactly as the rulebook orders it.

**Both plants are load-bearing**: A proves the step reaches the plan, B proves the order is derived rather than incidental. A test that passes with the call removed would be testing the fixture, not the product.

**But a plan-level proof is not a delivery proof**, so `kit/secret_delivery_realize_test.go` goes the whole way — `walkFile` lives in `package kit`, so a `package kit_test` file can drive `kit.WalkPlans` with a recording `DeployExecutor`:

1. a temp host file with known bytes,
2. `CompileSecretSteps` on a candy whose `use: secret:` block came through `NewSpecCandyModel`,
3. `spec.StepsToView` → the IR the deploy targets actually walk,
4. `kit.WalkPlans(ctx, recorder, …)`,
5. assertions: **the bytes land at `Dest` with mode `0600`** and nothing else was written, **and the bytes appear nowhere else** — not in the plan, not in the serialized `InstallPlanView` a ledger or a log would record.

```console
PLANTED A (the step's Source corrupted, so the walk cannot read it):
  --- FAIL: TestACompiledSecretStepLandsTheFileAndOnlyThere
      WalkPlans: walk step "File" (candy=lab-signing): read file source /nonexistent/planted:
      open /nonexistent/planted: no such file or directory

PLANTED B (the value smuggled into an Op step's Env):
  --- FAIL: TestACompiledSecretStepLandsTheFileAndOnlyThere
```

**Plant B is the assertion that earns the Summary's sentence.** It is not "the bytes moved" — it is **"the bytes are nowhere except the destination"**, which is D-SEC-1 as a property rather than a hope.

And `TestTheSecretStepRefusesAnUnreadableSource` pins the race `spec#363` names: the source is present at compile (so a REQUIRED entry is accepted), then removed before the walk reads it — **the walk FAILS rather than landing nothing and reporting success.**

## Change classification

Kind: a new compiler pass in `sdk/deploykit` plus a `spec` pin bump.

**Breaking change + rollback:** none. `BuildDeployPlan` gains a step at slot 2.8 for a candy that declares `use: secret:`; a candy that declares none compiles byte-identically (`CompileSecretSteps` returns nil for an absent `CandyUse`). `spec.CandyReader` is **not** widened — the accessor lives on `deploykit`'s adapter. The pin bump moves to a merged `spec` tag. Rollback reverts the pin and removes the pass; nothing downstream reads the new steps yet, so the rollback is invisible to every current consumer.

## Filed issues

- **opencharly/spec#363** — `FileStep` has no `optional`, so this module decides `#SecretUse.optional` at compile time with a named residual race. Asks for `optional?: bool` on the File shape so `walkFile` can skip an unreadable source — one authority for the tolerance instead of two.
- **opencharly/sdk#552** — `InjectSecretsIntoPlans` puts secret VALUES into the IR, which D-SEC-1 forbids; delete it once `plugin-deploy-pod` compiles `FileStep`s. Filed from this PR's own finding, with the producer-first order and the out-of-tree call site named.
