# 0.2026250.417 — fix(loaderkit): the declared-but-unconnected structural kind is exempt from the targetless-bed member requirement

## Summary

A structural-kind check bed whose kind is DECLARED in the schema vocabulary but whose serving plugin is NOT CONNECTED during `charly box validate` is now EXEMPT from the targetless-bed-must-have-folded-members requirement in `loaderkit.ValidateCheckBeds`.

After the group:-kind removal (spec #105) a TARGETLESS bed node can only be an external STRUCTURAL plugin kind — every resource deploy kind carries #DeployTraits. When such a kind is declared (`Threaded.StructuralKinds` — connected providers ∪ parse-time pre-scan declarations) but its provider never connected, its OpLoad never runs and the bed folds (or is deferred) without its authored member tree, so the member requirement fired on a shape the plugin never had the chance to produce — the live-verified exposure on the `check-structkind` witness bed (candy/plugin-example-structkind, NOT compiled in).

The principled fix completes the declared-fields design: membership semantics come from the PARENT kind's DECLARED schema, not from runtime registry state. The validator recognizes the structural kind via the recognizedKind vocabulary (`t.StructuralKinds`, clause-D DATA — never a registry query) and exempts the member requirement when the kind's input schema is absent from `t.StructuralDeclaredFields` — the host's documented no-declared-schema signal (a word whose schema is not loaded is left absent; a CONNECTED structural kind's OpLoad dispatch hard-requires the registered def, so presence proves connection). A CONNECTED structural kind whose bed is STILL targetless+memberless keeps failing: the plugin was there and did not fold the authored members — a real defect.

Note on precision: the folded FleetNode does not carry its discriminator word (a structural kind's OpLoad reply is a plain `spec.Deploy`), so the exemption is deliberately load-scoped and conservative — it fires only when at least one declared structural kind is unconnected, and never when every declared structural kind connected.
