# 0.2026268.2244 — feat(loader): wire the kubevirt substrate kind into loaderkit + deploykit

feat(loader): wire the kubevirt substrate kind into loaderkit + deploykit

Companion to opencharly/spec#161 (the `kubevirt` schema, merged + tagged **`v0.2026268.2214`**). The loader recognizes the kind, validates its value against `#KubeVirt`, and resolves a `kubevirt:` deploy's cross-ref.

## Summary of changes

Six files:

- **`loaderkit/cue_schema.go`** — `cueKindDefs["kubevirt"] = "#KubeVirt"` (plus the doc-comment sweep).
- **`deploykit/deploy_nodeform.go`** — `deployCrossRefKeys["kubevirt"] = true` (a `kubevirt:` deploy's `from:` resolves).
- **`loaderkit/kubevirt_test.go`** (NEW, 2 tests) — `TestCueKindDefs_HasKubevirt` (the def resolves + exists) and `TestDeployTraits_DrivesKubevirtStandalone` (the standalone-kind resolution is trait-driven with no kind-word switch).
- **`deploykit/deploy_nodeform_disc_test.go`** — adds **two** table cases to `TestDeployDiscForEntity_PodWorkloadNotGroup`: `{"kubevirt cross-ref -> deploy", "kubevirt: base-vm\n", "deploy"}` and `{"vm cross-ref -> deploy", "vm: base-vm\n", "deploy"}`. The kubevirt case fails without the `deployCrossRefKeys` entry.
- **`go.mod` / `go.sum`** — the `spec` pin bump `v0.2026268.2152 → v0.2026268.2214` (the tag spec#161 minted at merge). This lands the pin IN THIS PR so the committed tree carries `#KubeVirt`; without it the loader's schema fail-fast panics on every call.
- **WS-2.3 (cloud-init renderer hoist)** was already satisfied upstream — `RenderCloudInit` already lives in `sdk/vmshared/cloud_init_render.go` and `plugin-vm` consumes it; no hoist needed, no `plugin-vm` copy exists.
