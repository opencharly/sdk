# 0.2026331.1440 — feat(buildkitdrive): a 100 GB GC budget by default, and every daemon setting configurable

## Summary

`charly box build` of an unchanged tree re-executes its layers on this host. The cause is not the per-build tag (a changed tag with an unchanged digest is a cache HIT): it is **BuildKit's own GC pruning the cache**. buildkitd's compiled default policy keeps a **373 GB free-space target** (`--oci-worker-gc-keepstorage 10000,373000,100000` MB); this host has **247 GB free**, so every GC pass prunes reclaimable cache toward the **~10 GB reserve floor**. The next build then re-executes the evicted layers, and the floating `pacman -Syu` / `releases/latest` steps change the bytes, so the image digest (and the CalVer tag minted for it) moves.

Measured 2026-11-27 (buildkitd 0.35.1, 1.9 TB disk at 87% used):

```
$ buildkitd --help | grep oci-worker-gc-keepstorage
--oci-worker-gc-keepstorage string  (default "10000,373000,100000")  # Reserved 10GB, Free 373GB, Max 100GB

# captured per-step output of `box build arch.arch --tag gap-d` (buildctl wrapper in PATH):
#7  [stage-0] RUN pacman -Syu ... curl ca-certificates   CACHED
#9  [builder] RUN pacman -Syu ... nodejs npm            DONE (re-ran)
#16 [builder] RUN pacman -Syu ... base-devel git        DONE / base-devel downloading+installing
# same parent digest (arch config 53f3ea52f802) — selective cache loss, not the tag

$ buildctl du
Reclaimable: 6.64GB   Total: 7.93GB        # the cache floor, across builds
```

**The change.** `DaemonOptions` now carries the whole `[worker.oci]` daemon surface charly manages — `process_mode`, `max_parallelism`, `snapshotter`, `no_process_sandbox`, the GC budget (`reservedSpace` / `maxUsedSpace` / `minFreeSpace`), per-record `[[worker.oci.gcpolicy]]` entries, the registry mirror, and a raw `extra` TOML escape hatch — and `DaemonConfig` always writes an explicit **100 GB GC budget** (`reservedSpace = "100GB"`, `maxUsedSpace = "100GB"`, `minFreeSpace = "10GB"`). `Ensure` reports, without failing the build, a running daemon whose GC policy predates the request; the value takes effect at the next daemon start.

This is the producer leg of the `charly.yml` surface (`defaults.buildkit`) implemented in `opencharly/spec` and consumed by `opencharly/plugin-build`.

### Spike

**RCA claim:** the cache loss is BuildKit's GC pruning (default free-space target 373 GB > this host's 247 GB free), not the per-build tag.

**Candidates spiked:**
- *A. Leave GC unset (status quo).* Instrument: `buildkitd --help` default + `buildctl du` + a captured per-step build. Result: **fails** — the cache floors at ~10 GB and the builder's large RUNs re-execute while a small one stays cached.
- *B. Explicit 100 GB GC budget + configurable daemon settings.* Instrument: unit-level rendering (`TestDaemonConfig_CarriesTheGCBudget`) + `ConfigGC` round-trip. Result: **works** (rendered and read back); the live daemon-level effect is the consumer boundary's bed (the charly pin-bump PR), per the contract-module gate.
- *C. Set only `minFreeSpace` small, leave the rest to the default.* **Rejected by inspection**, with the daemon's own defaults as the instrument:
  ```
  $ buildkitd --help | grep gc-keepstorage
     --oci-worker-gc-keepstorage string   Amount of storage GC keep locally, format "Reserved[,Free[,Maximum]]" (MB)
                                          (default: "10000,373000,100000")
  ```
  So the worker's three values are NOT undefined — they are **Reserved 10 000 MB (10 GB), Free 373 000 MB (373 GB), Maximum 100 000 MB (100 GB)**, and the running daemon demonstrates the consequence on this host:
  ```
  $ buildctl --addr unix:///run/user/1000/charly/buildkitd.sock du
  Reclaimable:  9.38GB
  Total:        10.35GB
  $ df -h /home | tail -1
  /dev/mapper/root  1.9T  1.7T  170G  91% /home
  ```
  170 GB free, and the cache sits at ~10 GB: the **reserve floor**, not an undefined budget, is what retains it. C expresses one of the three values (the free-space target) and leaves the reserved floor and the ceiling inherited, so a policy that wants a different floor or ceiling cannot be authored — which is exactly what #1292 needs. The explicit three-key budget makes all three the operator's.

**Winner:** B. **RCA verdict:** confirmed — the default policy's free target is the pruning driver; the explicit budget removes it.

## Change classification

The default GC budget changes behaviour: a buildkitd started by this drive keeps up to 100 GB of cache instead of pruning to ~10 GB, and an already-running daemon keeps its old policy until restarted (reported on stderr, never fatal). **Breaking change + rollback:** none for the module API beyond new optional fields on `DaemonOptions`; rollback is a revert of this squash, which restores the GC-unset renderer.
