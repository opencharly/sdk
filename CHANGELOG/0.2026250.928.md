## Summary

Cutover C tasks 5-7 (CC-3 wave, PR 2 of 3: spec → **sdk** → charly → umbrella).

**The canonical stage-grouped + concurrent bed-member walk** (`kit/planrun_staged.go`, task 5):
- `RunPlanStaged(ctx, members []MemberRun, parallel, strict)` executes a bed's member plans with the CC-3 execution model; `RunPlan` now delegates to it (ONE canonical engine, R3).
- When ANY step carries `stage:`: steps are grouped by stage and stage groups execute in FIRST-SEEN order (recorded from the authored order at load — task 4). Within a stage, steps on DIFFERENT members run as INDEPENDENT Runner instances CONCURRENTLY (A4 — never share one Runner); same-member steps keep authored order. `parallel:` does not interact with stages — stages dominate.
- Without stages: today's sequential per-member walk, plus whole-member-plan concurrency when `parallel: true`.

**Concurrency-safe result collection** (task 6): per-member result slices; ONE mutex serializes every shared-summary append (the A4 fix — no races in the -race run); final order is venue-keyed deterministic (members in authored order, steps in authored order), never completion-time.

**Drain semantics** (task 7): a member step failure does NOT stop other members — every stage's WaitGroup barrier drains all its members before the next stage starts; per-member verdicts land in the results. Tear-down of all members on every terminal path stays the bed runner's job (plugin-check), which the drain makes safe to rely on.

**Load-time all-or-nothing validation** (task 4): `loaderkit.ValidateCheckBeds` now rejects a bed whose root + whole uniform member tree MIX staged and unstaged steps (stage authoring is all-or-nothing per bed) — the walk can then rely on unambiguous grouping. Dot-free stage names are CUE-enforced on #Op (spec #116).

Spec re-pin: `github.com/opencharly/spec v0.2026250.709 → v0.2026250.903` (the stage:/parallel: schema).
