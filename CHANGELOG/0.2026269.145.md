# 0.2026269.145 — feat(schema): carry a command parent through the capability authoring surface

## Summary

Complete the capability-identity contract on the SDK authoring surface, consuming
opencharly/spec#167 (tag `v0.2026269.138`).

A command capability's identity is `(class, word, parent)`. The parent — the CLI group a
command nests under, e.g. `box` for `charly box generate` — is now a DECLARED field, not a
compiled-in fact, so an authoring plugin expresses it identically whether it runs compiled-in
or out-of-process.

**What this PR adds, precisely** (the field itself arrives through the spec bump, so it is not
in this diff):

- the sdk go.mod pins the **merged** spec tag `v0.2026269.138`, whose
  `capability.ProvidedCapability` (which the sdk aliases as `ProvidedCapability`) now carries
  `CommandParent`;
- **`BuildCapabilities`/`BuildCapabilitiesWithRequires`** map `ProvidedCapability.CommandParent`
  onto the wire `pb.ProvidedCapability.command_parent`, and **reject** a parent on any
  non-`command` class (only commands nest), mirroring the CUE grammar;
- **`Requirement.CommandParent`** — a declared peer may be a nested command, named distinctly
  from its top-level same-word twin — plus its wire mapping onto `pb.PluginRequirement`.
