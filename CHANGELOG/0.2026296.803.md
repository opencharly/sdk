### The candy, and what it is not

`sdk-skill-shelf` is a **CONCEPT candy**: `plan:` is a `true` no-op plus a `true` check, it ships
no install content, and it composes no box. Its only job is to own routing metadata:

```yaml
sdk-skill-shelf:
    candy: { … }
capabilities-skill:
    skill:
        name: capabilities
        family: internals
        owner: sdk-skill-shelf
        triggers: [ "OCI labels / capabilities contract" ]
```

Routing-only: `name`/`family`/`owner` plus the `triggers:` that generate the `DISPATCHER.md` row.
**No inline `description:`/`content:`** — the shape `pod-ollama#7` and `#612` both used. The prose
is the file, and an inline body that disagrees with its file is a hard error in the marketplace
generator. `family` stays `internals`, so every `/charly-internals:<skill>` address and the corpus
path `<family>/skills/<name>/SKILL.md` are unchanged.

**Two things this candy is not, stated plainly rather than implied.** Its second plan step is
`command: "true"` and asserts nothing — it is a validate-satisfying no-op, and the real
body-existence gate is `charly box validate`, proven to read these files by the negative control
below. And **three of the seven nodes carry no `triggers:` at all** — `cloud-init-renderer`,
`libvirt-renderer`, `ovmf` — because the carrier declared none for them: this PR preserves a
pre-existing absent `triggers:` rather than dropping one, and adding one would be a config change
(it emits a dispatcher row) that is not a relocation's business.

**How the name respects the class rule.** "Repo classes and naming" says bare names are for
core/contract repos — `sdk` **is** one, and this PR does not touch its name. What it adds is a
*carrier candy inside a repo that already holds code*, which that same section explicitly
sanctions. The name is chosen so it cannot be read as a product family: a family is a
`layer-<family>` repo, never a bare name, and product candies are bare nouns or
`<noun>-layer/-full/-base` — whereas `sdk-skill-shelf` states what it *holds* (this repo's skill
shelf) and carries the repo's own class in its prefix. It is deliberately **not** the retired
`*-skills` carrier-**repo** shape either: that class is a repo whose only content is prose, and
this is one node in a repo full of Go.

**No OCI label entry.** The candy composes nothing, so there is no image for `CollectSkills` to
project onto — measured, not asserted:
