## Summary

`plugin.providers:` and `plugin.requires:` both name a `#PluginCapability`, but only the `providers:` path had its **class vocabulary** checked. `spec#216` made the CUE pattern's class segment *structural* — retiring the CUE-side check on both paths — which would have left `requires:` with no vocabulary check anywhere. This PR moves the check into the one shared reporter, so both paths share one taxonomy (R3) and `requires:` names an undeclared class instead of calling a correct word `malformed`.

What changes:

- `candy/plugin-box/validate_rules.go` — one `reportCapabilityFault` shared by both paths.
- `candy/plugin-box/validate_parity_test.go` — `TestPluginRequiresClassVocabulary` covers both directions.
- `charly.yml` — one `check:` step in `check-box-local` witnessing the `requires:` arm.
- The fixture rename `workflow:lobster` → `zzznotaclass:lobster` is **required, not incidental**: `workflow` joined the known vocabulary (`schema/candy.cue:559`), so the old fixture went **red** on `main`, and nothing surfaced it because this repo has **no `ci.yml`** (`#38`).

Fresh branch off `origin/main`; supersedes `#37`, which the verdict counter auto-closed. The pre-change ref here is simply `origin/main`, which retires the proof-binding findings the old thread kept producing.
