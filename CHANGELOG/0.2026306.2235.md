# 0.2026306.2235 — fix(buildkitdrive): --progress plain, plus a premise guard that tells broken from invisible (successor to #479)

## Summary

Two changes in one cutover, both about **a failure having to say what happened**.

1. **`buildkitdrive/buildctl.go` — `buildctl` now gets `--progress plain` explicitly.** Its progress mode was left to `auto`, which picks the mode from whether the caller looks like a terminal. The same build therefore reports differently in a terminal and in CI, and a non-terminal caller (a workflow, a captured subprocess, a log file) loses the failing step's own output — surfacing only `did not complete successfully: exit code: 1`. Measured on an org image build in CI: a recipe's first `RUN` failed with no step output at all, which cost five wrong hypotheses before the daemon log named the real cause (`opencharly/.github#271`).

2. **`vmshared/qemu_liveness_test.go` — tell an unreadable argv apart from a dead helper.** `TestQemuAliveLiveForeignQemu` failed on CI with `premise broken: ""` — an **empty** cmdline. Its helper is a live `sleep(30)` symlink named `qemu-system`, so an empty read means one of two opposite things: the helper is **gone** (the premise really is broken and the test must fail), or the helper is **alive** but the runner does not expose another process's argv (a **visibility limit of the runner**, not a defect in `QemuAlive`). The test now signals the helper to distinguish them: dead fails with the error, alive-and-unreadable skips **visibly, naming the reason**.

**Files in the diff — all four:**

| file | change |
|---|---|
| `buildkitdrive/buildctl.go` | `args := []string{"build", "--progress", "plain", "--frontend", "dockerfile.v0"}` plus the rationale comment |
| `buildkitdrive/buildkitdrive_test.go` | `TestBuildArgs_ExportShape` now **requires** `build --progress plain --frontend dockerfile.v0` |
| `vmshared/qemu_liveness_test.go` | the liveness test now switches on `qemuPremiseOutcome` instead of inlining the branch |
| `vmshared/qemu_premise_test.go` (new) | the pure decision `qemuPremiseOutcome(cmdline, alive)` and `TestQemuPremiseOutcome`: marker present → assert; **empty** argv while alive → skip visibly; **readable argv without the marker** → the premise is broken and the test fails; helper gone → fails |

**No import hunk is needed in `vmshared`.** `syscall` was already imported (line 10 of the import block) because the file already called `cmd.Process.Signal(syscall.Signal(0))` for its first premise guard; this change reuses it. That is why the diff has no import change, and it is a fact about the file rather than an omission.
