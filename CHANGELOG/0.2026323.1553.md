## Summary

A quadlet deploy was emitted with `UserNS=keep-id:uid=…,gid=…` **whenever it had a bind mount**, and a unit that
also carries the CDI GPU device cannot start under that mapping:

```
Error: crun: mount_setattr `/usr/bin/nvidia-cuda-mps-control`: Operation not permitted: OCI permission denied
```

Measured today on this host (podman 6.2.0, crun 1.31, rootless, overlay) against **two different images**, so the
image is ruled out: `--device nvidia.com/gpu=all` alone rc=0; the same with `--userns=keep-id` rc=126; with
`--userns=keep-id:uid=0,gid=0` rc=126; with `--group-add keep-groups` rc=126; with the CDI target paths pre-created in
the image rc=126. `--userns=host` + the device rc=0, and `--userns=host --user 0` + the device + a bind rc=0 with the
bind writable and the file owned by the host user. `--userns=keep-id` without a device, and with a FILE or DIR bind
but no device, is rc=0 — keep-id itself is fine, keep-id × CDI is not.

So the renderer's OWN existing fact decides the mapping: `carriesCDIDevice(cfg)` — the same predicate that already
emits `AddDevice=nvidia.com/gpu=all` — turns the keep-id line into `UserNS=host` + `User=0:0`. In a rootless pod that
"root" is still the unprivileged host user, which is why a host-owned bind stays writable AND the CDI device resolves.

One decision, three arms, no second list of "GPU deploys":

| resolved deploy | emitted user-namespace mapping |
|---|---|
| bind mount + CDI device | `UserNS=host` + `User=0:0` — **new** |
| bind mount, but the unit carries NO CDI device (no GPU, **or** a privileged unit, which gets every device through `--privileged` and is never given a CDI mount) | `UserNS=keep-id:uid=<uid>,gid=<gid>` — **unchanged, byte for byte** |
| no bind mount, with or without the device | unchanged — keep-id was never in play, so neither `UserNS=` nor `User=` is emitted |

The consumer half is **opencharly/plugin-deploy-pod#81**: the argv emitters (the engine `start_plan` body,
`charly shell`, `charly exec`) take the same rule from one predicate over the resolved GPU fact and the existing
`GPUArgStyle == "cdi"` capability seam. This PR is the producer leg — the quadlet render is the only emitter this repo
owns, and `deploykit.GenerateQuadlet` cannot be post-processed by its caller.
