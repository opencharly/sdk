# 0.2026269.920 — fix(sdk): namespace-aware descent stamp, deploy projection, entity resolver

## Summary of changes

Make the SDK's deploy/entity resolution namespace-aware — the SDK half of the
whole-roster failure fix (plan §4.1).

### RCA (8-step, measured live)
**Unexpected.** `charly check run check-all-beds` failed EVERY namespaced VM-root bed
(`charly.check-agentteams-vm`, `charly.check-helm-vm`, …). A namespaced node reached
the bed runner with `Descent==nil` → `deploy.IsVmVenue` false → a `vm:` root
misclassified as a pod (`vm-build` skipped; `deploy-add` failed on an empty ref).

Three root-scope-only projections:
1. `loaderkit.StampDeployDescents` iterated only the ROOT `uf.Deploy` map.
2. `deploykit.ProjectDeployConfig` projected root-only `uf.Deploy`.
3. `loaderkit.ResolveKindEntityBody` descended only ONE namespace level.

### Fix
- `StampDeployDescents` recurses every namespace (path-scoped ancestor guard).
- `ProjectDeployConfig` projects `uf.Deploys()` (the namespace-qualified fold).
- `ResolveKindEntityBody` resolves via `ProjectTemplates().ByKind` (recursive).

## Change class

`charly-or-sdk Go` (the sdk contract module) — changes charly's runtime resolution.
