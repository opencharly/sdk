## Summary

Closes the one residual `#411` deliberately left open. Prose that slips past the shape rule is now rejected **by shape**, not by the context rule the issue itself proposed.

```
rejected already (from #411):  vTAG · v · v2026.xxx.yyyy · <tag> · v<version> · 2026.xxx.yyyy
now also rejected:             vx.y.z
```

`vx.y.z` starts `v`+letter, so it misses the tag-namespace arm, and `x.y.z` is lowercase alphanumerics, so the branch arm took it — a prose token that reaches the resolver as a ref that cannot exist.

```go
// every component one or two characters: a real version's components are digits (a tag) or words (a branch)
stubVersionRe = regexp.MustCompile(`^[A-Za-z]{1,2}(\.[A-Za-z0-9]{1,2}){2,}$`)
```

**What this change deliberately does NOT do, because checking killed two of the three rules I first designed.** `#412` proposed deciding from the token's **context**. I wrote that design, then ran it against the fixtures already on `main` before writing any code, and two of its three rules did not survive:

1. **"Inside a markdown code span means prose" is harmful.** This repo's own fixture requires that a **backticked real ref be collected clean** (`candywalk_refs_class_test.go`, `"a backticked real ref must be collected clean"`), and the corpus writes live refs in backticks. That rule would have rejected them — `opencharly/sdk#322`, written fresh.
2. **Its premise was already green.** The form it was meant to catch, `v2026.xxx.yyyy`, is **already in `#411`'s reject list** — handled two rounds before the rule was proposed.
3. **"A placeholder in the repo path" is dead code**, because the scanner already excludes `<` and `>` from the repo-path class, so no match reaches such a rule.

So the fix is one shape rule, and the issue closes rather than shrinking.
