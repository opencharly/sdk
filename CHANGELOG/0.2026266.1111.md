# 0.2026266.1111 — refactor(loaderkit): materialized tree on the OCI ArtifactStore + DeriveRepoView

## Summary

Folds the materialized-tree cache onto the new `spec/cache` **ArtifactStore** (the OCI-Image-Layout, content-addressed cache merged in **opencharly/spec#148**) and replaces the in-place repo-cache schema migration with **`DeriveRepoView`**.

1. **Materialized tree → `ArtifactStore`.** `loaderkit/load_cache.go` opens the shared store as `cache.OpenLayoutLimited(dir, N)` (was `cache.Store`/`Open`/`OpenLimited`), reads/writes via `Layout.Get`/`Put` with `Entry{Payload, Components}`, and keys on the same components digest (`cache.HashHex`/`KeyDigest`, unchanged). The Docker-cache rule is preserved: components-only validity, no TTL; prune stays storage-only.

2. **`DeriveRepoView` — derive, never mutate.** `loaderkit/refs_collect.go`'s `EnsureRepoDownloaded` no longer auto-migrates the fetched cache **in place**. Instead:
   - a tree already at HEAD is returned as-is (fast path, no copy);
   - a behind-HEAD tree gets a **schema-keyed derived view** (`<cachePath>.view.<headSchema>`) materialized once by copying + migrating a private staging dir, published by **atomic rename** with a completeness marker — so a crash never publishes a torn view, and the **pristine export is never rewritten**.
   - the re-entry guard (`markRepoAutoMigrating`) now keys on the VIEW path (a migration re-enters `LoadUnified` → `EnsureRepoDownloaded` for the same view; the per-view once-per-process guard terminates the cycle).

**Why this is the root fix for the `check-substrate` `deploy-add` failure.** The pre-cutover loader rewrote `~/.cache/charly/repos/github.com/opencharly/charly@main/charly.yml` in place to the *consumer binary's* schema CalVer (261), poisoning the shared cache for every 249 consumer — the exact error `config schema 2026.261.1747 is newer than this charly supports (max 2026.249.2125)`. With a derived view, each schema version reads its own tree and the pristine export stays exactly as fetched. (The spec half — v2 provenance hard-rejecting the legacy sidecar so an already-poisoned cache self-heals — is in #148.)

3. **Pin the merged spec.** Bumps `github.com/opencharly/spec` to the merged tag `v0.2026266.1044` (the #148 merge tag). (The branch was developed against a temporary local `replace` for the in-flight art; the NET diff drops it — `git diff origin/main -- go.mod | grep -c replace` → 0 — and `go.mod` now pins the published tag, no `replace` directive in the shipped tree.)
