# 0.2026264.731 — fix(llmkit): carry the full reasoning text on empty-completion and stall errors

## Summary

Carry the **full reasoning text** on `EmptyCompletionError` and `StallError`, alongside the existing `ReasoningBytes` count.

**Why.** These are the two terminal failures a reasoning model produces. Both kept only the *byte count* of the reasoning they generated. A byte count cannot tell a model **stuck re-deriving one point (a loop)** from one **deliberating a genuinely long chain** — the exact distinction a runaway-thinking RCA turns on. Measured on a real PR-review run: 371 KB of reasoning was indistinguishable, from the logs alone, from productive work; the full text is what proved it was a re-derivation loop.

This is a diagnostic-completeness fix: the data existed at each construction site and was discarded. It is now carried on the typed error so every caller can surface it.

Change:
- `EmptyCompletionError.Reasoning string` — set at its construction site in `Chat`.
- `StallError.Reasoning string` — set at its construction site.
- Both `ReasoningBytes` fields are unchanged.

No behaviour change on the success path; no wire/API change.
