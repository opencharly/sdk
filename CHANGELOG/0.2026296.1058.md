# 0.2026296.1058 — feat(deploykit): the W3.1 selection resolvers — engine, VM backend, containerd target

## Summary

The W3.1 producer leg in `sdk`: three canonical selection resolvers in `deploykit`, over ONE precedence rule.

**Precedence (every setting):** `flag > deploy entity > env > settings file > built-in default`. The env > settings fold is `hostenv.ResolveRuntime`'s existing job — this change does not re-implement it; the runtime argument carries the folded value and the tests drive that fold end-to-end.

```go
func ResolvePodEngine(flag string, deploy Selection, rt *kit.ResolvedRuntime) (spec.EngineName, error)
func ResolveVmBackend(flag string, deploy Selection, rt *kit.ResolvedRuntime) (spec.VmBackend, error)
func ResolveContainerdTarget(engine spec.EngineName, deploy Selection, rt *kit.ResolvedRuntime) (ContainerdTarget, error)
```

- **`ResolvePodEngine`** — `auto` detects (podman then docker). A candy's `engine:` is a CONSTRAINT: a conflicting resolved engine is a validation error, never an override.
- **`ResolveVmBackend`** — `auto` detects in the schema's own word order (`spec.VmBackends`: libvirt then qemu); krun is explicit-only and has no probe. The probe table's keys are drift-tested against `spec.VmBackends`.
- **`ResolveContainerdTarget`** — `{engine, rootful, address, namespace, privilegePrefix}`. Rootful is capability-checked (`supports_rootful`); `native` applies no privilege prefix, every other concrete mode uses `privilege_prefix`. Namespace is `flag > deploy > settings > the capability's namespace fact` (`default` for containerd). Address comes from the capability row.
- No word literals for engine behaviour: `spec.EngineNames`, `#EngineBinaries`, `#EngineCapability`, `spec.VmBackends` and `spec.RootfulModes` are the sources.

**Spec pin:** `github.com/opencharly/spec` advances `v0.2026295.2356 → v0.2026296.1036`, the tag minted at merge of `opencharly/spec#275` (`a431987`). That producer added the three surfaces W3.1 needs: `#RootfulMode` + `#Deploy.rootful` + the `rootful` selector, `#VmBackendName` → `spec.VmBackends`, and `ContainerdConfig.Namespace` / `ResolvedRuntime.Namespace`.

**Not touched:** every consumer repo. The migration work list is filed on `opencharly/opencharly#589` (see Change classification).
