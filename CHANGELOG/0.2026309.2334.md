# 0.2026309.2334 — fix(loaderkit): collect an imported namespace's kind:local remote refs

## Summary

Fixes opencharly/sdk#488. `CollectRemoteRefsOpts` collected `kind:local` template candy refs from
only the ROOT `Config.Local` map. `UnifiedFile.ProjectTemplates` folds every imported namespace's
local templates into the resolved-project envelope under qualified keys
(`cachyos.charly-cachyos-app`), so `plugin-box`'s `validateLocalTemplates` checked those refs
against a candy-model set that never received them and reported candies that exist as missing.

The collector now walks `cfg.Namespaces` recursively with the SAME path-scoped ancestor guard the
loader already owns (`namespace_walk.go`'s `ancestorStack`, now the one implementation behind
`NamespaceAncestors`). One implementation serves the root and imported paths: a mutual import
terminates, and a namespace mounted at several alias paths still contributes under each.

Head `1f5b7954e54aaf2ac355b072212b1c622bc94225`.

- `loaderkit/refs_collect.go` — the root-only `Local` loop becomes the recursive walk.
- `loaderkit/namespace_walk.go` — `ancestorStack[T]` extracted; `NamespaceAncestors.Enter` delegates to it.
- `loaderkit/refs_local_namespace_test.go` — the regression guard (imported-namespace collection,
  cycle/multi-alias termination, and a negative control for bare local candies).
