# 0.2026248.632 — fix(loaderkit): cached latest-tag route — kill the version-less ls-remote fanout

## Summary

The version-less `@github` ref resolution fell back to the RAW `refs.GitLatestTag` (`git ls-remote --tags`) when the walk's in-memory tags map missed. That map is PER-PROCESS, so every CLI-subcommand child of a wave (each `charly fleet add` / `check live` / rebuild) re-ran the ls-remote — measured at 90–94 concurrent `git ls-remote` procs across the fleet-adds (waves respawned ~every 2 min) → GitHub throttling → the deploy-add phase stalling (104–325s per lane). The fix routes the fallback through `gitClient().LatestTag` — the 1h-default-TTL cache (spec #93), disk-persisted and shared across processes — so a warm cache serves every child with zero network.
