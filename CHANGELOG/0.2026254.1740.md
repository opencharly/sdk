# 0.2026254.1740 — refactor(loaderkit): export RepoOverrideDir — the ONE CHARLY_REPO_OVERRIDE parse (R3 root fix for charly#587)

## Summary

**R3 root fix for the charly#587 validator finding (B7).** That PR's body claimed loaderkit
`repoOverrideDir` was the single implementation of the `CHARLY_REPO_OVERRIDE` parse — but the
function was **UNEXPORTED**, so charly core could not call it and re-implemented the parse
(`localOverrideRootFor` in `charly/plugin_loader.go`: comma/`=` split, `~/` expansion,
path normalization, dir check). The duplicate existed *because* the sdk's one implementation was
unreachable from outside the module.

This PR makes it reachable:

- **`repoOverrideDir` → `RepoOverrideDir`** (`loaderkit/refs_collect.go`), exported with the
  signature and semantics **unchanged**: `(repoPath, envValue string) (string, bool, error)`.
  Body untouched — malformed entry → hard error; missing/empty dir → error; non-directory target →
  error; no match → `("", false, nil)`.
- The doc comment now states the contract: this is **THE single implementation of the
  `CHARLY_REPO_OVERRIDE` parse** — the comma-separated `repoPath=localDir` split, the LHS
  repo-path normalization (bare `owner/repo` auto-prefixed with `github.com`, the same rule as
  `spec.NormalizeRepoSpec`), the `~/` home expansion, and the exists-and-is-a-directory check —
  serving **both** this mechanism's own ref resolution (`EnsureRepoDownloaded`) **and** external
  consumers (charly core's provenance logging). A consumer MUST call this rather than re-parse the
  env value.
- The internal call site in `EnsureRepoDownloaded` is updated.
- `normalizeOverrideRepoPath` stays unexported — it is an implementation detail of the parse.
- The three existing test functions (`TestRepoOverrideDir`, `TestRepoOverrideDir_LocalResolution`,
  `TestRepoOverrideDir_OperatorFirstWins`) are updated to the exported name and remain green.

Consumer note (the follow-up charly PR, **not** this one): the call sites that know the repo path
(`host_build_remote_image_resolve.go` has `parsed.RepoPath`) can now resolve the override root by
calling `loaderkit.RepoOverrideDir(repoPath, os.Getenv(proc.RepoOverrideEnv))` instead of parsing
the env value themselves; the plugin-loader provenance line keeps only its own "does this source
dir lie under that root" question, not a second parse.

No schema, wire, proto or go.mod change — an export rename only.
