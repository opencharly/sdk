## fix(ci): replace inline auto-merge with reusable engine from .github

### The change

Replace the inline auto-merge engine (353 lines of bash in `.github/workflows/auto-merge.yml`)
with a ~15-line dispatcher that calls the canonical reusable engine at
`opencharly/.github/.github/workflows/auto-merge-reusable.yml`. All the
engine logic (checking status checks, finalizing CHANGELOG, enabling
native auto-merge, tagging) is preserved — just moved to a single source
of truth.

Adds a companion `tag-on-merge.yml` dispatcher for CalVer tagging on merge.

Removes `.github/scripts/auto-merge-harness.sh` and `.github/scripts/auto-merge-runblock.sh`
(the old RDD coverage; replacement harness lives in opencharly/.github).

### Why

**Single source of truth.** Previously, 14 repos each had their own copy
of a 353-line inline bash engine. Any bug fix or improvement required
14 identical PRs. Now one reusable workflow in `.github` serves all repos.

**Trigger mechanism.** The dispatcher uses `pull_request: [labeled]` with
the `auto-merge` label, triggered explicitly when the PR author or a
maintainer adds the label. This is more reliable than `workflow_run` or
`check_run` events (which don't always fire correctly cross-repo), and
gives explicit user control over when merging happens.

The reusable engine (`auto-merge-reusable.yml`) then:
1. Checks ALL check runs on the PR head — if any pending or failed, exits
2. Finalizes the CHANGELOG placeholder to the merge-time CalVer
3. Enables native auto-merge (`enablePullRequestAutoMerge` via GraphQL)
4. Exits — GitHub handles the merge via branch protection
