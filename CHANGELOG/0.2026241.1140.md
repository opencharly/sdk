# 0.2026241.1140 — feat(kit): PopulateSystemInfo — the `system:` section of the per-host charly.yml

## Summary

The per-host charly.yml (`~/.config/charly/charly.yml`) is the SINGLE home for local system state — deployments (`deploy:`), install records (`ledger:`), local system info (`system:`), and cache status (`cache:`). This adds the `system:` populator (spec#66 `schema/system.cue` `#SystemInfo`): it detects the host identity (hostname, distro, kernel, arch, GPU, virtualization, podman) and writes it into the `system:` section via a lightweight YAML read-modify-write that preserves every other key, under the advisory file lock. `charly status` (via plugin-substrate) is the natural refresh point.

- **`kit/system_info.go`**: `detectSystemInfo` (best-effort probes — an unreadable /etc/os-release, a missing podman, or an undetectable GPU leaves that field empty) + `PopulateSystemInfo` (detect + section-preserving write).
- **`kit/system_info_test.go`**: the populator preserves deploy/cache sections and stamps the HEAD schema version on a fresh file.
