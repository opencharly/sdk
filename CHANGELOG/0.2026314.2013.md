# 0.2026314.2013 — fix(loaderkit)!: the candy body's load-time field gate is the closed #Candy schema

## Summary

`loaderkit` gates a candy BODY's top-level keys before CUE-decoding it, because the load-time decode is
LENIENT (`DecodeEntityViaCUE` does `BuildFile`+`Decode` with no `Unify` against the schema, so an
unknown key is silently dropped — only `charly box validate` would catch it). The gate's admitted set
was a hand-written map of 43 keys, and **nothing tied that map to the CLOSED `#Candy` schema it
duplicated**, so it had drifted in BOTH directions. Measured against the contract's own field set
(`cueDefFields("#Candy")`) on this change's base (`665a4f9`) and on this head:

```console
$ go test ./loaderkit/ -count=1 -run TestZZScratchDrift -v      # scratch harness, BASE tree 665a4f9
PROBE schema #Candy fields = 44, candyKnownFields = 43
PROBE admitted-but-NOT-in-schema (4): [from libvirt localpkg version]
PROBE in-schema-but-NOT-admitted (5): [agent_provide external_builder packaging skills terminal_profile]

$ go test ./loaderkit/ -count=1 -run TestZZScratchDrift -v      # scratch harness, THIS HEAD 24b7d46
PROBE schema #Candy fields = 44, candyBodyFields() = 44
PROBE admitted-but-NOT-in-schema (0): []
PROBE in-schema-but-NOT-admitted (0): []
```

- **Four retired fields were still admitted**, and silently dropped on decode: `version` (the version
  stamp retired by `opencharly/spec` `CHANGELOG/0.2026270.938.md`), `libvirt` (the candy-level raw-XML
  snippet field, removed), `localpkg` (replaced by `packaging:`), and `from` (a `#Box` field — a candy
  node carrying one is routed to `#Box` in the node form, so a `from:` reaching a candy BODY is a shape
  error the loader swallowed).
- **Five fields the schema DECLARES were refused**, each under the generic message *"almost always a
  plural/singular typo"*: `skills:`, `packaging:`, `external_builder:`, `agent_provide:`,
  `terminal_profile:`. A legacy manifest declaring any of them **failed to load**, with a diagnosis
  that sent its author hunting for a typo that does not exist.

This PR deletes the copy and makes the gate's vocabulary **the schema**: `candyBodyFields` projects
`#Candy`'s own field set through `cueDefFields(cueKindDefs["candy"])` — the *same*
contract-declared-field extraction `declared_fields_floor.go` already uses for the parse's
declared-fields floor, so this is not a second mechanism (R2). A field the schema drops stops being
admitted; a field the schema declares is admissible. The four retirements get a **named** diagnosis in
`rejectLegacyCandyKeys`, beside the `depends`/`directory`/`info` cases it already carries, so a
retirement is never reported as a typo.

This is `TODO.md` item **2.4** ("A second field gate: the loader's `candyKnownFields` still admits the
removed `version` … *Delete it*"), the sdk leg of the campaign sequence
(`opencharly/opencharly#950`). It adds no row to the D-PAT census (`opencharly/opencharly#945`) and
moves none.

## Change classification

Library change inside the plugin contract module (`github.com/opencharly/sdk`, package `loaderkit`);
no binary and no image is built here.

- **What changes for a consumer:** a legacy kind-keyed candy manifest (`candy:` as the sole top-level
  key) is judged by `#Candy` itself. A field the schema declares is admitted — five are newly admitted,
  fixing the false refusal; a field the schema does not model is refused, and the four known
  retirements are refused with a message naming the retirement. The node form — every manifest in the
  materialized corpus — is untouched (that path uses `DecodeEntityViaCUE`, unchanged).

**Breaking change + rollback:** it breaks the case that was already broken silently — a legacy
`candy:`-keyed body carrying `version:`, `libvirt:`, `localpkg:` or `from:` used to load with the key
dropped and now fails to load with a named diagnosis, deliberately, because a silently dropped `from:`
can produce the wrong artifact. Rollback is the previous tag: pin `require github.com/opencharly/sdk`
back to the tag before this merge, or revert this commit. No authored config anywhere in the org needs
a migration either way — 0 of the 2047 `charly.yml` files in the materialized tree use the legacy form.
