# 0.2026251.1749 — fix(loaderkit): F5.1 cache mutex + F5.2 read-only validators (Cutover F unclean-code)

## Summary

Cutover F unclean-code fixes (sdk/loaderkit leg).

**F5.1 — flatYamlFieldsCache mutated without a mutex while loaderkit runs concurrently.**

Evidence: `decode_entity.go:183` — `var flatYamlFieldsCache = map[reflect.Type]map[string]reflect.Type{}` written by `flattenYamlFields` while the 32-lane materialize runs the decode hot path; map writes are NOT goroutine-safe.

Fix: the cache is guarded by `flatYamlFieldsMu` (compute-then-store, double-checked). The lock is released across the recursive embedded-struct walk (`flattenYamlFields(ft)` for inline/anonymous embeds) so the recursion cannot deadlock.

**F5.2 — ValidateEphemeralUnified mutates its subject.**

Evidence: `validate_ephemeral.go:84-96` — the validator auto-promoted `disposable:true` by WRITING `uf.Deploy[name] = node` (a validator with a side effect).

Fix: the promotion is now `fillEphemeralDefaults` — a LOAD/finalize defaults fill invoked ONCE in `LoadUnified` (after FoldMembers, before the validation chain); `ValidateEphemeralUnified` is read-only. Test `TestFillEphemeralDefaults_PromotesAndValidatorReadOnly` proves the validator does not mutate and the fill is idempotent.
