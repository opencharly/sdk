# 0.2026324.2252 — feat(deploykit): the resolved description carries a candy's var:

## Summary

**The resolved description now carries a candy's declared `var:`** — the shape a bed actually walks.

**The gap this closes, measured.** `CollectDescriptions` built each candy's `LabeledDescription` from its description and its baked plan only. `CandyReader.Vars()` **already existed** on the interface; it was simply never read here. So a candy's `var:` reached nothing, while two merged PRs (`spec#403`, `sdk#600`) added a field and a reader for the *other* carrier:

```console
$ git -C charly grep -rn 'Vars' origin/main -- 'charly/*.go' | grep -v _test \
    | grep -icE 'meta\.Vars|\.Vars\b.*meta'
0
$ git -C charly grep -c 'BoxMetadata{' origin/main -- '*.go'
origin/main:charly/service_test.go:3
```

**Zero non-test readers of `meta.Vars`, and the only construction sites are in a `_test.go`.** `BoxMetadata` is reconstructed from an image's **OCI labels**, and `var:` is deliberately not one — it is in `DeployOnlyCapabilityFields` for exactly that reason. **The resolved description is built from the project, so it is the carrier that can travel.**

**`#Op`'s `config:` comment already states the rule a `check:` step never received:** *"substitutes ${VAR} refs in content: at generate time (**candy var: ∪ auto-exports**)"*.

**One behavioural detail worth naming:** the collection guard was `if description == "" && len(baked) == 0 { continue }`, which would have **silently skipped a candy that declares only variables**. It now also admits `len(vars) > 0`.
