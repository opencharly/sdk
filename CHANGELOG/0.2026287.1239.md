# 0.2026287.1239 — chore(vmshared): drop the six pass-through spec aliases their referents no longer exist for

## Summary

`opencharly/spec#225` removed eight silently-inert `#Kubernetes` cluster-template fields and the six
wire types that typed them. This file re-exported all six as pass-through aliases, so the next
`go get github.com/opencharly/spec@<post-#225 tag>` here could not compile. **Witnessed, not
argued** — the pin bumped with the aliases still present:

```
$ go build ./...
# github.com/opencharly/sdk/vmshared
vmshared/spec_aliases.go:56:36: undefined: spec.KubernetesGatewayAPI
vmshared/spec_aliases.go:57:36: undefined: spec.KubernetesHostname
vmshared/spec_aliases.go:60:36: undefined: spec.KubernetesObservability
vmshared/spec_aliases.go:64:36: undefined: spec.KubernetesResources
vmshared/spec_aliases.go:65:36: undefined: spec.KubernetesResourceValues
vmshared/spec_aliases.go:66:36: undefined: spec.KubernetesSecretsBackend
```

The deletion therefore rides the pin bump in ONE commit, which is why it is not a PR of its own:
against the old pin the aliases have live referents, against the new one they have none, and no
revision in between is both consistent and compiling.

Nothing referenced them. Before the deletion, every one of the org's 19 references to the six names
was a **definition site** — the six lines here plus the thirteen in the older pinned
`spec/spec/cue_types_gen.go`. After it:

```

# literal and print matches=0 unconditionally, which is a sweep that cannot fail.
```
