# 0.2026281.713 — fix(candywalk): collect every remote ref form, never drop a branch or SHA (opencharly/sdk#322)

## Summary

`candywalk`'s remote-ref collector matched **CalVer tags only**:

```go
var remoteRefRe = regexp.MustCompile(`@github\.com/opencharly/[a-zA-Z0-9._/-]+:v[0-9]+\.[0-9]+\.[0-9]+`)
```

A branch (`:feat/…`) or a commit SHA matched **nothing** — no error, no warning. In a **fail-closed**
generator (`charly marketplace generate` rejects an undeclared family) a silently dropped ref means
the generator validates a **stale** entity and reports a failure the author cannot fix by editing the
map, because the map is never read. Same "a ref that does not pin" class as opencharly/charly#715.

Implements the issue's **preferred arm (1)**: the collector now hands over **every ref form** the
loader can resolve. The path class stops at the first `:` (so the version stays unambiguous even when
the ref itself contains `/`, `.` and `-` — a branch is indistinguishable from the path by character
class, which is exactly why the CalVer anchor existed), and the ref class stops at the delimiters that
end a YAML scalar.

## Why arm (2) is NOT implemented — measured, not skipped

Arm (2) is "hard-error when a ref is present but unrecognised". `collectRefs` scans **raw file bytes,
comments included**, and a sweep of the org's tracked `charly.yml` files finds **42 distinct
VERSIONLESS `@github.com/opencharly/…` tokens living in PROSE** — a `layer-nodejs` mention in a
comment, a `distro-*` glob, a trailing-backtick example:

```
$ grep -rhoE "@github\.com/opencharly/[^ '\"',}#]+" --include=charly.yml . | grep -v ':' | grep -v '/charly/' | sort -u | wc -l
42
```

Failing closed on those would break every tree that documents a repo path. A versionless token is
therefore not evidence of a declared ref; only a token carrying a `:version` is, and every such form
is now collected. The measurement is recorded in `collectRefs`' doc so the arm is not re-attempted
blind.

## How tested — the changed path executed live, with a control

`collectRefs` is reached by `CollectEntitiesRemote`, the discovery entry point the two consumers
(`plugin-docs`, `plugin-marketplace`) drive. That entry point was **executed live**, against the real
GitHub remotes, over a scratch project declaring two refs at a **branch** (`:main`), with the real
`refs.DownloadRepo` as the resolver seam:

```
########## POST-FIX (this branch):
  resolve(github.com/opencharly/plugin-box, "main")
  resolve(github.com/opencharly/plugin-example-kind, "main")
remote entities collected: 4 (from the two declared refs)

########## PRE-FIX (CalVer-only pattern, restored for the control):
remote entities collected: 0 (from the two declared refs)
```

Not one `resolve(...)` line is even reached pre-fix: both declared refs vanish before the fetcher
sees them, which is precisely the "the map is never read" failure the issue describes. Post-fix the
branch refs are handed over and **4 remote entities are collected**. That harness is a scratch module
under `/tmp`, never committed; the same call is pinned by
`candywalk.TestCollectRefs_AcceptsEveryRefForm`, which **fails on the pre-fix pattern** (the branch
and the SHA are DROPPED) and passes with it.

Gates on the committed tree: `gofmt -l .` empty · `GOWORK=off go vet ./...` clean ·
`GOWORK=off go test ./...` exit 0 · the repo's CI cross-compile matrix (amd64/arm64/arm/386) green.
