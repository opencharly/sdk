# 0.2026205.1559 — feat(deploykit,seam,proto)!: K1-α compile-seam delta — W4 relocation + K5-A items 1&2

## Summary of changes

The sdk-side legs for the `charly` superproject's K1-α wave (W4 pure-helpers
relocation + K5-A items 1 & 2). Opened AFTER `feat/k1-unblock-w3-venue-container`
(#98) merged to `main` (531c196) — this branch merged that main forward first, so
the diff below is scoped to ONLY this delta (the check-family `"container"`
VenueDescriptor / `#CheckEnv` / `#CheckLoadPluginsRequest` content already lives
on `main` via #98 and produces zero diff here).

- **W4**: `ClassifyNodeTarget`/`PathLeaf` promoted to `sdk/deploykit` (pure
  functions of `(node, path)`, no `LoadUnified`/executor dependency), shared by
  charly-core's `deriveChildExecutorForPath` and `candy/plugin-bundle`'s walk
  classification (R3, one source of truth instead of two). `#DeployNodeDispatchRequest`
  gains `target`/`vm_entity` fields so the plugin's pre-resolved classification
  crosses the wire instead of the host recomputing it.
  `#DeployEntityResolveRequest.kind`'s documented vocabulary extended with
  `"local"` (doc-comment only, no field/type change).
- **K5-A item 1 — compile-seam ctx-threading** (`deploykit/compile_construct_step.go`,
  `deploykit/compile_service_steps.go`, `deploykit/deploy_state.go(+test)`,
  `deploykit/install_build.go`, `deploykit/steps.go`,
  `deploykit/service_render_context.go`): retires the core-`init()`-set
  `deploykit.CompileActOp`/`CompileServiceSteps` func-var indirection (a hidden,
  implicit same-process dependency — silently nil for any caller that didn't
  share it; `deploykit/compile_seams.go`, now empty, deleted). `BuildDeployPlan`/
  `CompileOpSteps` take explicit `ctx`/`exec` parameters instead. The common case
  (every non-`plugin:`-verb op — mkdir/copy/write/link/download/setcap/build/
  command — plus the packaged-unit/supervisord service cases) is fully portable
  and never touches the wire. Two genuinely host-only pieces reach back over new
  CUE-sourced HostBuild seams: `#ConstructStepRequest`/`#ConstructStepReply`
  (`schema/seam.cue` — a `run: plugin: <word>` op resolving against the host
  provider registry, a clause-M kernel mechanism) and `#RenderServiceRequest`/
  `#RenderServiceReply` (rendering a systemd CUSTOM unit, which needs
  `candy/plugin-init`'s `OpResolve` + the M16 egress gate). A dead lazy-fallback
  path (`LoadBuildConfigForBox`'s per-call compile outside the deploy-compile
  seam) is deleted, not ported — it was unreachable in production and every test
  exercising it relied on it FAILING, never succeeding.
- **K5-A item 2 — `DescribeProvider` RPC + pod-overlay dispatch relocation**
  (`executor.go`, `proto/plugin.proto`+generated stubs,
  `protocol/schema/plugin.cue`, `deploykit/plugin_step_words.go`): new
  `ExecutorService` RPC, CUE-sourced (`task wire:gen`):
  `DescribeProvider(class, word)` → cached capability metadata (today:
  `#StepContract`) for another provider — the metadata twin of `InvokeProvider`
  (dispatch) and `HostBuild` (host-side build). Lets a plugin make a routing
  decision about a peer provider (e.g. "does `class:step` word X declare
  `Emits=true`?") without holding the provider registry itself or paying a live
  `Invoke` round-trip merely to query shape. `#DescribeProviderRequest{class,
  word}` / `#DescribeProviderReply{found, step_contract}` — `found=false` is a
  QUERY RESULT, not an RPC error. Client:
  `sdk.Executor.DescribeProvider(ctx, class, word) -> (found bool,
  *StepContract, error)`. The kind→word vocabulary for the 12 compiler-emitted
  `InstallStep` kinds (formerly charly-private `pluginEmitStepWords`) relocates
  to `sdk/deploykit.PluginEmitStepWords` — a genuine cross-boundary shared
  constant now that the pod-overlay step-emit DISPATCH DECISION itself moves
  plugin-side (charly-side companion: `candy/plugin-installstep`'s new
  `oci-dispatch` word).
- **R1 finding fixed in this PR** (`kit/reexec_ssh.go`): a pre-existing,
  untouched-until-now comment cited `install_build_act.go`'s
  `deploykit.CompileActOp = compileActOp` as the placement precedent for
  `ReexecOverSSH` — both that charly-side file and this func var are retired by
  item 1 above, so the comment was about to go stale in this same cutover.
  Repointed at the actual current successor
  (`deploykit/compile_construct_step.go`'s `buildGenericOpStep`).
