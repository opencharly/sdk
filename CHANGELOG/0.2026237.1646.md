# 0.2026237.1646 — feat: candywalk gains remote-ref-aware discovery (the candy cutover Phase 3 — the generators survive Phase 4)

## Summary

The candy de-submodule cutover, Phase 3: **sdk/candywalk gains a remote-ref-aware discovery mode** — `CollectEntitiesRemote` resolves every `@github.com/opencharly/...` ref in the walked files' `require:`/`candy:` lists through a caller-supplied resolver seam, and unions the fetched repo's candy entities into the result, transitively (fix-point until closure). `Entity.SourceRoot` carries the fetched repo dir so schema reads resolve against the fetched tree. This is the mechanism that keeps the docs + marketplace generators (both built on candywalk) emitting the full moved corpus after Phase 4 deletes the in-repo `candy/` dirs.

R3: ONE discovery kit — the FS-walk default (`CollectEntities`, resolve == nil) is unchanged; the remote mode is the same walker with the resolver seam. No fork.

Two behavioral changes beyond the seam, both in the diff:
- `ReadEntityFile` now tolerates the standalone repos' prepended scalar `version: <calver>` header (skipped, not an entity) and skips per-key non-mapping shapes instead of rejecting the whole file — the standalone repo manifests carry the header.
- `collectRefs` explicitly skips the pre-cutover in-repo form `@github.com/opencharly/charly/candy/<name>` (RepoPath == github.com/opencharly/charly) — only standalone kind-prefixed refs are resolved.
