# 0.2026242.1032 — feat(kit): FetchArtifact — the qcow2 fetcher, generalised over extension

## Summary

`source.kind: iso` (landed in spec#71) needs to fetch an installer ISO. `kit.FetchQcow2`
is already exactly the fetcher that job wants, and **none of what makes it careful ever
looks inside the file**:

- a content-addressed cache keyed on `sha256(url)`, stable across query params
- a cross-process `flock` so two beds building from the same URL do not race on one `.part`
- sidecar-sum auto-resolve (`.SHA256` / `.sha256` / `.sha256sum`)
- `Range: bytes=` resume, with the **stale-partial single refetch** — the deterministic
  cache invalidation that exists only because `check-k8s-deploy` hit it under concurrent
  fan-out
- atomic promote + a recorded sum sidecar

Writing a second one for ISOs would duplicate every one of those, including that fix (R3).

So **`FetchQcow2` becomes a one-line face over `FetchArtifact(src, ext)`**, and the only
thing the extension changes is the cached file's suffix. `+35 -6` in the fetcher; the
whole download/verify/promote body is untouched.

### Two decisions worth naming

**The extension is a parameter, not derived from the URL.** A URL suffix is not
trustworthy — query params, redirect endpoints, `images/latest/` rotations — and the
caller always knows what it asked for.

**It is guarded non-empty.** An empty ext content-addresses onto a bare hash with no
suffix. That is reachable only by a caller bug, but it silently poisons a cache directory
a human reads during an incident, and it makes `file`/`qemu-img` on a cache entry
meaningless.

Four prose comments that said "qcow2" about behaviour that is not qcow2-specific were
corrected in the same pass (the resume-retry stderr line, the no-timeout rationale, the
lock's doc comment, the re-hash note). No behaviour change.

## Rulebook compliance

- **R3 — no duplication.** This is the whole point: one resumable, lock-protected,
  checksum-verifying downloader, not two. The alternative on the table was an
  ISO-specific copy.
- **R4 — no workarounds.** No sleeps and no retries added. The existing stale-partial
  refetch is deterministic invalidation, not a retry, and is carried over unchanged.
- **R5 — delete legacy completely.** There is no legacy path left: `FetchQcow2` does not
  keep its own body, it *is* `FetchArtifact(src, ".qcow2")`. The face test holds that.
- **R7 — prove the gate.** Full `-count=1` suite pasted above from the committed tree.
- **R10 — fresh disposable proof.** The negative controls were run against a
  deliberately-broken tree which was then restored from a backup; every result pasted
  above is from the committed state, re-run after restoration.
