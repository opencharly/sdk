# 0.2026313.433 — feat(schema): compose a plugin's served schema as a CUE module instance

## Summary

Closes the composer half of #490 (its ordered roots 1 and 2 live in two repos because of the
module pin; this is the producer, and the host half follows it).

Every site that judged a plugin's served schema compiled it as package-less text in a context
with no CUE module in scope. So a plugin could not `import "github.com/opencharly/spec/schema"`:
the compile refused the import at its first clause, and adding a `cue.mod` on the consumer side
changed nothing — the module was never in scope — while a second failure waited behind it, because
N units concatenated into one file put N import clauses in one compilation unit, which is not CUE
at all.

This lands the composer in the sdk, which is where it belongs: both halves of the contract must
judge the same schema with the same code. `schema_compose.go` composes the plugin's concatenated
schema body as one CUE module instance, and `BuildCapabilitiesWithRequires` uses it instead of
`CompileString`.

What the compose does:

- **Module declaration.** The plugin's own `cue.mod/module.cue` when its embedded FS ships one,
  otherwise a derived declaration that pins the language version the spec module declares and
  names `github.com/opencharly/spec@v0` as its one dependency. A plugin's own declaration is used
  verbatim after ONE check: its `language.version` must be the spec module's. The check exists
  because the host composes the same body under the derived declaration (the wire carries no module
  declaration), so a plugin evaluated under different semantics on the two sides would be judged
  twice, differently.
- **Dependency.** Served by a `modconfig.Registry` from the embedded CUE module the spec Go module
  already carries — offline: no network, no module cache, no `cue.mod/pkg` vendoring, and no local
  `replace` (the pinned modfile schema admits `source!: kind!: "self" | "git"` and no path field).
  The loader requires that dependency's source FS to implement `module.OSRootFS`, because it maps
  an imported package to an absolute directory, so spec's module is materialized ONCE at a
  content-named directory under the system temp root — never the host tree — and every compose
  shares it. The registry matches on the base path, since the loader asks with the major-suffixed
  path.
- **Agreement.** `ComposeServedText` composes the package-less body that travels on
  `Capabilities.schema_cue`, using the SAME compose under the derived declaration. That is what
  lets the serve side and the host agree byte for byte, and it is asserted, not assumed.

**Equality with today's behaviour.** A plugin that imports nothing composes to the value the
deleted text compile produced. Asserted twice: the canonical rendering of both values is
identical, and both judge the same corpus of documents (conforming and violating) identically.

`go.mod` moves the spec require to `v0.2026313.48` — the version that exports the module
declaration the composer reads.

**Out of scope, stated plainly.** #490's ordered roots 3 (the param generator keeps a module) and
4 (the per-consumer units) are not here; a plugin that imports spec still needs those before its
Go params can be generated from the same source. The host gate — `compileBasePlusServed` must stop
joining unit sources — is in `opencharly/charly`, which pins this module: it is the next unit, it
calls this composer, and it needs this tag first.

## Change classification

Library change in the plugin contract module; the sdk ships no binary and no image, so there is no
disposable bed in this repo's gate.

- **Consumers:** a plugin that imports nothing is unaffected — proved, not asserted. A plugin that
  imports the spec schema now serves instead of failing at start-up; its Go params are still
  generated by the text pipeline until #490's root 3 lands, so this change enables nothing on its
  own and is the producer for the host unit.
- **The public Go surface** only gains two functions; the existing entry point keeps its signature
  and its acceptance for every schema shape that composed before, so nothing has to change on the
  consumer side.
- **Reversing it:** the commit is additive; moving the spec require back is enough to leave every
  consumer where it was.
