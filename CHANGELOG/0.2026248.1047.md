# 0.2026248.1047 — loaderkit: desugar instrument + pipeline capture entries like plan steps

## Summary

The parse-time plugin-verb desugar (sdk/loaderkit/parse.go) now treats `instrument:` capture entries and their `pipeline:` word lists EXACTLY like plan steps: the authored `<word>: <input>` sugar is rewritten into the internal `plugin`/`plugin_input` pair with byte-identical semantics, error strings, and precedence. Part of Cutover A of the authoritative plan `plan/nested-capture-architecture.md` (instrument surface) — the CUE contract (`#Instrument`/`#PipelineWord`) landed in the same wave's spec PR (opencharly/spec#96, MERGED); the CUE substrate schemas gate where `instrument:` may appear (the parse stays kind-blind).

Changes:
- `desugarEntityPlan` additionally walks a body-level `instrument:` sequence beside `plan:`.
- NEW `desugarInstrumentEntry` + `desugarPipelineWord` (single verb-position key, byte-identical to a step verb; hard load error on authored `plugin:`/`plugin_input:`; multi-key rejection).
- `desugarStep` refactored onto shared machinery (`sugarKeyIndexes`/`sugarKeyNames`/`desugarVerbKey`) with pre-existing tests passing unchanged (error-string/order compatibility proven).
- 10 new tests: instrument-verb desugar, verbatim pair-equality between a step and an instrument entry, scalar shorthand in capture position, pipeline-word desugar, instrument on a nested member child, and five negatives.
