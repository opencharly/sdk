# 0.2026267.2215 — fix(deploykit): guard POSIX shell drop-ins against cross-shell execution

## Summary

Fix cross-shell execution of a candy's POSIX `shell:` drop-ins.

A candy's generic `shell.init` is substituted per shell into
`/etc/profile.d/charly-<candy>-bash.sh`, `-zsh.sh` and `-sh.sh` — one file per
POSIX shell. But `/etc/profile` sources **every** `/etc/profile.d/*.sh` in
**every** POSIX login shell, so the per-shell **file name** does not actually
scope execution. Reproduced on a built image composing `direnv`:

```
$ bash -lc true
direnv: error unknown target shell 'sh'
/etc/profile.d/charly-direnv-zsh.sh: line 8: (I)_direnv_hook: arithmetic syntax error ...
```

bash ran the **zsh** body (zsh syntax) and the **sh** body
(`direnv hook sh` is not a valid direnv target), spamming every login shell.

### The fix

`CompileShellSnippetSteps` now wraps each container-build POSIX drop-in body in
a runtime guard that makes the file name truthful:

| file | guard |
|---|---|
| `-bash.sh` | `[ -n "${BASH_VERSION:-}" ] && [ -z "${ZSH_VERSION:-}" ]` |
| `-zsh.sh`  | `[ -n "${ZSH_VERSION:-}" ]` |
| `-sh.sh`   | `[ -z "${BASH_VERSION:-}" ] && [ -z "${ZSH_VERSION:-}" ]` |

The BASH_VERSION-vs-ZSH_VERSION discrimination is load-bearing: **bash exports
`BASH_VERSION` even when invoked as `sh`** (documented in this repo at
`spec/exec/deploy_executor_nested.go`), so a bare `-n "$BASH_VERSION"` test would
still fire under bash; the `sh` guard covers dash/ash/busybox where neither is
set. The body is wrapped in an `if … fi` so an early `return`/`exit` inside a
snippet cannot abort the caller's shell startup. The guard is applied on **both** paths: the container `/etc/profile.d/*.sh`,
and the host/venue path where the `sh` snippet appends to `~/.profile` — the
**shared** POSIX login profile that bash also sources when
`~/.bash_profile`/`~/.bash_login` are absent (verified: `bash -lc` sources
`~/.profile`). The guard is true whenever a file is sourced by its own shell, so
it is inert where a file is already shell-scoped and required at `~/.profile`.
fish uses its own `conf.d` drop-in and is never guarded.

`TestGuardShellDropin_HostProfileLeak` writes the guarded `sh` body into a fake
`~/.profile` and runs a real `bash -lc`; neutering the guard makes it fail
(`RAN:sh-guard`) — proving it catches the host leak. `-run 'GuardShellDropin'`
executes all three top-level tests above.

A genuine non-bash `sh` (busybox, via podman) was verified separately to run only
the `sh` guard and to decline the bash guard:

```
$ podman run --rm docker.io/library/alpine:latest sh -c \
    '/bin/sh -c "[ -z \"\${BASH_VERSION:-}\" ] && [ -z \"\${ZSH_VERSION:-}\" ] && echo GUARD_OK"'
GUARD_OK
```

### At the artifact boundary (the emitted Containerfile)

Generating a direnv-composing box emits each drop-in guarded:

```
RUN mkdir -p '/etc/profile.d' && cat > '/etc/profile.d/charly-direnv-bash.sh' <<'…'
# opencharly: guard — this drop-in is for bash only (every /etc/profile.d/*.sh is sourced by every POSIX login shell)
if [ -n "${BASH_VERSION:-}" ] && [ -z "${ZSH_VERSION:-}" ]; then
	eval "$(direnv hook bash)"
fi
…
```

`TestCompileShellSnippetSteps_GuardsDropins` pins this wiring for **both**
venues (container + host): guarded bash/zsh/sh; fish never guarded.
`TestGuardShellDropin_HostProfileLeak` writes the guarded `sh` body into a fake
`~/.profile` and runs a real `bash -lc`, proving bash does not execute it (fails
without the guard).

## Rulebook compliance

- **R1** — the cross-shell failure was reproduced live (`bash -lc` sourcing the
  zsh/sh drop-ins) and root-caused to `/etc/profile` sourcing every `*.sh`.
- **R3** — one `GuardShellDropin` owner, applied centrally in the compiler; no
  per-candy guards.
- **R4** — the guard is a deterministic shell predicate, not a sleep/retry/shim;
  validated against real shells.
- **R5** — no legacy path: the same compiler emits the guarded body, so no
  unguarded container drop-in survives.
- **R6** — append-only commit, no force-push, no direct push to `main`.
- **R7** — the real-shell tests fail without the guard; the emitted Containerfile
  was inspected at the artifact boundary.
- **R8** — the emitted artifact (Containerfile) is validated, not just the Go unit.
- **R9** — the changed source is proven in the proof binary/artifact; the scratch
  build was never installed.
- **R10** — module gate green on the committed tree; the runtime behavior proven
  against real shells + the generated Containerfile.
- **R2 / companion PR (named, landing alongside)** — the `direnv` candy also
  offered no valid `sh` hook (`direnv hook sh` is unsupported), so with the guard
  the `sh` body was inert under bash/zsh but still errored under a genuine non-bash
  `sh`. That candy-side correction lands as the named companion PR
  **`opencharly/layer-direnv` #4** (branch `fix/direnv-no-sh-hook`): it opts `sh`
  out with an empty `sh: {}` override and asserts no `sh` drop-in is baked. The
  two PRs land together — this is the mechanism half, the candy PR is the
  contribution half; with both, a direnv-composing image emits only guarded
  bash/zsh drop-ins plus the fish conf.d hook (proven against the local candy:
  zero `sh` drop-in writes in the generated Containerfile).
