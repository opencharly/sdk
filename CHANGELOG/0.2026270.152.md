# 0.2026270.152 — fix(deploykit)!: resolve the host-libvirt VM by its stamped descent, not the substrate word (C6)

## Summary

Closes **C6** of the core/plugin-independence crutch sweep: the ONE residual `.Target` substrate-word read in the deploy Mechanism.

`sdk/deploykit/deploy_state.go`'s `FindVmDeployNode` identified a host-libvirt VM deploy by comparing `e.Target == "vm"` — a switch on the concrete substrate kind **word**, which the kernel/plugin boundary law forbids (consult the trait, never the word). The node's substrate identity is already carried by the loader-**STAMPED** `Descent` descriptor: `loaderkit.StampDeployDescents` re-derives it from the substrate plugin's declared `#DeployTraits` on **every** load — both a `LoadUnified`'d project tree (`rp.Deploy`, the plugin-check `tree`) and a per-host overlay read (`LoadHostDeployConfigViaExecutor` → `LoadUnifiedViaExecutor` → `LoadUnified`).

The fix reads `deploy.IsVmVenue(&e)` (the ssh venue + the exclusive host-resource lease) — the same canonical predicate the rest of `sdk/deploykit` already uses (`deploy_members.go`). `IsVmVenue` selects **exactly** the former `Target == "vm"` set: it deliberately excludes the ssh-venue `kubevirt` substrate (which declares no `exclusive_venue`), whose `Target` is its own word (`kubevirt`, per `loaderkit.DeployTargetForDisc`).

### Why no state-schema change was needed (the plan's premise, verified — not re-litigated)

The settled C6 plan proposed persisting `Descent` in the deploy state so the reader could recover the substrate. That premise was **verified against the live code and does not hold**: `MarshalDeployNode` does drop `descent:` on write, but the read path **re-stamps** it. A live spike — `LoadUnified` over a per-host-style `charly.yml` with a `vm:` entry and **no** `descent:` — returned:

```
SPIKE Deploys() "charly-local-vm" Target="vm" From="eval-vm" Descent=&{Transport:ssh Venue:ssh MachineVenue:true ExclusiveVenue:true ...}
```

Persisting a derived field would therefore be dead weight (immediately overwritten on reload) and would re-introduce the derived-field round-trip Cutover H deliberately removed. The residual word-read was simply an **un-migrated P9 consult site**; this PR migrates it. The `spec` repo is untouched (no schema change is required).
