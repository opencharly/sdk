# 0.2026297.129 — fix(kit): a step killed by its own never-hang bound must FAIL, not report the verdict it never produced

## Summary

**A step that was killed by its own never-hang bound reported PASS.** The per-attempt deadline in `kit.RunOne`'s dispatch set the kill annotation and left the status as the verb happened to return it:

- A `command:` step is safe **by accident** — the exec layer turns a killed process into an error, so the verb returns fail.
- An **in-process** verb is not: it returns whatever it computed when its context was cancelled. The `task:` hop in `opencharly/plugin-task` is exactly that — the nested walk is cut short, produces no completed step, and the hop's aggregate branch (*"ran 1 task(s), 0 step(s) failed"*) reports PASS over a nested run that never produced its evidence.

The step read green, the gate read green, and the missing evidence was invisible in a 30-step report. This is opencharly/sdk#454.

**The fix: the deadline decides the verdict.** An attempt that was killed has not passed. When the attempt's own bound fires, the result is now `StatusFail`. The **verdict** is what this change adds: the message that names the bound was already there — the unfixed tree printed it too, with `pass` where the verdict now reads `fail` — and it matters because the exec layer reports only *"process terminated by signal (signal: killed)"*, which describes the *mechanism* of death and not its cause: a step killed by this bound used to read as a crash in whatever the step was running, and the reader went looking for a bug in their own command. A legitimately slow step raises the bound with `timeout:` (`ProbeNeverHang` honours a longer authored value), which is the mechanism's own parameter.

**The sibling surface, in the same cutover.** The `do:act` branch **returned** its result *before* the deadline check ran, so a provision act killed by its own ceiling reported whatever it returned and carried no kill annotation at all. It now goes through the same verdict — one mechanism, one verdict.

**The scope of the defect is one site, and it was checked rather than assumed** — the three `context.DeadlineExceeded` sites in the module are pasted in *How tested*, below. `kit/grader.go:193` and `kit/images.go:41` both **return an error** when the deadline fires (they enforce), and only `kit/planrun.go:268` annotated without enforcing. The issue's "one place" claim holds, and the `do:act` early return is that same mechanism's second surface.

**The diff is two files.** `kit/planrun.go` carries the fix; `kit/planrun_test.go` carries the coverage (the test-support additions and five new tests). The stat is pasted in *How tested*, below.
