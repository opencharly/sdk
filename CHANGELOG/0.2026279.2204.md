# 0.2026279.2204 — fix(packagekit): declare the variant family's Provides/Conflicts/Replaces

## Summary

`sdk/packagekit` — the ONE shared native-package builder behind every `charly-<distro>` package repo — emitted variants that **cannot be installed over one another**. Every variant unconditionally ships the SAME paths (`/usr/bin/charly`, `/usr/lib/charly/plugins/*`, the systemd units via `buildContents`), but `BuildInfo` set no package relationship, so pacman/dpkg/rpm all refused to overwrite another package's files.

MEASURED on the published `charly-arch` repo (2026.268.1917), swapping the default variant for `charly-minimal`:

```
charly-minimal: /usr/lib/charly/plugins/plugin-doctor.providers exists in filesystem (owned by charly)
charly-minimal: /usr/lib/systemd/system/charly-mcp.service exists in filesystem (owned by charly)
... 27 shared paths ...
Errors occurred, no packages were upgraded.
```

All three published variants are mutually un-installable (41 shared paths `charly`↔`charly-full`, 27 `charly`↔`charly-minimal`), and none declared any relationship. The same defect blocked any local-dev package on top of a published variant.

**Change:**
- `variants.go`: new `FamilyNames(pkg, format)` — every package name the `(name, variants)` packaging produces for a format, applying the SAME rule `ResolveVariant` already uses (per-format, since `default_variant` is per-format).
- `nfpm_config.go`: on each variant, declare `Provides: [<name>]`, and `Conflicts` + `Replaces` every OTHER family member. This is the canonical Arch variant-family pattern (`nvidia` / `nvidia-dkms` / `nvidia-open`). One place, all formats the packager honours (archlinux/deb/rpm/apk/ipk); msix has no relationship concept and ignores it.

Closes #348
