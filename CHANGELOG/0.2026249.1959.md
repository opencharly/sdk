## Summary

Cutover C task 0's PARSE half (the nested-capture plan): the sdk consumes spec #103's ONE uniform ordered member tree (`Deploy.Member []Member{Name, Position, Node}`) end to end — the parse PRESERVES the authored depth, the FOLD stamps `Member.Position` from it, and the dual `Children`/`Members` map construction DIES from sdk. Re-pins `github.com/opencharly/spec` to `v0.2026249.1948` (the #103 tag).

- **Unified classification (8a)** — the three drift-prone member-kind spellings (`classifyKind`'s `asChild` arm, `parseNode`'s parent-allow check, `IsResourceDisc`'s fold set) collapse into ONE Threaded-fed function, `memberDisc` (clause-D data: resource kinds ∪ threaded structural kinds ∪ threaded deploy substrates). `classifyKind(asChild)` now consults `t.StructuralKinds` — the external-structural-child-under-external-structural-parent parse bug dies.
- **Parse preserves intent** — an entity-kind key INSIDE a disc value body parses as an IN-SUBSTRATE member child of that substrate, recursively (detection: a mapping value carrying a memberDisc discriminator — the same rule the node level applies); a key BESIDE the kind key parses as a DEPLOY-LEVEL member. Duplicate member names within a node are a hard parse error. The authored body KEEPS the in-body member keys (the fold's position channel), and every body EMITTER (`discValue`/`AssembleEntityBody`/`EntityBodyJSON`) omits them — which is how substrate closedness stops rejecting resource-member keys.
- **Fold by position** — `BuildFleetNode`'s `Target == ""` root-kind branch is DELETED; `BuildResourceMemberChildren` returns the ordered `[]spec.Member` per the frozen spec seam, stamping `Position` (in-substrate = named by a top-level key of the authored disc body; deploy-level = not). The dual-map construction is gone.
- **Consumers migrated** (no dual representation survives in sdk): `loaderkit/fleet_load.go` (FlattenFleetVenues/hoistVenueSubtree/FoldMembers/ValidateMembers over the ordered list — venue flattening now reads Position, not node kind), `loaderkit/validate_check_beds.go` (`HasMembers`), `deploykit/deploy_nodeform.go` (the overlay writer flattens the ONE ordered list; `member`/`member_of` skip-keys), `deploykit/deploy_state.go` (FleetWalkPre/PostOrder recurse IN-SUBSTRATE members — the old Children-only semantics; `FindFleetNode` searches BOTH positions at any depth), `deploykit/deploy_tree.go` (WalkDeploymentTree → in-substrate members), `deploykit/fleet_members.go` (BringUp/TearDownMembers over `DeployLevelMembers`; the new `fleet.DeployNestedLocalChildren(parent, node, apply)` signature), `deploykit/member_dns_preflight.go` (deploy-level member set), `deploykit/deploy_fleet_ops_aliases.go` (the dead `SortedNestedKeys` alias removed), `kit` tests (descent recursion + VM domain lock over the Member tree).
