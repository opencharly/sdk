# 2026.211.0915 — loaderkit.LoadUnifiedViaExecutor shared helper (#55 Cone A unit 2)

The sdk leg of #55 Cone A unit 2. Extracts the "run the whole project loader PLUGIN-SIDE
over the reverse channel" helper that four plugin candies each carried a private copy of,
so the pod deploy-key→box project fallback (candy/plugin-deploy-pod, the deploy-config-resolve
seam collapse) can reach it without a fifth copy.

## What lands

- **loaderkit/load_via_executor.go** (new) — `LoadUnifiedViaExecutor(ctx, ex, dir)` + an
  unexported executor-backed `LoaderExecutor` (the 4 core `loader-*` HostBuild legs + the 2
  self-serving capability validators). loaderkit is the correct home: it already imports BOTH
  the root `sdk` package (resolve_via_executor.go) AND owns the `LoaderExecutor` interface +
  `LoadSeamsFromExecutor` + `LoadUnified` + `UnmarshalMaterialized` — no new import direction
  (sdk root does NOT import loaderkit; deploykit does NOT import loaderkit). Same R3
  consolidation as `deploykit.LoadBundleConfigViaSeam`, blessed by the charly#176 round-1
  pr-validator ("an sdk kit is EXACTLY the mechanism this project uses to share code across
  plugin module boundaries").

Additive — no existing loaderkit surface changed; `loaderkit`/`deploykit` build + test green.
The remaining per-candy `execLoaderExecutor` copies (plugin-build/plugin-vm/plugin-loader) are
tracked R3 debt migrating onto this helper in a follow-up batch.
