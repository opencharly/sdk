### The split is the design

The **distro** owns the **format** — which files, with what names, in what syntax. The **VM
entity** owns the **data** — this username, this disk, these SSH keys.

A renderer that guessed the format from the distro name is precisely the failure mode
`validateSourceDistro`'s own comment records as having burned this codebase already. So
`RenderInstallerSeed` takes a `*spec.DistroInstaller` and a `spec.InstallerSeedContext` and
knows about neither Omarchy nor archinstall.

### One vocabulary, a whole optional matrix, no Go branch

The `when:` guard is what makes that possible:

| Guard | Effect |
|---|---|
| `{{if .DeferProvisioning}}false{{else}}true{{end}}` on `user_credentials.json` | credentials only when provisioning is **not** deferred |
| `{{if .DeferProvisioning}}true{{end}}` on `defer-provisioning` | the sentinel **instead** — an imaging rig hands the next owner a machine with no known password |
| `{{if .SSHAuthorizedKeys}}true{{end}}` | the key file only when keys were given |
| `{{if .Encrypt}}true{{end}}` | the encryption marker only when encrypting |

A file whose guard renders empty, `false`, `0` or `no` is **absent — not empty**. That
distinction is load-bearing: Omarchy's ISO reacts to the *presence* of `authorized_keys` by
enabling sshd and opening the firewall, so an empty one would open a machine for a key
nobody holds.

### One ISO writer, still

`WriteSeedISO` keeps its signature and becomes a thin face over `WriteLabeledISO`. The
**label** becomes a parameter because that is what an installer discovers the volume by —
`CIDATA` for cloud-init NoCloud, `OEMDRV` for Anaconda kickstart.

Files are staged in **sorted** order so the emitted image is byte-reproducible: Go's map
iteration is randomised, and an ISO whose file order changed between runs would defeat
content-addressed caching downstream.

### Purity, and why it matters here

No filesystem, no network, no `crypt()`. The caller hashes the password **before** building
the context, so a plaintext password never reaches a template, a log, or a temp file —
asserted directly by `TestRenderInstallerSeed_Omarchy`.

The **corpus** case is the real archinstall vocabulary as it will be authored on the omarchy
distro entity, and it asserts more than "it rendered": both JSON files are **parsed**, the
credentials carry `users` (not `!users` — read off the shipping ISO's own configurator), the
user has `sudo: true`, and the hash is a `$6$` crypt.

The **teeth**:

| Rejected / asserted | Why it matters |
|---|---|
| deferral **suppresses** credentials | shipping both hands the next owner a known password |
| optional files are **absent**, not empty | an empty `authorized_keys` opens sshd for nobody's key |
| a mis-keyed template | a broken answers file surfaces as an installer hanging at a prompt nobody is watching |
| the `<no value>` sentinel | the map-key shape the per-distro `answer?` extras will take |
| no installer / no files / no path / duplicate path / everything excluded | five ways to declare a volume that cannot work |
| determinism over 5 runs | the ISO writer's sorted staging is only meaningful if content is stable too |

## Rulebook compliance

- **R0 — skills first.** `/charly-internals:git-workflow`; the existing `WriteSeedISO` and
  `RenderCloudInit` shapes were read before a sibling was added.
- **R1 — RCA every anomaly.** Two surfaced while writing the tests, both instructive rather
  than incidental. (a) `spec.DistroInstallerFile` is a **value** slice, not `[]*T` — CUE's
  `optional=nillable` applies to the optional *field*, not to list elements, so the nil
  check had to become a `Path == ""` check. (b) The `<no value>` guard fired on **neither**
  mis-key I first tried: against a *struct* context Go's template errors outright and names
  the field, which is **stronger**. The guard is kept and its real target documented — absent
  map keys, which is what the per-distro `answer?: {[string]: string}` extras will be —
  and the test now covers both paths rather than asserting a message that never appears.
- **R2 — finish the whole cutover.** Renderer, ISO generalisation, both call sites and tests
  land together.
- **R3 — no duplication.** There is still exactly **one** ISO writer. `WriteSeedISO` did not
  grow a parallel implementation; it delegates.
- **R4 — no workarounds.** No sleeps, no retries, no special-casing by distro name.
- **R5 — delete legacy completely.** `WriteSeedISO`'s inline staging block is **removed**,
  not left beside the generic one — the old three-file path no longer exists anywhere.
- **R6 — preserve user work and Git safety.** Feature branch off current `main`, PR-only, no
  force-push, no direct push to `main`, no hook bypass.
- **R7 — prove behavior, not compilation.** The tests parse the rendered JSON and assert the
  emitted file *set*, which is the behaviour an installer actually consumes.
- **R8 — preserve emitted artifacts.** `N/A — no build artifact; the ISO writer's output is
  covered by its own builder test.`
- **R9 — binary equals source.** `-count=1` from this worktree.
- **R10 — fresh disposable proof.** `N/A — sdk has no bed. Its gate is the unit suite on the
  final tree.` The consuming bed is `check-omarchy-iso-vm` in `distro-omarchy`, which needs
  `BuildIsoVM` in plugin-vm — the next step, named rather than used to defer.
- **ADE — spec-is-the-test.** Every claim the doc comments make is asserted: the split, the
  guard semantics, absence-not-emptiness, sorted staging, purity, and the label parameter.
- **RDD — prove high-risk assumptions before editing.** The archinstall file set and its
  exact key names (`users`, `enc_password`, `root_enc_password`) were read off a real
  unattended install performed earlier in this cutover, not from documentation.
