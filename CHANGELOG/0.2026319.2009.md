# 0.2026319.2009 — feat(deploykit)!: the candy hook crosses the IR as bytes

## Summary

The **consumer half** of `opencharly/spec` `v0.2026319.1942`, where `#CandyModel.hook` became `bytes`. Three lines, one direction each:

| where | change |
|---|---|
| `loaderkit/scan_candy.go` (producer) | `m.Hook = ly.Hook` → **marshals** the authored `#CandyHook` into the body |
| `deploykit/spec_candy_adapter.go` (consumer) | `Hooks() *HooksConfig { return a.m.Hook }` → **decodes** the bytes |
| `deploykit/hooks_collect_test.go` | the fixture marshals, exactly as the producer does |
| `loaderkit/scan_candy_hook_test.go` | NEW — exercises the **real** producer |
| `deploykit/hooks_opaque_test.go` | NEW — decode, empty, and corrupt-bytes paths |

**Both halves PANIC on an invariant violation, and that is deliberate.** The bytes come from marshalling a typed `#CandyHook`, so a marshal or decode failure means the body was written by something other than that producer — or that the contract changed under us. In that case a candy's `pre_remove` would silently never run, with nothing saying why, so the code fails at the point the invariant breaks instead of dropping a hook. An error return was rejected because `CandyReader.Hooks()` has no error channel, and widening the interface would push the same decision onto every caller.

The build engine still sees a typed `*HooksConfig`; the IR carries bytes; the authored shape stops being imported by the contract (`DESIGN.md` §3.1, I1/D-SCH-7).

**Why the wire does not move.** The OCI label `ai.opencharly.hook` was already JSON — authored YAML → struct (`scan_candy`) → `json.Marshal` into the label (`write_labels.go:110`) → struct (`spec/container/box_metadata_coneb.go:151-156`). The bytes this PR produces are exactly what the label already carried, so every existing reader keeps working; only the *provenance* changes, from an implicit struct copy to an explicit marshal/decode pair.

**The reader set was swept against this repo's `origin/main`** before the spec change landed:

```console
$ git grep -n 'm\.Hook\|\.Hook\b' origin/main -- '*.go' | grep -vE '_test|BoxMetadata|meta\.Hook'
origin/main:deploykit/spec_candy_adapter.go:171:func (a *specCandyAdapter) Hooks() *HooksConfig { return a.m.Hook }
origin/main:loaderkit/scan_candy.go:327:	m.Hook = ly.Hook
```

Two sites, both in this diff. `MergeCandyHooks` and `render_prep` read the result through `Hooks()`, so they are unaffected by construction.

## Change classification

Kind: an SDK library change (the consumer half of a contract change). It breaks any consumer that passes `*CandyHook` into `spec.CandyModel.Hook` — in this repo that is one fixture, adapted here; outside it, consumers pin the wave.

**Breaking change + rollback:** `CandyModel.Hook` is `RawBody` from spec `v0.2026319.1942`; a consumer must marshal rather than assign. Rolling back reverts to spec's previous tag and restores `m.Hook = ly.Hook` — the label wire is identical either way.
