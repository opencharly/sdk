# 0.2026269.12 — feat(deploykit+loaderkit): write KubeVirtState + resolve kubevirt entities

feat(deploykit): write KubeVirtState so a kind:kubevirt deploy persists its venue identity

Companion to opencharly/spec#165 (**merged, tagged `v0.2026269.4`**). Closes the R5 gap found while building `plugin-kubevirt`: `#Deploy.kubevirt_state` existed but nothing wrote it.

## Summary of changes

- **`deploykit/deploy_state.go`** — `applyDeployState` writes `entry.KubeVirtState` whenever `input.KubeVirtState` is non-nil (the kubevirt analogue of the existing `VmState` write), so a kind:kubevirt deploy's venue identity round-trips through the per-host overlay.
- **`deploykit/deploy_state_test.go`** — `TestApplyDeployState_KubeVirtState` (fails without the write).
- **`go.mod`/`go.sum`** — spec pin bump `v0.2026268.2214 → v0.2026269.4` (the tag spec#165 minted), so the committed tree builds at its own `go.mod`.

**Dropped:** the earlier `ResolveKubeVirtEntityViaExecutor` addition — it has no consumer (`plugin-kubevirt` reads `uf.PluginKinds` directly), cannot be unit-tested without a live substrate executor, and shipping an unexercised new code path is an R10 violation. It lands with its first real consumer.
