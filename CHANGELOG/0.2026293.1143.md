# 0.2026293.1143 — feat(skills): CollectSkillBodies resolves every authored body, composition-independent

## Summary

Adds `CollectSkillBodies` and extracts the one decode loop both entry points share: `collectSkillsFiltered`.
`CollectSkills` passes the composition predicate; `CollectSkillBodies` passes `nil`, so it resolves the body of
**every** authored `skill:` node regardless of whether any box composes it.

**No duplication:** `decodeSkillNodes(cfg.Skills)` has exactly one call site in the file, and the loop
(decode → project → dedup → sort → assemble) exists once. This is the same discipline that refused a per-repo
Python transcription on `plugin-review#43`.

`CollectSkills` gates body reads on `BoxCandyChain` — a **label-size** policy, documented in its own comment as
*"union-of-composed-only, which bounds the label size"*. Whether a body *exists* is not a label question, so that gate
must not decide it. A repo that authors `skill:` nodes but composes no box has no call site that ever reads a body,
which is why `charly box validate` returns `0 warnings, 0 errors` on a tree whose body sits at a path nothing reads.

Measured on `opencharly/plugin-review` at `3e82898` — the tree that opened `plugin-review#42`:

```
$ charly box validate
charly box validate: OK — checked 1 candy, 7 distros, 7 builders; 0 warnings, 0 errors
$ echo $?
0
```

and the same command returned `0 warnings, 0 errors` before the change too, when the body did not exist anywhere. **A
gate that returns 0 on both sides is not a gate.** Diff against `main`: **103 insertions and 6 deletions across two files** — the shared loop refactor (`+21/−6`) and the tests (`+82`).

Filed as `opencharly/opencharly#530`.

## Rulebook compliance

- **R0:** skills loaded before the first action, `/charly-internals:git-workflow` before any git command.
- **R1:** this is the **producer half** of `opencharly/opencharly#530`, which closes when `plugin-box` consumes it. **No call site is added here, deliberately:**
  producer-first means the consumer (`plugin-box`, whose `validateSkillBodies` calls
  `deploykit.CollectSkillBodies(cfg, vc.dk)` from `runAllValidations`) pins a merged `sdk`, so the consumer PR is the
  next leg and its body carries the end-to-end evidence. Adding the caller here would mean editing a consumer against
  an unmerged producer — the ordering the rulebook forbids.
- **R2:** no duplication — the new function reuses `decodeSkillNodes`, `projectSkill` and `readSkillFile`; it is
  `CollectSkills` minus one `if`. This is why a per-repo transcription was rejected on `plugin-review#43`.
- **R3:** no workaround, no sleep, no retry, no bypass.
- **R4:** the product is fixed at the layer that owns the contract, not in 24 consumer repos.
- **R5:** nothing is removed, so nothing legacy survives; `CollectSkills` keeps its behaviour and its callers.
- **R6:** `git status` read first; branch off `origin/main` in a session worktree; one commit; no force-push.
- **R7:** the negative control is a *test that asserts an error*, so its own run exits 0 — the evidence is the
  message it logs, not an `rc=1`. `prepush_body_check.py` flags that shape as "no negative control" because its heuristic looks for
  `rc=1`/`FAIL`/`error:`; that false positive is filed as `opencharly/opencharly#532`, not merely disclosed.
  Coverage fails without the change — the negative-control test errors only because the body is at the wrong
  path, and it passes only because the resolver reads beside the candy.
- **R8:** no live service boundary.
- **R9:** worktree-local build; `go build` and `go test` run on the committed tree.
- **R10:** SDK change; the gate is `go build ./deploykit/` (rc=0) plus the three tests above, with both controls.
