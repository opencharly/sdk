# 0.2026254.439 — sdk: add LandArtifact — the ONE caller-side artifact-landing entry point (G-8)

## Summary

Adds `sdk.LandArtifact(ctx, ex, venuePath, artifact, op)` — the ONE caller-side artifact-landing entry point (R3) every capture plugin uses, host-side AND venue-side:

- **Venue-side** (`ex != nil && venuePath != ""`): pulls the artifact bytes via the executor's `GetFile` (the reverse-channel read), writes them to the host `artifact` path (`os.WriteFile` 0644, creating parent dirs), then validates.
- **Host-side** (`ex == nil || venuePath == ""`): the artifact is already host-side — no pull, no write; validation runs straight on the existing path (the spice-screenshot / media-transcode path).
- **Always** finishes with `sdk.RunArtifactValidators(op)` on the host artifact path and returns its result. A pull failure returns a descriptive error naming both paths.

The executor IS the placement abstraction — no venue-kind switch anywhere. This is the seam the five hand-rolled capture paths (plugin-wl, plugin-record, plugin-cdp, plugin-adb, plugin-spice/media host-side) migrate to in their own PRs after this tag lands; none of those repos are touched here (R5 cutover happens plugin-side).

Also updates the `RunArtifactValidators` doc to point callers at LandArtifact as the entry point.
