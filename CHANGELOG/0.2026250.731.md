# 0.2026250.731 — kit: thread mcp_provide declarations through Runner (check-env carrier for VM venues)

## Summary

P4 substrate-neutral mcp_provide threading (check-env carrier): the check env
(`spec.CheckEnv`, which carries `mcp_provide` since spec v0.2026250.709) must be
POPULATED with the deployment's mcp_provide declarations for VM venues, so the
out-of-process `mcp:` check verb can resolve a VM's MCP server (a VM has no
podman-inspectable OCI label). This PR makes the runner the carrier:

- `RunnerConfig` gains `MCPProvide []spec.CandyMCPProvide` (mirrors the `VmName` field pattern);
- `NewRunner` copies it into the `Runner`;
- `Runner` gains the `MCPProvide()` accessor.
- Spec pin bumped `v0.2026250.656` → `v0.2026250.709` (the tag that defines `CandyMCPProvide` + `CheckEnv.MCPProvide`); `go mod tidy` refreshed go.sum.

The charly provider_checkenv / plugin-check verb_resolver snapshots are the consumers
(wired in the follow-up wave); the construction-site population (VM-check runner builds)
lands with the charly consumer.
