# 0.2026236.813 — fix(deploykit): skip localpkg step when the candy's distro repo provides the package

## Summary

The charly meta-candy declares BOTH a `packaging:` section (`name: charly`) and a new `distro:` section whose `repo:` entries provide the same package. A box composing the charly candy therefore fired TWO install paths:

1. The `distro:` repo install (`apt-get install charly` from the published repo) — the new canonical path
2. `CompileLocalPkgStep`'s direct `.deb` download+install (the candy declares `packaging:` AND the deb format declares `local_pkg:`)

apt then failed with `Packages were downgraded and -y was used without --allow-downgrades` (the same .deb landing twice).

**The fix**: `CompileLocalPkgStep` now returns nil when the candy's `distro:` section declares a repo entry whose package list includes the packaged name for the target distro. The check walks the SAME `CascadeTagChain` as `ResolveCascadePackages` (the system-package repo install), so the skip can never diverge from the repo resolution. `local_pkg` remains the fallback for candies that declare `packaging:` but no distro repo.
