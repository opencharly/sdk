# 0.2026241.2117 — fix: resolve the deferred {{.Home}} token on machine venues

## Summary

Fixes opencharly/charly#460: a candy's `copy:` step silently fails to deliver on a
`target: vm` / `target: local` deploy.

**Root cause.** A home-relative `copy: to: ${HOME}/...` is *tokenized* at compile into
`{{.Home}}/...` so each emit target resolves it against the **destination** home — the
deliberate design recorded in `install_build.go` ("Tokenize a home-relative `to:` so each
EmitTarget resolves it against the real destination home at emit"). The OCI target does
that, in `OCITarget.emitPlan`:

```go
if t.Home != "" {
    ResolveHome(plan, t.Home)   // spec.ResolveHome: `case *OpStep: s.To = sub(s.To)`
}
```

The machine-venue walk had **no equivalent**. `walkOp` passed `step.To` straight to
`PutFile`, so the literal token reached the venue.

**Observed on a live Arch guest** — the file is delivered, just to a directory literally
named `{{.Home}}`:

```
$ ls -la ~/copyprobe
-rw-r--r--  written.txt          # write: applied
                                 # copy:  absent

$ sudo find / -xdev -name copied.txt
/home/arch/{{.Home}}/copyprobe/copied.txt

$ ls -la ~
drwxr-xr-x  copyprobe
drwxr-xr-x  {{.Home}}            # created by the unresolved token
```

No error is raised, which is why it went unnoticed: `mkdir:`, `write:` and `command:` from
the same candy in the same deploy all apply normally, because those legs render shell that
expands `$HOME` at runtime. Only the `PutFile`-staged verbs are affected.

**Why it matters beyond one candy:** `pod-sway` delivers both its `sway-wrapper` and its
`config` via `copy:`, so a `target: vm` deploy of the sway stack lands a compositor whose
launcher is in a junk directory.

## The fix

`WalkPlans` resolves the token before any step runs, across the **same field set**
`spec.ResolveHome` covers, so the machine venue and the OCI target resolve the same places
rather than drifting (R3). Three details worth reviewing:

- **Lazy probe.** Only a plan that actually carries the token pays the extra `RunCapture`,
  so the common case costs nothing.
- **One probe implementation.** `ensureVenueManagedBlock` carried its own inline
  `printf %s "$HOME"`; both now call `probeVenueHome`.
- **Empty home is a no-op**, not an empty substitution — a failed probe must not silently
  rewrite `${HOME}/x` into `/x`.

The field list lives in one function (`homeBearingFields`) that both the predicate and the
resolver read, so a future view field cannot be added to one and forgotten in the other.

## How tested

**The regression test fails without the fix.** Neutralising only the resolution call, with
the helpers left in place, reproduces the live symptom exactly:

```
--- FAIL: TestWalkPlans_ResolvesHomeTokenForCopy
    copy did not land at the resolved home path "/home/u/probe/copied.txt";
    PutFile saw [{{.Home}}/probe/copied.txt]
    PutFile destination still carries the unresolved token: "{{.Home}}/probe/copied.txt"
--- FAIL: TestWalkPlans_ExplicitHomeOptWins
    explicit WalkOpts.Home not honoured; PutFile saw [{{.Home}}/m]
```

With the fix restored:

```
--- PASS: TestWalkPlans_ResolvesHomeTokenForCopy
--- PASS: TestWalkPlans_ExplicitHomeOptWins
--- PASS: TestStepCarriesHomeToken
--- PASS: TestResolveStepHomeNoopOnEmptyHome
ok  github.com/opencharly/sdk/kit
```

`TestStepCarriesHomeToken` walks every field family (`To`, `Dest`, `ExtractDest`,
`UnitPath`, `UnitText`, `Snippet`, `Destination`, `EnvVars`, `PathAdd`, `PathAppend`),
asserting each is both detected and resolved, and that a token-free step does **not**
trigger a probe.

### Live acceptance is not in this PR, and why

The end-to-end proof needs `plugin-deploy-vm` rebuilt against this sdk, which means this
tag first, then that plugin's pin. The minimal reproducer is committed in the issue and
reproduces in ~2 minutes on a disposable Arch cloud-image VM bed:

```
- run: mkdir: "${HOME}/copyprobe"
- run: copy: marker.txt   to: "${HOME}/copyprobe/copied.txt"
- run: write: "${HOME}/copyprobe/written.txt"
```

Before: only `written.txt` in `~/copyprobe`, `copied.txt` under `~/{{.Home}}/`. The unit
test above encodes exactly that assertion at the seam where the defect lives, which is why
it fails without the change.

## Rulebook compliance

- **R1** — root-caused to the specific missing call by tracing the OCI target's
  `ResolveHome` and confirming the token on a live guest; the fix addresses the cause, not
  the symptom.
- **R3** — reuses `spec.HomeToken` and mirrors `spec.ResolveHome`'s field set instead of
  inventing a second notion of "home-bearing"; the duplicated inline `$HOME` probe is
  collapsed into one helper.
- **R4** — no defensive `|| true`, no path-guessing fallback: an unresolvable home is an
  explicit no-op.
- **Scope** — one function plus its helpers and a test file; no behaviour change for plans
  that carry no token.

## Change classification

- **Change class:** bug fix in the deploy walk (`sdk/kit`), plus a regression test.
- **Verification gate:** `go test ./...` on the module, `go vet`, `gofmt`, and a negative
