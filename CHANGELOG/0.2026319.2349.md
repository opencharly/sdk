# 0.2026319.2349 — feat(deploykit)!: the last four candy IR fields cross as bytes, in ONE shared package

## Summary

The **consumer half** of `opencharly/spec` `v0.2026319.2325`, where the last four `#CandyModel` fields (`service`, `volumes`, `aliases`, `artifact`) became opaque. Closes **opencharly/sdk#536**.

**The crossing now lives in ONE package, and that is this PR's real content.** `loaderkit` and `deploykit` do not import each other, so the four earlier fields grew **two** copies of the same encode/decode — and they had already drifted (one guarded on `!= nil`, one on `len() > 0`, and the first answered the wrong question for a slice). `sdk/rawbody` now provides `Encode`, `HasSlice`, `HasPtr`, `Decode`, `DecodeOne`; both packages delegate to it. That is why fields five, six and seven cost no new mechanism.

| where | change |
|---|---|
| `rawbody/rawbody.go` | **NEW** — the one crossing, with the guard rule stated once: a SLICE asks `len() > 0` (an empty non-nil slice marshals to `[]`, two non-empty bytes), a POINTER asks `!= nil` |
| `loaderkit/scan_candy.go` | the producer encodes `service`, `volumes`, `aliases`, `artifact` through it |
| `loaderkit/finalize_candy.go` | `candyTriggersInit` decodes `Model.Service` — it runs **before** the adapter exists, so it cannot use the accessor |
| `deploykit/spec_candy_adapter.go` | `Service()` and `Artifact()` decode; **`Volume()`/`Alias()` are unchanged** — they read the `CandyView`, not the model |
| `loaderkit/opaque_body.go`, `deploykit/opaque_body.go` | now thin delegations to `rawbody` |
| the `*_test.go` fixtures | route through `rawbody.Encode`, which is what the producer does |

**`Volume()`/`Alias()` genuinely need nothing.** The adapter's own comment says so (`:180-183`): alias/volume/env-provides read off `CandyView`, artifact/capabilities off `CandyModel`. So the model's bytes for those two are written by the producer and decoded only where the model is read directly.

`TestOpaqueBodiesDecodeAndRejectCorruptInput` now covers **five** fields in one table (`hook`, `extract`, `data`, **`service`**, **`artifact`**), each asserting: the authored values decode, an empty body is nil, and corrupt bytes panic. `loaderkit`'s producer tests call the real `populateFromYAML`.

**`volumes`/`aliases` have no adapter accessor**, so their encoding is pinned where it is the ONLY coverage: `TestPopulateFromYAMLWritesVolumesAndAliases` drives the real `populateFromYAML` and asserts both bodies decode to the authored entries, that absent lists yield no body, and that an **empty non-nil** list does too.

**And `rawbody` itself is tested**, because its guard rule is the drift this PR consolidates: `rawbody/rawbody_test.go` pins `Encode`/`Decode`/`DecodeOne` round-trips, both corrupt-body panics, and `HasSlice([]T{}) == false` / `HasPtr(nil) == false`.
