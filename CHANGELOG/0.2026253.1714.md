# 0.2026253.1714 — feat(loaderkit): the namespace-aware runtime entity resolution (the vm-build counterpart)

## Summary

The load-time validator now resolves namespace-qualified refs (sdk #246), but the RUNTIME vm-build path still used local-only lookups: DeployTargetEntity (the clone-base deploy-hop) and the vm template body lookup both enumerated the top-level maps only, so a bed cloning from a git-linked namespace golden (omarchy.check-charly-omarchy-vm:golden) validated GREEN at load but failed vm-build with "has no kind:vm entity".

This lands the runtime counterpart of the canonical reference-resolution surface (R3):
- **DeployTargetEntity**: the namespace-qualified form (ns.entity) resolves through the namespace's own vm templates and deploys; the returned target is the qualified template name (ns.template) so the caller's subsequent lookup resolves it the same way. The unqualified form stays local-only (the no-leak contract).
- **ResolveKindEntityBody**: the opaque kind:<word> template body lookup, local or namespace-qualified — the runtime counterpart of ResolveEntityRef (a ref that validates must resolve here).
- **Tests**: the qualified bed-hop → qualified template, the qualified template direct, the no-leak contract, and the body lookups.
