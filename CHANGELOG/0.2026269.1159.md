# 0.2026269.1159 — fix(loaderkit): exempt a from: whose structural kind folded no template here

fix(loaderkit): exempt a `from:` whose structural kind folded no template here

**R1 — a real project-wide validation defect**, found while wiring the KubeVirt R10 beds
(charly#676).

## The anomaly

`ValidateCheckBeds` requires a `kind:check` bed's `from:` cross-ref to resolve. It
returns on the FIRST error, so ONE mis-resolving bed aborts validation for the WHOLE
project. Measured live:

```
$ charly deploy add <any-vm-bed>
charly: error: … plugin-deploy-vm prepare-venue: resolve vm entity "k3s-vm":
resolve kind:vm entity "k3s-vm": <charly.yml>: kind:check bed "check-kindcluster"
references kindcluster entity "check-kindcluster-cluster" which is not defined
```

**Every VM bed becomes un-runnable**, not just the kindcluster one. Reproduced on
**pristine `origin/main`** with a **pre-existing main bed** (`check-charly-vm`) — so it
is not a caller's fault.

## Root cause

`candy/plugin-deploy-vm`'s `prepare-venue` re-loads the project via
`loaderkit.LoadUnifiedViaExecutor` — a read-only **plugin-side** load that has **no
connect pass** and does **not** compile in every structural-kind provider (plugin-kube,
which folds the `kindcluster` template, is absent). So in that process
`PluginKinds["kindcluster"]` is empty and the same-file `from:` cannot resolve — even
though the SAME file validated fine host-side, where the provider IS connected.

The existing `declaredStructuralKindUnconnected` helper only exempts a **targetless**
bed, not a bed with an unresolvable `from:`.

## Summary of changes

- **`loaderkit/validate_check_beds.go`** — when a bed's `from:` fails `ResolveEntityRef`
  **and** its target kind folded **zero** templates in this scope
  (`kindTemplatesAbsentHere`), the cross-ref cannot be judged here (the provider never
  ran) → exempt. The signal is **local to the `uf`** (folded templates), NOT the
  host-computed `StructuralDeclaredFields` snapshot: a plugin process receives the
  host's "connected" snapshot while its own `PluginKinds[target]` is empty.
  - A kind that folded **some** templates but not this ref is a real typo → still
    rejected.
  - A built-in resource kind (`vm`/`pod`/…) is never in `t.StructuralKinds` → never
    exempt.
- **`loaderkit/validate_check_beds_unconnected_kind_test.go`** — new: the un-folded case
  is exempt (fails without the fix); the folded-but-bad-ref case is still rejected; the
  built-in case is unaffected.
