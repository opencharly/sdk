# 0.2026249.2239 — fix(loaderkit): the substrate-branch member scan excludes the declared #Deploy fields — the deploy-declared-fields channel (sdk #221 class)

## Summary

Fixes the sdk #221 parse regression for DEPLOY-SUBSTRATE bodies: the substrate-branch member scan misclassified declared #Deploy field bodies as in-substrate members.

The #222/#223 guards fixed the STRUCTURAL arm, but the SUBSTRATE arm (`t.DeploySubstrates`) still scanned disc values by VALUE SHAPE (`discEntityPairs`/`isEntityValue`): a declared #Deploy field whose value mapping carries a kind-word key classified as an IN-SUBSTRATE MEMBER. The proven repro (the canonical charly-cli ADE iterate-entity bed, `charly/charly.yml:2032` pattern): a pod primary body with `iterate: {sandbox: check-agent-pod, agent: [check-agent-live-claude], plateau_iteration: 1, prompt: ..., note: false, env: {}}` — `agent` is a kind word, so `iterate:` classified as a member named "iterate", `parseNode("iterate")` took `agent` as ITS disc, and the scalar `sandbox:` hard-failed "node sandbox: expected a mapping value, got yaml kind 8". (Renaming the key to `agentsX` got past the raw parse, then CUE said "field not allowed" — isolating the parse class.) Blast radius: the canonical iterate-entity bed + 3 more `iterate{agent:}` beds + every AI-benchmark bed in the distro conversions.

Same mechanism as #223, extended to deploy substrates — membership semantics live in the PARENT kind's declared schema; for substrates that is **#Deploy's OWN CUE schema**:

- The new `spec.Threaded.DeployDeclaredFields` channel (opencharly/spec#107, `v0.2026249.2215` — the #104 `StructuralDeclaredFields` twin) is consulted by the substrate branch: a pair whose KEY is a declared #Deploy field (`iterate`, `plan`, `record`, `disk_size`, `ram`, ...) is DATA — its value is NEVER looked inside.
- Every other entity-keyed value-shape member (`web:`/`chrome:`/`sidecar:`) stays a member.
- A substrate word with NO declared schema threaded keeps the plain value-shape scan (the documented no-declared-schema fallback).
- Zero hardcoded lists: the host feeds the channel from the registered substrate schema.

Also bumps the spec pin to `v0.2026249.2215` (the channel's contract change).
