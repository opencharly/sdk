# 0.2026269.1717 — feat(sdk): project plugin.requires onto CandyView + adapt the venue fixtures to spec#168

## Summary

Project a candy's authored `plugin.requires:` list onto the resolved `CandyView`, and expose it
through `spec.CandyReader.GetPluginRequires()` — the **consumer leg** (sdk) of the spec → sdk →
charly chain whose spec leg is **opencharly/spec#173** (tag `v0.2026269.1640`, merged).

**The gap this closes:** `plugin.requires:` was authored on `#Plugin` (spec#163) and carried on
the wire as `Capabilities.requires`, but the resolved-project projector
(`loaderkit/scan_candy.go`'s `populateFromYAML`) copied `Plugin.Source` + `Plugin.Providers`
into `CandyView` and **never `Plugin.Requires`**. So the view every consumer reads a candy
through — the same view `plugin_source` / `plugin_providers` live in — exposed a plugin's
providers but never its declared inter-plugin dependencies; the requirement was inert.

Two edits, mirroring the existing `providers` path exactly (R3):

- **`loaderkit/scan_candy.go`** — `populateFromYAML` now also does
  `v.PluginRequires = append(v.PluginRequires, ly.Plugin.Requires...)`, beside the existing
  `PluginSource` / `PluginProviders` writes (clause D: a projection of the plugin repo's own
  manifest).
- **`deploykit/spec_candy_adapter.go`** — `GetPluginRequires()` returns `a.v.PluginRequires`,
  beside the existing `GetPluginProviders()` — the accessor the host's requires gate reads.

### The named consumer leg (producer-first, B6)

This is the **sdk leg**. The consumer lands as its own branch that bumps its `sdk` pin to this
change: **`opencharly/charly` branch `feat/requires-manifest-consume`** — the host's requires
gate reads the declared dependencies through the resolved view (`candy.GetPluginRequires()`),
the reference plugin declares `requires:` in its manifest + Go meta, and the disposable R10 bed
exercises resolve/connect/cycle/missing-peer live.

### The required spec pin bump carries a pre-existing venue drift (R2)
Bumping `spec` to `v0.2026269.1640` (required to compile against `CandyView.PluginRequires` /
`CandyReader.GetPluginRequires()`) also pulls in **spec#168** (`feat(schema): give kubevirt its
own venue value`), which changed `deploy.SshVenue` to read the DERIVED `Descent.Transport`
instead of the raw `Venue` token. Two sdk fixtures hand-built an incomplete `DescentDescriptor`
(`Venue` only, no `Transport`) and were already stale against that spec change — the pin bump
made them fail. This PR fixes them at the source by stamping the fixtures through the REAL
derivation (`spec.DescentFromTraits(...)`), exactly as the loader's `StampDescent` produces a
node — so the fixtures carry the DERIVED transport the predicates read:

- `deploykit/deploy_members_test.go` — `vmNode`/`kubevirtNode`/`podNode`/`localNode`.
- `kit/vm_domain_lock_test.go` — `vmDescent`/`podDescent`.

Without this the sdk `go test ./...` is red (`TestIsVmVenue_IsContainerVenue`,
`TestBedVmDomains`); with it, green.

**The surfaced SDK `go` gate (R2, fixed in-tree):** bumping the pin also surfaced a **pre-existing
gofmt drift** in `kit/render_test.go` (merged in #303) that reddened the module's own `go` CI job
on `main`. A gofmt fix is trivial and lives in THIS module, so R2 requires it be fixed in-tree
rather than parked: `kit/render_test.go`'s comment carried a literal `''` that Go's doc-comment
reformatter rewrites to a curly quote (so `gofmt -w` would CORRUPT the comment, not fix it). The
fix reworks the comment to be gofmt-stable without the raw `''` token, preserving its meaning. The
whole module is now `gofmt -l .` clean.
