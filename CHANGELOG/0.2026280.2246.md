# 0.2026280.2246 — feat(loaderkit): one `cluster:` resolve helper for the kube/kubevirt verbs (R3)

## Summary

`opencharly/sdk#338`, **producer half**: the `cluster: <profile>` resolve mechanism now has ONE declaration, in its home, instead of a copy per plugin.

Two copies existed on `origin/main`:

- `hostProjectDir` — **byte-identical** in `candy/plugin-kube/preresolve.go:138` and `candy/plugin-kubevirt/cluster.go:148`, with four call sites (`plugin-kube/k3s_post.go:164`, `plugin-kube/provider.go:162`, `plugin-kubevirt/cluster.go:131`, `plugin-kubevirt/command.go:391`);
- the five-step wrapper each plugin then wrote around it — `resolveKubeVerbCluster` (kube) and `resolveClusterContext` (kubevirt), the same five steps with different error prose.

This PR adds `loaderkit/resolve_cluster_via_executor.go` with `ProjectDirViaExecutor` and `ResolveClusterContextViaExecutor`; the two consumer repos then call it and delete their copies (their own PRs, producer-first — this issue closes with the last of them).

**The contract is deliberately asymmetric, and that is the load-bearing part.** A legitimate MISS — the project declares no such `kind: kubernetes` entity — is `("", nil)`, so the caller keeps the kubeconfig's own current-context. Every FAILURE is loud and names the cluster: a nil executor, a failing `deploy-plugins-connect` seam, a failing entity resolve, an undecodable reply. Reading a failure as "no cluster profile" is exactly the silent-degradation defect opencharly/plugin-kube#15 fixed, which is why its coverage moves here rather than being lost.

**Rule 11(c):** this file's docstring is now **the source of truth** for the mechanism — the plugins' comments will point here instead of restating it, and `ResolveClusterContextViaExecutor`'s own comment states the miss/failure asymmetry in full.

**Files (2, +257):** `loaderkit/resolve_cluster_via_executor.go` (+91), `loaderkit/resolve_cluster_via_executor_test.go` (+166).

Refs #338 (closed by the two consumer PRs that delete the copies)

**Coverage that fails without the behaviour:** the three loud arms are assertions about the *asymmetry* — they fail the moment any failure path is softened into the `("", nil)` miss (and the two miss arms fail if a legitimate miss is turned into a hard error). They do not merely exercise the happy path.

**How the arms became testable without a host:** the resolve leg is a parameter of the unexported `resolveClusterContext`, so the entity-failure and resolved-but-empty arms need no live reverse channel and the SDK needs no package-var seam (the pattern `loaderkit/resolve_retention_defaults_test.go` established is reused for the project-dir seam: a stub that embeds `pb.ExecutorServiceClient` and overrides only `HostBuild`).

**What this PR does not claim:** the duplication is still live in the two plugins until their PRs land — this PR adds the shared declaration, it does not pretend the copies are gone. And the *pre-fix* form of these nine tests cannot run in `loaderkit` at all (the helper is what this PR introduces), so the pre-fix evidence is the consumers' own suites, which fail to compile the moment their copies are deleted without calling this helper — the mechanical proof that the copy is what fed them.
