# 0.2026319.104 — feat(loader): the gate resolves through the threaded kind gates first

## Summary

Successor to #523 (auto-closed at the verdict threshold with this code; the last block found a real defect — a declared gate falling back silently — which this head fixes and pins with a test).

The SDK half of the RCA's step 3 (`PROGRAM/schema-ownership-rca-rdd.md` §3 I3/I4), and the fix for the defect a live test found in charly.

**The defect:** `ApplyCueDefaults` resolved a kind's def through `cueKindDef(kind)` — the BASE schema's table. After the vm body moved into plugin-substrate, that table returns the envelope (`#ResolvedVm`, correct for the loader) while the defaults helper needs the authored `#Vm`. Six tests failed:

```console
--- FAIL: TestApplyCueDefaults_FillsFirmware (0.00s)
    cue_defaults_test.go:80: applyCueDefaults: applyCueDefaults vm: decode: firmware: cannot convert non-concrete value string
```

**The fix:** `ApplyCueDefaults(kind, out, gates)` resolves through `kindDefFor`, which consults the THREADED gates first — the SERVED CUE source a plugin declared, compiled here, in this process — and falls back to the base module only for a word nobody declared. That is what lets a loader-side helper unify an authored body that moved into a plugin, without a registry query and without a second private copy of the schema.

The local test seam follows unit 4: `spec.Local` moved, so it decodes the authored bytes into the surviving resolve envelope.
