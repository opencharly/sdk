# 0.2026296.1141 — fix(skills): resolve a `type: agent` body through ONE candywalk authority, so `box validate` reads .agents/agents

## Summary

**`charly box validate` can resolve a `type: agent` skill node's body, because ONE authority in
`candywalk` now owns the shape→location rule and `deploykit` calls it instead of hard-coding the
skills tree.**

The defect (opencharly/sdk#456): `candywalk` gained the agent reader and `AgentsAgentsDir` in sdk#420,
but `deploykit`'s collector — the path a repo's own `charly box validate` runs — resolved
`.agents/skills` for every node whatever its `type:` said. Every project declaring an `agent` node
therefore failed its own validate gate on `main`, for a body sitting exactly where `AGENTS.md`
Part II #5 and the `skills` skill place it.

The fix is deliberately NOT a second path in `deploykit`. The shape→location rule is encoded in
three places today — the collector (wrong), the marketplace generator's read branch, and the same
generator's `extract` write branch — while `candywalk` owns the readers and both tree constants but
has no dispatcher. Teaching `deploykit` the branch would make it four. So the rule moves to where
the readers already live:

- **`candywalk.ShapeOf(nodeType)`** — the ONE `type:` → authored-layout mapping (`agent` ⇒
  `ShapeAgentFile`, everything else — including the schema's default — ⇒ `ShapeSkillFiles`).
- **`candywalk.ReadNodeBody(base, name, nodeType, trees)`** — the ONE resolution: the declared skill
  trees (default `AgentsSkillsDir`) for a skill, `.agents/agents/<name>.md` for an agent, with the
  "an agent's path does not move with `skills:`" contract owned here.
- **`candywalk.NodeBodyLocation(nodeType, name, trees)`** — the shape's own file, so a "no body"
  message cannot name the other tree.
- **`candywalk.AuthoredBody`** — the shape-agnostic projection (`Shape/Name/Description/Content/
  References`) a consumer that only publishes or labels the prose consumes.

`deploykit`'s collector calls `ReadNodeBody` and carries **no** type branch of its own, so the tree
the GATE validates and the tree the CORPUS publishes cannot drift apart. The visible half of the
defect is the message: a missing body for an agent node now names `.agents/agents/<name>.md`
instead of a `SKILL.md` path no agent read ever looks in.

`ReadSkillFile` / `ReadAgentFile` keep their contracts unchanged (both are what `ReadNodeBody`
dispatches to); nothing is deleted from the public surface.
