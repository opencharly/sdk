## Summary

**The drive kit, and the second Containerfile-build site routed through it.**

`deploykit/vm_box_emit.go` no longer shells out to an engine's `build -t`: the emit path builds through the new drive kit and bridges the result into the run engine's store. That closes this half of the cutover at the build sites — the drive's own site (`plugin-build`) is leg 4, and every other engine-build invocation is enumerated in the plan's deletion list.

**`buildkitdrive/` is deliberately not named for "builder"**, a word that already carries three meanings in this tree (the `builder:` provider class, the `builder:` selection map, the multi-stage stages themselves). `buildkit/` is the Containerfile **render** machinery; this is the **drive**:

| file | what it owns |
|---|---|
| `paths.go` | the socket and the state root through the **ONE roots resolver** (`storekit`), never a literal — the uid-1000-hardcoded `/run/user/1000/buildkit/…` path is the deviation this ends; the state root must be a real filesystem, so a tmpfs root is refused by design |
| `daemon.go` | the measured rootless spawn — `rootlesskit --state-dir … --net=host buildkitd --rootless --root … --addr unix://<socket> --config …` — attach when a daemon already answers, else start it and probe readiness under a **bounded deadline**; the daemon outlives its starter, so it logs beside its state root instead of inheriting the caller's streams |
| `buildctl.go` | the argv model. The OCI export is **not a caller option**: the daemon writes into its own content store, which the run engine cannot read |
| `bridge.go` | the **(A)** export+load bridge, including its **named duty** (below) |

**⚑ The tag re-application is implemented as a duty, not left as a caveat.** The plan is explicit that option (A) is not implemented until that step is in the code *and* asserted: a load returns success while landing an OCI-exported image **untagged** (`<none>:<none>`), because the layout's `index.json` carries only `org.opencontainers.image.created` and no `org.opencontainers.image.ref.name`, so the CalVer reference would resolve to nothing and every downstream verb (labels, deploy, status, `charly clean`) would break. `LoadExport` therefore performs **three** steps — load, read the image ID **from the archive** (`index.json` → manifest blob → config digest, the digest a runtime computes an ID from), tag by it, then **verify the reference resolves** — and the verification lives inside the function so the duty cannot be skipped silently.

**BREAKING:** `EmitVmBox`, `EmitVmBoxAt` and `EmitVmBoxMicroVM` now take a `context.Context` first. The build they perform is minutes-long and was previously uncancellable. The compiler forces the one external caller (`plugin-vm`) in its own leg; every in-repo caller is updated here.

Changed: **11 files, +988/−22** — **5** new kit files, **5** updated `deploykit` files (the build site, three live-test files, and the new drive guard), and this repo's `AGENTS.md` — 5+5+1 = 11, which is the diff's file count. Five commits: the change, the round-1 linter fix, the round-2 skip guard, the round-3 helper cleanup, and a catch-up MERGE of `main` (which had gained `storekit/orphans.go` and its CHANGELOG) — a merge and never a rebase, so the branch is no longer BEHIND under the ruleset strict status checks, and the diff against the new `main` is unchanged.

**⚑ And that live gate caught two REAL defects, which is the point of running it.** Both are fixed here, and both are the same class — *an instrument that did not cover the wiring*:

1. `EnsureDirs` returned the socket's **directory** and I bound it as the socket **path**, so the daemon was told to create a socket at a directory and refused outright:
   `buildkitd: failed to create unix socket on /run/user/1000/charly: is a directory`. **Every unit test passed**, because they asserted the pure helpers and never the value the daemon is actually addressed with. All four live tests failed at ~16s (my 15s readiness deadline).
2. The daemon inherited the caller's **stderr**, so a short-lived caller could not finish:
   `*** Test I/O incomplete 1m0s after exiting` / `exec: WaitDelay expired before I/O complete` — a package-level gate failure **with every assertion passing**. Its output now goes to a log beside its state root (which is also where a reader looks for its startup diagnostics). This one is not test-only: in production the daemon would have held charly's streams open.
