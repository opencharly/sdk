# 2026.227.0000 — honor the NFPM_*_PASSPHRASE env vars in the struct-direct nFPM build path

The `generate-packages` plugin's CLI documents deb/rpm signing as "passphrase
via `NFPM_PASSPHRASE`" (and apk via `NFPM_APK_PASSPHRASE`, msix via
`NFPM_MSIX_PASSPHRASE`), but the struct-direct build path never read them:
`packagekit.buildOne` calls `nfpm.WithDefaults` (which does no env expansion),
not `nfpm.Parse` (which is where nFPM reads the passphrase env vars). A
passphrase-protected signing key therefore failed at package-build time with
`signing error: armored detach sign: key is encrypted but no passphrase was
provided` — surfaced while validating the Phase 2 distro-repo workflows against
the released plugin.

- **`packagekit/build.go`** (`applyPassphrases`): mirrors nFPM's Parse-time env
  expansion for the struct-direct path — the general `NFPM_PASSPHRASE` fills
  deb/rpm/apk, and the per-format `NFPM_DEB_PASSPHRASE` /
  `NFPM_RPM_PASSPHRASE` / `NFPM_APK_PASSPHRASE` / `NFPM_MSIX_PASSPHRASE`
  override it. Called in `buildOne` after `BuildInfo`, before `WithDefaults`.
- **`packagekit/build_test.go`** (`TestApplyPassphrases`): asserts the general
  passphrase reaches deb/rpm, the per-format override wins for apk, and msix
  reads its own var. End-to-end verified against the real passphrase-protected
  distro-repo GPG key: a `.deb` builds and embeds the `_gpgorigin` signature
  member (previously the exact failure above).
