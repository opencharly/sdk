# 2026.224.2004 — materialize extract steps on machine venues; fix machine-venue write parents

The sdk half of the AgentTeams VM-substrate fix (spec → sdk → main): gives the
new `ExtractStep` IR (spec v0.2026224.1942) an execution body and closes the
machine-venue write gap the VM bed surfaced.

- **`deploykit/venue_extract.go`** (`RunVenueExtractStep`): the machine-venue
  counterpart of the container-venue `FROM <source> AS <candy>-extract-<i>` +
  `COPY --from=...` stage. A machine venue has no image build — the install
  plan executes over the venue's own filesystem — so the content must be
  materialized on the HOST (where podman + the source images live) and shipped
  into the venue over the DeployExecutor. Pulls the source image through the
  same resolve/ensure closures the container path uses, validates the step,
  honors dry-run.
- **`deploykit/install_build.go`** + **`deploykit/steps.go`**: wire the
  `ExtractStep` into the machine-venue install-plan execution (the `extract`
  word, deploy-only).
- **`kit/render.go`**: the machine-venue `write:` verb now creates the parent
  dir first (`install -d -m0755 <dir> && install -m<mode> /dev/stdin <path>`),
  matching the container-venue COPY behavior (Docker auto-creates parents) and
  the download verb's existing `install -d`. A write into a not-yet-existing
  dir (e.g. `/etc/nginx/conf.d` on a distro whose nginx ships no conf.d)
  failed on a machine venue where the same candy succeeds on a container
  substrate. `install -d` is a no-op on an existing dir, so this is always
  safe.
- **`kit/walk.go`**: the walker now descends into the new `ExtractStep`.
- **`go.mod`/`go.sum`**: spec pin bumps `v0.2026224.403 → v0.2026224.1942`
  (the released ExtractStep IR); the dev-aid local replace (`=> ../spec`) is
  removed.
