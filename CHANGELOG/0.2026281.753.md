Adopts `github.com/opencharly/spec` **v0.2026280.2244** in the sdk contract module — the consumer leg of

**What the adopted range changes, and the consumer adaptations:**

1. **spec#208 removed `spec.LocalPkgInstallStep.Version`** (and its view round-trip). The provenance is
   the one this diff and its comments MEASURE, and this body states it the same way: **the field's writer
   was lost in `sdk#313`** (which removed `deploykit.ComputeEffectiveVersions`), and the retirement is
   tracked by **ISSUE `sdk#315`**, with **`spec#208`** the spec half. The dead-vestige guard in this
   module asserted the field was *empty*, which no longer typechecks against the new spec. It now asserts
   **structurally** that the type carries no `Version` field: a reinstated `Version:` assignment is a
   compile error (the strongest form of the same guarantee), and the reflection check keeps the vestige
   from creeping back as a field with no writer. (I do not attribute the guard to a PR number: the commit
   that added it is not measurable from this checkout, and naming the ISSUE is the honest answer.)

2. **spec#202 made a ref's identity its PROJECT identity, not the enclosing repository** — the fix for
   the false local-import back-edge that sdk#253 measured as three namespace failures.
   `loaderkit.RepoIdentity` is a plain alias of `spec.RepoIdentity`, so `TestRepoIdentity`'s subpath
   expectation is stale and is updated to the project identity, with the reason recorded at the
   assertion (stripping `@github.com/o/r/candy/x:v1.2.3` to `github.com/o/r` is the PRE-#202 behaviour).

This also **closes the residual the sdk#253 dossier named** — "sdk's own go.mod still pins spec
v0.2026276.0 (a pin bump, not the defect)" — in the same range that carries spec#202.
