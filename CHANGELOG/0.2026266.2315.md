# 0.2026266.2315 — feat(kit): transport-agnostic console-wizard engine + one shared OCR path

## Summary

Adds a **transport-agnostic console-wizard engine** to `sdk/kit`: drive a
text-console wizard (an OS installer, a first-boot provisioning flow, a firmware
setup screen) from screenshots + OCR + keyboard input, with the recipe supplied
as plain Go DATA.

It is shared (R3) because **more than one transport drives the same wizard**: the
`jetkvm` verb drives a real machine's keyboard/video, and the `spice` verb drives
a VM's console — the SAME recipe must produce the SAME drive on either. An sdk kit
is the mechanism this project uses to share code across plugin module boundaries,
so the engine lives here and each transport implements the small
`ConsoleTransport` interface.

Alongside it, this PR **consolidates the SDK's OCR and error-clip paths** (R3):
`sdk/artifact.go`'s `artifact_contains_text` validator now calls the shared
`kit.OCRBytesScaled`, and its private `upscaleForOCR` helper and `truncateForError`
clip are deleted. There is now ONE tesseract invocation and ONE error-line clip
in the SDK.

**Why this exists (measured).** Driving an Omarchy install over a JetKVM live
proved the mechanism end to end: the machine installed unattended, rebooted, ran
first-boot owner provisioning, and reached the Hyprland desktop — every step
OCR-gated on a screen-unique anchor. That work first carried a private engine in
`plugin-jetkvm`; a VM console bed needs the SAME engine, so it is hoisted here
rather than duplicated (the private copy is removed in the consuming plugin PRs).

### Contents — the complete exported surface

- `ConsoleStep` — the neutral step (WaitFor / Action / Key / Combo / Text / TimeoutSec / Optional / Artifact / Description).
- `ConsoleWizard` — the driver (`Steps`, `Answers`, `Transport`, optional `OCR`, `PollInterval`, `Logger`); its `Run(ctx)` executes the recipe.
- `ConsoleTransport` — the per-transport primitive set each plugin implements: `Capture` (screen → PNG), `PressKey`, `PressCombo`, `Type`.
- `BuildConsolePlan(steps, answers)` — the PURE validator + `{{answer}}` substitution (unknown placeholders left visible, never silently empty); returns `ConsoleStepPlan`.
- `SelectRecipe(recipes, steps, name)` — FREE FUNCTION: picks a named recipe from a `map[string][]ConsoleStep`, with a bare `steps` list as the single default recipe.
- `MergeAnswers(envVars, secrets, authored, envName, secretName)` — FREE FUNCTION: resolves the three answer sources **lowest-to-highest** (`env` < `secret` < `authored`). An unresolved env var/secret is left OUT, so a missing var fails visibly as an unsubstituted placeholder rather than silently empty.
- `SubstituteConsoleAnswers` — the `{{answer}}` substitution helper.
- `ConsolePreview(s, n)` — the ONE error-line clip in the SDK: collapse ALL whitespace runs (newlines included) to single spaces, truncate to `n`, append an ellipsis only when truncated. `sdk/artifact.go`'s error paths call it too.
- `ConsoleStepPlan`, `ConsoleOCRPSM`, `ConsoleDefaultTimeoutSec` — exported types/constants (the plan type `BuildConsolePlan` returns, the shared tesseract PSM, the default per-step timeout).
- `OCRBytes` / `OCRBytesScaled` — the ONE tesseract OCR implementation. `OCRBytes` reads at native scale; `OCRBytesScaled` enlarges first by an explicit caller factor. The artifact validator (`sdk.assertArtifactContainsText`) AND the console transports BOTH call it (R3 — one OCR path), so the OCR invocation and its "failing to RUN is not failing to MATCH" error contract live in exactly one place. A missing engine or language data returns a NAMED error, never a vacuous empty read.
- `UpscalePNG(png, scale)` — the nearest-neighbour enlargement `OCRBytesScaled` uses, exported so its GEOMETRY is testable (a test asserts the output dimensions; deleting the enlargement fails it).

That list is the file's complete exported surface, verified against `go doc`. The
per-plugin CUE-step → neutral `ConsoleStep` conversion is NOT exported here — each
consuming plugin converts its own schema-generated step type in its own package,
which is exactly right: the kit holds the mechanism and no authored surface.

**No wire type lives here (SDD).** `ConsoleStep` and the recipe/answer maps are
engine-internal Go inputs; the AUTHORED shape is CUE-sourced in each consuming
plugin's own `schema/*.cue` (`#JetkvmInput`/`#JetkvmInstallStep`,
`#SpiceInput`/`#SpiceConsoleStep`), which each plugin decodes and converts to this
neutral form. The kernel/plugin boundary law is respected: the schema stays the
single source of the authored surface, and this kit holds only the mechanism.

removed):

PNG (the file's `exec("tesseract")` path runs live) and skips cleanly when
tesseract is absent. The `Run` path is exercised against a scripted transport
(including the optional-skip branch). `TestArtifactContainsText_*` exercises the
SAME shared OCR path from the artifact-validator side.

**Live proof boundary (honest).** The full device-driving `Run` is proven live in
