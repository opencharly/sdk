# 0.2026258.154 — feat(vm): resolve the disk-image root from vm.image_dir (configurable)

## Summary

`VmDiskDir` returned a hardcoded relative literal — `output/qcow2/<vm>` — which reads as disposable build scratch. It was deleted as such during a cleanup while 55 live VMs' qcow2 **backing chains** still pointed into it, breaking every one. The name was a footgun; the hardcoded root was the defect.

Route the root through a new `VmDiskRoot()` resolver (mirroring the existing `VmStateRoot()` shape, including its `(string, error)` contract — a resolution failure is PROPAGATED, never silently substituted with a different root):

1. `CHARLY_VM_IMAGE_DIR` env var (highest), else
2. the `vm.image_dir` runtime setting (spec#135, merged+tagged), else
3. the obvious default `image` (relative — resolved against the working project, exactly like the old literal).

`VmDiskDir(vm)` keeps its per-VM namespace, so a sibling VM never shares a disk or a stale `seed.iso`. An **absolute** `vm.image_dir` is honored as-is by `vmDiskPath` (the `filepath.IsAbs` guard) — `filepath.Join` does NOT reset on an absolute element, so gluing `cwd` onto an absolute root would stat a path that does not exist and break exactly the relocation this feature exists to enable.

This PR also:
- **bumps the spec pin** to `v0.2026257.1817` (the tag carrying `vm.image_dir` and the new 3-arg `FindVMClaimant`), so the build is self-contained — no local replace;
- **follows the merged spec#135 signature** in this repo's own `deploykit/deploy_ops_aliases.go` doc + its three `preempt_resolve_test.go` callers (the `FindVMClaimant(tree, entity, claimantID)` change is spec#135's, already merged+tagged; the sdk alias re-exports it, so the test call sites must pass the new third argument). This is the ONLY reason `deploykit/` appears in the diff.

**Operator note (restores the broken VMs):** the default root moves `output/qcow2/<vm>` → `image/<vm>`. Rebuild a base disk whose chain points at the old path with `charly vm build <entity>`. To keep the OLD layout without a rebuild: `CHARLY_VM_IMAGE_DIR=output/qcow2` (or `charly settings set vm.image_dir output/qcow2`).
