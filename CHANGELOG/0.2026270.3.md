# 0.2026270.3 — feat(deploykit)!: key a VM's per-host state by its deploy IDENTITY

## Summary

Key a VM's per-host deploy state by its **deploy identity** — the same string
the deploy tree, config, and CLI use (`charly.check-k3s-vm`) — for every
substrate. The `vm:`-prefixed, dot-sanitized key (`vm:<dashed>`) is **retired**.

This is the SDK leg of the unified-deploy-identity cutover; it depends on
spec#172 (MERGED — a deploy identity may contain `.`).

### Changes

- `saveVmStateInto` keys by the identity; the VM entity is carried in the
  entry's `vm:` cross-ref (`entry.From`), never derived from the key. The
  `vm:<entity>`-key derivation fallback is deleted; the no-op preserve case is
  collapsed to an implicit `if vmEntity != ""`.
- `PruneStaleVmDottedTwin` (the dotted-twin self-heal) is **deleted** — it existed
  only to repair the lossy-key collision, which the unified identity removes at
  the source.
- `VmDeployEntryKeys`: a deploy-identity teardown takes the literal-key path ONLY;
  the entity From-scan is gated on the `vm:` addressing prefix (the only form the
  direct `charly vm destroy` path sends), so an identity equal to a sibling's
  `vm:` cross-ref can never over-match.
- `VmStateFromDeployConfig` / `ResolveVmStateViaExecutor` look up the identity
  verbatim (dots legal).
- `ResolveVmSshPort` reads the identity key.
- `FindVmDeployNode` drops the `vm:`-prefixed fallback.

Two `"vm:"` sites remain at HEAD, both intentional:
1. the ADDRESSING-prefix gate in `VmDeployEntryKeys`
   (`strings.CutPrefix(deployName, "vm:")`) — not a key construction, retained for
   the direct `charly vm destroy` path;
2. the legacy-key PRUNE in `saveVmStateInto`
   (`"vm:" + spec.VmDomainIdentity(deployName)` → `delete`) — a key construction,
   but one that DELETES the retired key rather than reading/writing it; pinned by
   `TestSaveVmDeployState_PrunesLegacyDashedCanonicalKey`.
No legacy key is READ or WRITTEN; the only construction of a `vm:` key is the
teardown of the retired form.

### Legacy overlay-DATA cutover (R2/R5/B6)

Overlays written before this cutover keyed a deploy's per-host state under the
dashed `"vm:"+VmDomainIdentity(identity)` canonical key (e.g.
`vm:charly-check-k3s-vm`), and — via the now-deleted dual writer — under a raw
dotted twin equal to the NEW identity key.

Disposition: `saveVmStateInto` now DROPS the legacy dashed canonical key on the
next identity write (the one-touch cleanup the retired `PruneStaleVmDottedTwin`
used), so it cannot sit orphaned carrying a stale `ssh_port`/instance-id. The raw
dotted twin already shares the new identity key's exact shape, so re-writing at
the identity key overwrites it. Regression:
`TestSaveVmDeployState_PrunesLegacyDashedCanonicalKey` (fails if the prune is
removed; leaves unrelated entries untouched).
