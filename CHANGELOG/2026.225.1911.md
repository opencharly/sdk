# 2026.225.1911 — sdk/packagekit: the nFPM packaging driver + the localpkg download-leg replacement

The sdk half of the nFPM packaging cutover (spec → sdk → plugin → main): lands
the shared nFPM packaging driver (`sdk/packagekit`) and replaces the localpkg
source-build machinery with the download-leg + plugin-based dev build, adopting
the post-Phase-0a `packaging:` section and the shrunk `LocalPkg` type (spec
v0.2026225.1800).

- **`packagekit/`** (new): the nFPM packaging driver shared by the
  `generate-packages` plugin AND the localpkg replacement. `packaging.go`
  parses the `packaging:` section from a charly.yml (yaml.v3 into the
  `spec.Packaging` type — no hand-transcribed struct); `arch_map.go` maps
  GOARCH → per-format nFPM arch names from the nFPM arch-mapping docs
  (deb amd64→amd64/arm64→arm64; rpm/apk/archlinux amd64→x86_64/arm64→aarch64;
  ipk amd64→x86_64/arm64→arm64; msix amd64→x64/arm64→arm64); `variants.go`
  resolves a variant's plugin list + package name (default variant → the
  format's `default_variant`, named variants → `charly-<variant>`);
  `nfpm_config.go` builds `nfpm.Info` structs struct-direct from the
  packaging section + inputs (binary at `/usr/bin/charly`, the variant's
  plugins + `.providers` at `/usr/lib/charly/plugins/`); `build.go` calls the
  nfpm packagers via the library API; `arch_optdepends.go` post-processes the
  `.pkg.tar.zst` to inject `optdepend = <pkg>: <desc>` lines into `.PKGINFO`
  (nFPM's arch packager never emits `optdepend` — zstd decompress → tar
  rewrite → re-compress, the same libs nFPM uses).
- **`deploykit/localpkg.go`**: the localpkg source-build machinery is REMOVED
  (`BuildLocalPkgOnHost`, `stageLocalPkgSource`, `copyLocalPkgSource`,
  `gitLocalPkgSourcePaths`, the `pkg/arch` walk-up, the `charly-localpkg-`
  temp-dir machinery that only served source builds). `ExecLocalPkgInstall`
  now has two legs: the PRODUCTION download leg (`downloadLocalPkg` — resolves
  `${ARCH}` to `runtime.GOARCH`, downloads the published package from the
  distro's `download_template` on the HOST where curl lives, reuses
  `TransferAndInstallPkgs`) and the DEV build leg (`generateLocalPkg` —
  invokes `<binary> generate-packages` with the full flag surface, no
  `--variant`, then globs the out dir). `localPkgGlobFromDownload` derives the
  install glob from the download_template URL's extension chain;
  `charlyFormatToNFPM` maps pac→archlinux, deb→deb, rpm→rpm, apk→apk.
  `BuildDepPkgsOnHost` takes the builder name from the step (`s.Builder`)
  instead of the removed `lp.DepBuilder`.
- **`deploykit/install_build.go`** (`CompileLocalPkgStep`): reads the candy's
  `packaging:` section for the package name (gate: `pkg != nil && pkg.Name !=
  ""`), sets `Version` from `img.EffectiveVersion`, and drops the removed
  `PkgbuildRef`/`ProjectDir` fields — the `LocalPkgInstallStep` IR is now
  `{PackageName, Version, CandyName, CandyDir, Format, LocalPkg}`.
- **`deploykit/spec_candy_adapter.go`**: `Packaging()` on the CandyReader
  adapter (the `spec.CandyReader` interface now requires it).
- **`deploykit/render_generator.go`** + **`render_generator_from_project.go`**
  + **`candy_steps.go`**: the Generator carries a
  `LocalPkgBuild *spec.LocalPkgBuildContext` field; the
  `RenderLocalPkgImageInstall` seam signature becomes
  `(step, devLocalPkg, localPkgBuild, imageDir, boxName)` — the production
  leg renders the curl+install RUN, the dev leg builds via the plugin.
- **`loaderkit/scan_candy.go`**: `m.Packaging = ly.Packaging` replaces the
  removed `localpkg:` map copy.
- **`go.mod`/`go.sum`**: spec pin bumps `v0.2026224.1942 → v0.2026225.1800`
  (the `packaging:` section + shrunk `LocalPkg`); adds
  `github.com/goreleaser/nfpm/v2 v2.47.0` + `github.com/klauspost/compress`
  (the zstd lib nFPM uses) + their indirect deps; go `1.26.0 → 1.26.4`.
