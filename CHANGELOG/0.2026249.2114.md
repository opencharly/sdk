# 0.2026249.2114 — fix(deploykit): drop the dead group-root self-skip guard — spec #105 deleted Deploy.IsGroup()

## Summary

spec #105 (v0.2026249.2106) deleted `Deploy.IsGroup()` as part of the hard group-kind cutover (`group:` removed from `#ResourceKind`; group deploys now migrate onto a primary substrate with deploy-level sibling members). sdk's `deploykit/bed_session.go:71` still called it — the group-root self-skip guard in `PersistBedDeployOverrides` — so every consumer compiled against spec 2106 failed: plugin-check and plugin-preempt (both with in-flight IsGroup migration PRs) and charly's next consumer bump. This PR re-pins the sdk to spec v0.2026249.2106 and removes the guard.

## RCA — delete, not re-derive

The one nuance checked before deletion: could a PRE-cutover persisted state file still deliver a group-shaped deploy root to this code path? **No — two independent proofs:**

1. **The `node` argument never originates from persisted state.** It is the bed's folded node from the caller's CURRENT project config (a LoadUnified'd project under the spec #105 schema): a `group:` root cannot be authored or parsed post-cutover, and `charly migrate` rewrites pre-cutover group deploys onto the primary substrate + deploy-level siblings before anything reaches this function.
2. **The persisted per-host overlay structurally cannot contain a group root.** `SaveDeployState` (the only writer) takes `SaveDeployStateInput` = spec's type, which carries ZERO member fields (verified at spec 2106 `spec/cue_types_gen.go:4868` — Ports/Env/Volume/Tunnel/... only). This is exactly why the deleted guard's own comment documented that persisting a group root would write a memberless bed: pre-cutover persisted state is substrate-shaped only.

The targetless member-bearing deploy shape the guard defended against is unauthorable post-migrate — the guard is dead code. Deleted outright per R5 (no positional re-derivation, no stale-state tolerance comment needed). The local/host-rooted (`fleet.HostRooted(&node)`) and in-place-external (`externalInPlace`) self-skips at the same site REMAIN — they are live, load-bearing guards.

## IsGroup sweep

spec #105's merge note said bed_session.go:71 was the only known sdk call site — verified: `git grep -n IsGroup` on the committed HEAD returns ZERO matches. The `IsGroup` occurrences remaining in spec 2106 itself are the seam.cue/arbiter.cue wire FIELDS (`is_group?: bool @go(IsGroup)`) deliberately kept for plugin-check/plugin-preempt consumers — a different type, untouched here. deploy_state.go's remaining member handling (`InSubstrateMembers`, `n.Member`) is the member-tree IR that SURVIVED the cutover — not group-kind code.
