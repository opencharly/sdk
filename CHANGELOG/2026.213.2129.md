## StepContract decision (the load-bearing high-risk — RDD-spiked)

`sdk.StepContract` (string `Scope` / int `Venue` / string `Gate`, in `schema.go`)
is the SDK-facing AUTHORING form two candies CONSTRUCT
(`candy/plugin-example-stepkind`, `candy/plugin-installstep` —
`&sdk.StepContract{Scope: "user", Venue: 0, Gate: "", Emits: ...}`). `spec.StepContract`
(`spec/spec/provider_carriers.go`, typed `Scope`/`Venue`/`Gate` enums) is the form
charly core already uses (`charly/plugin_provider_common.go` constructs
`&spec.StepContract{Scope: spec.ScopeFromName(...), ...}`). These are DIFFERENT
types; a naive `type StepContract = spec.StepContract` re-export would BREAK the
two candy constructors. Decision: **keep `sdk.StepContract` as the string-scope
authoring form (NOT a re-export)**; the typed form lives in `spec/spec`, and the
proto→typed conversion lives in `spec/exec.Executor.DescribeProvider` (via
`spec.ScopeFromName`/`spec.Venue`/`spec.Gate`). The one candy `DescribeProvider`
caller (`candy/plugin-installstep/oci_dispatch.go`) reads only `.Emits` (bool,
field-identical across both forms) via `:=`, so the `sdk.Executor = spec/exec.Executor`
alias is call-site-compatible. charly's eventual repoint (super leg) is clean:
charly already uses `spec.StepContract` directly.
