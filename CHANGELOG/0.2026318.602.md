# 0.2026318.602 — fix(loaderkit): resolve the kubevirt kind through the contract envelope

## Summary

`opencharly/spec#304` unit 6, a consumer leg. The authored `#KubeVirt` body moved into the plugin that SERVES the kind (`opencharly/plugin-substrate#37`, merged), so this package's kind table — which reads the **base** schema only — can no longer name `#KubeVirt` once the contract leg deletes it; a name the base does not carry panics at first use, which `pod`, `local` and `kubernetes` each taught.

The entry now names **`#ResolvedKubeVirt`** — the contract's remaining declaration for the kind, carrying `cluster`/`kube_context`/`namespace`/`raw`. **Note the capital V**: `#ResolvedKubeVirt` differs from the kind word by one letter, and this unit's own measurement first concluded "no envelope exists" because a naive grep for `ResolvedKubevirt` found nothing. A case-folded grep found it.
