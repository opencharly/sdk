# 0.2026238.957 — fix: version-less remote refs resolve to the latest tag via the LatestTag seam

## Summary

A version-less remote candy ref (e.g. a builder plugin connected by word ref, where the caller knows the repo but not the tag) previously fell back to the **mutable default branch** — a freshness-checked ref that hangs in a network-bound CI/container and can advance under the resolver. The newest tag is immutable and deterministic; a repo with no tags errors loudly rather than silently pinning a branch.

This is the Phase-4 candy de-submodule cutover's builder-connect hang RCA: `connectPluginByWordRef`'s lazy-connect pass-1 vendors builder plugins by word ref, and a version-less ref resolving to `main` triggered the freshness-checked download path on every connect.

The tag resolver is now a **SEAM** (`spec.RefsCollectSeams.LatestTag`, spec#52 — MERGED) so the mechanism is unit-testable offline. The `defaultBranches` identifier is renamed to `latestTags` (R5 — no transitional name survives the cutover). The spec pin is the real spec#52 pseudo-version (`v0.2026232.521-0.20260826090151-ce44afab8bbf`) — **no local replace in the diff**; the committed tree builds from the proxy.
