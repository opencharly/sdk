# 2026.230.1200

## fix(deploykit): enable distro-shipped units through the RESOLVED init only

`EmitInitAssembly` rendered a box's `use_packaged:` system-unit list through **every
ACTIVE init**, emitting one enable command per init into a single Containerfile.

`activeInits` is a SET by design — `InitConfig.ActiveInit` returns every init any candy
in the chain contributes fragments for, and each one legitimately gets its own fragment
scratch stage and assembly step. Enablement is different in kind: a distro-shipped unit
is enabled by the ONE init that actually boots the image, which
`InitConfig.ResolveInitSystem` already resolves into `img.InitSystem`. The enable block
now runs only when `initName == img.InitSystem`; fragment stages and post-assembly
remain per-init.

### The failure

`agentteams-worker` — a **supervisord** container on an Arch base — composes
`virtualization`, whose `use_packaged:` entries put **openrc** into the active set.
supervisord declares no `system_enable_template` (correctly: it consumes no distro
units), so the box's own init emitted nothing while openrc's template emitted:

```
STEP 24/47: RUN rc-update add virtqemud.socket default && \
            rc-update add virtnetworkd.socket default
/bin/sh: line 1: rc-update: command not found        exit status 127
```

The base has neither OpenRC nor systemd, so the build died at step 24 of 47.

### Blast radius, measured

Latent rather than a regression: `virtualization` reaches an image only through the
`charly` candy, which no deployable box composed until now. Generating every box twice
from one tree — once with the guard neutralized, once with it in place — the ONLY
semantic difference across all 15 generated boxes is the four-line `rc-update` block
leaving `agentteams-worker`:

```
boxes emitting rc-update   before: 1 of 15      after: 0
whole-tree diff            one 4-line removal in agentteams-worker;
                           every other differing line is ARG BASE_IMAGE's CalVer
                           tag (…1131 vs …1130), an artifact of the two runs
                           happening a minute apart
```

Nothing was silently dropped: no box lost an enable command it should have kept.

### Coverage

`TestEmitInitAssemblyEnablesOnlyResolvedInit` drives one candy carrying a packaged
system unit against an active set of `{supervisord, openrc, systemd}` and asserts, per
resolved init, that the resolved init's enable command is present and every foreign
one is absent. Neutralizing the guard fails all three subtests, the supervisord case
reproducing the production failure exactly (`rc-update` emitted into a supervisord
container).

Fixes opencharly/charly#313.
