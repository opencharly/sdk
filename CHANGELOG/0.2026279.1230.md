# 0.2026279.1230 — fix(vm-box): stamp ai.opencharly.box in the VM box emitter so retention can reclaim the tag (charly#808)

## Summary

`charly vm build` emitted a VM box image tagged per run that **grew unbounded** on local storage (opencharly/charly#808 — measured 24+ `localhost/<box>:<CalVer>` tags of one bed box, 741 MB / 143.7 GB of a reclaimable image store).

**Root cause (R1).** The retention engine (`candy/plugin-clean`'s `charlyImageTags`) **groups local images by the `ai.opencharly.box` label** (`spec.LabelBox`) — that is the key `charly clean` / the post-build prune use to elect a tag for removal. The pod-side `WriteLabels` stamps `ai.opencharly.box`; the **VM box emitter did not** — it wrote only `ai.opencharly.vm.box` + `description`. So every VM box tag was **invisible to retention** and accumulated forever. Confirmed live:

```
$ podman inspect localhost/<box>:latest --format '{{index .Labels "ai.opencharly.box"}}'
                                # empty — no retention-group label
$ charly box list tags <box>
charly: error: command "list": no locally stored charly images for box <box>
                                # the engine cannot see the 27 tags that exist
```

**Fix.** `renderVmBoxContainerfile` now stamps `ai.opencharly.box = spec.LeafName(ref)` — the **same value convention as the pod-side `WriteLabels`** (`sdk/deploykit/write_labels.go:42`) — so a VM box tag carries the retention-group key and is reclaimable by `charly clean` and the post-build prune.

**Live end-to-end proof** (combined with `opencharly/plugin-vm#71` — the label makes the tag *visible* to retention; the companion's prune *reclaims* it). A charly built against both PRs, on the disposable `check-kubevirt-vm-box`:

```
$ charly vm build check-kubevirt-vm-box
Wrote VM box localhost/charly-check-kubevirt-vm-box:2026.279.1223
Pruned 1 old VM box tag(s) (keep_images=3)

$ podman inspect localhost/charly-check-kubevirt-vm-box:2026.279.1223 --format '{{index .Labels "ai.opencharly.box"}}'
charly-check-kubevirt-vm-box            # the retention-group label, now stamped

$ charly box list tags charly-check-kubevirt-vm-box     # WAS: "no locally stored charly images"
charly-check-kubevirt-vm-box   localhost/charly-check-kubevirt-vm-box:2026.279.1223
charly-check-kubevirt-vm-box   localhost/charly-check-kubevirt-vm-box:latest
```

Before: 27 tags, none labeled (`ai.opencharly.box` empty), invisible to retention, unbounded. After: the tag carries the label, retention lists it, and repeated builds keep the labeled set bounded (`Pruned N old VM box tag(s)`).

**Found + fixed during the live proof:** the first attempt derived the label with `spec.LeafName(ref)`, which splits on NAMESPACE DOTS and returned the *tag* (`1211`) — the live `box list tags` stayed empty. `repoLeaf()` (strips tag/digest + namespace → the repository leaf) is the fix; `TestRepoLeafIsTheRepoNotTheTag` pins it.
