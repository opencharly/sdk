# 0.2026324.1613 — feat(sdk)!: adopt the XDG data root and resolve host paths through storeroot

## Summary

Adopts the spec XDG contract (`opencharly/spec#407`, tagged `v0.2026324.1605`) in the SDK and
routes the SDK's host paths through the one resolver.

- **Spec bump:** `github.com/opencharly/spec v0.2026324.1605`.
- **`storekit`** re-exports `RootData`, `Base`, `BaseDirs`, `Dirs`, `Search` and `DataDir` from
  the contract resolver; the package doc now states the cache/data split (D-STORE-3/D-STORE-12)
  instead of the prior “four roots / data root reverted” paragraph.
- **`kit.UserScopeEnv`** (an alias of the spec function) now returns
  `(map[string]string, error)`; its two `deploykit` callers handle the error.
- **Host paths resolve through `storeroot`:** direct-deploy markers, sidecar config, the
  quadlet/systemd directories (`XDG_CONFIG_HOME`), per-VM state (`XDG_DATA_HOME/charly/vm`, with
  `CHARLY_VM_STATE_DIR` unchanged) and the agent state store (`XDG_STATE_HOME/charly/agents`).
- **Host directory names use `charly`, not `opencharly`:** `kit.EnvdDir` is
  `~/.config/charly/env.d`, the fish managed block is `conf.d/charly.fish`, and the ledger
  comments are renamed. The managed-block `# opencharly:begin/end` markers are compatibility
  fences, not directory names, and are unchanged.
- **`dsh-tui` removed from the test comment** in `deploykit/plan_compile_test.go`.

## Change classification

**Breaking change + rollback:** `kit.UserScopeEnv` (the SDK's alias of the spec function) now
returns `(map[string]string, error)`; every external caller must handle the error. The
machine-venue env.d file moves from `~/.config/opencharly/env.d` to
`~/.config/charly/env.d`, and the fish block from `conf.d/opencharly.fish` to
`conf.d/charly.fish`; an operator’s existing files must be moved (no dual path, R5). The
`QuadletDir`/`SystemdUserDir`/`VmStateRoot` XDG behavior is additive (the defaults are
unchanged); `DirectDeployMarkerDir`, `SidecarConfigDir` and `agentkit.OpenStore` keep the same
default path through the resolver. The rollback is to revert this commit and re-pin the previous
spec tag; the consumer legs must be reverted with it.
