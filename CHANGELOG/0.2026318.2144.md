# 0.2026318.2144 — feat(deploykit): export the init-dependency warning's text (one prose source for the consumer)

## Summary

The second half of sdk#519 is plugin-box counting the "init depends_candy missing" warning into its
`box validate` summary. To do that the consumer needs the warning's **text**, and that text lived inside the
default stderr printer — restating it in plugin-box would be exactly the drift the seam was built to stop.

This exports it as one function:

```go
func UnsatisfiedInitDependsMessage(boxName, initName, dependsCandy string) string
```

and the default reporter becomes `fmt.Fprintf(os.Stderr, "warning: %s\n", UnsatisfiedInitDependsMessage(...))`.
One prose source, two surfaces: the sdk's stderr advisory and the consumer's diagnostic entry.

Details that are load-bearing:
- the formatter carries **no trailing newline** — the printer owns the line break, so a consumer embedding
  the text in a diagnostic does not end up with a stray blank line;
- it names the **init**, never `depends_candy`, for the runtime (the vocabulary spells that field as a bare
  name or a pinned remote ref; only the init's own name is the binary the image looks for in `$PATH`).
