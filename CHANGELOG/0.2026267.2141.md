# 0.2026267.2141 — feat(sdk): one namespace-aware bed resolver + adopt spec v0.2026267.2121

## Summary of changes

The sdk leg of the plugin-native check-bed roster cutover. Depends on the merged producer opencharly/spec#154 (tag `v0.2026267.2121`).

- `loaderkit/resolve_entity_ref.go` — `ResolveEntityRef`'s bed-hop arm calls the ONE `spec.UnifiedFile.ResolveBed(ref)` (namespace-aware) instead of the local-only `bedRef`; `bedRef` is DELETED.
- `loaderkit/validate_check_beds.go` — `ValidateCheckBeds` iterates `uf.Beds()` (local + namespace-qualified) instead of the local-only `uf.CheckBeds()`, and validates each bed's `from:` against its OWNING namespace (`uf.BedScope(name)`).
- `schema.go` — `BuildCapabilities` passes `ProvidedCapability.Interactive` (defined in `spec/capability/capability.go`, merged in spec#154) through to the proto.
- `loaderkit/beds_test.go` — NEW: exercises the spec-provided `Beds()`/`ResolveBed()`/`BedScope()` as the sdk's consumer sees them.
- `loaderkit/validate_check_beds_namespace_test.go` — NEW: `ValidateCheckBeds` on namespaced beds; `_NamespacedFromRejectedWhenUndefined` FAILS without the change (proof below).
- `loaderkit/validate_deploy_hop_test.go` — stale `uf.CheckBeds()` comment corrected.
- `schema_capabilities_test.go` — NEW `TestBuildCapabilitiesCarriesInteractive` locks the pass-through.
- `go.mod`/`go.sum` — bump `github.com/opencharly/spec` to `v0.2026267.2121`.

**Pre-change behavior (resolving the earlier contradiction):** `uf.CheckBeds()` was LOCAL-ONLY, so a namespaced bed was **never enumerated** by `ValidateCheckBeds` — not rejected, simply unvalidated. The change enumerates it and validates against its owning namespace.

**Closes / relates to:** producer opencharly/spec#154 (MERGED, tagged v0.2026267.2121).

**Breaking change + rollback:** none in sdk's public surface (`ResolveEntityRef`/`ValidateCheckBeds` signatures unchanged). Rollback is a revert.
