# 0.2026322.2154 — feat(storekit): serve the store read-only as a registry view (D-STORE-10, TODO 7.5)

## Summary

TODO.md **row 7.5** (D-STORE-10, §20): the store is served **read-only** as an image registry to the deployments that pull images.

`storekit.Registry(s *Store) http.Handler` answers exactly the **four reads** a distribution client needs and nothing else:

| read | answers from |
|---|---|
| `GET /v2/` | `{}` + `Docker-Distribution-Api-Version: registry/2.0` |
| `GET /v2/<store>/tags/list` | `Entries()`, filtered by OCI's tag grammar |
| `GET /v2/<store>/manifests/<tag\|digest>` | `ManifestDigest(key)` then `ReadBlob` |
| `GET /v2/<store>/blobs/<digest>` | `ReadBlob` |

plus `storekit.ManifestDigest(key) (string, bool, error)` over `readIndex()` — the one exported reader a tag-addressed manifest needs. **The `bool` is "this key has a manifest" and is not "no error"**: an absent key is a 404 to the caller and an unreadable index is a 500, and collapsing the two turns a missing image into a silent empty answer.

**Read-only is the shape, not a flag.** There is no push and no delete anywhere in `registry.go`; every method other than `GET`/`HEAD` is answered `405` with `Allow: GET, HEAD`. The view adds no storage, no index and no cache: every byte is the store's own, and deleting the view deletes nothing the store needs.

The view serves `<name>` as the store it was opened over, and a key becomes a tag only when it is a legal distribution tag; a key that is not is still served by digest, so a tag that does not exist is a `404` rather than an alias for some entry.

## How tested

**The test IS the enumeration**, and it found a real bug on its first run — the routing cut the verb before the store name, so `<store>` became the verb and every route 404'd:

```console
$ go test ./storekit/ -run TestRegistryServesExactlyTheFourReads -v
    registry_test.go:59: GET /v2/registry/manifests/v1.0.0 (manifest-by-tag) = 404, want 200
--- FAIL: TestRegistryServesExactlyTheFourReads (0.00s)
```

after the fix:

```console
$ go test ./storekit/ -run TestRegistryServesExactlyTheFourReads -v
--- PASS: TestRegistryServesExactlyTheFourReads (0.00s)
```

The fixture is a **real store** (`PutBlob` + `PutEntry`), not a hand-built one, and the test asserts:

- **five reads answer 200** — `/v2/`, `tags/list` (body carries the tag), `manifests/<tag>`, `manifests/<digest>`, `blobs/<digest>` (body equals the payload bytes);
- the manifest's `Docker-Content-Digest` **equals** what `ManifestDigest` returned, so the read and the reader cannot drift;
- **four mutating methods (`PUT`, `DELETE`, `POST`, `PATCH`) answer `405`** with `Allow: GET, HEAD`;
- an absent tag is `404`, never an empty `200`.

**A `405` on `PUT`/`DELETE` proves only that the handler answered those two verbs.** The enumeration is what proves nothing else was written — the absence is proven by the enumeration of what exists, not by a search for the word `DELETE`.

`ManifestDigest` has its own test, driving a real `PutEntry` and asserting both halves (existing key → a digest that `HasBlob` confirms is in the store; absent key → `found=false, err=nil`).
