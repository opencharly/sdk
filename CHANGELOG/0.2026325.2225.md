# 0.2026325.2225 — docs(skills): say where a skill body lives, by repo class, and make the owner rule explicit

## Summary

States where a skill body lives — **the repo class decides it, one answer per class** — and makes the owner rule explicit. This is the clarification that opencharly/layer-strata#28 needed and did not find in the guideline.

**The outdated claim.** Step 1 said the prose lives at `<owning candy dir>/.agents/skills/<name>/SKILL.md` — inside the candy directory. The collector never reads there: `sdk/deploykit/skills_collect.go` resolves the body at `candyRepoRoot`, the repo **root** of the repo that DEFINES the owner candy.

**Both authored shapes are corrected**: the skill body (`<owner repo>/.agents/skills/<name>/SKILL.md`)
and the sub-agent DEFINITION (`<owner repo>/.agents/agents/<name>.md`) — the second is a distinct
change in the same sentence, not part of the skill-body wording, and it moves for the same reason: the
repo, not the candy directory, is the base.

**Now stated once, for the four classes that share a config:**

| the repo that declares the node | where the BODY lives | `owner:` names |
|---|---|---|
| the repo that DEFINES the candy (layer repo) | its own root | that candy |
| a box / pod / VM repo composing a FOREIGN candy | **the foreign candy's repo root** — the node may sit in this repo, the body may not | the foreign candy |
| a box / pod / VM repo that wants its OWN skill | its own root | a candy **this repo declares** in its `candy/` |

Plus the rule behind it: `owner:` must name a candy **defined in the same repo as the body**; a node whose owner is composed from another repo is a load error, quoted with its message. A pod repo therefore has two legal shapes and no third — node only with the body in the engine candy's repo, or a candy of its own. `layer-strata` / `pod-strata` is the reference case, and #25 is the measured failure.
