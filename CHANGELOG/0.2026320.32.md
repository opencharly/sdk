# 0.2026320.32 — feat(deploykit)!: the candy views carry volumes and aliases as bytes

## Summary

The **SDK half** of `opencharly/spec` `v0.2026320.16`, where `#CandyView.volumes`/`aliases` and `#ResolvedBoxView.aliases` became opaque — the last three fields in the contract that named `#CandyVolume` / `#CandyAlias`. Closes **opencharly/sdk#539**.

| where | change |
|---|---|
| `loaderkit/scan_candy.go` | the producer encodes the view's volume and alias lists through `rawbody.Encode` |
| `deploykit/resolved_project.go` | the box-view writer encodes its alias list rather than appending `spec.CandyAlias` values |
| `deploykit/spec_candy_adapter.go` | `Alias()` and `Volume()` decode through `rawbody.Decode` |
| two test fixtures | route the view lists through `rawbody.Encode`, matching the producer |

**No new mechanism.** Every crossing is `rawbody`, the one implementation `sdk#538` consolidated — this leg adds no encoding logic.

**What it moves forward, and what it does NOT.** The MODEL and both VIEWS now carry bytes, so the contract no longer holds these shapes in order to *project* them. But the claim "no referent in `spec` except `#Candy`" would be false, and my first revision of this body said it: sdk still **constructs** `spec.CandyAlias` in `resolved_project.go` (it must, to encode the box view) and `spec.CandyVolume` in a fixture, and `deploykit.AliasYAML`/`VolumeYAML` are aliases of the spec types, so the decoders name them too.

So the honest state: **the projection barrier is gone, the decode barrier is not.** Moving `#CandyVolume`/`#CandyAlias` to `plugin-candy-kind` additionally requires the consumer-side types, which is a bigger question — the plugin would have to export the Go shape its consumers decode into. That is the next design question, not a step this PR completes.

## Change classification

Kind: an SDK library change (the consumer half of a contract change). It breaks a consumer passing the authored slices into these three view fields — two fixtures here, adapted; outside, consumers pin the wave.

**Breaking change + rollback:** the three view fields are `RawBody` from spec `v0.2026320.16`; a writer must `rawbody.Encode` and a reader must decode. Rolling back reverts the pin and restores the direct assignments; the wire is identical either way.
