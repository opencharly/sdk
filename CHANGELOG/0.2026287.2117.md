# 0.2026287.2117 — feat(storekit): `OrphanedLayouts(root)` — the ONE orphan-layout discovery both sweep closes need (closes #393)

## Summary

**Closes opencharly/sdk#393.** Two closes of one ruling need the same discovery and R2 forbids two copies: `charly-registry`'s store cutover (`#12`, merged) sweeps the pre-store per-ref layouts a deleted writer left **inside the store's own tree**, and `charly-registry#11` sweeps the pre-rename `~/.cache/charly/images` root (measured still present, `3.5M`). **Discovering orphaned layouts is a property of the store layout, not of any policy a plugin owns**, so the boundary law puts it here, beside the store it inspects — one definition, both closes.

```go
type Orphan struct {
	Dir   string
	Bytes int64
}

func OrphanedLayouts(root string) ([]Orphan, error)
```

**Three properties, each deliberate:**

1. **The predicate is `NamedStores()`'s marker test, INVERTED.** `NamedStores()` calls a marker-carrying child of the cache root a *store*; the same directory inside a store's own tree is junk — a store keeps every byte in `blobs/<alg>/<digest>` and its entries in `index.json` and never reads a child layout. **One `LayoutFile` constant, two directions, so the two readings cannot drift** — and a test asserts the agreement rather than trusting it.
2. **The CALLER names the root, because liveness is policy and this is mechanism.** The function does **not** decide which layouts are orphaned and cannot: `NamedStores()` answers nothing here either (it returns exactly the marker-carrying children in question), so a function that tried to guess *"no merged writer still writes this"* would be policy wearing a mechanism's name. The contract is the opposite: the caller passes a root in which a marker-carrying child cannot be live — **a store's own tree** (a child layout is an orphan by construction) or **a root the migration table retired** (the caller's justification, recorded in that migration).
3. **Discovery and sizing only — never deletion.** Removing stays with the caller, so a sweep's destructive half lives with the surface that also reports it (`--dry-run` first, then the removal). A missing root returns `(nil, nil)`, the same shape `NamedStores()` uses.

**`Orphan.Bytes` counts every file in the tree, the marker included** — that is what `os.RemoveAll` reclaims, and a size that omitted the marker under-reported a real sweep by the marker's own bytes. (I made that exact mistake in the first consumer's assertion; the contract now names it so the next reader does not.)

**What this is NOT:** not a liveness oracle, not a recursive walker (direct children only, pinned by a test), not a deleter, and not a second copy — the local `orphanedLayouts` in `charly-registry` becomes a delegation to this function in the follow-up consumer leg.
