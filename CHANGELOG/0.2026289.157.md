# 0.2026289.157 — feat(candywalk): read an `agent`-type node's body from `.agents/agents/<name>.md`

## Summary

**The shared kit can now read an `agent`-type node's body from the file D8 names: `.agents/agents/<name>.md`.**

The relocation's reader had exactly ONE file source, and it was a skill's: `ReadSkillFile` resolves
`<tree>/<name>/SKILL.md` plus `references/<stem>.md`. An `agent`-type node has a different SHAPE — one
file, no entry directory, no `references/` half — so that reader cannot express it:

```console
$ git -C <sdk at origin/main> grep -n 'AgentsSkillsDir\|skillEntryName\|skillReferencesDir' candywalk/skillfile.go
39:	AgentsSkillsDir = ".agents/skills"
42:	skillEntryName = "SKILL.md"
45:	skillReferencesDir = "references"
```

The consequence was measured in the wild: `pod-charly-automation#25` had to leave one node inline
because `marketplace extract` wrote its body into the SKILLS tree while the emitter published it into
the corpus's *agents* class — a body no agent reader read. Nothing here is speculative: it is why
`layer-charly-internals-extra#21` (2 skills **and** 6 agent definitions) cannot start.

**What lands, in one file:**

- `AgentsAgentsDir` — the Agent-Skills location for sub-agent DEFINITIONS, the **sibling** of
  `AgentsSkillsDir` and never a child of it. A candy's `skills:` list is a list of SKILL trees and does
  not govern it, which is what makes a mixed repo the legal shape rather than a half-move.
- `ReadAgentFile(agentsDir, name)` — reads `<agentsDir>/<name>.md`, frontmatter split, marker stripped,
  id checked. A missing file stays `(nil, nil)`: whether a node MUST have one is the caller's call, and
  the marketplace generator is the caller that hard-errors on it.
- **`readAuthoredEntry` — the ONE parse both shapes now go through.** The frontmatter fence split, the
  DO-NOT-EDIT marker strip and the "frontmatter `name` must agree with the file it is filed under"
  check existed once, inline in `ReadSkillFile`. Copying them for agents would be one behaviour
  implemented twice — the R2 failure this kit exists to prevent — so `ReadSkillFile` and
  `ReadAgentFile` are now two thin path resolvers over one read, and the shared half keeps the
  `description: |` vs `|-` discrimination (the newline before the closing fence is part of the block
  scalar) that the docs projection's earlier copy cut and that leg L5 converged here.
- `AgentFile` is a distinct type, deliberately: an agent file has no `References` and no entry
  `Dir`, so reusing `SkillFile` would carry two fields that can only ever be nil/empty.

**Producer-first, and this is the middle leg of three.** The `spec` PR corrects the comment that named
the skills tree; this PR makes the reader able to read D8's path; the `opencharly/plugin-marketplace` PR
consumes it (`fillSkillFromFile`'s agent branch, `extract`'s agent half, and the
`extract → read → emit == the corpus` round-trip test) and pins this module once it has a tag. The
consumers are named rather than promised: **`layer-charly-internals-extra#21`** and
**`pod-charly-automation#24`** (`opencharly/plugin-marketplace#34` is the cutover's issue).
