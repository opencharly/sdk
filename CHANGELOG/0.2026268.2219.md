# 0.2026268.2219 — feat: add the plugin requires authoring surface

## Summary

Bump the spec pin to **v0.2026268.2152** (the `plugin.requires` + required-`source`
contract, opencharly/spec#163) and add the SDK authoring surface for declared
inter-plugin dependencies:

- **`sdk.Requirement`** — one declared inter-plugin dependency
  (`Class`/`Word`/`Source`/`Optional`), the authoring twin of the wire
  `PluginRequirement` and the candy `plugin.requires:` entry.
- **`BuildCapabilitiesWithRequires`** + **`NewMetaWithRequires`** — marshal a plugin's
  declared requires onto the wire `Capabilities.requires` field, so the host can
  resolve + connect each peer declaratively.
- **`BuildCapabilities`** / **`NewMeta`** forward `nil` requires — the 145 existing
  `sdk.NewMeta(` call sites across the plugin corpus are unchanged and byte-identical
  (counted: `grep -rn 'sdk\.NewMeta(' --include='*.go' . | grep -v /marketplace/ | wc -l`
  → 145).
- **`requires_test.go`** — the requires wire round-trip, plus the nil-requires
  no-change case.

The host-side resolution (the loader's requires gate, topological order, cycle
rejection) lands in the charly consumer PR; this is the SDK serve-side surface only.
