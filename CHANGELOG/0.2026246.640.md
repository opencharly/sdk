# 0.2026246.640 — feat(deploykit): generic BoxRef resolver — ParseBoxRef / ResolveBoxRef (VM-box cutover task 4)

## Summary

VM-box cutover task 4 (plan/vm-from-box-layering.md §2.2): the generic **BoxRef resolver** — ONE resolver over every VM source form, so no caller re-implements per-kind resolution (R3). The source arms keep their schema shape; this is the generic engine underneath them.

Adds `sdk/deploykit/box_ref.go`:

- **`ParseBoxRef(ref)`** parses the four forms `box:<candy-image>`, `vm:<entity>[@<snapshot>]`, `image:<registry-ref>`, `imported:<domain>`; a bare name defaults to the `box:` (container-image) form, matching how `source.box:` behaves today. Empty / empty-payload forms error.
- **`ResolveBoxRef(ctx, ex, ref) → *ResolvedBoxRef`** dispatches on the parsed form onto the arms' EXISTING primitives:
  - `box:` → SourceKind `bootc` — a full ref (contains `/`) passes through untouched (bootc may pull from a registry); a short name resolves via `kit.ResolveLocalImageRef` to its newest local CalVer tag — exact mirror of plugin-vm's `resolveBootcImageRef` (candy/plugin-vm/vm_build_resolve.go).
  - `vm:@snap` → SourceKind `clone` — the snapshot's external disk path via `vmshared.LookupSnapshot` (the same registry BuildClone's parent-disk pick reads); an internal-mode snapshot (no external disk) is refused.
  - `image:` → SourceKind `cloud_image` — URL passthrough (fetch/verify happens at build time).
  - `imported:` → SourceKind `imported` — domain passthrough (the entity's disk_path is resolved at build time).
  - Metadata stays nil on every arm (best-effort field; the distro-from-box read is a later cutover).
- **`ResolvedBoxRef`** carries the plan §2.2 `ResolvedBox{diskSource, metadata}` contract fields `SourceKind`/`DiskSource`/`Metadata`. NAMED `ResolvedBoxRef` (not `ResolvedBox`) deliberately: package deploykit already declares `type ResolvedBox = buildkit.ResolvedBox` (buildkit_aliases.go, used by 49 files) for the pod/box BUILD-graph result — a different domain that cannot share the name in one package (R1 finding during implementation, documented in the file header).

Tests (`deploykit/box_ref_test.go`): parse table over all forms + malformed inputs; pure resolve arms (image:/imported:/full-ref box:); deterministic short-name CalVer election via the spec/container var swap plugin-vm's own tests use; a live short-name arm against real local container storage (skips when no engine/images); and the vm:@snapshot arm against a minimal snapshot registry under a temp `CHARLY_VM_STATE_DIR` (external resolves, unknown errors, internal refused).
