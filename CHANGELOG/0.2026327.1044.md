# 0.2026327.1044 — fix(deploykit): never stage the build root; stage only what a candy's plan reads

## Summary

The generator emitted `FROM scratch AS <candy>` + `COPY <CopySource>/ /` for **every** candy. An
**inline candy** — one declared in the project's root `charly.yml` — has the build root as its own
directory, so the generated Containerfile carried **`COPY ./ /`**: the entire project in the image's
build graph, with `.git`, `.check` run logs, `.build` staging and any local secret protected only by
the context-ignore **denylist** (opencharly/sdk#623). BuildKit prunes the stage today because
nothing references it; one `copy:` step would make it live.

Two rules now, both in one shared emitter (`g.emitScratchStage`):

1. **A candy nothing copies from gets no stage at all.** `copy:` ops (`EmitCopy`) and `data:`
   declarations (`WriteDataStaging`) are the ONLY consumers of a candy scratch stage — every other
   `COPY --from=` in the tree names a **builder** stage (`<candy>-<builder>-build`) or an init
   **fragment** stage, so the predicate is complete.
2. **A candy whose directory IS the build root is staged by the EXACT paths its plan reads**
   (`stageSources`: the `copy:` sources and `data:` sources, deduplicated in plan order), never with
   a whole-root COPY. A consumed candy whose sources are not expressible leaves a stage with no
   COPY, so the consuming instruction fails **naming the missing path** instead of being silently
   served the whole project.

The emitter is shared with the data-image path (`generateDataImageContainerfile`), so the rule
cannot hold in one shape and not the other.

The diff, item by item:

- `deploykit/candy_stage.go` — `EmitScratchStages` delegates to the new `emitScratchStage`, plus
  `stageConsumed` and `stageSources`. `CandyCopySource`/`candyOrigin` are untouched.
- `deploykit/generate.go` — the data-image path calls the shared emitter.
- `deploykit/candy_stage_test.go` — the regression test.
- **No dependency changes**: `go.mod`/`go.sum` are untouched by this diff.

## Change classification

Patch (`fix`), no breaking change to any candy that names a `copy:`/`data:` source, and none to the
conventional `candy/<name>/` layout. The two behaviour changes are: a candy nothing copies from no
longer emits a dead stage, and an INLINE candy at the project root no longer stages the whole tree —
a build that relied on that would now fail naming the missing path, which is the loud form of the
defect this fixes. Rollback is a revert of this commit.

Closes opencharly/sdk#623.
