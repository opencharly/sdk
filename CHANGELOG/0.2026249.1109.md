# 0.2026249.1109 — feat(loaderkit): Docker-style materialize cache — valid while inputs unchanged, no TTL, drift auto-update

## Summary

Two clean-architecture changes on the from: name:tag axis:

1. **Docker-style materialize cache** (RCA 2026-09-06 - the Phase 3 stale-loader-logic class): the cached tree is a function of THREE components - the content-hashed config envelope, the compiled schema CalVer, and the compiled LOADER identity (the sdk module version). The key = hash(all three) (content addressing: valid as long as the charly.yml content + schema + loader are the same); the entry RECORDS its components and the read REFUSES drift (any change -> re-materialize -> auto-update); the 1h TTL is REMOVED from validity (an old entry with matching components is served - unit-proven at 720h); reclamation is the write-time prune (the Docker builder --keep-storage analogue), sorted by the entry's Resolved write-time (semantic, never the drift-prone file ModTime).
2. **DeployTargetEntity** - the ONE deploy-hop chain resolver (the from: name:tag clone spelling): a plain entity passes through; a Fleet deploy (the clone-base bed) hops its from: chain to the terminal template. The build drive, the create's config-resolve, and the validator all consume it (R3).
