# 2026.229.0947 — a hardcoded bash, and four ways to ship an image without its packages

Placeholder CalVer (the pr-validator finalizes it at merge). Chosen after the newest
landed tag `v0.2026227.1923` and the newest entry `2026.228.0209`, with no filename
collision.

Two defects in the Containerfile emitter, found while composing the first candy onto a
busybox base. The second is the more serious one: the emitter had four separate paths on
which a candy's resolved packages were dropped **without a word**, and the resulting
Containerfile looked correct.

## 1. Every emitted build step hardcoded bash

`deploykit/tasks_emit.go` had two emit sites, and both named `bash` as the interpreter:
the `-c` form wrote `… bash -c '<cmd>'`, the heredoc form wrote `bash <<'OVCMD'`. Alpine
ships busybox `ash` and no `/bin/bash`, so **every** candy shell step — the `cmd` verb and
the `download` verb alike — was unbuildable on any busybox base, regardless of what the
step did.

Both sites now route through one of two shared helpers (R3), which prefer `/bin/bash`
when it exists and fall back to POSIX `sh`:

```go
func BuildStepShellDashC() string {
    return `sh -c 'SH=/bin/sh; [ -x /bin/bash ] && SH=/bin/bash; exec "$SH" -c "$1"' sh`
}
func BuildStepShellHeredoc() string {
    return `sh -c 'SH=/bin/sh; [ -x /bin/bash ] && SH=/bin/bash; exec "$SH"' sh`
}
```

The authored command reaches the chosen shell unchanged — it is passed as `$1` and
re-exec'd, so author `$(cmd)` and `${VAR}` still expand in the shell that runs them; the
heredoc form relies on `exec` preserving stdin. This mirrors the probe `WriteBootstrap`'s
create branch already emitted for the login shell, so the two now agree.

A doc comment claiming "Shell is bash via a single-quoted heredoc" was corrected in the
same change rather than left to describe the old behaviour.

## 2. Four silent drops in the package-install emit

`deploykit/candy_steps.go` resolved a candy's packages through the shared cascade and
then discarded them on any of four conditions, three in one nested `if` and one a few
lines below:

| condition | old behaviour |
|---|---|
| `img.DistroDef == nil` | guard failed, nothing emitted, no error |
| `img.DistroDef.Format[img.Pkg] == nil` | inner guard failed, nothing emitted, no error |
| `RenderTemplate` returned an error | `if err == nil { … }` with no `else` — error discarded |
| `EmitTasks` returned an error | written into the Containerfile as `# emitTasks error: …` and execution continued |

**The third is the one that actually shipped**, and it is worth being precise about why
it was expensive. A format's `install_template` calling a function that is not in
`buildkit.TemplateFuncs` is a plain authoring mistake. The emitter turned that mistake
into a Containerfile that built successfully, exited 0, and produced an image with none
of the candy's packages in it. Nothing in the artifact indicated a step was missing. The
failure surfaced later, in an unrelated place, as a binary that was not on the image.

All four now return an error naming the candy, the format, and the box. A candy that
resolves **no** packages for this box still passes through untouched — that is the common
per-distro case (a `distro:` map with no section for this box's distro), and it is not an
error.

The precedent was already in this same function: the localpkg render's identical
silent-mask (an error emitted as a Containerfile *comment*) had been converted to a hard
error earlier, for the same reason and with the same reasoning in its comment. These four
bring the rest of the function into line with it.

## Coverage

`deploykit/candy_steps_loud_failure_test.go` pins all four. Reverting the package block
to its pre-fix form fails exactly three of them and leaves the fourth passing:

```
--- FAIL: TestWriteCandySteps_UnrenderableInstallTemplateIsLoud
--- FAIL: TestWriteCandySteps_MissingFormatDefIsLoud
--- FAIL: TestWriteCandySteps_NoDistroDefIsLoud
```

The fourth, `TestWriteCandySteps_NoPackagesStillRenders`, is the **presence control** and
passes both before and after — deliberately. Without it, an emitter that errored on every
path would satisfy the other three just as well, and the suite could not tell a working
fix from a broken one.

The emitted-artifact check is the other half: with the fix, generating a box whose
`install_template` calls an undefined function fails with

```
candy sudo-nopasswd: rendering the apk install template for box alpine-repo-box failed:
  parsing template "apk-install": template: apk-install:4: function "base" not defined
```

and without it, the same tree generates 0 install lines and exits 0. Fifteen boxes across
the superproject generate clean under the new hard errors, so the added strictness has no
false positives on any existing box.

## 3. A kill that named no deadline

`sdk/kit/planrun.go` already detected that the per-attempt never-hang deadline had fired —
it set `DeadlineExceeded` on the result — and then reported the exec layer's message
unchanged: `process terminated by signal (signal: killed)`. That names the *mechanism* of
death and not its cause, so a step killed by the bound is indistinguishable from a step that
crashed, and the reader goes hunting a bug in their own command. **The bound was known at
the moment the deadline fired and thrown away.**

Measured cost: installing charly from a published distro repo pulls ~190 packages, so
`dnf install` crossed the 90s floor (`runnerProbeNeverHangFallback`) while `pacman -S` fitted
under it. Two beds differing only in package manager, one green and one "killed", invites a
distro-specific theory — repo layout, signing, cloud image — when the variable is elapsed
time against a shared floor. A peer confirmed the same trap independently: they had put
`timeout: 600s` on an image-stream step by guessing at a duration, not knowing a floor
existed, and without that guess would have hunted a transfer bug that did not exist, *in
their own new code*.

`AnnotateNeverHangKill` (extracted into `sdk/kit/runner.go` so it is testable rather than
inline) now names the bound, states that the step ran longer rather than crashed, and points
at `timeout:` — which `ProbeNeverHang` honours over the floor, making it the mechanism's own
parameter rather than a workaround.

Coverage: `sdk/kit/never_hang_message_test.go` asserts the message carries the bound, the
remedy, and an explicit contradiction of the crash reading; the second test is the presence
control — it pins that the original text survives verbatim and that an authored `timeout:`
raises the bound that gets *reported*, so an implementation that appended the text
unconditionally, or that always printed the floor, fails.
