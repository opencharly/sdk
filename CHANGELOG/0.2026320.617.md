## Summary

Head `bb43b43e7244bcb9e90046d00b10281d83fb280f`, based on `origin/main` `9d43f04` (0 behind, 1 ahead):

**The package carried the coordinate rule twice.** `SecretKeyForDep` was the exported rule, and
`EnsureCandySecret` carried an inline copy of the same predicate — with a subtle difference: `idx >= 0` in the
rule, `idx > 0` in the copy. That duplication is the seam **opencharly/sdk#526** and
**opencharly/pod-openwebui#19** both live in: a secret's coordinate is computed in more than one place, and the
copies drift apart — which is how a value gets written somewhere the resolver never reads.

```
-	service, key := "charly/secret", dep.Name
-	if dep.Key != "" {
-		if idx := strings.LastIndex(dep.Key, "/"); idx > 0 {
-			service = dep.Key[:idx]
-			key = dep.Key[idx+1:]
-		}
-	}
+	service, key := SecretKeyForDep(dep)
```

Behaviour is unchanged for every valid declaration: the build-time contract (`validateSecretDeps`) is
`^charly/<service>/<key>$`, where the two predicates coincide, and a leading slash cannot appear. What changed
is that there is now exactly ONE implementation, and the resolver and the rule cannot disagree.
