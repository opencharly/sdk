# 0.2026293.2302 — fix(deploykit): name a skill owner that is not a candy, and report the same node twice

## Summary

A `skill:` node whose `owner:` names a `candy:` node carrying `base:`/`from:` could not resolve its prose **by any placement**, and the failure said something untrue about why.

The loader routes a `candy:` node with `base:`/`from:` to the **box** set (`charly/charly/provider_kind_invoke.go:310` `foldCandyKind` → `acc.Box`), so it never reaches `layers`, and `deploykit.readSkillFile` returns `(nil, nil)` on `layers[owner]` missing — **before any path is composed**. `projectSkill` then reported

```
skill "pskill": no body — the node carries no in-line `content:` and no SKILL.md exists under .agents/skills beside the owning candy "pimage"
```

which names a search that never ran: an author who reads it moves the file, and no placement can make it reachable (measured in three positions on a two-candy repro, `rc=1` every time).

This commit fixes **the finding only** — it does not decide *where* a skill body must live:

- `projectSkill` separates the two causes of "no file": the owner absent from the candy set (never looked up) versus no `SKILL.md` beside a present owner (searched, absent). The first now says so and names the image shape.
- `collectSkillsFiltered` projects the decoded nodes in **sorted** order. The loop returns on the first error, and it walked a `map`, so one tree named a different skill on every run (5 distinct names over 34 runs of `distro-arch`).

**Which body location is canonical stays open on opencharly/sdk#434.** The three root-fix options each change a contract (the candy-model set, or the envelope's missing per-image source dir, or the authoring shape), and opencharly/opencharly#528 already recorded that the choice between "beside the owning candy" and "the repo root" is an operator decision. This PR takes no position: under any of the three, a finding that names a search which never ran, and names a different skill each run, is wrong.

Diff: **2 files, 106 insertions, 2 deletions** — `deploykit/skills_collect.go` and `deploykit/skills_owner_diagnostic_test.go` at `ca8e890`.
