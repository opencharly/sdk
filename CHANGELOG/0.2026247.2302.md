# 0.2026247.2302 — fix(kit): serialize the managed ssh-fragment save — the lost-stanza race hangs concurrent check-run executors

## Summary

`saveStanzas` (kit/sshconfig.go) held the whole managed ssh-config fragment as ONE block and replaced it from the caller's map. Under concurrent `charly vm create` (the 16-lane check-run batch) the read-modify-write raced: each writer merged against its own stale load and dropped the other's aliases. The lost alias makes that lane's ssh executor dial hang — measured as the 16-lane check-run inflation/stalls (535s per lane vs 93s single-lane) with ZERO CPU/RAM pressure (PSI 0.00, load ~13).
