# 0.2026296.1207 — feat(deploykit): one image resolver for every engine (W3.7)

## Summary

W3.7: one image resolver for every engine. `sdk` previously had no single place that answered "is this reference in the target store, the charly image store, or the registry?" — `podmanOps`, `ctrOps`, plugin-build's ensure path, plugin-deploy-pod's gate and `spec/container`'s transfer each answered a slice of it.

This adds, in `deploykit`:

- **`ImageStore`** — `Has`, `Import(ociSource, ref)`, `Pull`, `Tag`, `Remove`, `List`. ONE implementation configured from the capability table; no engine-name literal appears in a code path.
- **`ImageResolver.ResolveImage(ref, target)`** — target store → charly image store import → registry pull → `build:ensure` re-entering at import.
- **Rootful daemon identity** — `nerdctl info` `SecurityOptions` is checked before EVERY store operation; a rootless answer on a rootful target refuses the op.
- **The annotation control in code** — `Import` proves the archive's `io.containerd.image.name` naming at the engine boundary. A tag-only archive lands unaddressable, so the import is refused rather than reported successful.

The W3.6 charly image store is consumed through `CharlyImageSource`, not copied. Its layout move into `sdk/storekit` is filed (below).

### Interface

```go
type ImageStore interface {
    Has(ctx context.Context, ref string) (bool, error)
    Import(ctx context.Context, ociSource, ref string) error
    Pull(ctx context.Context, ref string) error
    Tag(ctx context.Context, src, dst string) error
    Remove(ctx context.Context, refs ...string) error
    List(ctx context.Context) ([]string, error)
}
```

`NewImageStore(exec, ContainerdTarget)` derives every fact from `spec.EngineBinaries` + the capability row (`ImageExistsArgv`, `Address`, `Namespace`, `PrivilegePrefix`).

### Per-engine argv (asserted exactly in `TestImageStoreArgvPerEngine`)

| Engine | presence | import | pull | tag | remove | list |
|---|---|---|---|---|---|---|
| podman | `podman image exists '<ref>'` | `podman load -i '<archive>'` | `podman pull '<ref>'` | `podman tag '<src>' '<dst>'` | `podman rmi -f '<ref>'` | `podman images --format '{{.Repository}}:{{.Tag}}'` |
| docker | `docker image inspect '<ref>'` | `docker load -i '<archive>'` | `docker pull '<ref>'` | `docker tag '<src>' '<dst>'` | `docker rmi -f '<ref>'` | `docker images --format '{{.Repository}}:{{.Tag}}'` |
| containerd (rootless) | `nerdctl --address '/run/containerd/containerd.sock' --namespace 'default' image inspect '<ref>'` | `nerdctl … load -i '<archive>'` | `nerdctl … pull '<ref>'` | `nerdctl … tag '<src>' '<dst>'` | `nerdctl … rmi -f '<ref>'` | `nerdctl … images --format '{{.Repository}}:{{.Tag}}'` |
| containerd (rootful `sudo`) | `sudo -n nerdctl … info` first, then the same `image inspect` | `sudo -n nerdctl … load -i` | `sudo -n nerdctl … pull` | `sudo -n nerdctl … tag` | `sudo -n nerdctl … rmi -f` | `sudo -n nerdctl … images` |

`k8s.io` is reachable with the same operations (the namespace is a resolved fact, not a literal).

### Resolution order (`TestImageResolverOrder`, with a control per layer)

1. `target.Has(ref)` → `OriginTarget` (charly, registry and build are not consulted).
2. `Charly.Has(ref)` → `Charly.Archive(ref)` → `target.Import` → `OriginImported` (registry and build are not consulted).
3. `Registry.Has(ref)` → `target.Pull` → `OriginPulled` (build is not consulted).
4. `Build(ref)` → re-enter step 2 → `OriginBuilt`; a build with no charly store is an error, never a false success.

Empty tag → newest CalVer across the target and charly stores (`YYYY.DDD.HHMM`, fixed-width, so the comparison is the chronological order); a `v`-prefixed store tag is returned in its own spelling; a digest-pinned reference is left exact. No CalVer tag is an error naming the repository.

### Round 1 — verdict PASS, both raised findings fixed

The first verdict (`## Review — PASS`, run 39946711029) raised two non-blocking findings. R1 does not allow a finding raised on the PR to be filed away, so both are fixed in the review-round commit `dad3170`:

1. **`Has` could report absence for an unreachable daemon.** docker and nerdctl exit 1 both for a missing image and for an unreachable daemon, so an unqualified exit-1 read hid a daemon failure — contradicting `ImageStore`'s own contract. A not-found exit is now confirmed with `<binary> info`; a failed probe is an error. A rootful addressed store already proved identity at the top of the operation and is not probed twice. New test: `TestImageStoreHasDoesNotHideDaemonFailure` (both arms).
2. **`build:ensure` ran before the missing charly store was reported.** The store is now checked first, so a build cannot have side effects ahead of the configuration error. The existing subtest now also asserts build was never called.

Mutation controls for the fixes: removing the reachability probe fails `TestImageStoreHasDoesNotHideDaemonFailure`; moving `Build` before the store check fails `TestImageResolverOrder/build_without_a_charly_store`.

### Round 2 — CI caught an assumption the local gate could not

CI run `39948410453` failed `go test` on the live Docker arm: `docker load -i <oci-archive>` on the ubuntu-latest runner returned `open /var/lib/docker/tmp/docker-import-…/blobs/json: no such file or directory` — the classic Docker importer falling back to its legacy tar shape. The same archive loaded on this host's Docker (server 29.7.2), podman and nerdctl.

- **Mechanism:** the live arm assumed every Docker accepts an OCI image layout.
- **Missed control:** the arm had no capability pre-flight, so an engine that cannot perform the operation became a test failure instead of a visible skip (R8). The local green run used a Docker that supports it.
- **Blast radius:** this PR's CI only. `Import` fails loudly, so no runtime claim was false.
- **Root fix:** the control archive now runs FIRST as the capability probe. A load success with the annotation refusal proves the annotation is load-bearing; the measured `blobs/json` signature is a visible skip naming the engine's limitation; any other error still fails. `TestIsUnsupportedOCILayout` pins the signature and that a daemon/permission error is NOT a skip.

The measured consequence for the store adapter — a Docker that cannot read OCI needs the plan's `type=docker` fallback — was added to opencharly/sdk#460 rather than invented here.

The branch now carries the W3.7 commit and its review-round fix commit, on top of the `gh pr update-branch` merge of `main` (required because the PR was `BEHIND`). No rebase, no force-push.
