# 0.2026268.5 — feat(buildkit): pkgName template func — strip a package version pin for uninstall

## Summary

Adds the `pkgName` template func to the shared buildkit FuncMap: it strips a
package version specifier, returning the bare package NAME.

### Why

A candy may pin an exact version in `distro: <d>. package:` so the install RUN
text carries the version and a version bump invalidates exactly the install layer
(RCA 2026-09-25). The blocker: the **same** `.Packages` list feeds each format's
`uninstall_template`, and pacman/apk reject a versioned spec for removal
(`pacman -Rs charly=2026.267.2134` → `target not found`). An uninstall template
renders `{{pkgName .}}` so an install-side pin never breaks teardown.

It handles both forms:
- `name=VERSION` (pac/apt/apk) → `name`
- `name-<version>-<rel>` (rpm) → `name`

Only a suffix that starts with a digit **and contains a dot** is stripped, so a
genuinely hyphenated name (`libfoo-2`, `gtk-3`) is left intact.


`TestPinnedInstallRendersPinAndBareUninstall` pins the contract: the pac install
template renders the pinned spec verbatim; the pac uninstall template renders the
bare name. `TestPkgNameStripsVersionNotName` pins the strip rules (both pinned
forms stripped; `libfoo-2`/`gtk-3` preserved).

Live package-manager behaviour the strip matches (real repos):

```
pacman -Rs charly=2026.267.2134   -> error: target not found   (bare needed)
apk del charly=2026.267.2134      -> fails                     (bare needed)
apt-get purge charly=2026.267.2134 -> ok   (tolerated; stripped uniformly)
dnf remove charly-2026.267.2134-1  -> ok   (tolerated; stripped uniformly)
```
