# 0.2026250.17 — fix(loaderkit): the declared-fields channels floor to the CONTRACT at the parse seam — the executor-boundary declared-fields completion

## Summary

The declared-fields channels (spec.Threaded.StructuralDeclaredFields from spec #104, spec.Threaded.DeployDeclaredFields from spec #107) are HOST-process registry state: charly's loaderThreaded() snapshots each recognized word's declared input-schema body field names from pluginSchemas.inputDefs, whose population is lazy (the builtin schema gate runs inside loadProjectPlugins, mid-load; an external plugin's served schema registers only at its connect). A parse that consumes a Threaded BEFORE that gate — the executor loader legs (loaderkit.LoadUnifiedViaExecutor's "loader-walk"/"loader-threaded" host legs, shared by plugin-fleet fleet add, plugin-build build:project, and the deploy-target surfaces), the plugin-side Threaded consumers (plugin-box validate, plugin-build resolve), or any process whose load interleaves differently — receives EMPTY declared-fields maps, and the documented no-declared-schema fallback re-arms the unsafe value-shape scan: a converted tree's declared #Deploy fields re-scan as in-substrate members.

Live repro (RCA'd and reproduced on the settled pin set, charly 2026.249.2351): charly fleet add check-agent-pod in distro-arch fails deterministically with:

    charly: error: command "fleet": /…/distro-arch/charly.yml:doc0: node "sandbox": expected a mapping value, got yaml kind 8

— the exact regression sdk #223/#225 fixed for the populated host-side parse, re-armed at the executor seam. The walk leg runs host-side, but its Threaded is assembled from the LIVE registry at parse time, so the channel's completeness depends on process-lifecycle timing — violating the design ruling: the declared-fields maps are CONTRACT DATA (what each kind schema declares), not host-registry state.

THE FIX — the declared-fields CONTRACT FLOOR (mechanism (c), proven by RCA): loaderkit already compiles the embedded spec/schema contract lazily (cue_schema.go's sharedCueSchema + the cueKindDefs table). The parse's declared-fields lookup (ONE helper, threadedDeclaredFields, serving both the substrate branch and the structural branch of parseNode) now consults: the threaded (served-schema) entry when present — authoritative, presence wins, byte-identical host-side behavior — else the CONTRACT-declared field set derived from the embedded spec/schema (the SAME single source cue:gen and charly's base-schema splice derive from — R3); a word the contract does not declare (an external plugin kind) floors to nil — the documented no-declared-schema fallback, unchanged. Result: a parse of a converted tree behaves IDENTICALLY at every placement and every registry-timing state — host-side or plugin-side, gate-run or pre-gate — because the tier-1 declared fields never depend on process lifecycle.

Two prior tests (TestParseFold_PreservesAuthoredDepth, TestParse_MemberCarrierKeysStrippedFromBody) fabricated an in-body member keyed `sidecar:` — a field the vm contract DECLARES — pinning the pre-floor empty-Threaded divergence. Their in-body member key is renamed to a non-declared name (`inbed`); every assertion (authored-depth positions, body retention, emitter stripping, nested recursion) is preserved, with the naming rule documented in the test comments.
