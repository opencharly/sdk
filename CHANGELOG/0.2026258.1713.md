# 0.2026258.1713 — fix(vmshared): auto-refresh a snapshot whose backing chain was rebuilt (R1)

## Summary

**RCA (R1).** `candy/plugin-vm`'s clone guard refuses a snapshot whose BACKING disk was rebuilt
after capture, with an actionable error: *"snapshot `X@golden` is STALE … Re-run the base bed
that captured the snapshot (e.g. `check-vm-clone-base`) to refresh it before cloning."* But
`vmshared.CreateSnapshot` treated the SAME snapshot as a LIVE conflict — its staleness check
was only `os.IsNotExist(entry.DiskPath)`, and the disk was present — so it returned
`snapshot "golden" already exists`, and `candy/plugin-check/bed_run.go` turned that into
*"keeping the existing baseline"*. **The guard's promised recovery was impossible:** re-running
the base bed kept the stale golden forever, and every clone of it booted a guest whose
filesystem referenced the OLD base data.

Two staleness definitions disagreed:

| site | stale when |
|---|---|
| clone guard (`candy/plugin-vm/vm_clone.go`) | a BACKING file's mtime is newer than the snapshot's `Created` |
| capture (`vmshared.CreateSnapshot`) | the snapshot DISK is missing |

**This PR makes `vmshared` own the canonical predicate and makes the capture path honour it.**

`SnapshotBackingStalePath(entry)` is the shared predicate (`qemu-img info --backing-chain`,
mtime vs `Created`, second-precision to avoid a sub-second false STALE). `CreateSnapshot` now
honours BOTH forms of stale:

1. the disk is MISSING (the prior case), or
2. the disk is PRESENT but its backing chain was rebuilt (`SnapshotBackingStalePath`).

An external snapshot that is stale-and-present is re-captured **in place**: the libvirt
metadata is cleared (metadata-only `DomainSnapshotDelete`), the per-snapshot DIRECTORY is
removed (libvirt's external create refuses an existing target file and owns creating it), and
then the create runs. A **fresh** snapshot is still a hard conflict; an **indeterminate** probe
(a non-qcow2 disk, a transient `qemu-img` failure) is treated as LIVE — the burden is on a
PROVEN staleness, never a deletion on an unproven one.

The capture path also clears an **orphaned** snapshot dir when no registry entry exists (a
crashed run, or a re-capture whose registry delete landed but whose dir removal did not) —
without it, the first re-capture after an interrupted one can never succeed.

### R3 — the single definition, and its consumer

`SnapshotBackingStalePath` is now the ONE canonical staleness definition, living in the
contract module (`vmshared`). The **consumer switch** — deleting
`candy/plugin-vm/vm_clone.go`'s inline `snapshotBackingStale` in favour of this predicate — is
a `candy/plugin-vm` change that must bump this repo's `require github.com/opencharly/sdk` to the
release carrying it, so it lands AFTER this merge+tag (the documented sdk-first landing order in
`/charly-internals:git-workflow`). It is **not** a deferral to a vague batch: the consumer PR
already exists — **opencharly/plugin-vm#34** — and its next commit (its sdk pin currently
`v0.2026258.154`, the pre-predicate tag) will bump the pin and switch the guard once this tag
lands. This PR advances that exit by putting the predicate where the consumer can reach it.

## How tested

`gofmt -l vmshared/` empty, `go build ./...` clean, `go vet ./vmshared/` clean,
`go test ./...` green (all sdk packages).

The two new tests pin BOTH arms and were mutation-verified:

```
$ go test -run TestCreateSnapshot ./vmshared/
ok  	github.com/opencharly/sdk/vmshared
# mutation: drop the form-2 (stale-backing) arm ->
--- FAIL: TestCreateSnapshot_StaleBackingRecaptures (0.00s)
    a stale-backing snapshot must be re-captured, got: vm "test-vm": snapshot "golden" already exists
```

- `TestCreateSnapshot_StaleBackingRecaptures` — disk present + probe reports a rebuilt backing
  → re-captured (libvirt metadata cleared, create invoked). FAILS without the fix.
- `TestCreateSnapshot_FreshBackingStillConflicts` — the negative twin: disk present + probe
  reports fresh → hard conflict, create NOT invoked (guards against "always re-capture").
- The existing `TestCreateSnapshot_StaleRegistryEntryRecaptures` (missing-disk form),
  `LiveEntryStillConflicts`, and `StatErrorStillConflicts` still pass.
