# 0.2026255.1708 — feat(loaderkit): export DesugarSteps — the verb-sugar seam for user-authored step sequences

## Summary

Export **`loaderkit.DesugarSteps`** — the seam that applies the loader's plugin-verb **sugar** rewrite to a *user-authored step sequence*, the way it already applies it to entity plans.

**The defect it fixes (proven live, not theorised):** `charly check live <bed> --steps-file <file>` raw-`yaml.Unmarshal`s the file into `[]spec.Step`. `spec.Op` has no per-verb fields, no catch-all and no `UnmarshalYAML`, so the canonical `<word>: <input>` authoring sugar is **silently dropped** — the step reaches the engine with **no verb set** and exits 2 **while proving nothing** (a false pass). That is exactly what the committed G-8 verification assets did in `opencharly/plugin-adb#8`: `screencap-negative-control-steps.yml` exited 2 without ever running, and `screencap-live-steps.yml` aborted with `cannot unmarshal !!map into string`. The desugar existed only in the loader's entity-plan path.

Two deliberate differences from the entity path, both pinned by tests:

1. **Accepts a document or a bare sequence** — `yaml.Unmarshal` into a `yaml.Node` yields a `DocumentNode`, so the seam unwraps it.
2. **Passes the wire form through.** `desugarStep` *rejects* `plugin:/plugin_input:` for entity docs (*"the plugin envelope is internal-only"*), but a steps file may legitimately be either form — `plugin-check` has shipped and documented the wire form — so the seam skips an already-wired step instead of erroring on it.

Three focused tests in `loaderkit/desugar_steps_test.go`:
- **`TestDesugarStepsRealStepShape`** — the real authoring shape (intent keyword + `id` + `context` + the `stdout` matcher shorthand + a verb sugar key) desugars to `plugin: adb` + `plugin_input:` while keeping the step's own fields and the matcher shorthand intact. This also proves the step's own keys are not misfired as sugar candidates.
- **`TestDesugarStepsWireFormPassesThrough`** — the wire form is left byte-equivalent (the difference from the entity path, and the case a first draft of this seam got wrong: `desugarStep` rejected it with *"the plugin envelope is internal-only"*).
- **`TestDesugarStepsRejectsNonSequenceAndNoIntent`** — a mapping document and a step with no intent keyword both error, rather than passing something invalid downstream.
