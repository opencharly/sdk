# 0.2026248.1522 — loaderkit: bypass the materialized-tree cache during the connect-declared-kind pass (R1 regression)

## Summary

The materialized-tree cache (PR #206, `MaterializeLoadedProjectCached`) keys on the walk envelope + schema CalVer — which omits the provider-registry connect state. During the F4 external-kind connect pre-pass (`connectDeclaredKindPlugins` → nested `LoadConfig`), the nested load's materialize DEFERS the declared-but-unconnected kind nodes (`materialize.go`: `t.Kinds[pn.Disc] && InKindConnectPass() → return nil`), and that incomplete tree (no `uf.PluginKinds[examplekind]`) is written to the cache under the SAME key the outer load then reads — handing the outer load a tree with the kind entities MISSING. This is the charly PR #540 go-check regression (`TestExternalKind_PrescanConnectDecode` + 3 siblings), introduced by the sdk pin bump that brought the cache in.

**Fix**: an executor that OPTIONALLY reports the connect-pass state (the compiled-in host implements the new `connectPassAwareExecutor` capability; out-of-process plugins have no connect pass) bypasses the cache for the duration of the pass, so the outer load re-materializes with the providers registered. Structural type-assert — no spec interface change. The charly host side (`hostLoaderExecutor.InKindConnectPass`) lands with the charly pin bump in charly #540.
