# 0.2026326.2242 — feat(packagekit): a package carries its release, so a packaging fix is a new pkgrel

## Summary

A package now carries a **release** (pkgrel) as well as its upstream version, so a packaging fix to an already-published version can be published as `<version>-2` instead of rewriting `<version>-1`.

This is the mechanism opencharly/layer-charly#23 needs. The charly packages at `2026.326.1922` were published by a packaging plugin built against a pre-`sdk#397` contract, so their control metadata carries the variant family's mutual `Replaces` and `pacman -Syu` refuses two of them. The packaging plugin has since been fixed and tagged (`plugin-generate-packages#21`), but republishing that *same version* must not silently overwrite `-1`: a client that already holds `-1` would never see the change. ALPM's answer is a new pkgrel, which this PR makes expressible.

- **`BuildOptions.Release`** — the pkgrel; `""` means `"1"`, the first build of that version.
- **`BuildInfo`** passes it to `nfpm.Info.Release`. The upstream `Version` never moves with it.
- A test pins all three properties: no release → `1`; release `2` → `2`; the version unchanged.
