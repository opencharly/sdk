# 2026.210.1407 — #55 step-3 unit 3a: buildkit.ResolvedBox embeds CUE-sourced spec.ResolvedBox

The sdk consumer leg of #55 step-3 unit 3a. `buildkit.ResolvedBox` becomes an
**embedding wrapper** around the CUE-sourced `spec.ResolvedBox` (from
`github.com/opencharly/spec` spec#4, merged spec main `172027b2`, tag
`v0.2026210.1533`): the ~30 wire-clean value fields (`Name`/`Version`/`Distro`/
`Tags`/`User`/`Merge`/`Builder`/`CandyCaps`/… — the shared contract type charly
core's render-seam floor, the resolved-project envelope projector, and
`candy/plugin-build` all read and construct) now live in `spec.ResolvedBox`;
only the genuinely buildkit-owned host-render-cache pointers stay in buildkit.

## What changed

- **`buildkit.ResolvedBox` (`buildkit/resolved_box.go`) is now an embedding
  wrapper** — `struct { spec.ResolvedBox; DistroConfig *DistroConfig; DistroDef
  *DistroDef; BuilderConfig *BuilderConfig; InitSystem string; InitDef
  *ResolvedInit; CandyCaps *AggregatedCandyCaps; BakedMetadata *spec.BakedLabelSet;
  RenderCandyOrder []string; ActiveInits map[string]*ResolvedInit }`. The five
  `DistroConfig`/`DistroDef`/`BuilderConfig`/`InitSystem`/`InitDef` build-vocabulary
  pointers plus the four `json:"-"` host-render caches
  (`CandyCaps`/`BakedMetadata`/`RenderCandyOrder`/`ActiveInits`) are the documented
  `json:"-"` gengotypes exception (spec is the bottom of the sdk dependency graph
  and must never import the capability-owned build vocabulary). Every promoted
  wire-clean field reads/writes unchanged via Go field promotion — zero read-site
  or write-site changes.
- **`MergeConfig`/`ResolvedInit`/`BuilderMap`/`AggregatedCandyCaps` are thin
  `= spec.X` aliases** in `buildkit`, consistent with buildkit's pre-existing
  alias convention.
- **Composite-literal construction sites nest the wire-clean fields under
  `ResolvedBox: spec.ResolvedBox{…}`** — Go does not promote field keys into an
  outer literal, so the three production sites (`buildkit/config_resolve.go`
  `ResolveBox`, `deploykit/intermediates_compute.go`,
  `deploykit/spec_resolved_box_adapter.go` `NewSpecResolvedBox`) plus the
  deploykit test fixtures restructure their literals. Field VALUES are preserved
  identically; test-function counts are unchanged (no coverage removed).
- **`go.mod` requires `github.com/opencharly/spec v0.2026210.1533`** (the merged
  3a spec, superseding the step-1 `v0.2026210.1121`), no `replace`; `go mod tidy`
  settled require-only via proxy.
