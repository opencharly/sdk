# 0.2026321.2010 — fix(deploykit): wrap a JSON label that would exceed the Dockerfile line limit

## Summary

`writeJSONLabel` emitted every label as ONE Dockerfile line, so a box whose serialized description is
larger than buildkit's per-line limit could not be built at all:

```
$ charly box build immich-ml-cdi            # opencharly/distro-cachyos, composing this SDK
 503 |     LABEL ai.opencharly.description='{"candy":[{"origin":"candy:…/layer-direnv",…
error: failed to solve: dockerfile line greater than max allowed size of 65535
```

The build fails before a single layer is produced. Nothing a box author can do fixes it — the only
box-side "remedy" is to compose fewer candies or write shorter descriptions, i.e. shrink the product to
suit a formatter (R3). The per-line limit belongs to the format this emitter targets, so the emitter owns
staying inside it. Filed as opencharly/sdk#553, fixed here.

**The fix wraps long values with the format's OWN continuation rule** — a backslash immediately before a
newline is removed by the parser — so the label's VALUE is byte-identical to the unwrapped form and every
reader (`ExtractMetadata` included) still sees one label with one value:

```
LABEL ai.opencharly.description='…first chunk…\
…second chunk…'
```

Two details that decide whether this works at all:

- **The split never lands on a backslash.** An EVEN run of backslashes before a newline is *not* a
  continuation, so cutting there would break the value instead of wrapping it.
- **One byte of every line is reserved** for that continuation backslash, so no emitted line can exceed
  the cap — the first version of this patch was 60001 bytes on line 0 and the test caught it.

## How tested

**1. The package builds, vets and tests clean:**

```
$ go build ./...
$ go vet ./deploykit/
$ go test ./deploykit/
ok  	github.com/opencharly/sdk/deploykit	139.800s
```

**2. The new tests, run:**

```
$ go test ./deploykit/ -run TestWriteJSONLabel -v
=== RUN   TestWriteJSONLabel_ShortValueOnOneLine
--- PASS: TestWriteJSONLabel_ShortValueOnOneLine (0.00s)
=== RUN   TestWriteJSONLabel_LongValueWrapsAndStaysByteIdentical
--- PASS: TestWriteJSONLabel_LongValueWrapsAndStaysByteIdentical (0.00s)
PASS
ok  	github.com/opencharly/sdk/deploykit	0.006s
```

`ShortValueOnOneLine` pins the common case: a value that fits is emitted exactly as before (`LABEL
k='["a","b"]'`, one newline), so no existing label changes shape.

`LongValueWrapsAndStaysByteIdentical` is the regression: a fixture deliberately larger than 65 535 bytes,
built from `x'y\z"` repeated 9 000 times so that a single quote and a backslash sit on both sides of
every split point. It asserts

- the fixture really is larger than the format's cap;
- **every** emitted line is ≤ `maxLabelLineBytes` (this is what failed on the first patch);
- no line ends in an even run of backslashes (which would not continue);
- the parser's reconstruction — backslash-newline removed — is **exactly one** logical line, and that
  line is byte-for-byte `LABEL ai.opencharly.description=` + `shellquote.ShellQuote(json)`.

The test computes its expectation with the same `json.Marshal` + `shellquote.ShellQuote` the emitter uses,
so it compares the WRAP against the pre-change output rather than against a hand-written string.

**3. R7 — the coverage fails without the change.** Reverting `writeJSONLabel` to the single
`fmt.Fprintf` makes `LongValueWrapsAndStaysByteIdentical` fail on its first line-limit assertion (a
65 535-plus line), and leaves `ShortValueOnOneLine` passing — i.e. the test measures exactly the property
the change adds.

**4. Where the real consumer is proven.** The build that exposed this is `box/immich-ml-cdi` in
opencharly/distro-cachyos. It runs at the tag this merge mints, in the pin-bump PR that follows
producer-first (sdk → charly → distro-*), and that is where the pasted `BUILD=0` will come from.

## Change classification

**Breaking change + rollback:** none — the emitted bytes for every label under the limit are unchanged
(proven by the short-value test), and a label over the limit changes from "a build failure" to "the same
value wrapped". Rollback is reverting the commit, which restores the unbuildable wide box.

Change class: **Library (render emitter)** — `go build`/`go vet`/`go test` pasted, the two new tests pasted
with their assertions described, and the consumer build named.
