# 0.2026282.1654 — fix(loaderkit): name the unrecognised kind and both causes, not just the migrate hint

## Summary

One rejection message in `loaderkit` asserted **one** cause it cannot know, and omitted the one that
mattered. When a node declares no entity, `parseNode` cannot tell *why* — but the message said:

> `no kind discriminator — collections and plan steps live INLINE in the kind value (the named child-node shape was removed); run: charly migrate`

For the case it was first hit on, that is wrong in both halves. The node —
`check-structkind: { examplestructkind: … }` in `opencharly/charly`'s own `charly.yml` — is
*syntactically correct*: `classifyKind` (`loaderkit/parse.go:71`) accepts a kind key as a child of the
node name whenever the word is a builtin kind **or** a member of the threaded kind set
(`spec.Threaded.Kinds`). `examplestructkind` is an OUT-OF-PROCESS plugin kind whose provider had not
been registered, so the word never reached that set. `charly migrate` cannot fix a missing provider,
and following that hint is the wrong move.

The cost was measured, not hypothetical: a full session went first on the config-shape reading, then
on the provider, before the mechanism was isolated (`opencharly/opencharly#437`).

The rejection now names the keys it could not classify and states **both** causes with their
remedies — the unregistered plugin kind *and* the genuine leftover named child — and reads as a
sentence for a node with no keys at all:

```
node "check-structkind": no kind discriminator — none of its keys ("examplestructkind") is a
recognized kind, so it declares no entity. Either a key names an OUT-OF-PROCESS plugin kind whose
provider is not registered — loading a provider binary is not by itself enough, the kind word must
reach the threaded kind set — or the node is a leftover named child whose collections and plan steps
now live INLINE in the kind value; for the latter run: charly migrate
```

The second commit extracts the key rendering into `unclassifiedKeys()` so `parseNode` stays inside
the lint budget — CI caught what my local gates could not (`gocyclo` at 32, limit 30). The extraction
also collapses a second declaration of the key/value pair shape: it was a defined type in
`parseNode` and an alias in the sibling walker, now one package-level alias.

Scope: **diagnostics only.** No success path changes; no schema, wire, or deployment behaviour.
