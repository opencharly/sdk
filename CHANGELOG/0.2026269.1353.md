# 0.2026269.1353 — fix(host): guard empty download `to` + honour unless_exists in the host renderer

## Summary of changes

Fix **two defects in the HOST / machine-venue renderer** (`sdk/kit`) that the
container build emitter already handles correctly. Both block applying a candy
with a `download:` step to a `target: local` host.

### 1. `install -d ''` for an `extract: sh` download with no `to:`

`kit/render.go` `RenderDownloadScript` emitted

```sh
install -d -m0755 <to>
```

**unconditionally**, so `layer-kubernetes`'s helm step —

```yaml
- download: "https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3"
  extract: sh
  unless_exists: /usr/bin/helm
  run_as: root
```

— with **no `to:`** (the script installs itself) rendered `install -d -m0755 ''`
and failed:

```
install: cannot create directory ‘’: No such file or directory
```

The container emitter (`deploykit.EmitDownload`) emits **no** `install -d` for
`extract: sh`; it only creates a destination dir for the archive branches. This
PR skips the `install -d` when no `to:` is declared.

### 2. The host renderer ignored `unless_exists`

`unless_exists` is honoured on the container path
(`deploykit.EmitDownload`/`EmitCmd` via `kit.WrapUnlessExists*`, added
2026.230.1550) but **not** by the host/machine-venue renderer — so a guarded
step ran unconditionally on a host where the tool already existed (observed:
`layer-kubernetes`'s helm step re-running on Arch, immediately after
`warning: helm-4.3.0-1 is up to date -- skipping`). This PR applies the same gate
in `kit/walk.go`'s `walkOp`.

**Terminator form:** the host venue runs the rendered command as a **script**
(`RunSystem`/`RunUser`), so the newline-terminated **Block** form is always used —
and is REQUIRED for the multi-line payloads (`download:` renders a full script, a
`write:` renders a heredoc, a multi-line `run:` command). The inline `;` form is
safe only for a single simple command and would corrupt any payload with a
trailing newline (`…{ : ; <script>\n; }; fi` → `syntax error near unexpected
token ';'`). The new test asserts every gated render parses under `sh -n`.

### R3 — one definition of the gate

`WrapUnlessExists`/`WrapUnlessExistsBlock` moved from `deploykit` to `sdk/kit`
(the importable leaf — `kit` does NOT import `deploykit`, so both renderers can
share it), with `deploykit` keeping thin `var` aliases so every existing
`deploykit.WrapUnlessExists*` call site is unchanged.

| File | Change |
|---|---|
| `kit/unless_exists.go` | NEW — the gate (relocated from deploykit) |
| `kit/render.go` | guard the empty-`to` `install -d` |
| `kit/walk.go` | apply the gate (Block form) in the host `walkOp` |
| `deploykit/tasks_emit.go` | delete the moved functions; alias them to `kit` |
| `kit/render_test.go` | + `TestRenderDownloadScript_EmptyToNoInstallD` |
| `kit/unless_exists_render_test.go` | NEW — `TestHostRenderHonoursUnlessExists` (with `sh -n` parse assertions) |
