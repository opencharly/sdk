## Summary

**Producer-first pin bump**, following opencharly/spec#330 (merged `16:19:48Z`, tagged `v0.2026319.1619`), which added
`diagnostics` to the build-resolve reply so a resolve can report what it printed.

```diff
- github.com/opencharly/spec v0.2026319.26
+ github.com/opencharly/spec v0.2026319.1619
```

**Why it is a separate PR and not folded into the consumer:** a consumer of the new field cannot compile against the new
schema while this module still pins the old spec, and this module is what the consumer pins in turn. The order is
`spec → sdk → plugin-build`, and this is the middle leg. No code here; the field's consumer is the next unit.
