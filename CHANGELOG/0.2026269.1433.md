# 0.2026269.1433 — fix(kit): OCR-robust, stale-proof console completion marker

## Summary

Fixes a real stale-echo + OCR-fragility bug in `kit.ConsoleSession`'s completion
marker, surfaced driving a live Omarchy console.

**Stale-echo.** A marker from a PREVIOUS run left in the terminal scrollback
equals the current marker, so the wait completed on the stale echo before the
command ran. The marker now carries a **digit-only 12-digit nonce, FRESH PER COMMAND** (not a cached per-session one — see below):

```
CHARLY_DONE_<12 digits>_<counter>_END
```

**OCR fragility (the live RCA).** The exact-line match assumed pixel-perfect OCR.
MEASURED on the real console, tesseract both INSERTS/SUBSTITUTES separators
(`CHARLY DONE_…`, `CHARLY_DONE_… _1_END`) and MISREADS individual marker
characters (`2`→`Z`, `b`→`h`, `q`→`g`). The marker WAS echoed on screen, yet the
wait timed out non-deterministically on the SAME code (one run passed, the next
failed). The match is now:

- whitespace-and-underscore **normalized** on both sides (`normalizeOCRForMarker`);
- bounded **edit-distance** tolerant (`ConsoleMarkerMaxEditDistance=2`, via
  `editDistanceAtMost`), so a couple of OCR substitutions still match;
- `stripCommandEcho` uses the same normalized containment AND the same edit-distance
  bound, so an accepted marker line is always stripped and cannot satisfy `Expect`.
- **Per-command nonce (review regression fix).** With a cached per-session nonce,
  two commands' markers differ only by their counter (`..._1_END` vs `..._2_END`
  = 1 edit), so within the 2-error tolerance the wait for command N+1 matched
  command N's marker still on screen and completed early. Each command now gets a
  FRESH nonce, so consecutive markers differ by the whole 12 digits. A test drives
  two commands in ONE session and asserts the second does NOT complete on the
  first's marker (it fails with the cached nonce).

It stays a (fuzzy) EQUALITY test, preserving the exact match's invariants: the
ECHOED command line (marker + the whole command) is far longer, so its edit
distance exceeds the bound and it does NOT match (the echo trap); and a STALE
marker differs by its whole nonce. With a 12-digit nonce and a 2-error tolerance,
the chance a given stale marker is within distance 2 is ≈5.5e-9 (≈3e-7 across 50
stale lines) — negligible, not an absolute guarantee (the comment states this
honestly).
