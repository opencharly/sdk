# 0.2026331.2334 — fix(bootstrap): create the account the image DECLARES (name-guarded, all measured forms)

## Summary

The bootstrap's account creation was guarded on the **UID** while everything downstream consumes the **NAME**. On a base whose uid 1000 already belongs to another account (`ubuntu`, a builder image, a distro whose `base_user` differs), the guard short-circuited, `user` was never created — and the image went on declaring `USER user`, so every `podman exec` failed with:

```
Error: unable to find user user: no matching entries in passwd file
```

Field evidence: opencharly/charly#1309 (post-`charly update` overlay step) and the same container-level shape on the agent channel's `terminal:tmux` round-trip (opencharly/distro-arch#85).

This makes the emitted creation match the emitted contract, on **both** userlands, by trying the measured forms in order:

- **shadow-utils leg** — the guard is the **declared name**; the group guard accepts an existing group of that NAME at any gid; then:
  1. `useradd -m -u UID -g GID …` (the normal case),
  2. `useradd -o -m -u UID -g GID …` (uid 1000 taken by another account, group at GID present),
  3. `useradd -m -u UID -g <user> …` (group `<user>` exists at another gid — `-g GID` would fail),
  4. `useradd -o -m -u UID -g <user> …` (both unusual cases at once).

  Every shadow-utils form keeps `-u %d`: this userland can hold the uid, so it never needs a uid-less form.
- **busybox leg** — `adduser` creates its own same-named group and takes `-G` by NAME; three forms:
  1. `adduser -D -h DIR -u UID -s SHELL user` (uid free),
  2. `adduser -D -h DIR -s SHELL user` (uid taken, group absent),
  3. `adduser -D -h DIR -G user -s SHELL user` (group `user` pre-exists, uid taken).

  A busybox userland has no `--non-unique`, so the uid may move; the contract is the declared NAME resolving, which every form guarantees.

`Closes #655`

### Spike

- **A. Guard on the name; keep both group guards as they were.** Rejected on measurement: the busybox gid-keyed guard leaves group `user` absent and both `adduser -G user` forms die `unknown group user`; the shadow-utils gid-keyed guard short-circuits on a base that ships group `user` at another gid.
- **B. Ensure a group of the NAME at any gid, then keep `-G`/`-g GID`.** Rejected on measurement: busybox's pre-created group makes the group-free form die `group 'user' in use`; and `useradd -g GID` still fails when no group has that gid.
- **C. Emit `USER <uid>` instead and stop resolving names.** Rejected: `ai.opencharly.user`, `HOME` and `WORKDIR` are name-based and the overlay restores `USER <label>`, so a numeric-only fix leaves the overlay and the agent channel resolving a name, and does not fix an image whose declared name is absent.
- **D. Treat a uid-owned-by-another-name base as "adopted".** Rejected: adoption asserts the base already provides the declared account; here it demonstrably does not.
- **E. WINNER — ordered measured forms per userland, with no pre-created group on busybox.** shadow-utils: `-g GID`, `-o -g GID`, `-g NAME`, `-o -g NAME`; busybox: `-u UID`, group-free, `-G NAME`. The diff implements exactly E; its proof is the four live executions and the three red arms above.
