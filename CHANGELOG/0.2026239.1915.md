# 0.2026239.1915 — fix(deploykit): materializeBuildConfigAsset must search ALL remote cache roots

## Summary

The candy de-submodule cutover moved each candy to its OWN standalone repo, so remote candies no longer share ONE `repo@version` cache root. `remoteBuildConfigCacheRoot` returned only the FIRST remote candy's root; a build-config asset (e.g. the supervisord init `header_file`) referenced by a candy in a DIFFERENT repo was never found, so the header COPY stayed as-authored — every service-candy box failed at `COPY templates/supervisord.header.conf: no such file or directory`.

**Fix:** `remoteBuildConfigCacheRoots` returns the DISTINCT roots across all remote candies (root-level standalone candies return `SourceDir` directly; subpath candies strip `candy/<name>`), and `materializeBuildConfigAsset` searches each root in turn for the asset before giving up.

### 3. The fix restores the header materialization path (live build, PASTED output)

Built with the fix (via a local-replace binary) and ran `charly box build arch-coder` on the distro-arch sweep branch. The build now passes the previously-fatal supervisord header stage and enters the main 211-step stage:

```
[61/62] STEP 1/6: FROM scratch AS supervisord-conf
[61/62] STEP 2/6: COPY templates/supervisord.header.conf /supervisor/00-header.conf
... (resolves — the header materializes from the layer-supervisord cache root)
[62/62] STEP 1/211: FROM ghcr.io/opencharly/arch-layer-gnupg:2026.239.1702
[62/62] STEP 2/211: USER root
...
[62/62] STEP 88/211: RUN ... pacman-key --lsign-key ... && pacman -Syu --noconfirm --needed charly
```

Before the fix the build died at `[61/62] STEP 2/6: COPY templates/supervisord.header.conf` with `no such file or directory`; after the fix it advances past that stage into the main 211-step stage (reaching STEP 88). The residual stop at STEP 88 is the charly-arch package-repo install requiring the **GPG signing key** that this host lacks (`pacman-key --lsign-key`: no secret key) — owned by the named thematic batch **`feat/box-build-race`** (the R10 KVM-bed venue in `plan/candy_to_repo.md`, which provisions the charly checkout + GPG secrets), unrelated to this deploykit change.

**Attribution tier:** `analysed on a live system` — the changed `materializeBuildConfigAsset` loop executed live (the build advanced past the previously-fatal header COPY), but the full arch-coder build could not complete in this environment due to the GPG key absence (routed to the named batch).
