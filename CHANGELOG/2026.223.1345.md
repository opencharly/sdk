# 2026.223.1345 — download: creates the destination dir before extracting

Producer half of the AgentTeams Unit-1 cutover (rootless installs). The `download:`
verb emitted `tar -xzf ... -C <to>` / `unzip -o ... -d <to>` directly at the
destination, which **fails when the destination directory does not exist yet** — a
rootless install into a fresh tree (`/opt/<app>`, or any not-yet-created path)
aborted the image build with `no such file or directory`.

- **`deploykit/tasks_emit.go` (`EmitDownload`)**: the emit now creates the
  destination before extracting — `tar.gz`/`tar.xz`/`tar.zst`/`zip` →
  `mkdir -p <to> && …`; `extract: none` (where `<to>` is a **file**) →
  `mkdir -p $(dirname <to>) && cp -f …`; `extract: sh` unchanged. This matches
  `copy:`'s auto-create-parents behavior. The mkdir runs in the build container as
  the step's `run_as` user, so a download lands wherever that user can write — no
  root required.
- **`deploykit/tasks_emit_test.go`**: `TestEmitDownload_TarGz` extended to assert
  `mkdir -p <to> && tar …`; new `TestEmitDownload_NoneCreatesParentDir` asserts
  `mkdir -p $(dirname <to>) && cp -f …` for `extract: none`. Both fail without this
  change.
