# 2026.229.1400 — the renderer stops guessing the distro, and stops hardcoding two of its traits

Placeholder CalVer (the pr-validator finalizes it at merge). Chosen after `2026.229.0947`,
with no filename collision.

Three pieces of guesswork are deleted outright, not narrowed.

## 1. `effectiveDistro` — DELETED

It inferred the distro from `base_user`: `arch` → arch, `alpine` → alpine, everything else →
`""`, which `composePackages` and `composeRunCmd` then treated as Arch/Fedora. So a
Debian-family cloud image that did not spell out `distro:` was rendered with the Arch package
name `openssh` and `systemctl enable --now sshd` — a unit Debian and Ubuntu do not have. With
`composeBootCmd`'s deliberate `mask ssh.socket`, that left a socket-activated sshd masked and
never started, and the guest booted permanently unreachable.

An account name says nothing about an operating system. `Source.Distro` is now read directly;
the field is validated by the vm kind's OpValidate capability, so an omission is an authoring
error rather than a silent default.

## 2. The `ssh || sshd` fallback — DELETED

A previous entry added `systemctl enable --now <unit> || systemctl enable --now <other>` so a
missing `distro:` "could not brick SSH". That was a stopgap: it made the wrong input survive
instead of rejecting it, and it hid the very omission that needed reporting. With the field
required and closed, the unit name is known exactly and exactly one command is emitted.

## 3. Two hardcoded distro traits — now generated data

`sshUnitForDistro` was a Go `switch` returning `ssh` for debian/ubuntu and `sshd` for
everything else. The Alpine OpenRC path was `if spec.Source.Distro == "alpine"`. Both now read
the tables generated from `schema/distro_vocab.cue`'s `#Distros` (`spec.DistroSSHUnits`,
`spec.DistroInits` — see the spec entry). A branch on a distro NAME encodes a trait as a fact
about one distro: not enumerable, not validatable, silently treating every unlisted distro as
systemd, and needing to be found and edited again for the next OpenRC distro.

`distroInit()` is the only thing that decides how a service is enabled and started in a guest.

## The test named "ByteIdenticalToPreFix" is gone

Replaced by `TestRenderCloudInit_NonPacmanUsesPackagesKey`, which asserts the containment that
actually matters: non-pacman distros deliver packages via the `packages:` key and never reach
the pacman runcmd branch.

The old name pinned the rendered output against a historical baseline rather than a behaviour.
"pre-fix" named a moment nobody can look up; the assertion had to be re-baselined by every
legitimate change; and it had already accumulated a comment explaining why its own name was no
longer true. **A test whose name has to be explained away is pinning an accident.**

## Coverage

`TestRenderCloudInit_Alpine_OpenRC` survives the deletion of the inference tests and now
declares `distro: alpine` explicitly — it covers the OpenRC branch, which is not inference
coverage. `TestComposeRunCmd_AlpineOpenRC`'s second case varies `base_user` while pinning
`distro: alpine`, proving `base_user` no longer participates in the decision at all.

## Legacy removal: the frozen init table, and two fallbacks that hid failures

**`wellKnownInitDefs` is deleted.** It was described in its own comment as "the legacy fallback
for pre-init_def-label images … frozen at the two init systems that predate the label; do NOT
add new ones". Three problems, any one sufficient:

- It was **triplicated verbatim** — `sdk/kit/entrypoint.go`, `candy/plugin-pod`, and
  `candy/plugin-deploy-pod`, the last one commented "mirrors charly-core service.go's table
  VERBATIM" (R3).
- It was **frozen at supervisord + systemd**, so with `openrc:` now a first-class init system
  the table could only ever answer for two of three — silently, for the third.
- It existed for images built before the `ai.opencharly.init_def` label. Every image charly
  builds today carries that label.

`ResolveEntrypointFromMeta` / `ResolveInitDefFromMeta` now read the label as their only source;
an image without it errors, naming the rebuild, rather than resolving a guessed management CLI
that would drive the wrong supervisor. `candy/plugin-deploy-pod`'s local
`resolveEntrypointFromMeta` — a fourth copy, of the *function* this time — is deleted with it and
its callers routed to the single `kit` implementation.

**`LibvirtSessionSocketWithProbes` no longer returns a path it did not find.** With neither the
modular (`virtqemud-sock`) nor the monolithic (`libvirt-sock`) socket present it returned the
monolithic path anyway, as though found. That made `status_vm`'s own `if sock == ""` guard **dead
code** and turned "libvirt is not running" into a stat failure on a socket the host may never
have used. It returns `""`; every caller already stats the result. The two-socket probe itself
stays — that is third-party version compatibility, and `probed` still carries both for the
diagnostic trail.

**`SmbiosCredForRootSSH` is deleted** — a compatibility wrapper "preserved for the existing call
sites in vm.go", which has zero production callers; those call sites were removed in an earlier
K-wave and only its own test still referenced it.

## Triaged and deliberately kept

Two `legacy`-labelled branches are NOT charly's superseded paths and stay, with their comments
corrected so the next sweep does not mis-trigger: `status_pod`'s quadlet-description
fall-through handles units charly did not write, and `status_flat`'s `lookupDeploy` alternates
match bed-rolled container names. Neither has a superseded charly format behind it; deleting
them would remove capability, not legacy.
