# 0.2026296.2152 — fix(candywalk): read a manifest's DECLARED refs, not the refs in its block scalars

## Summary

`sdk/candywalk.collectRefs` regex-scanned a fetched repo's root manifest as **raw text**, so a ref a
manifest merely CONTAINS was collected as though it were DECLARED. `plugin-box`'s R10 bed
`box-reconcile-closure-reports-unfetchable` writes
`@github.com/opencharly/this-repo-does-not-exist-zzz/candy/nope:v1.2.3` into a scratch project at
runtime, on purpose, to prove `charly box reconcile --closure` **reports** an unfetchable ref instead
of swallowing it. The scanner collected the bed's own fixture and the corpus generator died resolving
it, `rc=1`, for every consumer of the corpus (`opencharly/sdk#455`).

**I picked candidate 1 — exclude block scalars — and the instrument is the YAML parser, not a
narrower regex.** Candidate 2 ("only scan a root manifest when the ref named the ROOT") only narrows
*when* the raw-text scan runs; it leaves the defective instrument in place, so a root-pinned repo with
an embedded fixture still kills the walk. Parsing fixes the class: a ref in a scalar is a declaration,
a ref inside a `|` / `>` body is data, whether that body is a shell script, a generated manifest
template, or prose.

The change, per file:

- **`candywalk/candywalk.go`** — `collectRefs` now parses the file and reads refs off its scalar
  nodes, skipping `LiteralStyle`/`FoldedStyle` entirely. A file that does not parse as a manifest
  (prose, a CHANGELOG) keeps the text scan, because there the text IS the declaration surface. The
  ref policy — skip the pre-cutover in-repo `charly` form, drop prose notation — moved into one
  `acceptedRef` home shared by both readers, so no policy was duplicated (R2).
  `manifestRoot` + `collectRefsNode` are the new parser reader; the package doc's claim that this is
  a raw-byte scan was corrected in the same edit (R4/R5).
- **`candywalk/candywalk_refs_declared_test.go`** (new) — three arms: the fixture-shaped bed's ref is
  NOT collected while the ref declared beside it IS; the SAME ref string in a DECLARED position IS
  collected (the negative arm — the scanner must not blind itself); and a versioned ref in a COMMENT
  is no longer fetched as though declared.

**The fixture is untouched.** `plugin-box`'s bed and its realistic ref stay exactly as they are — a
predecessor refused to rewrite it, because that "hides the defect and breaks on the next repo with an
embedded fixture" (`opencharly/sdk#455`, "What I did NOT do").

Two consequences of parsing, both measured rather than assumed:

- a versioned ref in a COMMENT is no longer collected (a comment declares nothing). Org-wide there is
  exactly one such token — `plugin-quickshell` documenting its own pin — and that repo is a DIRECT pin
  already, so nothing is lost;
- four refs org-wide live ONLY inside block scalars: `eval-omarchy`'s generated-manifest `template:`
  (plugin-record / plugin-spice / plugin-vision) and `plugin-migrate`'s bed (plugin-pipeline).
  plugin-vision owns no skill and plugin-pipeline is already a DIRECT pin, so the corpus cost is
  `record` + `spice` — which arrive today only through that template. They are repaid by DIRECT pins
  in the marketplace refs list at the same tags (their newest), which is what
  `opencharly/plugin-marketplace#41` asks for anyway: a skill reached only through the closure
  publishes whatever tag a sibling happens to name.
