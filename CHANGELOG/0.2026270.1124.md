# 0.2026270.1124 — fix(sdk)!: require a CUE schema and a typed input on every plugin capability (delete the input-less waiver)

## Summary

Delete the SDK's **"stub-gate relaxation"** — the exception that let an *input-less* plugin (no capability declaring an `InputDef`) pass a `nil` schema FS and serve an **EMPTY** CUE schema. It made a plugin whose input is validated against **nothing** a legal shape.

`BuildCapabilitiesWithRequires` now rejects, **unconditionally**:

1. a `nil` schema FS — **NO CUE schema**;
2. a schema concatenating to an empty body — **EMPTY CUE schema**.

The uniform rule is **the schema**, not a per-capability `InputDef`. This is deliberate and evidence-led: the canonical command plugin (`plugin-example-command`) and the substrate kinds (`kind:candy`) and deploy targets (`deploy:local`) declare **no** structured `plugin_input` by design — their contract is their CLI grammar / the substrate — and the pre-compaction **"doc schema"** existed for exactly that case (`plugin-candy`'s own comment: *"plus the self-contained doc schema, via sdk.NewMeta"*). Requiring a per-capability `InputDef` would force invented, unvalidated defs onto those classes. So every plugin must ship a non-empty schema — a pass-through command ships a minimal **doc schema**, never nothing. That is the one deliberate wiggle room.

This is the **sdk leg** of the R5 cutover tracked in **opencharly/charly#712**. A sweep finds **~dozens** of plugins passing `nil` (not 4), so the consumer legs restore their schemas in producer-first order; because they are pinned to older SDK versions, this leg is safe to land first.

### Files

- `schema.go` — the relaxation deleted; the two unconditional rejections (nil FS, empty body) plus the standalone-compile check retained.
- `loaderkit/parse.go` — the "a null value is an input-less verb" note corrected: a null value is an EMPTY input map, decided by the plugin's own served schema.
- `requires_test.go`, `schema_capabilities_test.go` — fixtures now ship a real schema (the tests exercise the real contract instead of waiving it).
- `schema_contract_test.go` (new) — pins both rejections **and** `TestBuildCapabilitiesAcceptsDocSchemaWithoutInputDef` (a command/kind/deploy plugin with a doc schema serves fine). Fixes the validator's stale-identifier finding (`inputlessSchemaFS` → `emptySchemaFS`).
