# 0.2026270.1024 — fix(emit): move build-cache mounts off /tmp to /var/cache/charly (RCA)

## Summary

Moves the SDK emitter's default BuildKit **build-cache mounts off `/tmp`** to
`/var/cache/charly/...`, eliminating the root cause of a family of
image-corruption bugs where a consumer image ships `/tmp` as `root:root 0755`.

### Root cause (RCA 2026-09-24, proven by controlled experiment)

A BuildKit **cache mount rooted under `/tmp`**
(`--mount=type=cache,...,dst=/tmp/...`) combined with a **nested container
runtime that writes under `/tmp` in the same RUN** makes BuildKit
**materialise `/tmp` as a fresh directory at the process umask (`0755`)** instead
of preserving the lower layer's `1777`. The change is committed into the image,
so every uid-1000 writer of `/tmp` then fails — supervisord's
`logfile=/tmp/supervisord.log` and pod-dbus's `unix:path=/tmp/dbus-session` both
`EACCES` at container start.

`EmitCmd` is the trigger: a non-root `command:` step gets a BuildKit cache
mounted at `dst=/tmp/npm-cache`, and a step that also runs a nested container
runtime (`layer-container-nesting`'s `podman pull` pre-pull) is exactly the
combination. `EmitDownload` attaches `dst=/tmp/downloads` the same way.

Minimal reproduction (base = `cachyos-layer-agent-forwarding`, unmodified):

| variant | cache dst | nested runtime | image `/tmp` |
|---|---|---|---|
| base | — | — | **1777** |
| cache under `/tmp` | `/tmp/npm-cache` | no | **1777** |
| nested runtime, cache outside `/tmp` | `/var/cache/npm` | yes | **1777** |
| **both** | `/tmp/npm-cache` | yes | **755** |

Either factor alone is harmless; only the combination breaks it. The host `/tmp`
is **not** affected — rootless isolation holds; the `0755` lives in the image's
own overlay layer.

### The fix (2 files)

- **`deploykit/tasks_emit.go`**: three shared constants (`buildCacheRoot =
  "/var/cache/charly"`, `downloadsCacheDir`, `npmCacheDir`); `EmitDownload`'s
  cache mount + fetch path and `EmitCmd`'s non-root fallback cache use them.
- **`deploykit/tasks_emit_test.go`**: assertions updated to the new paths (same
  structural checks — content-addressing, uid/gid-owned vs shared form).

### Scope — the emitter (the trigger) vs the multi-stage builder caches

**This change sweeps the EMITTER's build-cache surface** — the `EmitDownload`
(`/tmp/downloads`) and `EmitCmd` (non-root `/tmp/npm-cache`) caches. `EmitCmd`'s
non-root `command:` cache is *the trigger*: it is the mount that coexists with
`layer-container-nesting`'s nested `podman pull`, and it lands in the **final**
image's `/tmp`.

The multi-stage **builder-stage** cache targets named in the round-1 review
(`/tmp/{pixi,rattler,aur-srcdest,aur-xdg,cargo,npm}-cache`, plus the builder
`*_CACHE_DIR` env) are a **distinct class**, and are a deliberate scope
decision, not an oversight:

1. they live in a **builder `FROM … AS <stage>` stage** whose filesystem is
   discarded — only `Home`/artifacts are `COPY`'d forward, so they never touch
   the final image's `/tmp`;
2. those stages run **no nested container runtime** (`yay`/`cargo`/`npm`/`pixi`
   only), so they are neither triggers nor victims of this bug;
3. their mount targets are declared in the **charly build vocabulary**
   (`charly/charly.yml` `cache_mount:`) and the sdk builder templates
   (`kit/builder_resolve.go`), which must move **together** to stay consistent
   (mount dst ↔ cache env) — a coordinated two-repo change.

That relocation is therefore routed to the named batch
**opencharly/distro-cachyos#95** ("/tmp build-cache cutover — retire the
tmp-sticky belt once the SDK emitter is repinned"), which owns the full
`dst=/tmp` sweep across the emitted Containerfiles. It is **not** required for
this emitter fix's correctness: the emitter surface — the only one that reaches
the final image — is fully swept here (§4).
