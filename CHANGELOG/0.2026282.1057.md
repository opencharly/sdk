# 0.2026282.1057 — fix(kit): the never-hang kill names what was absent, not only which bound fired (charly#650 part 3)

## Summary

A step killed by the per-attempt never-hang bound could only report the **mechanism of its death** —
`process terminated by signal (signal: killed)`, plus the bound line added by the earlier message fix.
That answers *"how long did it run"* and not *"was the probe making progress, or was it wedged?"*, and
those two have different owners: a wedged probe is a defect in the probe, a legitimately slow probe needs
an authored `timeout:`.

Where a **local pid** exists, the process itself is the witness, so the kill now names which it was:

| file | change |
|---|---|
| `kit/never_hang_evidence.go` (new) | `KillEvidence` (bound, pid, alive-at-the-bound, silence) + `ObserveLocalKill`, which reads liveness and elapsed silence from **injected** readings — the seam that makes the never-hang path provable without waiting for a production bound |
| `kit/runner.go` | `AnnotateNeverHangKillWithEvidence` is the ONE implementation; `AnnotateNeverHangKill` becomes its unobserved case, so every existing caller and message is byte-identical (R3) |
| `kit/images.go` | `runEngineCommand` reads liveness **inside `cmd.Cancel`** — at the instant the bound fires and *before* our own SIGKILL — and annotates the deadline error |

Remote/venue probes have no local pid, so they keep exactly the message they had: the qualifier is
*"where a local pid exists"*, not "everywhere".

**Unchanged by design:** the never-hang ceiling is still a **hang bound** (`ProbeNeverHang` untouched),
it still honours an authored `timeout:` over the floor, and **no timeout was widened** — `charly#846`'s
isolated-cache fix is the precedent: the number is the symptom, never the fix.

Relates to `opencharly/charly#650` (the row's part 3; see `## Filed issues` for what is left in it).
