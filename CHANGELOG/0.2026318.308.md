# 0.2026318.308 — fix(loaderkit): resolve the kubernetes kind through the contract envelope

## Summary

`opencharly/spec#304` unit 5, a consumer leg. The authored `#Kubernetes` body moved into the plugin that SERVES the kind (`opencharly/plugin-substrate#35`, merged), so this package's kind table — which reads the **base** schema only — can no longer name `#Kubernetes` once the contract leg deletes it; a name the base does not carry panics at first use, which is exactly what `pod` (unit 3) and `local` (unit 4) each taught.

The entry now names **`#ResolvedKubernetes`**: the contract's remaining declaration for the kind. Its `raw` carries the full cluster model opaquely, and the consumer that decodes it is `candy/plugin-k8sgen` — the envelope's own note says so, which is why the entry does not need the authored def.

`kindcluster` has **no entry** in this table (measured), so no sibling change is owed.
