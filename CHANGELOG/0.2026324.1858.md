# 0.2026324.1858 — feat(kit): a candy's declared var: resolves in a check step (successor to #597)

## Summary

**A candy's declared `var:` now resolves in a check step.**

`buildTimeVars` (`kit/checkvars.go`) builds the map a `check:` step's `${NAME}` is substituted from. It read six fields off `*spec.BoxMetadata` — `User`→`USER`, `Home`→`HOME`, `UID`, `GID`, `Box`→`IMAGE`, `DNS` — plus `INSTANCE` from its own `instance` argument, and **a candy's declared variables were not among them.**

So a bed could declare one and the runner would **know the name and never have a value**. The host's unresolved classifier sees the declaration, which is why the step reported

```console
SKIP  check PROBE does a candy var reach a check step  [probe-var]  unresolved variables: PROBE_FLAG
```

**rather than failing `DEAD` as an unknown name would.** Two different maps, and only one had ever been extended.

**`#Op`'s `config:` comment states the rule `check:` steps never received:** *"substitutes ${VAR} refs in content: at generate time (**candy var: ∪ auto-exports**)"*. `opencharly/spec#403` carried `var:` onto `BoxMetadata`; **this is the leg that reads it.**

**Declared values are merged last**, so an authored declaration wins over a value the builder inferred from another field — a candy that declares `USER` means its own.

**`Vars` also joins `DeployOnlyCapabilityFields`**, and the repo's own gate asked the question before I did:

```console
$ GOWORK=off go test ./deploykit/ -run TestCapabilityLabelCompleteness
capabilities_test.go:11: spec.BoxMetadata fields without CapabilityLabelMap entry: [Vars]
```

**It is not an OCI label:** authoring data read from the resolved project, not an image-declaration capability. There is nothing for a pushed image to advertise, and `charly deploy from-box` reconstructs a deployment, not the source a bed tests — the same reason `Tunnel`, `DNS` and `Engine` are exempt.

## Change classification

Kind: **a behaviour change in a mechanism library** plus a `spec` pin bump. A deployment whose candies declare `var:` gains those names in its check-substitution environment; one that declares none is unaffected.

**Breaking change + rollback:** not breaking — an empty `var:` map is the previous behaviour exactly. Reverting restores the previous key set; nothing else reads `meta.Vars`.
