# 0.2026249.2036 — fix(loaderkit): structural bodies scan in-body members by the KEY rule, minus the declared input-schema fields

## Summary

Follow-up to #222 (the parent-disc guard), incorporating the refined design ruling. #222's parent gate alone does NOT fix the live corpus bug: **group is a STRUCTURAL kind** (plugin-group declares `Structural: true`, word `group`, `InputDef: #GroupInput`), so the #222 scan ran for group bodies and the value-shape channel (`isEntityValue`) still classified iterate's `agent:` key as a disc — the fixture had threaded group as a non-structural kind, mis-modeled against the live host.

The refined rule, data-driven from `spec.Threaded` (zero hardcoded words):

- **SUBSTRATE parent** (`t.DeploySubstrates`) — **UNCHANGED**: the entity-keyed value-shape scan (`discEntityPairs`/`isEntityValue`). Substrate bodies have no colliding declared fields (their unknown keys are already rejected by their own decoders); the authored-depth sidecar shape keeps working.
- **STRUCTURAL parent** (`t.StructuralKinds`) — **the KEY rule**: an in-body key is a member iff the KEY ITSELF is a memberDisc word, minus the kind's DECLARED input-schema fields — the new `spec.Threaded.StructuralDeclaredFields` channel (opencharly/spec#104, `v0.2026249.2030`), fed by the host from the registered `#XInput` schema. A non-kind key is opaque data whose value is NEVER looked inside (no transitive recursion — the `iterate:`-carrying-`agent:` collision class dies); a kind-word key that IS a declared field stays data; a kind with NO declared schema threaded falls back to every kind-word key being a member (documented + tested).

Also bumps the spec pin to `v0.2026249.2030` (the channel's contract change).
