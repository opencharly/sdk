# 0.2026243.1202 — feat(artifact): artifact_contains_text — the assertion that a surface RENDERED

## Summary
A fifth artifact validator beside min_bytes, min_dimensions, not_uniform and
min_cast_events, so it works on every verb that produces an artifact - wl, cdp, vnc,
libvirt and spice screenshots alike - rather than one of them.

It is the assertion that separates a surface MAPPED from a surface RENDERED. A layer can
be present, correctly sized and on screen while drawing nothing, and every existing
validator passes it: min_bytes passes on a blank PNG, not_uniform passes on a wallpaper
with no text at all. Upstream omarchy's acceptance suites use exactly this shape
(screen_contains) for the assertions that matter most - that the weather panel really
rendered SAN FRANCISCO, that the menu shows Apps, that a notification body is on screen.

## Failing to run is not failing to match

The design property this validator lives or dies by, learned the hard way while building
it. With eng.traineddata absent, tesseract writes its complaint to STDERR and exits with
EMPTY stdout. A caller reading only stdout sees precisely what a genuine no-match looks
like.

That cost real debugging time: OCR was pronounced unable to read an omarchy desktop after
returning zero words at 1x, 2x and 3x, from an image whose bar reads Monday 10:52 plainly
to a human. The truth was that OCR had never run at all - the host had only afr and osd
language data. Re-run with an available language, the same image read the clock correctly.

So this checks stderr FIRST and unconditionally, before the exit status, and returns an
error naming the cause: a missing engine, missing language data, an undecodable artifact
and a real no-match are four different errors. A check verb that cannot tell "I looked and
it was not there" from "I could not look" is failure-open, which this SDK has shipped
before and fixed before.

## Why it upscales

Tesseract drops small UI text at native resolution - a desktop capture is
screen-resolution, and tesseract wants roughly document-resolution. Measured: zero words
at 1x, and the clock read correctly once enlarged. The artifact is enlarged 4x with
nearest-neighbour, which keeps glyph edges hard; a smoothing filter blurs thin UI type.
Sparse-text page segmentation is used because a desktop is scattered labels rather than a
page of prose. Both match what upstream omarchy's harness does.

## How tested

    go test -count=1 ./...
    exit 0, 10 packages ok

NEGATIVE-CONTROLLED, and the control is the whole point. Reverted to a stdout-only
implementation, the missing-language-data test fails with the message that misled a human:

    a setup failure was reported using the NO-MATCH message:
      artifact_contains_text: "anything" not found in the text OCR read from "..."
      (read 0 characters; first 200: "")

Read 0 characters is indistinguishable from a real absence. With the fix the same case
returns an error that names the missing language pack.

Five tests cover the four distinct failures plus the upscale: missing engine, missing
language data, missing artifact, undecodable artifact, and that the enlargement happens
and its temp file is cleaned up.

### The gofmt warning, fixed rather than parked

An earlier revision of this body dismissed a gofmt warning on
`deploykit/intermediates_move_test.go` as "pre-existing on main … not touched here". That is a
forbidden R2 classification and the block on it was correct: a warning in a gate's own output
is a finding, and "someone else's" is not an exit.

It is fixed in-tree — three lines of map-literal alignment, whitespace only, no behaviour. The
module is now gofmt-clean:

```
$ gofmt -l .
(no output)

$ go test -count=1 ./...
exit 0, 10 packages ok
```

Cheaper to fix than to route to a batch, so it is fixed.

## Rulebook compliance

- **R1 — RCA every anomaly.** "OCR cannot read this desktop" was a WRONG conclusion, reached
  from zero-word output at three scales. It was root-caused to missing language data rather
  than accepted, and the root cause became the validator's central design property.
- **R2 — Nothing parked.** The host dependency this introduces (`tesseract` + a language pack)
  is not left implicit: it is declared in charly's candy `packaging:` in the companion PR, so a
  charly install brings it. The consuming assertions land with the bed that uses them.
- **R3 — No duplication.** Added to the SINGLE artifact-validator implementation every
  artifact-producing verb already calls, so `wl`, `cdp`, `vnc`, `libvirt` and `spice` get it at
  once. The test reuses the package's existing `writePNG` rather than adding a second helper.
- **R4 — No workarounds.** No retry loop around flaky OCR and no "best effort" swallow; a setup
  failure is an error, not a soft pass.
- **R6 — Git safety.** Branched from a fresh `origin/main`; no force-push, no hook bypass, no
  direct push to main.
- **R7 — Prove behavior, not compilation.** Full `go test ./...` pasted, plus a negative control
  that reproduces the exact misleading message the naive implementation produces.
