# 0.2026325.1511 — fix(build): a declared builder that cannot run is a hard failure, for every format

## Summary

Closes opencharly/sdk#608. A candy declaring packages for a builder whose plugin is not connected was **silently skipped**: the build exited 0 and the image shipped without them (measured on opencharly/layer-kde-shell: `aur: package: [kdotool]`, no `/usr/bin/kdotool`, green build, on arch and cachyos).

**Root cause.** `EmitBuilderStages` had `if !external { continue }` — `external` is true only when the builder's plugin is connected — and `CandyNeedsBuilder` decided "needs" from detect-files or detect-config, so a bare declaration could go unnoticed even with the plugin present.

**Fix, the default for every builder format:**
1. A builder that cannot run because its plugin is not connected is a hard error when any candy declares packages for that format, naming candy, format and reason.
2. A candy declaring packages for a format counts as needing that builder.
3. **The rule runs FIRST, ahead of every early return.** `if img.BuilderConfig == nil { return nil }` used to skip every candy before any check — the widest suppression of all. `requireDeclaredBuilders` now precedes it, and the loop's arm delegates to the same function (one rule, one place).
4. **The probe set is DECLARED formats, not configured ones.** A box configuring `pixi` while a candy declares `aur:` — or a non-nil-but-empty builder map — used to probe nothing; the union of declared and configured formats is now probed, so a declaration cannot hide behind configuration.

`external_builder:` already hard-failed; this closes the other plugin-facility path in the render.
