# 2026.206.1338 — K4 unit B: plugin-side candy/box selection wire contract

Core-min wave 3, K4 dispatch-kernel cutover (task #34), the sdk producer leg for the
"K4 unit B" slice: `charly bundle add`'s per-node COMPILE selection (the InstallPlan
compile seam, `#DeployCompileRequest`) moves from a host-computed BoxView+Order into
two additional plugin-resolved shapes.

- **`schema/seam.cue`** — `#DeployCompileRequest` gains `candy_ref`/`vm_entity`/`box_ref`,
  a discriminated set alongside the existing `box_view`/`order`:
  - `candy_ref`/`vm_entity` (K4 unit B candy-half): a standalone `target: local`/`vm`
    candy deploy — `candy/plugin-bundle`'s OpCompile handler resolves the candy topo
    order (`deploykit.ResolveCandyOrder` over its own resolved-project envelope) and
    builds its own synthetic host/vm box (`vmshared.DetectHostDistro`/`DetectHostGlibc`
    for a host target — already sdk-portable; the `kind:vm` provider's own `OpResolve`
    leg for a vm target) — no `LoadUnified`, no registry, no new HostBuild kind.
    `vm_entity` is threaded TOLERANTLY (a miss falls through to a plain host box,
    mirroring the pre-existing host-side lookup's own tolerance).
  - `box_ref` (K4 unit B box-half): a primary pod/k8s image deploy — the plugin reads
    `rp.Boxes[box_ref]` directly (the same `ResolvedBoxView` the host used to build the
    envelope in the first place) and resolves the candy order the same way.
  - Both shapes proved on a live disposable bed that the pre-existing
    `preresolveBuilderContexts` builder pre-pass (already unconditional for every
    `OpCompile`) already S2-lazy-connects any externalized builder the resolved
    order+img trigger — an exhaustive repo grep found no `target:local/vm` or
    `pod/k8s` deploy anywhere needing a builder plugin outside the calling project's
    own candy closure, so no new `HostBuild` kind was needed for builder-connect.
  - Regenerated via `task cue:gen`; `TestGenReproducible` passes.
- **`deploykit/graph.go`** — `PruneContainerInitForSystemd` relocated from charly core
  (a pure function of `order`+`HostContext.MachineVenue`, no core-only dependency),
  now shared by the host's unchanged box-view compile path and the plugin's
  candy/box-ref compile paths instead of being duplicated.
- **`deploykit/install_build.go`** — doc-comment fixes for two caller-specific
  references (`syntheticHostBox`/`syntheticVmBox`) that went stale once those
  functions moved to `candy/plugin-bundle/candy_select.go`.
