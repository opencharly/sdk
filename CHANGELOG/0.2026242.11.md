# 0.2026242.11 — fix(deploykit): skip a nil layer in GenerateInitFragments instead of panicking

## Summary

Fixes a nil-pointer panic in `deploykit.(*Generator).GenerateInitFragments` (and the two sibling candyOrder scans in `init.go`): a deploy's `candyOrder` can include an `add_candy` that the build's layers map does not carry (e.g. `check-agentteams-snapshot`'s `layer-agentteams-snapshot` add_candy during prepare-venue). The pre-fix code dereferenced the nil layer (`layer.Service()` / `layer.HasInit()`), panicking the out-of-process `plugin-deploy-pod` with a nil pointer and failing the bed's deploy-add.

The fix skips a candy absent from `g.Candies` in all three candyOrder scans — a candy with no layer contributes no services.
