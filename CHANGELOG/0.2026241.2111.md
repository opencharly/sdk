# 0.2026241.2111 — fix(loaderkit): fold namespace candies into the project candy scan

## Summary

Fixes the namespace-candy resolution inconsistency that blocks every image build from the charly main project: a namespace image (pulled via `resolveNamespacedBases`) composes its candies by BARE name, and those candies live in the namespace's own `UnifiedFile`. The project candy scan (`ProjectCandiesScanned`) only scanned the root project's `uf.Candy`, so the global candy order failed with `unknown candy` for every namespace image that composes a vendored candy — e.g. `distro-cachyos`'s `cachyos` base composing `cachyos-base-check` from its `candy/` discover.

**Fix:** fold the mounted namespaces' candies into the scan (root-wins, mirroring the materialize merge), recursing with each namespace's own `RootDir` to anchor its relative `from:` paths.

**Also:** bumps the spec pin `v0.2026241.931` → `v0.2026241.1322` — the sdk main references `container.InvalidateImageCache` (added in #186) which the pinned spec lacks, so the module did not build.
