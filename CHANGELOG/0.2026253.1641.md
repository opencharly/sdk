## Summary

The canonical entity-reference resolver (ResolveEntityRef) — the reference seam (plan/omarchy-acceptance-corpus.md M1). The load-time bed validator resolved a bed's from: cross-ref against the LOCAL PluginKinds/CheckBeds maps only, while the runtime entity resolver is namespace-aware via ProjectTemplates().ByKind. Two resolution surfaces over one data model diverged: a git-linked (namespace-qualified) from: was runtime-green by design but validate-red — the validator BLOCKED legal authoring.

This lands ONE canonical surface (R3):
- **loaderkit/resolve_entity_ref.go**: ResolveEntityRef(uf, kind, ref) — (a) a template entity, local or namespace-qualified (ProjectTemplates().ByKind, the existing fillNamespacedTemplates machinery); (b) a clone-base deploy-hop, a kind:check bed, local or namespace-qualified (the qualified ns.bed form only — the unqualified form stays local-only, matching the runtime template lookup's contract).
- **validate_check_beds.go**: the from: cross-ref check now uses ResolveEntityRef (the local-only PluginKinds lookup retired).
- **resolve_kind_entity_via_executor.go**: the not-found path shares the same surface.
- **resolve_entity_ref_test.go**: every ref shape — local template, namespace-qualified template, local bed hop, namespace-qualified bed hop, missing-red, empty, nil fold; plus the no-leak contract.

Effect: EVERYTHING in charly is referenceable — locally AND via git-linked imports (ns.entity) — validated once, resolved everywhere.
