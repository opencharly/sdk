# 0.2026320.1345 — chore(deps)!: declare spec v0.2026320.1252 (the stage contract)

## Summary

**The lockstep tag `sdk#547` asks for** — `spec v0.2026320.857 → v0.2026320.1252`, the stage contract.

**This is not a convenience bump.** `sdk v0.2026320.911` declared `spec v0.2026320.857`, while `plugin-pipeline`'s new body needs the stage vocabulary at `1252`. MVS resolved it, so the plugin built and its tests passed — but **no RELEASED sdk declared 1252**, and the consequence showed up where it mattered:

```console
$ charly/scripts/bootstrap-charly.sh --dev-plugin plugin-pipeline=<repo-checkout>
plugin-vm/…/vm_host_seams.go:132: cannot use … loaderkit.ApplyCueDefaults
  have (string, *spec.ResolvedVm)
  want (string, any, map[string]spec.KindGate)
```

A charly built with `--dev-plugin` is **the only way to grade a plugin's own change** — otherwise the binary welds the released copy and grades that instead (`opencharly/plugin-pipeline#70`). And that build pulls the current sdk against released plugins compiled for the old one, so the R10 proof for every plugin leg was blocked on a tag nobody had cut.

The chain, which this change breaks open:

```
a plugin leg's R10 proof
  └─ needs `--dev-plugin` to build
      └─ needs every released plugin to compile against the current sdk
          └─ needs an sdk that declares the spec its consumers use   ← this PR
```

The failure above was against released `plugin-vm` compiled for the old sdk; with this tag, the next build pulls a consistent set — but the proof is that build, not this test run, and it is the next step on `plugin-pipeline#69` rather than a claim made here.
