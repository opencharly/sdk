# 2026.217.0030 — the non-keyring encrypted-quadlet path is gone

Loading an encrypted volume's secret from anything other than the keyring has been unsupported for
a long time. `deploykit` still carried the machinery for it, and the machinery was actively harmful:
it was read as live behaviour and written into the documentation twice before anyone checked whether
the configuration it served still existed.

## What went

| File | Removed |
|---|---|
| `quadlet.go` | the `KeyringBackend` field; the `[Install]` branch emitting a comment instead of `WantedBy=default.target`; the `TimeoutStartSec` 0-vs-900 fork |
| `quadlet_pod.go` | the same `[Install]` branch — a second site the first sweep missed |
| `quadlet_test.go` | `TestQuadletWithEncryptedBindMountsNonKeyring`, which asserted the removed behaviour, plus the field setter |

## What it means now

Every quadlet carries `[Install] WantedBy=default.target` unconditionally, so systemd starts it at
boot. An encrypted deploy additionally gets `ExecStartPre=charly config mount` with
`TimeoutStartSec=0` — it starts at boot and waits for the keyring to unlock, with no deadline and
no second path.

That is a **behaviour change** for a configuration that was already unsupported: a deploy with
encrypted volumes and no keyring backend previously received no `[Install]` target at all and
therefore did not start at boot. It now starts and waits, in common with every other deploy.

## Coverage

Deleting `TestQuadletWithEncryptedBindMountsNonKeyring` is not a coverage loss — it existed only to
assert the branch this removes, and it was the *only* test that failed when the branch went, which
is the correct blast radius. `TestQuadletWithEncryptedBindMounts` continues to assert the surviving
keyring path including `TimeoutStartSec=0`.

## Consumer

`candy/plugin-deploy-pod` stopped computing and threading the flag in the same cutover
(`secretBackendIsKeyring()` and the `isKeyring` return value existed only to feed it). That half
lands in the charly repository, which picks this up by gitlink.
