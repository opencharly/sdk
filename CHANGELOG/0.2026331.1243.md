# 0.2026331.1243 — fix(deploykit)!: persist a bed member's from: cross-reference

## Summary

Persist a bed member's `from:` same-kind cross-reference when the check runner seeds the per-host deploy overlay, so the member survives the persist→load round-trip.

`deploykit.PersistBedDeployOverrides` built its `SaveDeployStateInput` from the bed node's image and target but never set `VmCrossRef`. A member declared `from: <vm>` has no image (`node.Image` is empty), so the written entry was `vm: {disposable: true}` with no source; the next load dropped it as a degraded entry, and the SDK save guard refused the following write:

```
refusing to write …/charly.yml — it holds 2 deploy entr(y|ies) but only 1 load
```

That is how `charly check run check-sidecar-pod` failed at `[config]` for its ephemeral-VM member `check-sidecar-pod-ephvm` (opencharly/charly#1299).

- `deploykit/bed_session.go` — set `VmCrossRef: node.From` in the `SaveDeployStateInput` at the one call site; `applyDeployState` already maps it onto `entry.From` (`deploykit/deploy_state.go:519-520`).
- `deploykit/bed_session_test.go` — the round-trip test: a `from: eval-vm` member saved through `PersistBedDeployOverrides` must still name its source on reload and must not be dropped as degraded.

Head `62d4ea83937b4f3a185d3f8d82832b71419c09f2`; two files changed (+129/−10).

### Spike

R12 candidates, each checked against the real code and real behaviour:

**(a) Set `VmCrossRef: node.From` at the call site — WORKS (winner, implemented).** A focused spike called `SaveDeployState` with `VmCrossRef: node.From` for a `{From:"eval-vm", Target:"vm", Disposable:true}` node; the written overlay was:

```
ephvm:
    vm:
        from: eval-vm
        disposable: true
```

The permanent test then proves the full `PersistBedDeployOverrides` round-trip (persist → reload → the member keeps its source and the next save is not refused).

**(b) Resolve the cross-ref inside `SaveDeployState` from the node itself — FAILS.** `SaveDeployState(boxName, instance string, input SaveDeployStateInput, marshalNode, read, ctx)` (`deploykit/deploy_state.go:464`) receives no node, so there is nothing to resolve from; handing it one is candidate (c)'s API change, and it would duplicate the semantic `SaveDeployStateInput.VmCrossRef` already owns — `applyDeployState` already writes `entry.From` from it.

**(c) Have the bed session pass the full node rather than its image — ALREADY TRUE, and not the defect.** `PersistBedDeployOverrides(ctx, name string, node DeployNode, …)` already receives the full node (`deploykit/bed_session.go:63`); the defect is the field mapping inside it (`Box: node.Image`, no `VmCrossRef`), not the parameter type. Making `SaveDeployState` take a node is (b) again.

Only (a) is implemented.
