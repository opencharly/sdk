# 0.2026320.911 — feat(deploykit)!: the alias and volume decode targets are the RESOLVED twins

## Summary

The **sdk leg** of `spec#337`'s resolved twins and `spec#338`'s reader contract. Closes **opencharly/sdk#545**.

```go
	AliasYAML  = spec.ResolvedCandyAlias
	VolumeYAML = spec.ResolvedCandyVolume
```

**This is the same one-line change that failed a round ago**, and the failure is worth quoting because it names the whole barrier:

```
*specCandyAdapter does not implement spec.CandyReader (wrong type for method Alias)
	have Alias() []AliasYAML
	want Alias() []spec.CandyAlias
```

The contract's own reader interface was naming the authored def, so no consumer could stop naming it either. With the interface on the twins (`spec#338`), the alias switch compiles.

**And the sweep the review demanded found two sites the alias change had NOT covered** — my first revision claimed sdk was clean without having run the command:

```console
$ grep -rn 'spec\.CandyAlias\|spec\.CandyVolume\|spec\.AliasYAML\|spec\.VolumeYAML' --include=*.go . | grep -v _test
./deploykit/resolved_project.go:125:  authored := make([]spec.CandyAlias, 0, len(als))
./vmshared/spec_aliases.go:29:         AliasYAML = spec.AliasYAML
./vmshared/spec_aliases.go:163:        VolumeYAML = spec.VolumeYAML
```

Both are fixed here: `CollectBoxAlias` already returns the resolved twin, so `resolved_project.go` now encodes it directly instead of converting through `spec.CandyAlias`; and `vmshared` carried a **second** alias set that was still pointing at the authored defs. After the fix, the same command returns one hit — a comment explaining why:

```console
$ grep -rn 'spec\.CandyAlias\|spec\.CandyVolume\|spec\.AliasYAML\|spec\.VolumeYAML' --include=*.go . | grep -v _test | wc -l
1   # ./deploykit/resolved_project.go:125 — a comment, not a reference
```

**`plugin-box` does NOT follow automatically, and my first revision said it did.** Its three `inspect_list.go` decodes spell `spec.CandyAlias`/`spec.CandyVolume` directly rather than through these aliases:

```console
$ git -C <plugin-box> grep -n 'spec\.CandyAlias\|spec\.CandyVolume' HEAD -- '*.go'
HEAD:candy/plugin-box/inspect_list.go:229:  rawbody.Decode[spec.CandyAlias](view.Aliases, "aliases")
HEAD:candy/plugin-box/inspect_list.go:368:  rawbody.Decode[spec.CandyVolume](rp.Candies[name].Volumes, "volumes")
HEAD:candy/plugin-box/inspect_list.go:378:  rawbody.Decode[spec.CandyAlias](rp.Candies[name].Aliases, "aliases")
```

So `plugin-box#85` is genuinely needed, exactly as the Filed-issues section says.

**Why the resolved twin is the right target.** A reader decodes a body that has **already been validated**: the plugin validates the authored shape, the host encodes it, the consumer decodes the resolved form. That is the three-way split `DESIGN.md` 3.1 + 10.2 require together, and the precedent is `spec/charly_names.go`'s `VmSpec = ResolvedVm`.

**What it unlocks.** In `sdk`, `#CandyAlias` and `#CandyVolume` now have **no production reader at all** (the sweep above). `plugin-box` still names them in three places, so the defs cannot move until `plugin-box#85` lands — but the sdk half of the barrier is gone, measured rather than asserted.

## Change classification

Kind: an SDK library change. It breaks nothing at the API level — the two alias names are unchanged; only what they alias moved.

**Breaking change + rollback:** `deploykit.AliasYAML`/`VolumeYAML` now denote the spec structs `ResolvedCandyAlias`/`ResolvedCandyVolume`, which are field-compatible but distinct types. A consumer comparing them to `spec.CandyAlias` would notice; none does. Rolling back reverts the pin and the two alias lines.
