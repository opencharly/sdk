# 2026.226.0913 — include plan-bearing pure-composition candies in the resolved order

The sdk half of the AgentTeams snapshot-tool cutover (main-repo Unit 3): a
pure-composition candy (one whose only body is a `candy:` composition list —
no env, ports, services, or install files) that carries a `plan:` or
`description:` was dropped from the resolved install order, so its spec never
baked into the `ai.opencharly.description` OCI label. ADE requires every
candy's plan to be runnable acceptance — a plan-bearing composing candy must
enter the closure even though it contributes nothing to the build.

- **`deploykit/graph.go`** (`ExpandCandy`): a composing candy now appears in
  the expanded result when it has content OR a spec (plan/description), not
  only when it has content. A content-free, spec-free composing candy remains
  a pure grouping node and is still omitted.
- **`deploykit/graph.go`** (`addTransitive`): the same predicate governs the
  transitive-closure membership, so a plan-bearing composing candy is marked
  needed (its spec bakes into the label) while contributing nothing to the
  build.
- **`deploykit/graph.go`** (`layerEntersOrder`): the shared 3-term predicate
  (`HasContent() || len(PlanSteps()) > 0 || GetDescription() != ""`) is
  extracted into one helper used by both sites (R3 — no duplicated logic).
- **`deploykit/graph_shim_relocated_test.go`** (`TestComposingCandyWithPlanEntersOrder`):
  a pure-composition candy with a plan enters the resolved order; a
  content-free, spec-free composing candy is still omitted.
