# 0.2026262.937 — refactor(loaderkit): delegate RepoOverrideDir to proc (R3)

## Summary of changes

Sibling of `opencharly/spec#139`, which moved the `CHARLY_REPO_OVERRIDE` parse to its canonical home (`spec/proc`, next to `RepoOverrideEnv`) and enforced it at the fetch LEAF (`spec/refs.DownloadRepo`).

`loaderkit.RepoOverrideDir` had its own copy of the parse. That copy was the ONLY enforced one at the time — which is exactly why the leaf consumers (`charly marketplace generate`, `charly docs generate`, pluginsgen) bypassed the override. The parse now lives once in `proc`; this loader-side seam **delegates** to it, so there is no second implementation to drift (R3) and the loader path stays on the single source.

Concrete edit (1 file, +6/−60): `loaderkit/refs_collect.go` — `RepoOverrideDir` becomes a delegation; the local `normalizeOverrideRepoPath` and the parse body are removed.
