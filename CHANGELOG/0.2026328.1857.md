# 0.2026328.1857 — fix(remove): delete the provides section a removal empties

## Summary

`charly remove` reported **"Removed env provides from <box>"** while the entry stayed in `~/.config/charly/charly.yml`. Measured on a live deployment: two consecutive `charly remove` runs each printed the removal, and `source: immich-cdi` survived both.

The mechanism: the cleaner empties the provides lists and sets `dc.Provides = nil`, but `SaveDeployConfig` wrote the `provides:` key only when `dc.Provides != nil`. A nil value therefore meant "nothing to write", and `provides` is a reserved key the deploy-key sweep never removes — so the deletion was unreachable by the writer.

The removal path now asks for the deletion explicitly (`PruneEmptyProvides`), and the writer removes the key with `perhost.Set(root, nil, "provides")` — whose nil value is its documented remove form. The option is variadic, so no other writer changes and an ordinary save still cannot silently drop a section.
