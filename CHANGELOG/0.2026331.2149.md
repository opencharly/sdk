# 0.2026331.2149 — fix(loaderkit): keep an import back-edge as an alias so a child's base: still resolves

## Summary

Fixes `opencharly/charly#1295`. The materialized wire (the project graph crossing the executor reverse
channel to an out-of-process plugin) **flattens** the namespace tree and, by design, **skips a
back-edge** — a namespace already on the current path — on the rationale that it "contributes nothing to
any finite walk, since `collectBeds` returns the instant it re-enters an ancestor".

That holds for bed enumeration. It does not hold for a box **base**:

```
distro-cachyos/charly.yml   - pod-whisper: '@github.com/opencharly/pod-whisper:v2026.331.0121'
pod-whisper/charly.yml      - cachyos: '@github.com/opencharly/distro-cachyos:v2026.330.1852'
pod-whisper/box/whisper     base: cachyos.cachyos
```

Inside distro-cachyos, `pod-whisper`'s `cachyos` alias IS the ancestor the loader already mounted. Across
the wire that alias vanished, so the reloaded child resolved `base: cachyos.cachyos` to nothing — and the
failure surfaced two stages later as `build: field required`, then `DistroDef == nil` at
`sdk/deploykit/candy_steps.go:53`.

**The fix.** The envelope now records a back-edge as a **reference** to the ancestor's path
(`ref: true`, `alias_of: "<path>"`, `""` = the root), and the rebuild re-attaches the **pointer** after
every real level is attached. Nothing is fabricated: the restored node is the same `*spec.UnifiedFile`, so
every guarded walk terminates exactly as before.

Two supporting changes, both in the same cutover:

- `captureNamespaceLevels` carries a `paths map[*spec.UnifiedFile]string` so a back-edge can name the
  ancestor's path;
- `attachNamespaceRef` / `namespaceAtPath` (new in `materialize_wire.go`) recreate the alias, and are run
  in a second pass so an alias may target another alias's target.

**The two cycle tests asserted the OLD truncation** (`len(got.Namespaces) == 0`). They now assert the
restored pointer, which is the stronger contract: a round-trip preserves the graph, and the cycle guard
in every walk is what keeps it safe (`namespace_walk.go`).

The test asserts the mechanism the renderer actually uses, not just pointer identity: after the
round-trip it resolves `cachyos.cachyos` as an INTERNAL box (`ResolveBoxRef`) and inherits
`build: [pac]` across it (`WalkBaseChainBuild`) — the empty answer being the filed defect.

### Spike

R12's round for this issue, and **two earlier conclusions on it were withdrawn before this PR** — the
record is on `charly#1295` and it is why the instrument here is a unit test:

| candidate instrument | result |
|---|---|
| `charly -C distro-cachyos box list boxes` (does `pod-whisper.cachyos.*` appear?) | **rejected**: `box inspect pod-whisper.whisper` cannot resolve the box `generate` DID resolve, so the listing does not report the namespace tree |
| `box inspect <qualified ref>` | **rejected**: same mismatch — "not found" for a box that resolves elsewhere |
| a hand-built `spec.Config` calling `ResolveBox(ref)` directly | **rejected**: the `BoxMap` body is an opaque decode (`DecodeBox` ignores unknown keys, so a malformed body silently yields a zero config) |
| **the materializer round-trip with the real two-way import shape** | **wins**: it fails exactly at the filed symptom when unpatched, and the same test passes with the fix |
