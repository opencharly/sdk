# 0.2026327.1226 — feat(candywalk): add a per-file RefScope seam to the remote walk

## Summary

`sdk/candywalk` gains a per-file ref seam, and keeps its full-closure contract:

- `type RefScope func(path, candyName string, ents []Entity, all []string) []string` — decides which `@github` refs ONE walked file contributes to the remote fix-point. `all` is exactly what `collectRefs` found; `ents` are the file's entities.
- `CollectEntitiesRemoteScoped(roots, resolve, scope)` — the same remote walk with that seam.

`CollectEntitiesRemote` is now `CollectEntitiesRemoteScoped(…, nil)` and is **behaviourally unchanged**: the scope is only consulted when non-nil, in the two places a walked file contributes refs — a repo root's `candy/<name>/charly.yml` (and `box/<name>/charly.yml`) and a fetched repo's root `charly.yml`. Every existing walk test (remote candy discovery, the progress line, skip-and-warn, files-only fetch) runs against that path and passes untouched.

**Why a seam and not a stricter walker.** The rule this unlocks — "follow a source's corpus manifests, never its fixtures" — is the CONSUMER's policy. This kit is shared and must stay kind-blind (sdk `AGENTS.md` boundary law): it hands the caller the file, the entities and the refs, and the caller decides. Other consumers of `CollectEntitiesRemote` (the loader's own scan) genuinely need the full closure, so tightening the walker itself would regress them. The alternative measured in the consumer repo — forking the walk — duplicates the fix-point, the cache contract and the skip-and-warn policy; this seam adds one comparison to the existing function instead (R2).

The test `TestCollectEntitiesRemoteScoped_NarrowsOneFile` fixtures a local tree with an owner candy (`require:` + `candy:` refs) and a non-owner box, applies an owner scope, and asserts the two owner refs are resolved and the box's ref is **not**. The same fixture returned unfiltered before the seam — the assertion fails without the change (R7).
