# 0.2026266.623 — feat(sdk): capability-driven start args, systemd-unit emitter, engine capability accessors

## Summary

The `sdk` leg of the **engine provider class** cutover (pins `spec v0.2026266.545`, the merged engine class). The engine becomes a provider whose capability facts drive the SDK, instead of switching on the engine name.

- **`deploykit/start_args.go`** — the engine-specific bits are **capability-driven** (`kit.EngineCapabilityFor`), not `if engine == "podman"`:
  - the CLI binary from `EngineBinary` (podman/docker/nerdctl);
  - GPU passthrough from `GPURunArgs` (CDI for podman, `--gpus` for docker/nerdctl);
  - **host↔pod uid-identical sharing**: when the engine has keep-id, use its own flag (`--userns=keep-id:uid=…,gid=…`); when it does NOT (rootless nerdctl), launch the workload as the engine's declared `WorkloadUser` (container-uid `0` == the invoking host user in the rootless userns).
- **`deploykit/start_args.go`** also gains **`BuildForegroundRunArgs`** — the same one argv body (`buildRunArgs`) with NO `-d`, for a generated unit's `ExecStart`. `BuildStartArgs` stays detached (`-d`) for direct-mode `charly start`. One body, two entry points.
- **`deploykit/systemd_unit.go` (+ test, new)** — the non-quadlet supervision-unit generator: a plain systemd **user** unit (`Type=simple`) wrapping the engine CLI **in the foreground** (`<engine> run --rm …`, no `-d`), so systemd supervises the CLI for the container's lifetime. nerdctl has no quadlet equivalent; podman keeps its native quadlet generator.
- **`kit/engine.go`** — re-exports `EngineCapabilityFor` / `EngineRunModeFor` / `IsUnitRunMode` so kit consumers stop switching on the engine name; no alias for the capability struct (consumers name the generated `spec.EngineCapability`).
- **`kit/exec_aliases.go`** + **`deploykit/kit_aliases.go`** — the **removed** per-engine jump arms (`JumpPodmanExec`/`JumpDockerExec`) are replaced by the ONE `JumpContainerExec` alias; the engine is DATA (`NestedJump.Engine`). `kit/infra_classify_test.go` migrates to `JumpContainerExec{Engine: "podman"}`.
- **`box_engine.go` / `deploy_file.go` / `loaderkit/scan_candy.go`** — `string(engine)` where the spec field is now the `#EngineName` string type. `go.mod` pins `spec v0.2026266.545`.

### Review round 2 fixes

- **Emitter determinism:** `GenerateSystemdUnit` ranged a Go map for `Environment=`, producing different units across runs — now **sorted keys**, pinned by `TestGenerateSystemdUnit_DeterministicEnvOrder` (20 re-renders byte-identical, sorted).
- **systemd specifier escaping:** a literal `%` was quoted but **not doubled**; systemd expands `%` even inside quotes, so it must be `%%`. `systemdQuote` now doubles `%` in every path (quoted or not), for argv AND Environment values — pinned by `TestGenerateSystemdUnit_EscapesSystemdSpecifier`.
- **Live-found: nerdctl rejects `-d --rm`.** Running the generated unit live surfaced `nerdctl 2.3.5: level=fatal msg="flags -d and --rm cannot be specified together"` (podman/docker accept both). `BuildStartArgs` now drops `--rm` for an engine whose new **`NoRemoveWithDetach`** capability is set (spec `v0.2026266.545`), and keeps `--rm` for podman/docker — `TestBuildStartArgs_NerdctlDropsRemoveWithDetach` pins both arms.
- **Live-found: the unit's argv must be FOREGROUND.** The unit is `Type=simple` with a foreground `run --rm …` contract (no `-d`), so systemd supervises the CLI for the container's lifetime. A detached `-d` argv would go inactive the instant the CLI returned (and is illegal with `--rm` on nerdctl).

## How tested

### The live proof of the nerdctl uid-sharing mechanism (block 2)

The `--user 0` mechanism is **not doc-read** — it was executed live against the host's rootless nerdctl 2.3.5:

```console
$ nerdctl info | grep -i rootless
  rootless

$ ls -ln nerdsharet/            # a host-created, mode-600 file, owned by host uid 1000
-rw------- 1 1000 1000 10 Sep 23 01:30 host-file

$ nerdctl run --rm --user 0:0 -v $PWD/nerdsharet:/data alpine \
    sh -c 'cat /data/host-file && echo pod-file > /data/pod-file && id -u'
host-file
0

$ ls -ln nerdsharet/            # the pod-created file is owned 1000:1000, NOT 100999
-rw------- 1 1000 1000 10 Sep 23 01:30 host-file
-rw-r--r-- 1 1000 1000 19 Sep 23 01:31 pod-file

$ echo host-edit >> nerdsharet/pod-file    # the host can edit a pod-created file
succeeded (tail: host-edit)

$ nerdctl run --rm --user 1000:1000 -v $PWD/nerdsharet:/data alpine \
    sh -c 'echo x > /data/wrong-uid-file'   # the OLD (uid-1000) path
sh: can't create /data/wrong-uid-file: Permission denied
```

This proves the mechanism the SDK encodes: rootless nerdctl has no keep-id, and container-uid `0` **is** the invoking host user, so `--user 0` gives exact bidirectional uid-identical sharing (host 600 files readable; pod files owned by the host user). The unit tests then pin the argv construction that reaches this state.
