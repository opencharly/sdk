# 0.2026326.2248 — feat(deploykit)!: the host refuses a builder reply that does not name its output

## Summary

The host half of the DESIGN-conformant incompatibility check. spec#424 (merged, `v0.2026326.2226`) made `#BuilderResolveReply.output` **required**; this PR makes the host act on it, so a builder plugin built against the older reply contract **fails at its first message, naming the field** — DESIGN §4.4's rule ("there is no version negotiation… a plugin built against a different protocol shape fails at its first message", D-PROTO-6), not a version counter.

- **`deploykit.ValidateBuilderResolveReply(word, reply)`** refuses:
  - an **empty `output`** — an old plugin's reply — naming the builder and saying to rebuild it against a current sdk (`opencharly/sdk#615`'s exact case: `plugin-builder-aur:v2026.271.2317` shipped a payload and no package, and nothing failed);
  - a **package output with no package**, a **files output with no copies**, an **inline output with no fragment** — the pair the discriminator promises;
  - an **unknown `output`**, against the closed vocabulary.
- **The render seam calls it immediately after decoding** the plugin's answer, so the refusal happens where the message arrives: no coercion, no fallback, no upgrade path.
- **`kit.BuilderResolve` stamps the discriminator** on every built-in reply (pixi/npm/mise → `files`, aur → `package`, cargo → `inline`), with the vocabulary exported from `kit` and used directly by both producer and checker — one definition, no duplicate block.
- **spec pin → `v0.2026326.2226`**, the release carrying the required field.

## How tested

Three tests, each failing without the change:

- **`TestValidateBuilderResolveReply`** — a table over every refusal (empty `output`, a package output with no package, a files output with no copies, an inline output with no fragment, an unknown value) and every acceptance, each case naming what it asserts.
- **`TestResolveBuilderStageRefusesAnOldStyleReply`** — drives the SEAM with exactly what `plugin-builder-aur:v2026.271.2317` answered (a stage and payload copies, no discriminator) and requires the refusal. Proven able to fail: with the validation call removed it reports *"the seam accepted a reply with no `output`: an old plugin would ship without its package again"*, then passes once restored.
- **`TestBuilderResolveStampsTheOutputPerBuilder`** — requires `package`/`files`/`inline` per built-in word, so a built-in that stopped stamping the discriminator cannot pass.
