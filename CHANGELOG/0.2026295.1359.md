# 0.2026295.1359 — fix(deploykit): select the workload user by launch mode

## Summary

`spec` `v0.2026295.1243` (`spec#266`) split `spec.EngineCapability.WorkloadUser`
into `WorkloadUserRootless` and `WorkloadUserRootful`. `deploykit` still read the
deleted field, so every consumer importing `sdk/deploykit` that bumps `spec`
failed to compile (`opencharly/charly#1023`, `opencharly/opencharly#589`).

This change:

- bumps `github.com/opencharly/spec` `v0.2026294.929` -> `v0.2026295.1243`;
- threads the launch mode (`rootful bool`) through `BuildStartArgs` /
  `BuildForegroundRunArgs` / `buildRunArgs`, and selects the capability fact with
  the canonical `container.WorkloadUserFor` (re-exported by `kit`);
- replaces the single-mode `TestBuildStartArgs_NerdctlSharesViaWorkloadUser`
  with `TestBuildStartArgs_ContainerdSelectsWorkloadUserByMode`, asserting both
  modes;
- moves the test engine word from the retired `nerdctl` to `containerd` (the
  binary is still `nerdctl`).

### Field choice at each of the two former read sites

Both former reads now consume ONE mode-selected value, so the guard and the
emitted flag cannot disagree.

| Site (head `5e2465a`) | Code | Fact |
|---|---|---|
| guard, `deploykit/start_args.go:103` | `case hasCapability && workloadUser != ""` | `WorkloadUserRootless` when `rootful == false`; `WorkloadUserRootful` when `rootful == true` |
| argv, `deploykit/start_args.go:106` | `args = append(args, "--user", workloadUser)` | the same mode-selected value |

`workloadUser := kit.WorkloadUserFor(capability, rootful)` (`start_args.go:98`).
Why: for rootless containerd (driven through the nerdctl CLI), container-uid 0
IS the invoking host user in the rootless userns, so the workload runs as `0` for
host-identical bind-mount sharing. For a rootful launch, uid 0 is host root and
`WorkloadUserRootful` is empty: forcing `--user 0` would run the workload as root
instead of the image's declared user. The old single field assumed rootless,
which is exactly the assumption `spec#266` removed.
