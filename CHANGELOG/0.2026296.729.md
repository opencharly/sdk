# 0.2026296.729 — fix(deploykit): stage a candy's project-root copy sources, so a carrier candy builds

## Summary

A carrier candy cannot build, and it takes its whole distro family with it. `copy:` sources resolve
inside the candy's own scratch stage, so `copy: .agents/skills` — the Agent-Skills tree, which lives
at the REPO ROOT (`opencharly/opencharly#557`) — reads a path the stage does not have, and the image
build dies outright:

```
#9 ERROR: failed to calculate checksum of ref ...: "/.agents/skills": not found
```

Measured on a clean clone of `opencharly/distro-ubuntu@1a55a5d`: `charly box build ubuntu` is red,
because `ubuntu` composes `ubuntu-skills`. The blast radius is not the install step — it is **every
Ubuntu-family container build**, and every box that declares a `distro:` tag, since that builds box
`ubuntu` as a dependency. `sdk#444` left the `copy:` base undecided; this decides it.

**The rule, and why it is measured rather than declared.** A `copy:` source that exists at the build
root and NOT inside the candy's own directory is root-relative, so `EmitScratchStages` stages it
into that candy's scratch stage with one extra `COPY <src>/ <src>/`. A candy-relative source — the
overwhelming majority — keeps exactly today's behaviour, so no existing candy changes meaning and no
new authored field appears. Remote candies are skipped: their files live in the materialized
`_candy/<name>.<ver>` dir whose own repo root is not present at generation time, and staging the
build root's tree there would substitute the wrong repository.

`golangci-lint` v2.13.2 is CI's arm and is not runnable on this host: the installed binary was built
with go1.27.3 and cannot decode this toolchain's export data (`export data version 5 is greater than
maximum supported version 4`). That is an environment mismatch, not a finding; CI runs the pinned
tool with its own toolchain.

**The changed path, executed end to end.** Before and after on the SAME project
(`opencharly/distro-ubuntu`, the carrier candy that reproduces the defect):

```console
# BEFORE — clean clone at 1a55a5d, released charly 2026.295.0418
$ charly box build ubuntu
--- Building ubuntu ---
#9 ERROR: failed to calculate checksum of ref ...: "/.agents/skills": not found
error: failed to solve: failed to compute cache key: "/.agents/skills": not found

# AFTER — charly rebuilt from this commit (charly version 2026.295.2309)
$ charly box generate ubuntu; echo gen-rc=$?
gen-rc=0
$ sed -n '5,7p' .build/ubuntu/Containerfile
FROM scratch AS ubuntu-skills
COPY candy/ubuntu-skills/ /
COPY .agents/skills/ .agents/skills/

$ charly box build ubuntu --tag 2026.295.3004
--- Building ubuntu ---
--- Building ubuntu-builder ---
$ podman images --format '{{.Repository}}:{{.Tag}}' | grep 'opencharly/ubuntu:'
ghcr.io/opencharly/ubuntu:2026.295.3004
```

The stage that used to die now produces the image. The build then continues past it to
`ubuntu-builder`, which bases on that tag and — on a host with no local mirror configured
(`CHARLY_BUILD_REGISTRY_MIRROR`) — fetches it from GHCR, where `opencharly/ubuntu` is not published.
That is the mirror's designed job (the drive owns the registry, `registry.go`), it is unrelated to
this change, and it reproduces on `main` with any carrier candy.
