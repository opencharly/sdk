# 0.2026255.2249 — fix(deploykit): bake plugins outside the package-owned plugin dir (unblocks charly#595)

## Summary

An image bake wrote its provider binaries into `/usr/lib/charly/plugins/**` — the directory the
**distro package owns**. When the same image later installs charly, the package transaction refuses
the file the bake had already created:

```
checking for file conflicts...
error: failed to commit transaction (conflicting files)
charly: /usr/lib/charly/plugins/plugin-mcp exists in filesystem
charly: /usr/lib/charly/plugins/plugin-mcp.providers exists in filesystem
```

That is **opencharly/charly#595**: `check-charly-selftest-pod`'s `image-build` dies there, which
leaves `distro-cachyos#82`'s selftest line with no passing gate.

**The collision cannot be cured by knowing WHICH plugins a package ships.** That set varies per
package build — the host package ships `plugin-{candy,clean,doctor,feature,preempt,secrets,settings,tmux,udev,vm}`
while the build that failed *also* shipped `plugin-mcp` — so any in-tree list is stale by
construction. The fix is therefore structural:

- baked plugins go to `/usr/local/lib/charly/plugins` — the FHS location for locally-installed
  software, which **no distro package owns**;
- the image registers that directory with `ENV CHARLY_PLUGIN_DIR=<dir>`, which charly's
  `bakedPluginDirs()` searches **first** — ahead of the FHS dir — so every baked plugin still
  resolves in the deployed container, and the package's own plugins stay reachable at the package path.

Two files: `deploykit/bake_plugins.go` (the emitter) and the new regression test.

## Rulebook compliance

- **R1 (root cause, not symptom):** the cause is an ownership error in the emitter — a build step
  writing into a package-owned path — not "the pacman step is flaky". The analysis also establishes
  *why* the obvious alternative fix is wrong (the package's plugin set is not a corpus constant).
- **R3 (no duplication):** the destination constants live beside the existing `bakedPluginDir`; the
  env-var name is documented as duplicated from charly's loader, which owns the search-order contract.
- **R4 (no workarounds):** no ordering hack, no `--overwrite`, no post-install repair — the write
  simply goes where it is allowed to go.
- **R5:** n/a (no legacy path removed; `bakedPluginDir` remains the package's own path, still read by
  `localpkg.go` and still searched by the loader).
- **R6:** `git status` before acting; branch work only; no force-push; the shared checkout was on
  another session's branch and this work was rebased `--onto origin/main` so it carries **only** these
  two files.
- **R7 (prove the gate):** `go build ./... && go test ./...` on the final tree, output in §3.
- **R8/R9 (emitted artifacts, binary equals source):** the emitted fragment was read back from a
  generated Containerfile (`§4`), and the generating binary was identity-checked with `strings`
  rather than assumed to contain the change.
