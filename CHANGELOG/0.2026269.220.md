## Summary of changes

- **`go.mod`/`go.sum`** — spec pin `v0.2026269.138 → v0.2026269.212`, the tag
  carrying the `SshVenue`/`IsVmVenue` split.
- **`deploykit/deploy_members_test.go`** — the vm fixture now stamps
  `ExclusiveVenue: true` (the host-lease trait the traits table declares for `vm`),
  and a new `kubevirtNode()` (ssh venue, no `ExclusiveVenue`) pins the split:
  `IsVmVenue` must be false for it, so `BringUpMembers`/`TearDownMembers` route a
  kubevirt member to `charly deploy add`/`del` (the plugin-kubevirt lifecycle arm),
  NOT `charly vm create`/`vm destroy`.
- **`kit/vm_domain_lock_test.go`** — the `BedVmDomains` fixture stamps
  `ExclusiveVenue` (it models a libvirt vm).

No production-code change: `BringUpMembers` already routes a
non-`IsVmVenue`/non-`IsContainerVenue` member to the `deploy add` default arm, which
is exactly correct for kubevirt. The pin bump is what makes a kubevirt member stop
matching the libvirt arm.
