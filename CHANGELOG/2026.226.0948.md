# 2026.226.0948 — privileged-run disk-space pre-flight + streaming output copy

The privileged-container exec primitive (`buildkit.RunPrivileged`) now fails
fast with a clear error when the output cannot fit on disk, instead of the
container dying cryptically mid-write with `gzip: stdout: No space left on
device`. This is the product fix for the bed failures surfaced during the
sdk-adopt cutover: the staging dir lands on the root fs (via `$TMPDIR`), and a
full disk used to surface only as an in-container ENOSPC with no indication of
where the space was needed or how much.

- **`PrivilegedRun.MinFreeBytes`** (new field): when > 0, `RunPrivileged`
  statfs's BOTH the staging directory (where the container writes the output)
  and the OutputDest directory (where the output is copied) and fails with an
  actionable error naming the directory, the free space, and the required
  space. Callers that know their output size MUST set it.
- **`buildkit.RootfsOutputFloor`** (new const, 4 GiB): the shared floor for a
  privileged rootfs build (a gzipped rootfs tarball is typically 1-3 GiB),
  set by the OCI-image bootstrap (`candy/plugin-build`) and the VM-bootstrap
  engine (`candy/plugin-vm`) — one floor, R3.
- **`CopyFileBytes` now streams** (`io.Copy`) instead of `os.ReadFile` +
  `os.WriteFile`: the privileged outputs can be multi-GiB (a VM disk qcow2, a
  rootfs tarball), and the former approach allocated the full file size in RAM
  — an OOM risk for a 20G+ disk.

Tests: `TestCheckFreeSpace` (zero-min no-op, small-min passes, impossible-min
fails with the actionable error) + the existing `TestCopyFileBytes` round-trip
covers the streaming rewrite's contract — all fail without the change.

R10: the sdk suite (`go build ./...`, `go test ./...`, `go vet ./...`) is green
at zero warnings; the runtime happy path is proven by the main-repo check beds
in the sdk-adopt cutover (the VM-bootstrap + image-bootstrap privileged builds
run with the space check active and pass on a healthy disk).
