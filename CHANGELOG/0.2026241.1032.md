# 0.2026241.1032 — feat(ledger): the install ledger lives in the `ledger:` section of the per-host charly.yml

## Summary

The per-host charly.yml (`~/.config/charly/charly.yml`) is the SINGLE home for local system state — deployments (`deploy:`), install records (`ledger:`), local system info (`system:`), and cache status (`cache:`). The install ledger moves HERE, out of the per-deploy JSON files under `~/.config/opencharly/installed/` (`deploys/<id>.json` + `layers/<candy>.json`).

- **`kit/install_ledger.go`**: `LedgerPaths` is now `{ConfigFile, LockFile}` — the per-host charly.yml + its advisory lock. The legacy `Root`/`Deploys`/`Candies` fields are DROPPED: a stale consumer (plugin-fleet, plugin-substrate) fails to COMPILE loudly against this shape — never a silent wrong answer (the previous deprecated stubs left the legacy fields at zero value, so `os.Stat("")` → ENOENT → "no local deploys" with a nil error). The consumers migrate to `ConfigFile` in the same wave (their PRs land with the new sdk pin). Every I/O function (`Write/Read/DeleteDeployRecord`, `Write/Read/DeleteCandyRecord`, `Add/RemoveCandyDeployment`) reads/writes the `ledger:` section via a lightweight YAML read-modify-write that preserves every other key (`deploy:`, `provides:`, `cache:`, `system:`), under the advisory file lock. The executor-routed variants (`AddCandyDeploymentVia`, `WriteDeployRecordVia`) do the same on the substrate's charly.yml via `exec.GetFile`/`exec.RunUser` — reading the `ledger:` section's candies map, updating the specific candy, and writing back (regression: the first cutover unmarshaled the WHOLE charly.yml into a CandyRecord, producing empty `candy`/`deployed_at` and failing egress validation on every nested deploy — caught live by the bed, fixed in-tree).
- **`deploykit/deploy_file.go`**: `SaveFleetConfig` now PRESERVES the existing `cache`/`ledger`/`system` sections — it starts from the current file's root and updates only `version`/`provides`/`deploy`, instead of rebuilding the file from scratch (which would clobber the GitClient's cache and the ledger).
- **`kit/migrate_helpers.go`**: one shared `SetMappingKey` helper (R3 — the section-preserving writers use it instead of hand-rolling).

The `ledger:` shape is CUE-sourced (spec#66 `schema/ledger.cue` `#LedgerConfig`).
