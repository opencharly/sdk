### Part 1 — the lowering bugfix (commits `05bf57c`, `516f7f6`)

Two defects in `workflowkit`'s IR→lobster lowering, both found by running the lowered output rather than reading it. `plan:` is **deleted** from the lobster step at lowering, so everything the *engine* must know about a charly step has to be copied onto the step itself — and one thing was not being copied, while the ref form that *was* written could not be expanded.

**Fix 1 — the ref must be written in brace form.** `rewritePlanRefs` rewrote `$step.path` to `$REF_<n>`. The expander that runs a generated plan (`kit.ExpandOpVars`, whose grammar is `kit.TestVarRefPattern`) is **brace-only**, so the bare form is passed through to a non-shell verb input as literal text — e.g. a plugin verb's opaque field would receive the four characters `$REF_1` instead of the value. The fix emits `${REF_<n>}`. This is not cosmetic: the whole point of lowering a charly step to `charly task` is that *the plugin verb* sees the resolved value.

**Fix 2 — the redo spec must reach the step.** The `redo` spec has two readers. The **verb** reads `redo.on_fail` to choose the trigger it emits, and that path was already correct. The **engine** reads `triggers` / `max` / `escalate_after` off the **step** — and since `plan:` is deleted at lowering, a migrated `redo` that lives inside the verb body was invisible to the engine, which therefore had nothing to rewind on. `carryStepRedo` copies it onto the step. It is deliberately:

- **guarded** — an already-present step `redo` wins, so a second `Lower` is a no-op and cannot duplicate the key;
- **defensive** — any shape mismatch, or no `redo` child at all, emits **nothing**; it never writes an empty `redo:`, which would be both noise and a behaviour change (pinned by `TestLowerNoRedoEmitsNoKey`);
- **cloning, not sharing** — the node is cloned so it is never inserted twice into the same YAML tree.

The lowered plan element's shape is **not** what this commit originally assumed — it was taken to be a one-pair `{<verbKey>: <verbBody>}` map, which is only the description-free case. The final verdict caught that, and **Part 5** replaces the positional lookup with a keyed one and pins both shapes; read the two together.

### Part 4 — the input gate's key, found while authoring the consumer's bed (commit `2a12585`)

Found by *authoring plugin-lobster's R10 bed* (`check-lobster-local`), not by reading this diff: that bed's `lobster-input-resume` step could not be written at all, because an input gate authored in the pipeline grammar never reaches the engine.

The input gate's schema is the **one** key whose spelling differs between the two forms:

| form | spelling | source |
|---|---|---|
| the authored pipeline | `response_schema` | `spec/schema/pipeline.cue` `#PipelineInput` → generated Go `yaml:"response_schema"` |

`mapLobsterInputKey` renames that one key on the lobster side as each step lowers — every step, nested `parallel.branches[]` / `for_each.steps[]` included, since `lowerStep` visits each one. ### Part 5 — the redo's verb body, found by key instead of position (commit `ed662d7`)

The final `BLOCK` (on `#339`'s head `23441f7`) raised two findings; this one commit cures both.

**Finding 1 (B5 / rule 4) — `carryStepRedo` looked for the verb body in the wrong place, and its own golden proved it.** Part 1's helper took the element positionally:

```go
el := plan.Content[0]
if el == nil || el.Kind != yaml.MappingNode || len(el.Content) != 2 {
	return
}
body := el.Content[1]
```

That is right **only** for a description-free plan step. A plan step authored with a description — the ordinary case — marshals from `spec.Step` as a **two-pair** element, because `spec.Step` emits its intent keyword (`run:`) **before** the inline `Op`:

```yaml
- run: rewind the oracle     # ← el.Content[1] is THIS scalar
  task:
    redo: {…}               # ← the redo lives HERE, in the verb body
    task: oracle
```

The `len(el.Content) != 2` guard did not stop it (the element genuinely has two pairs), so `el.Content[1]` was the `run` **scalar**, `body.Kind != yaml.MappingNode` held, and the function **returned early** — the redo was never copied onto the lobster step. That is exactly the engine-invisible failure the helper exists to prevent, and it recurred for every described step. The fixture had omitted `Run`, so the shape was never exercised: **the test was measuring the one shape that worked.**

The fix replaces the positional lookup with a keyed one, and states the invariant the old code never had:

```go
// stepIntentKeys are the plan-element keys that carry the step's INTENT DESCRIPTION (a
// scalar) rather than a verb body — derived from spec's own exported discriminator
// constants so the vocabulary is never duplicated here.
var stepIntentKeys = map[string]bool{
	string(spec.KwRun): true, string(spec.KwCheck): true,
	string(spec.KwAgentRun): true, string(spec.KwAgentCheck): true, string(spec.KwInclude): true,
}

// verbBody returns a lowered plan element's VERB BODY — the mapping that carries the step's
// verb input, and with it any `redo:` spec — or nil when the element has none.
// …
// The second shape is the ordinary authored one (spec.Step marshals its intent keyword
// BEFORE the inline Op, so a described step emits `run:` first), and there Content[1] is the
// `run` SCALAR — so a positional lookup finds a non-mapping, returns early, and silently
// drops the redo: exactly the engine-invisible failure this helper exists to prevent. Every
// intent keyword is skipped; the first remaining pair whose value is a MAPPING is the verb
// body (a verb's input is an object — the scalar shorthand belongs to a single-primary input,
// which cannot carry a `redo` child at all).
func verbBody(el *yaml.Node) *yaml.Node {
	if el == nil || el.Kind != yaml.MappingNode {
		return nil
	}
	for i := 0; i+1 < len(el.Content); i += 2 {
		if stepIntentKeys[el.Content[i].Value] {
			continue
		}
		if v := el.Content[i+1]; v.Kind == yaml.MappingNode {
			return v
		}
	}
	return nil
}
```

Two facts make the scan sound rather than a guess, and both are checked against the code rather than assumed: **a verb's input is always an object** (the scalar shorthand belongs to a single-primary input, which cannot carry a `redo` child), and **`ResugarPlan` emits the sugar key at the `plugin` field's position** — ahead of every *mapping-valued* modifier (`env`, `stdout`, `stderr`), and after no other mapping-valued field — so the first non-intent mapping in document order is the verb body in both shapes. The vocabulary is not restated: the intent keys come from `spec`'s own exported `Kw*` constants.
