# 0.2026331.837 — feat(sdk)!: follow the spec module's Android removal

## Summary

Advance `github.com/opencharly/spec` to **v0.2026331.808** — the tag carrying
opencharly/spec#446, which deletes the Android contract surface from the spec module — and
remove the SDK machinery that existed only to serve it. This is the sdk leg of the approved
org-wide Android retirement (umbrella issue opencharly/opencharly#1318); spec#446 is merged and
tagged, and this PR consumes it. Nothing here is Android-only *policy*: the SDK is a
kind-blind mechanism library, so the removal is confined to the aliases, step kind, validators
and resolvers that named the removed spec types.

**The compiler was the inventory, not a grep.** `go build ./...` / `go vet ./...` were iterated
until clean, so nothing was removed by pattern-matching. The removals, by package:

- **`vmshared`** — drop the `AndroidSpec`, `ApkPackageSpec`, `AndroidAdbEndpoint`,
  `AndroidGoogleAccount` aliases (`spec.AndroidSpec`, `spec.ApkPackageSpec`, `spec.AdbEndpoint`,
  `spec.GoogleAccount` are gone from the contract).
- **`kit`** — delete `apk_path.go` + `apk_path_test.go` (`checkhost.ResolveApkPath` /
  `ResolveCommittedApk`, the committed-APK resolver, are gone) and the `"ApkInstall"` arm of
  `WalkPlans`.
- **`deploykit`** — drop the `ApkPackageSpec` / `ApkInstallStep` / `StepKindApkInstall` aliases,
  `CompileApkStep` and its `BuildDeployPlan` arm, `specCandyAdapter.Apk()`, and
  `apk_format_test.go`; remove `android` from `substrateNodeOrder` and `deployCrossRefKeys`.
- **`loaderkit`** — drop the `ValidateAndroidDevices` validator and its `LoaderSeams` field and
  `LoaderExecutor` method, `ResolveAndroidViaExecutor`, `ResolveAndroidEntityViaExecutor`, the
  `"android"` `cueKindDefs` row, the `m.Apk` scan field, and the `Apk` term of
  `HasInstallFiles`.
- **R5 sweep** — the remaining `android`/`appium`-named prose and fixtures are retargeted to a
  generic word (`layer-example-sdk`, `example`, `parentvenue` for the generic `parent` venue,
  `cdp` for the generic artifact/verb examples); `newLoaderTestCandy` loses its now-unused
  `spec.CandyModel` parameter (its only non-empty caller was the deleted APK test).

**Two deploykit staging tests were aligned with the tag they now consume.** v0.2026331.808 also
ships opencharly/spec#445 (spec CHANGELOG 0.2026330.2134), which makes `CandyStageDirName`
content-addressed (`<name>.<sha256[:16]>`) instead of version-keyed. `TestCandyCopySource_ImportedNamespaceOrigin`
and `TestBuildStageContext_ImportedNamespaceCopySource` asserted the old `<name>.<version>` suffix;
they now assert the staged prefix, since their subject is the origin decision (staged vs
project-relative) and the suffix derivation is pinned by the spec module's own tests.

Kept deliberately generic: the `kvm`/`display` console surface, the `parent` venue, every other
substrate (`pod`, `vm`, `local`, `kubernetes`, `agent`), and the **Alpine `apk` package format**
(`packagekit`/nfpm, the `pac/apt/apk` pin form, `add-apk`) — a different concept from the Android
APK, which spec kept.

### Spike

The R12 round here answers one question: *how do you find every SDK site the removed spec surface
breaks, without removing the Alpine `apk` package format that shares the word?*

- **Candidate A — grep-driven inventory.** Rejected. `git grep -niE '\bapk\b'` returns 60 hits,
  and the majority are the Alpine package FORM (nfpm's `info.APK`, `packagekit`, the
  `pac/apt/apk` pin form, `add-apk`); a pattern sweep would have deleted working package-manager
  code alongside the Android app-install surface.
- **Candidate B — compiler-driven enumeration (the winner, implemented here).** Advance the pin,
  then `go build ./...` and `go vet ./...` repeatedly, fixing exactly what the compiler names.
  The observed progression, pasted from the runs:

## Change classification

- **Change type:** hard cutover of a consumer library, following a merged producer contract
  (`opencharly/spec` v0.2026331.808).
- **Breaking change + rollback:** **Breaking.** The exported Android/APK API in `sdk` disappears
  with the spec substrate it aliased: `vmshared.AndroidSpec`, `vmshared.ApkPackageSpec`,
  `vmshared.AndroidAdbEndpoint`, `vmshared.AndroidGoogleAccount`, `deploykit.ApkPackageSpec`,
  `deploykit.ApkInstallStep`, `deploykit.StepKindApkInstall`, `deploykit.CompileApkStep`,
  `kit.ResolveApkPath`, `kit.ResolveCommittedApk`, `loaderkit.ValidateAndroidDevices`,
  `loaderkit.ResolveAndroidViaExecutor`, `loaderkit.ResolveAndroidEntityViaExecutor`, the
  `ApkInstall` step kind, and the `apk:` app-install field on a candy. Any out-of-tree consumer
  that referenced those will no longer compile against this version — which is the point of the
  retirement (opencharly/opencharly#1318). **Rollback:** revert this commit and re-pin
  `github.com/opencharly/spec` to the prior `v0.2026328.1115`; the Android surface returns with
  the older contract.
