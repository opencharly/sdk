# 0.2026288.1718 — fix(candywalk): a one-character version is not a version — the prose placeholder truncates, it does not reject

## Summary

`#405`'s fix was correct and incomplete. Excluding `<` and `>` from `remoteRefRe` removed the placeholder shape it was written for — but it **truncates a placeholder rather than rejecting it**, and that is not the same thing:

```
$ charly marketplace drift --root <marketplace> --out <marketplace>    # with #406 in effect
drift rc=1
collect entities: resolve @github.com/opencharly/layer-omarchy-base/candy/omarchy-base:v:
  could not resolve ref "v" in https://github.com/opencharly/layer-omarchy-base.git
```

In this sibling shape the placeholder sits in the **version** and the repo path is real, so the match stops just before `<` and survives as a one-character version `v` — which then reaches the resolver as a ref that cannot exist. The failure moved one step later; it did not go away.

**The fix is the same idea applied to the version: a one-character version is not a version.**

```go
var remoteRefRe = regexp.MustCompile(`@github\.com/opencharly/[^\s'"\],}#:<>]+:[^\s'"\],}#<>]{2,}`)
```

Every real version is at least two characters — a CalVer tag (`v2026.288.1404`), a branch (`main`, `feat/x`), a SHA — while a truncated placeholder leaves exactly one. The repo-path half is untouched: it is legitimately long, and it is the *version* that carries the placeholder's stub.

## How tested

Proven by running it both ways, and the negative arm reproduces the production token character for character:

```
1. with the fix        → ok
2. `{2,}` reverted     → --- FAIL: TestCollectRefs_IgnoresATruncatedPlaceholderVersion
                         collectRefs returned "@github.com/opencharly/layer-omarchy-base/candy/omarchy-base:v"
                         — a truncated placeholder version reached the resolver
3. restored, full arm  → go build rc=0 · go test rc=0 (19 packages ok) · gofmt clean · go vet rc=0
                         golangci-lint 0 issues · cross-compile amd64 / arm64 / arm / 386: all ok
```

The test pins **both** directions, which matters for a tightening of this kind: no placeholder may be returned, *and* the real ref on the line beside it must still come through — otherwise a pattern that rejected everything would look like a pass.
