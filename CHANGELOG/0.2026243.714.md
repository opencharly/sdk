# 0.2026243.714 — feat(loaderkit): route scan advisories through an injectable sink

## Summary

`PickCandyVersion` wrote its skew advisory straight to stderr, and the local-shadow note in
`ScanCandyFromLocal` did the same:

```go
fmt.Fprintf(os.Stderr,
    "Warning: candy %s resolved to multiple versions; using newest %s (from %s), ignoring %s (from %s)\n", …)
```

That made both advisories unstructured and therefore **uncountable**: `charly box validate`
could not report how many warnings a run produced, because they never reached its diagnostics.
A draft of that summary printed `0 warnings` on a run that had just emitted two.

Both now route through a sink supplied via `spec.ScanSeams.Warn`.

### The sink is REQUIRED — no compatibility shim

The first version of this branch kept a two-argument `PickCandyVersion` delegating to a
`PickCandyVersionWith` variant, so existing callers compiled unchanged. **That was wrong and
is gone.** It is precisely the shim R5 forbids — *"hard cutovers remove old names, paths,
shims, adapters, aliases"* — and what *"Prioritize Clean Architecture Above All Else"* rules
out: compatibility convenience never justifies weakening the target architecture.

There is now ONE arbiter with a required sink. Passing `nil` selects stderr **explicitly**
rather than by omission, so every caller states where its advisories go. The sole external
consumer, `plugin-loader`, is cut over in the same sweep (opencharly/plugin-loader#4) rather
than carried by a shim.

## How tested

With a `replace` pointing at the spec branch — the only way this compiles until spec#85 tags,
per the ordering section above:

```
$ go mod edit -replace github.com/opencharly/spec=../spec-branch
$ go build ./... && go test ./loaderkit/...
ok  	github.com/opencharly/sdk/loaderkit	0.014s
$ go mod edit -dropreplace github.com/opencharly/spec   # committed go.mod has no replace
```

Three guards, each pinning something a counted total depends on:

- the advisory **reaches an injected sink** as data, and the arbiter still returns the newest
  per-entity version
- **agreeing versions produce NO advisory**, so a count cannot overstate
- a `nil` sink still arbitrates correctly, since nil now means "stderr, explicitly"

**Negative control** — suppressing the advisory emission:

```
--- FAIL: TestPickCandyVersionWithRoutesAdvisoryToSink
    candy_version_warn_test.go:29: expected exactly one advisory, got 0
```

**End to end**, with charly built against this branch plus the rest of the chain:

```
$ charly box validate
charly box validate: OK — checked 489 candies, 38 boxes, 29 deploys, 7 distros, 7 builders; 3 warnings, 0 errors
```

Three warnings — two skew, one shadow note — now counted instead of lost to stderr.

Built against the matching `spec` branch via a local `replace`, dropped before committing:
the committed `go.mod` is unchanged.
