**Why llmkit.** Two consumers need to speak an OpenAI-compatible endpoint: the
pipeline engine's agent stages and the new `vision:` check verb
(`candy/plugin-vision`), which validates a screenshot by sending it to the same
endpoint. A kind-blind, reusable endpoint client consumed by >1 plugin is an SDK
kit (the boundary law).

The SDK owns the wire format, the SSE decoder, the chunk accumulator, tool-call
assembly and the typed params; llmkit owns what it does not:

- the **IDLE bound** — a per-chunk watchdog that CANCELS the request, not a
  whole-generation deadline, so a slow-but-progressing model is never cut off
  while a silent provider fails in bounded time;
- ollama's **non-standard `reasoning` delta**, which the SDK accumulator drops,
  read per-chunk from the raw JSON and **surfaced on `Message.Reasoning`** (so
  the read is observable, and a reasoning-only 200 is reported as a NAMED empty
  completion rather than a bare one);
- the **empty-completion guard** (a 200 with neither content nor tool calls is an
  ERROR, never a silent empty turn);
- the **no-env-bleed guarantee**: the client is `NewChatCompletionService` with
  the given options ONLY — never `NewClient`, which prepends the `OPENAI_*`-reading
  defaults and would let a stray operator env hijack a call;
- **vision**: `ImageDataURL` / `VisionParts` / `ChatVision`.

Config resolves field-wise (`Default() → Apply(#LLMSpec) → FromEnv()`), with
`params`/`headers`/`extra` MERGING — the same precedence the pipeline documents.

### The `spec` bump and the deploykit test (exactly what is in the diff)

`go.mod` moves `github.com/opencharly/spec` from the base's `v0.2026257.1817` to
`v0.2026259.2033` (the tag this branch's own producer PR created), and adds
`github.com/openai/openai-go/v3 v3.61.0`.

That bump brings spec #135's `FindVMClaimant` signature change. **The call-site
updates already landed on `main`** (main's `deploykit/preempt_resolve_test.go`
carries the 3-arg calls and its alias doc names `claimantID`), so this branch's
diff against main is ONLY the appended
`TestFindVMClaimant_IdentityScoped` — the coverage for the behaviour the new
argument exists for: a GPU-free sibling sharing a VM entity must NOT inherit the
owner's exclusive claim. (Earlier revisions of this branch also carried the
call-site edits; the merge with main superseded them. This summary accounts for
the diff as it now stands.)

### The R3 companion (this is not a second implementation)

`llmkit` is the canonical client; the pipeline's plugin-local copy is REMOVED by
the named companion PR **opencharly/plugin-pipeline (branch
`refactor/consume-llmkit`) — "refactor: consume the shared llmkit client"**,
landed after this tag so it can pin it. That companion deletes
`candy/plugin-pipeline/llm.go` (the `chat`/config/union-map copy), keeps the
engine's turn loop + typed-output decoder, rewires them onto `llmkit.Chat`
(preserving the RCA'd idle bound, empty-completion guard and per-lane precedence
by passing the resolved `llmkit.Config`), and drops the plugin's now-unused
`openai-go` direct dep. So this PR ADDS the one canonical client and the
companion REMOVES the duplicate; neither leaves two live clients behind.

### Why a bed is inapplicable for THIS change class, and what stands in for it

no deployment to `charly update`, and no check bed that consumes it yet — the

applicable gate is the package's own suite executed against the REAL endpoint —
