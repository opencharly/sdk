# 0.2026326.342 — feat(builders)!: one mechanism for every build-time manager — aur behaves exactly like npm

## Summary

The sdk half of the unified builder mechanism (opencharly/sdk#608, Unit 1). Before, aur, npm, pixi, cargo and mise did one job spread over five surfaces, and aur took a different road on every one. Each road had a silent skip. `kdotool`, declared under `aur:` in layer-kde-shell, never reached any image while the build stayed green (opencharly/layer-kde-shell#7). Now every builder goes through one trigger, one fail-loud pre-pass, one install contract and one IR. aur behaves exactly like npm.

Closes #608. Closes #610: the #609 regression is superseded, because the tag-scoped trigger below keeps an arch-tagged declaration off non-arch boxes.

Consumes opencharly/spec#420, merged and tagged `v0.2026326.323`, which `go.mod` now requires.

**One trigger.** `NeedsBuilder(candy, image, builder)` fires on a detect file, or on a manager declaration the image's tag chain selects. `ResolveManagerPackages` reads it over the same `CascadeTagChain` the OS packages resolve over.
- The loader records `distro.<tag>.aur` on its own tag section. It used to merge every tag into one image-independent section, so an arch-tagged declaration no longer reaches a fedora image.
- There is no box `build:` opt-in.
- Stage emit, artifact emit, runtime env, plugin detection (`DetectExternalizedBuilders`) and the apply compile all call this one function.

**One fail-loud pre-pass.** `requireBuilders` runs first in `EmitBuilderStages`, over the builder vocabulary, not a hard-coded list. A needed builder with no definition, no vocabulary, no plugin, or no route to a builder box is a build error naming the candy and the builder. It replaces #609's `requireDeclaredBuilders`.

**One install contract, owned by the builder plugin** (DESIGN.cue `#BuilderAlt` under D-PLUG-2, D-IR-7, P3; the operator chose plugin-owned on #608). What a builder installs is the plugin's own knowledge, never the authored builder node.
- `kit` defines every stage builder's payload (`builderPayloadCopies`): pixi, npm and mise copy the stage home, and aur copies its extracted package tree. A stage word with no payload is an error.
- aur declares its package output in its replies (`BuilderResolveReply.Package`, `BuilderCollectReply.Package`, via `kit.BuilderPackageOutput`).
- On an image whose distro serves that format through `local_pkg`, pacman installs the candy's packages from the candy's own directory (`/tmp/aur-pkgs/<candy>`). There is no shared directory, so no double install.
- On any other image the payload is copied in, like npm's.
- The secondary-format loop and its swallowed render errors are deleted.

**One IR for both modes (D-IR-1).** `compileBuilderSteps` uses the same trigger and carries the plugin-declared package output onto `BuilderStep.Package`, never `bName == "aur"`.
- Its directory and glob come from that declaration, and the `find /` backstop is deleted.
- A host venue that cannot install a package output refuses the step (`RunVenueBuilderStep`). An image build copies the payload instead, so the shared compile no longer fails a fedora pod overlay.
- The pod overlay and the box build share one package-install render (`RenderBuilderPackageInstall`).
- `NeededBuilderImages` lists exactly the builder images the stages name, so the overlay ensures them first.

**Teardown parity (D-IR-2).** The collect input carries the candy's detected manifest. npm records its dependencies, cargo its package name, and mise its tools plus the copied manifest. Before, nothing filled npm's or cargo's teardown set. An unknown builder word or an unparseable manifest is an error.

**No swallowed errors, one dispatch (R2).**
- The `manylinux_fix` render error, a missing cached stage reply, and an `external_builder` stage that copies nothing now fail.
- `HasInstallFiles` counts mise manifests and manager declarations.
- `BuilderCollectInputFor` is the one constructor of the collect input.
- `sdk.InvokeBuilder` is the one Invoke dispatch every builder plugin serves. The four byte-identical plugin-builder-* copies and plugin-mise's three helpers become one call each.

**Cache.** The materialized-tree cache key's doc names the embedded-defaults digest among its inputs (spec#420 carries the field, charly's walk stamps it). `TestLoadedProjectCacheKeyCoversTheEmbeddedDefaults` fails if the key narrows to the documents.

**Also:**
- The intermediate format/tag union test modelled `build: [pac, aur]`, a box the schema now refuses. It now models a schema-valid box, and its new tag half covers the aur case, since manager declarations are tag-scoped.
- The aur payload has its own assertion: a mutation swapping it for the home copy used to survive.
- The `generate-source` skill, the `kit` comments and the npm stage template's comment stop naming the retired `copy_artifact`/`detect_config`.

**The chain (producer-first).** spec#420 (merged) → **this PR** → plugin-builder, plugin-fleet, plugin-box, plugin-installstep, plugin-loader, plugin-deploy-pod, the builder plugins (aur, npm, pixi, cargo, mise) → charly → distro-arch, plugin-migrate, distro-cachyos, pod-kde-vnc → layer-kde-shell. Each is its own PR, opened when its producer has tagged.
