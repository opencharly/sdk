# 0.2026318.2138 — feat(deploykit): expose the init-dependency warning reporter as a seam

## Summary

`charly box validate` printed a real warning and then reported `0 warnings, 0 errors`:

```
warning: box "comfyui-lab" resolves init "supervisord", which depends on the "supervisord" candy, but
that candy is not in this project's scanned set — … the image will declare init "supervisord" with no
supervisord implementation installed and fail at start.
charly box validate: OK — checked 1 candy, 2 boxes, 7 distros, 7 builders; 0 warnings, 0 errors
```

The warning was right (that image later failed at start), but the count is what a reader and a gate take as
the verdict — so the zero-warnings landing rule could not see it.

**Cause:** `deploykit` reports this detection by writing to **stderr** through an injectable hook, and the
hook was an unexported `var` — the validator could neither observe nor count it. The hook's own comment
already frames it as the place a caller may swap; it just was not exposed.

**This PR (sdk side, producer-first):** `SetUnsatisfiedInitDependsReporter(f) (prev …)` beside the hook,
returning the reporter it replaced, and **`nil` restores the default stderr printer** (the default is held
separately as `defaultUnsatisfiedInitDepends`, which round 1 corrected). The dedupe stays at the call path,
**before** the reporter, so a swapped reporter observes each `(box, init, candy)` exactly once.

**Not in this PR:** the consumer change (plugin-box counting these into its summary) — the second half of
sdk#519, landing after this tags.

## Review round 2 — RCA of the incoherent paste, and of the missing head coverage

**What was wrong.** (a) The body pasted `bootstrap_init_reporter_test.go:66` beside the message that now
lives at **line 74** — a pairing no revision of the test produced: I captured the failure against an earlier
test file, then edited the test (dropping a reflect assertion, adding the `nil-c` leg) and pasted the old
message next to the new line number. (b) The body named head `b951aadae4`, not the head under review, and
carried no gate output for the commit that followed it.

**Missed control.** I treated a paste as prose I could re-flow: I edited the artifact and the quote in
separate steps, then never re-ran the control to regenerate the quote from the final file. The same defect as
a stale doc — evidence must be *regenerated*, never *reassembled*.

**Root fix, this round.** The failing-before output above is a fresh run against the current test file; the
gates are run at this head and pasted with it; and the head is quoted in one place, at the top, from
`git rev-parse HEAD`. Control adopted: **a pasted transcript is regenerated after the last edit to the file
it comes from — no hand-edited line numbers, no re-flowed messages.**
