# 0.2026325.921 — feat(deploykit)!: owned content — render-prep asks the content kinds, the render installs what they contribute

## Summary

The build kit's half of opencharly/sdk#598, on the contract merged in opencharly/spec#415 (`v0.2026325.913`). A node of a plugin kind can be owned by a candy, and what it contributes to an image is now the KIND's to say (DESIGN §1.1 M1, D-PLUG-1). This kit stops interpreting skill nodes. Instead it asks every kind that declares `contents`, through `ops.OpContent`, and installs what the kind replies:

- **Request.** `OwnedContentRequestFor` builds one box's request: the image user, the composed candies with the roots of the repos that author them (`candyRepoRoot`), the scope's images, and the kind's raw nodes from the box's **owning** scope. For `arch.arch` that scope is the imported namespace's own document. Reading the root's nodes for an imported box gave it no skills at all.
- **Render-prep.** Render-prep asks through the new `Generator.Content` seam, an `OwnedContentSource` (kinds = the envelope's `content_kinds`; `Ask` wired by the plugin driving the build). The files become the box's `owned_content` render cache, and the labels become `BakedLabelSet.Contributed`. A kind's diagnostics fail the build, as does a label two kinds both claim, or declared kinds with no `Ask`.
- **Render.** `EmitOwnedContent` stages the files into `.build/_content/<box>/` and emits ONE `COPY --chown=<uid>:<gid> … <home>/`, reading nothing but the box (the plugin-build render runs with `Config` nil). `WriteLabels` writes contributed labels through the JSON label writer, so non-ASCII skill prose is never `%q`-escaped.
- **Deleted, because it is the skill kind's behaviour (D-PLUG-1):** `CollectSkills`, `CollectSkillBodies`, `projectSkill`, `readSkillFile` (`skills_collect.go`). Its rules and tests move to opencharly/plugin-harness-kind (table below).
- **Deleted, because its only users were the skill carriers' `copy: .agents/skills` steps (measured org-wide), which this cutover removes:** the scratch stage's root-relative copy probe, `rootCopySources` (the partial sdk#444 fix).
- **Kept and shared:**
  - `ProjectCandy` is the one candy projection both resolve scopes use.
  - `UnionOwnedSkills` merges ownership across scopes.
  - `candyRepoRoot` gains direct tests for every loader shape; its coverage used to come only through the deleted collector.
- `FillNamespaceBoxViews` takes the content source.
- `buildBakedMetadata` can no longer fail, and loses its error return.
- `sdk.ProvidedCapability` maps `Contents` onto the wire, and `sdk.OpContent` re-exports the selector.
- The `/charly-internals:skills` skill (`.agents/skills/skills/SKILL.md`) is rewritten where it described the retired carrier install.
- The sdk-skill-shelf's no-op `run:` step is deleted.
