# 0.2026308.444 — fix(loaderkit): dedupe diamond members by logical origin, not node pointer

## Summary

Repairs the regression introduced by opencharly/sdk#483 (`1175c7c7651b5789f40838abf027676329854f42`, tag `v0.2026308.351`), which made `charly box validate` fail on the bumped pins. This is the producer half of the chain that serves opencharly/charly#1083.

`sdk#483` added namespace recursion to `loaderkit.FoldMembers`, and its diamond/multi-alias idempotence guard compared `*spec.Deploy` **node pointers**:

```go
if prev, seen := folded[memberKey]; seen {
    if prev == memberNode { continue }
```

The real mount graph does not share one pointer. Measured with a temporary trace on the reproducer (root imports `arch` and `cachyos`; `distro-cachyos@v2026.281.1001` imports `github.com/opencharly/distro-arch@v2026.274.1256` under its own `arch` namespace):

```
FOLD scope=0x3ce4cb3508 repo="github.com/opencharly/distro-arch" root=".../distro-arch@v2026.274.1256.view.da6451d8a8f0b1c1"
FOLD member scope=0x3ce4cb3508 owner="check-arch-vm" key="charly-cachyos-tailscale-test" node=0x3ce707dc08 memberOf=""
...
FOLD scope=0x3ce4cb3b08 repo="github.com/opencharly/distro-arch" root=".../distro-arch@v2026.274.1256.view.da6451d8a8f0b1c1"
FOLD member scope=0x3ce4cb3b08 owner="check-arch-vm" key="charly-cachyos-tailscale-test" node=0x3ce71d9888 memberOf=""
```

The same `repo@ref` is materialized as two distinct `*spec.UnifiedFile` scopes with two distinct `*spec.Deploy` copies, both carrying the **same `RootDir`** — so the pointer test called the second copy a genuine bare-name collision:

```
charly: error: command "validate": validation error: deploy-level member "charly-cachyos-tailscale-test"
(declared under deploy "check-arch-vm") collides with the member of deploy "check-arch-vm" —
deploy-level member names are globally unique (the bare name is the CLI address); rename one
```

### The fix

Dedupe on the member's **logical origin**, reusing the loader's existing mount identity rather than inventing a parallel one:

- `memberOrigin{rootDir, scope, owner}`. `uf.RootDir` is the path `CanonicalRef` already resolves a mount to (`repo@ref/subpath` for a remote import, the absolute directory for a local one), so every mount of one `repo@ref` carries the same string however many aliases reach it; a different repo, ref or subpath carries a different one.
- `scope` (the `*spec.UnifiedFile` pointer) is the fallback only when `RootDir` is empty — a synthetic in-memory tree, never a loader result — so distinct scopes still collide.
- The fold map becomes `map[string]memberOrigin`. Same origin → skip (fold once). Different origin → the existing hard collision error, unchanged.
