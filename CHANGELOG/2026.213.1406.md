# 2026.213.1406 — R1 fix: loaderkit.LoadBundleConfigViaExecutor restores the non-nil-empty overlay contract (K5 regression)

`loaderkit.LoadBundleConfigViaExecutor` (the cycle-free plugin-side replacement for
the deleted `deploykit.LoadBundleConfigViaSeam`, K5 coneC Unit C2) returned `(nil, nil)`
for an absent/empty per-host deploy overlay. Its drop-in predecessor
`deploykit.LoadBundleConfig` (deploy_file.go) returns a NON-NIL `&BundleConfig{}` for an
absent/empty overlay — its line-112 wrap, documented "so callers that range/index
dc.Deploy without a nil guard keep working after an overlay's last entry is removed."
The K5 rewiring dropped that wrap (its comments even claimed `(nil, nil)`-on-absent
parity with `LoadBundleConfig` that never held), so K5's "drop-in replacement" was NOT
contract-equivalent.

## Root cause (R1)

`charly reap-orphans` (candy/plugin-substrate, command_reap_orphans.go) calls
`loadBundleConfig` → `LoadHostBundleConfigViaExecutor`. The check runner isolates a
bed's per-host overlay via `XDG_CONFIG_HOME=<per-bed temp>`, so the bed's overlay reads
as ABSENT. Pre-K5 (`deploykit.LoadBundleConfig` via the host seam) the absent overlay
returned `&BundleConfig{}` (non-nil) → the `if dc == nil` guard was NOT taken → the
orphan scan ran → "no orphaned ephemerals". K5 (`LoadBundleConfigViaExecutor`) returned
`nil` → the `if dc == nil` guard WAS taken → "no charly.yml; nothing to reap", a
short-circuit that skipped the scan entirely. The `check-commands-local` bed's
`reap-orphans-runs` step (expects stdout contains "no orphaned ephemerals") regressed:
PASS pre-K5 → FAIL post-K5. The other 10 K5-rewired `LoadDeployConfigForRead` callers
were unaffected (every one guards with `derr == nil && dc != nil` or
`if derr != nil || dc == nil`, for which nil-vs-`&BundleConfig{}` is observationally
identical via `dc.Lookup`→false).

## Fix

`LoadBundleConfigViaExecutor` now returns `&deploykit.BundleConfig{}` (non-nil) when
`!ok || uf == nil` (absent/empty overlay), matching `deploykit.LoadBundleConfig`'s
line-112 wrap and restoring the EXACT pre-K5 behavior for all 10 K5-rewired callers
(safe by construction: it is what they received pre-K5). The false
`(nil, nil)`-on-absent / nil-on-empty contract claims in the file's comments were
corrected (R1 claim-keyed sweep). The `dir == ""` path-resolution guard in
`LoadHostBundleConfigViaExecutor` still returns `(nil, nil)`, matching
`LoadBundleConfig`'s path-error nil (distinct from absent-file).
