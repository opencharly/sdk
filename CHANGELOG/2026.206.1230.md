# 2026.206.1230 — loaderkit: LoadUnified/ApplyDiscover orchestration relocated from charly core

K1 keystone (task #24), the sdk producer leg. Relocates the TOP-LEVEL loader
orchestration — `LoadUnified` itself and the standalone `ApplyDiscover` walk —
out of charly core into `sdk/loaderkit`, extending the seam-injection pattern
`spec.WalkSeams`/`spec.MaterializeSeams` already established (the prior
K1-unit-1 Materializer seam, banked in cutover 1's sdk leg). The internal
per-node WALK/MATERIALIZE mechanisms (`loaderkit.Walk`, `loaderkit.Materialize`)
are unchanged; this is the layer above them — the entry points every `charly`
command reaches to load a project's `charly.yml`.

Full diff: 3 files, purely additive (0 deletions) relative to `origin/main`.

- **`loaderkit/unified_file.go`** — `UnifiedFile`/`InlineCandy` relocated from
  `charly/unified.go` (K1 unit 1). Every field was already sdk-portable; no
  behavior change. `ResolvePluginKindViaPlugin`/`DecodePluginKindMap` are the
  registry-agnostic HALF of the plugin-kind resolution loop, exported so
  charly-core's free-function accessors (`Distros`/`Builders`/`resolveInits`/
  `resolveResources`/`resolveAndroids`/…) share one loop instead of
  re-deriving it per kind.
- **`loaderkit/load_unified.go`** (new) — `LoadUnified(dir, seams LoadSeams)`:
  the kind-blind orchestration (bootstrap phase, early + post-merge schema
  gate, kind-blind walk, registry materialize, venue flatten, member fold,
  descent stamp, the validation chain) ported verbatim from charly's former
  inline `LoadUnified` body. `LoadSeams` is an 11-field callback struct
  threading every registry-coupled or standing-core-resident step back to the
  host (`RunBootstrapPhase`, `WalkProject`, `MaterializeLoadedProject`,
  `FlattenBundleVenues`, `FoldMembers`, `StampBundleDescents`,
  `ValidateEphemeral`, `ValidateCheckBeds`, `ValidateAndroidDevices`,
  `ValidateMembers`, `ValidatePreemptible`) — `foldMembers`/`validateMembers`
  are threaded through unmoved, per the standing FINAL/K5 ruling in
  `bundle_members.go` (their own relocation, if any, is a separate decision).
  Also carries `GateSchemaVersion` and the `NormalizeV4Aliases` no-op, both
  zero-registry-coupling.
- **`loaderkit/discover.go`** — adds `RunDiscover(rootDir, specs, seams)`, a
  thin exported wrapper around the existing `walker.runDiscover`/
  `parseDiscoveredManifest` mechanism `Walk`'s own depth-0 discover pass
  already used internally. Charly's standalone `ApplyDiscover` (used by
  `ScanAllCandy`/`validate_project_host.go` — not on `LoadUnified`'s own call
  graph) now reuses this SAME mechanism instead of duplicating the walk+parse
  loop. Deliberately bypasses the `spec.ProjectWalker` plugin-swap indirection
  — `ApplyDiscover` never went through the whole-project walker before this
  move either, so this preserves its pre-existing scope exactly.
