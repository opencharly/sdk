# 0.2026327.625 — feat(kit)!: a bed-actions run executes the deployment's own run: steps

## Summary

The sdk half of opencharly/plugin-check#153 (G5). `charly check run`'s live stage is verify-only, so every bed `run:` step is skipped and a bed's actions never run; the schema now carries `#CheckRunRequest.bed_actions` (opencharly/spec#426, tagged `v0.2026327.605`) and this PR makes the walk honour it.

- **`PlanContext` gains `BedActions()`**, and a `flatStep` carries a `bed` marker set for the plan's **Deploy** section only (one construction site, so both the single-member and staged walks get it).
- **The verify-only skip gains exactly one exemption**: `if pc.VerifyOnly() && step.Mutates() && !(pc.BedActions() && fs.bed)`. A bed-actions run executes the deployment's OWN mutating `run:` steps in authored order between its checks; the **Candy and Box install timeline stays skipped** (it ran at build), and with the flag off every mutating step still skips — a plain `charly check live` is unchanged.
- **`runner.go` implements the accessor**, so a live runner built with `bed_actions` set threads it to the walk — and `TestNewRunnerCarriesBedActions` asserts the REAL constructor in both arms, so a dropped assignment cannot pass the suite.
- **Pin**: `github.com/opencharly/spec` → `v0.2026327.605` (the release carrying the field).

D-VERB-1 is why this exists (the one state-changing step is a `run:` step, so a bed's actions must be `run:` steps, not faked in `check:` steps); D-DEP-3 is why the plugin refuses it on a deployment that is not `disposable: true`.
