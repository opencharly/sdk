**Both predicates are untouched, and their answers now match the authored input exactly.** `HasExtract()` and `HasContent` use `len()` on the field, and `len()` on an empty `RawBody` is 0. That required a real fix the review caught: the producer first guard was `ly.Extract != nil`, so an **empty but non-nil** slice marshalled to `[]` — two non-empty bytes — and `HasExtract()` would have answered *true* for a candy declaring no extractions. The guard now keys on `len(ly.Extract) > 0`, which is the same question the predicate asks, and the test covers the empty-slice case (it previously exercised only a nil slice, which is why the bug survived).

**Both halves PANIC on an invariant violation.** The bytes come from marshalling a typed `#CandyExtract`, so a marshal or decode failure means the body was written by something other than that producer. A silently empty extraction list would mean a stage copies no files with nothing saying why, which is the same silent-drop class the `hook` PR was blocked on twice.
