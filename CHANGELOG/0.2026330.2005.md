# 0.2026330.2005 — fix(pixi): stop declaring RATTLER_CACHE_DIR, a cache root pixi never creates

## Summary

Stop declaring `RATTLER_CACHE_DIR` in the pixi builder stage. Measured on **both** pixi versions in
play, a `--frozen` install writes its package cache to `PIXI_CACHE_DIR` and **never creates**
`RATTLER_CACHE_DIR` — so the variable advertised a cache root nothing writes.

Head: `e0410164bfe6b286ae25ad4bd888f027a63e4b86`
Diff: 2 files changed, 39 insertions(+), 1 deletion(-)

- `kit/builder_resolve.go` — `ENV PIXI_CACHE_DIR=/tmp/pixi-cache` (the dead variable removed, with the
  measured reason at the line)
- `kit/builder_pixi_stage_test.go` — the regression witness

## How tested

The measurement, on both versions, a fresh cache dir each time, `PIXI_CACHE_DIR` and
`RATTLER_CACHE_DIR` both set exactly as the stage sets them:

```
$ pixi --version
pixi 0.84.2
$ PIXI_HOME=/tmp/e2h PIXI_CACHE_DIR=/tmp/e2c RATTLER_CACHE_DIR=/tmp/e2r pixi install --frozen
$ ls -A /tmp/e2c
pkgs
uv-cache
$ ls -A /tmp/e2r
MISSING
```

```
$ pixi --version
pixi 0.70.2
$ PIXI_HOME=/tmp/f0702h PIXI_CACHE_DIR=/tmp/f0702c pixi lock
$ PIXI_HOME=/tmp/f0702h PIXI_CACHE_DIR=/tmp/f0702c RATTLER_CACHE_DIR=/tmp/f0702r pixi install --frozen
The default environment has been installed.
$ ls -A /tmp/f0702c
pkgs
uv-cache
$ ls -A /tmp/f0702r
MISSING
```

Both are `--frozen` runs with a lock; the 0.70.2 `repodata` I first cited belonged to a **non-frozen**
run and is not comparable, so it is replaced by the frozen run above.

### Scope, stated plainly

This removes the **environment declaration**. The BuildKit cache **mount** for
`/tmp/rattler-cache` is emitted from the builder definition's declared mount list, which is a
different surface; if that mount is still emitted it is an empty, harmless mount, and removing it is
tracked separately (it is not claimed here).
