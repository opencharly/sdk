# 0.2026324.8 — chore(deps): move to spec v0.2026323.2211, and off the retired cache override

## Summary

**`sdk` moves to `spec v0.2026323.2211`, and the four tests that still used the retired `CHARLY_REPO_CACHE` override move to the one the contract admits.**

Two things, and the second is why the first was blocked.

**The bump.** `spec` released `#Retry` — the declared, bounded stage repetition that replaces `plugin-pipeline`'s timed `#PipelineRetry{max, delay_ms, factor}`. `sdk` pinned `v0.2026322.1814`, which predates it, so `plugin-pipeline` could not consume `schema.#Retry` at all. This is the middle leg of that producer chain.

**The straggler the `storeroot` cutover left.** `spec` re-based `refs.RepoCacheDir()` onto `storeroot.Dir(storeroot.RootCache)`, which honours **`CHARLY_CACHE_DIR` and only that**. Four `loaderkit` tests still set `CHARLY_REPO_CACHE`, so `RepoCacheDir()` resolved a real directory instead of the fake one and `logicalRepoMount` returned `""`:

```console
--- FAIL: TestLogicalRepoMount/tag
    fold_members_namespace_test.go:457: logicalRepoMount("/cache/repos/github.com/org/repo@v1.0.0.view.…") = "", want "github.com/org/repo\x00"
```

**`loaderkit/cache_root_one_test.go` already asserts the one-override rule** — *"the resolver, and D-STORE-1 admits exactly one (CHARLY_CACHE_DIR)"* — so these four sites were legacy the cutover missed, not a behaviour this change is changing.
