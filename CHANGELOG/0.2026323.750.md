## Review-round RCA

**The BLOCK this push answers:** `deploykit/bake_plugins.go` and `preempt_resolve.go` still carried phase tags in their package doc blocks -- `(K3 build-tail move, coneB-buildtail)` and `K1-UNBLOCK wave 1: extracted from charly/preempt.go` -- and a later BLOCK found that my replacement sentence (*"this file makes no claim about it"*) was falsified four lines below it by two constants that say they mirror `charly/plugin_loader.go` names.

**The mechanism, named.** The first pass matched the expression against the *function bodies* and wrote the replacement beside them; the *package doc block* above the first `const` was read as preamble and skipped. **A doc block is the densest concentration of provenance in a Go file, because it is where the file explains where it came from.**

**The missed control.** My pre-push check is the same `grep -nE` over the files I edited, and it *did* find these two lines -- **I read the count, not the lines.** `grep -c` over the package answered `0` for the two files I had swept first, and I carried that `0` forward to the rest of the unit without re-running it on the blocks I had not opened.

**The blast radius.** Two comment lines in two files, no behaviour; `go build` and `go test ./deploykit/` clean throughout.

**The root fix, applied here.** Every doc block in a unit's files is now read in full before the sweep, not after the grep says a line matches -- and the widened expression is run per file, so a `0` for one file is never read as a `0` for the unit. **The second repair also replaced a universal negative about my own file with a statement of what the two mirrored constants actually claim.**
