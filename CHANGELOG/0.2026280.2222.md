# 0.2026280.2222 — fix(loaderkit): the candy-manifest fallback runs the one desugar step (#323, #315)

## Summary

Fixes opencharly/sdk#323 and opencharly/sdk#315 (cluster C3 — the loader's parallel paths must not
bypass the one desugar/validate step).

**#323 — the candy-manifest fallback ran no desugar step.** `spec.DocDirectives` no longer contains
`version` (retired with the version-stamp cutover), so a project file carrying the legacy top-level
`version:` SCALAR makes `ParseDoc` fail on that scalar node and `ParseCandyManifest` takes its
FALLBACK branch. That branch is a different SHAPE SCAN, but it was also a different PARSE: it decoded
the candy body RAW, with no `desugarEntityPlan`. The authored `<word>: <input>` plugin-verb sugar then
matched no `#Op` field and the closed-schema CUE decode silently DROPPED it, so every authored plugin
verb in that candy's plan vanished. It now runs the same `desugarEntityPlan` the node-form path gets
from `parseNode`; the canonical `candy:` kind-keyed branch (reachable only when `ParseDoc` failed AND
no node-form candy node exists, so nothing had desugared it) runs the same idempotent step.
`DecodeNodeValue` consumes a `pn.Body` that `parseNode` already desugared, so no third bypass remains —
one parse-to-desugar path, not two.

**#315 — the dead `EffectiveVersion` vestige.** The box's `EffectiveVersion` lost its only writer when
sdk#313 removed `deploykit.ComputeEffectiveVersions`. The dead assignment is deleted, and
`CompileLocalPkgStep`'s doc — which still claimed the step "carries ... the release CalVer (the box's
effective version)" — is corrected in the same commit.

**Review-round fix 1 (R1).** Running this repo's OWN committed gate (below) found that the #323 change
had pushed `ParseCandyManifest` to cyclomatic complexity 31, one over the repo's configured `gocyclo`
threshold of 30 — the CI was RED. Fixed in the tree, not by raising the threshold: the function is
split into three behaviour-identical helpers (`candyFromParsedNodes`, `candyFromFlatScan`,
`candyFromKindKeyedForm`). The new flat scan reuses the ONE existing `kit.MappingChild` rather than
adding a second copy of the mapping lookup (R3).
