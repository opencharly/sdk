# 0.2026317.1803 — feat(schema): carry the StepContract plugin_paths flag onto the wire (#1131)

## Summary

A `class:step` plugin's `StepContract` is DECLARED by the plugin and **acted on by the host**: the host is what reads `Scope`, `Venue`, `Gate` and `Emits` off the declared capability. So every field has to survive the capability build, or a plugin declares a capability nobody can see.

`PluginPaths` — the opt-in added by `opencharly/spec#308` for `opencharly/charly#1131` — is the one that makes the host inject the connected plugin set into this step's input. Dropping it in this conversion is not a cosmetic loss: the plugin would declare the flag, the host would never receive it, and the step would go back to guessing where its plugin binaries are.

This PR is that one conversion plus its proof:

- `schema.go` — `BuildCapabilitiesWithRequires` carries `PluginPaths` into `pb.StepContract`, next to `Emits`, for the same reason: the host acts on it.
- `step_contract_test.go` (new) — drives the real `BuildCapabilitiesWithRequires` path and round-trips the result through protobuf, so it fails if the field is dropped and also pins that the contract's other fields did not drift with it.
- `go.mod` / `go.sum` — adopt `github.com/opencharly/spec v0.2026317.1755` (spec#308, merged and tagged), which is where the field is defined.
