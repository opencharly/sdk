## Summary

TODO.md **3.3** (D-LOAD-5, §12.1) — "Steps are typed only by `charly box validate`":

```
load            -> <nil>
box validate    -> measure: redis: plan step 0: plan.0: 5 errors in empty disjunction:
```

Same document (`- run: 42`), same `Threaded` snapshot, both paths driven. The load's desugar already judges a step's **intent keyword** — an unknown verb is refused today (`plan[0] has no intent keyword (run/check/agent-run/agent-check/include)`) — but the step's **body** against the closed `#Step`/`#Op` was typed in exactly one other place, `charly box validate`.

The gate now runs on **every load**. `ParseDocStream` is the ONE per-document pipeline the file walk *and* the binary-embedded vocabulary stream both drive, so every entity's plan steps are typed as each document parses and no caller can skip it.

The entity-tree walk keeps **one** recursion with two verdicts — `ValidateEntityNodeRec` (candy body + steps: the `box validate` verdict) and the new `ValidateEntityStepsRec` (steps only: the every-load verdict) — both over the same `assembleAndValidateEntitySteps`, so the mechanism is still written once. The candy-body half stays off the load path on purpose: it requires a non-empty `description`, a different obligation that a load must not newly impose on an otherwise well-formed manifest (measured — putting it on the load path rejected fixtures whose candy nodes are otherwise fine).

**This closes the "validate steps on every load" half of 3.3.** The row's second half — dispatch every key-tagged union on its tag keys and report "exactly one of …" — is a schema + dispatcher change and stays open; the row is **not** closed by this PR.
