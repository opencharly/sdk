# 0.2026313.513 — refactor(schema): the composer's home is the contract module, so the sdk delegates

## Summary

The composer's home is the contract module, so the sdk keeps ONE call site instead of a copy.

opencharly/sdk#491 (tag `v0.2026313.433`) put the module-aware compose for a plugin's served
schema in this module. It cannot stay here. `charly/charly/import_purity_test.go` states the
boundary as a tested invariant — `github.com/opencharly/sdk` (root or any subpackage) "is for
PLUGINS to import, never the host" — and both halves of the contract (the serve side and the
host gate) must judge the same schema with the same code. The ONE module both may import is
`github.com/opencharly/spec`, which already owns the family: `schemaconcat`, `schemaparams`,
`cuetoolchain`, the embedded schema source and its module declaration.

So the composer moved to `spec/schemacompose` (opencharly/spec#297, tag `v0.2026313.453`), and
this module now:

- calls it from `BuildCapabilitiesWithRequires` — the one place the sdk composes a plugin's
  schema;
- DELETES the two public helpers it added an hour ago, `ComposeServedSchema` and
  `ComposeServedText`. They carried no behaviour of their own, and keeping wrappers beside the
  real implementation is exactly the duplication R2 exists to prevent. A plugin that wants them
  imports `spec/schemacompose` directly, as every plugin already imports its siblings from the
  contract module.
- keeps the acceptance that belongs to the sdk's own surface: a plugin whose schema imports the
  spec package is SERVED (before the cutover it was refused with `package
  "github.com/opencharly/spec/schema" imported but not defined`), and a plugin that imports
  nothing is served with its source unchanged.

The composer's deep arms live where the composer lives (`spec/schemacompose`): the imported
definition enforced, equality with the deleted text compile, and the two entry points agreeing
byte for byte.

`go.mod` moves `github.com/opencharly/spec` to the release that carries the package.
