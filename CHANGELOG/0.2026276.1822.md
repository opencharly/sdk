# 0.2026276.1822 — fix(deploykit): emit a SELF-CONTAINED VM-box disk (flatten the COW overlay) [successor to #320]

## Summary

`charly vm build` produces a copy-on-write **qcow2 overlay** whose **backing file is a host-absolute path** under the build cache (`~/.cache/charly/vm-images/<sha>.qcow2`). A VM box is a `FROM scratch` + COPY image, so it carries **only the overlay** — on any other host (a KubeVirt node's containerd) the backing file is absent and the guest **cannot open the disk**. This is exactly what left `charly#730`'s `check-kubevirt-vm` VMI stuck un-Ready.

Fix: **flatten the overlay into a standalone qcow2** (`qemu-img convert`) before wrapping it into the box/containerDisk, so the COPY is the whole artifact. `isQcow2Overlay` **fails CLOSED** on an unreadable image (never a silent false), so a failed `qemu-img info` cannot wrap an unflattened overlay whose backing is missing on every other host.

This is the successor of the auto-closed **`opencharly/sdk#320`**, carried forward on the operator's **break A** (the same cycle break as `plugin-kubevirt#4`→`#10`, `plugin-vm#61`→`#67`).

Head `622ca75` (branch `feat/kubevirt-vm-box-flatten-3`) — the tip is a fix commit on top of a `main`-into-branch merge (`cd0983c`); the earlier tip `35fdf8a` was rebased. Every finding from the prior verdicts is fixed in this head.

**Supersedes `opencharly/sdk#320`** — the same change rebased, all findings addressed.

### Every diff item, accounted for

| File | Change |
|---|---|
| `deploykit/vm_box_emit.go` | `EmitVmBoxAt` now inspects the disk (`isQcow2Overlay`); if it is a COW overlay it `flattenQcow2`s it into a standalone qcow2 and COPYs **that**. `isQcow2Overlay` reads the **qcow2 magic first** — a non-qcow2 artifact (a raw whole-disk image, or a fixture) is not an overlay and needs no `qemu-img`, so a host/CI without `qemu-img` still emits a raw disk; only a real qcow2 image consults `qemu-img`. It **fails closed**: only `io.EOF`/`io.ErrUnexpectedEOF` (a genuine short read) means "not an overlay"; every OTHER read error (e.g. `EISDIR`) is a genuinely unreadable disk and is returned as an error, never a silent false. |
| `deploykit/vm_box_emit_e2e_test.go` | **ADDED** — `TestEmitVmBoxAt_OverlayIsFlattenedIntoSelfContainedBox`: a **live end-to-end** proof (real COW overlay → real container engine → `EmitVmBoxAt` at `VmBoxDiskPath` → `podman cp` the emitted disk out → assert it has **no** backing file and is non-zero). |
| `deploykit/vm_box_flatten_test.go` | **ADDED** — `TestIsQcow2Overlay_DetectsBackingFile` (an overlay is detected), `TestIsQcow2Overlay_NonImageIsRawWholeDisk` (a raw/whole-disk image is not an overlay → falls through to the plain COPY), `TestIsQcow2Overlay_UnreadableErrorsClosed` (an unopenable path AND an `os.Open`'d **directory** — the EISDIR read error — both **error**, never a silent false) — the latter two run **without** `qemu-img`. |
