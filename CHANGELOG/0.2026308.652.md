# 0.2026308.652 — fix(loaderkit): fold one member mounted at two refs of the same repo

## Summary

`loaderkit.FoldMembers` keyed bare deploy-level member idempotence on the **resolved mount directory**, so the same `repo+subpath` mounted at two git refs was reported as a hard collision. The umbrella's mixed-pin graph mounts `distro-cachyos` at `v2026.281.1001` (through its `charly` and `openclaw` namespaces) and at `v2026.290.2137` (through `strata`), so the umbrella project no longer loaded (`opencharly/charly#1107`).

A temporary trace in `FoldMembers`, run from the umbrella root on `charly@1a41472f` with `sdk v0.2026308.444`, printed the two origins for the colliding member:

```
$ CHARLY_PLUGIN_ONLY=1 /tmp/c1107-charly/bin/charly-instr box validate 2>&1 | grep 'FOLDTRACE.*selkies-kde-gpu-stream' | sort -u
FOLDTRACE rootDir="/home/atrawog/.cache/charly/repos/github.com/opencharly/distro-cachyos@v2026.281.1001.view.b4bf433f556980a4" repo="" owner="cachyos-gpu" key="selkies-kde-gpu-stream"
FOLDTRACE rootDir="/home/atrawog/.cache/charly/repos/github.com/opencharly/distro-cachyos@v2026.290.2137.view.b4bf433f556980a4" repo="" owner="cachyos-gpu" key="selkies-kde-gpu-stream"
```

Both paths name the SAME repo (`github.com/opencharly/distro-cachyos`); only the git ref differs, and the member body (`pod: image: selkies-kde-nvidia`) is identical at both refs. The import lines are `charly/charly.yml:21` and `layer-openclaw/charly.yml:36` (`v2026.281.1001`) and `layer-strata/charly.yml:31` (`v2026.290.2137`).

### The fix

`memberOrigin` now carries a **ref-independent remote mount identity** (`logicalRepoMount`) alongside the resolved `RootDir`. The helper parses the loader's derived-view shape:

```
<cache>/repos/<repoPath>@<version>.view.<identity>[/<subpath>]
```

and drops only `<version>`. `sameMemberOrigin` therefore folds two refs of one repo+subpath once, exactly as it folds a diamond; a different repo, or the same repo at a different subpath, keeps a different identity and remains a hard collision. A local import (no derived-view marker, or not under the repo cache, including a `CHARLY_REPO_OVERRIDE` working tree) retains its exact `RootDir` identity.

Measured correction from `opencharly/sdk#484` / PR #485: `uf.RootDir` is NOT the `CanonicalRef` key (`repo@ref/subpath`); it is the resolved derived-view directory above. The changed comments now state the measured shape.
