## Summary

Pins `github.com/opencharly/spec` v0.2026246.554 → v0.2026248.128 (spec PR #94). The new spec version bounds every network git subprocess in the @github ref resolution with a **context deadline + bounded retry**: `refs.GitResolveRef` / `GitLatestTag` / `GitDefaultBranch` / `GitClone` (commit-fetch + branch-clone paths) / `populateSubmodules` now run through an internal `runGitOp` runner — 30s deadline for ref metadata (`ls-remote`), 60s for transfer (clone/fetch/submodule), 2 retries with 500ms/1s backoff, re-issuing on a deadline kill or on git's transient-network signatures ("RPC failed / HTTP/2 stream reset", connection reset, "Empty reply from server", 5xx). The pre-fix path used a bare `exec.Command` with no deadline, so a connection killed in a GitHub HTTP/2 reset window (curl error 92 CANCEL) blocked the pre-deploy @github resolution FOREVER (r9 wave forensics: 3 eval lanes froze before deploy-add — 21 threads, 20x futex_wait + 1x do_epoll_wait on a dead socket). Permanent failures (repo not found / 404 / 403) fail fast without retry.

No sdk code change: the refs API surface is unchanged (the runner is internal to spec/refs); `loaderkit`'s version-less latest-tag resolution, `EnsureRepoDownloaded`, `GitClient` warm-up and `kit`'s `DefaultDownloader` all pick up the bounded resolution through this pin.
