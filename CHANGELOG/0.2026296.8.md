# 0.2026296.8 — feat(deploykit): emit the container init's declared runtime mode

## Summary

The `sdk` producer leg of the W3.8 cutover (opencharly/charly#1030, spike #1027), on top of opencharly/spec#269.

A container can host a real init as PID 1 only when the engine is told so, and the deploy must read that from the IMAGE — not switch on an init-system name. This leg makes the declared contract reach both pod render surfaces:

- **`kit.InitContainerRuntimeArgs`** — the ONE assembly of the init's container-runtime argv. The engine's own systemd-mode spelling is the capability fact `systemd_mode_arg` (podman `--systemd=always`); an engine without one (docker) gets no invented flag, and the engine-neutral stop signal (`--stop-signal=SIGRTMIN+3`) is always emitted when declared.
- **Direct-run argv** (`deploykit.BuildStartArgs`/`BuildForegroundRunArgs`) — takes the image's `init_def` and appends that assembly before the image ref.
- **Quadlet** (`deploykit.QuadletConfig.InitDef` + `emitInitRuntime`) — emits `PodmanArgs=--systemd=always` and `StopSignal=SIGRTMIN+3`. There is NO quadlet `Systemd=` key: podman 6.1.4's generator does not know it, and an UNKNOWN key makes quadlet skip the entire unit, so `charly start` reports "Unit ... not found" (measured live on the bed before the fix).
- **`deploykit/render_prep`** — copies `requires_root` / `systemd_mode` / `stop_signal` into the `ai.opencharly.init_def` label, so the deploy reads them from the image.
- **`deploykit/generate`** — the build's final `USER` reset is skipped for an init that declares `requires_root`, exactly as `preserve_user` already does. A non-root PID 1 makes systemd fail in system mode (exit 255 / start-limit-hit, from the spike).

The new assertions carry controls (each measured by reverting the production code):

- `TestBuildStartArgs_EmitsDeclaredInitRuntime` — a systemd init contract yields `--systemd=always` and `--stop-signal=SIGRTMIN+3`; a nil contract yields neither. Reverting the append fails on the missing flags.
- `TestBuildStartArgs_EngineWithoutSystemdModeStillStops` — docker has no systemd-mode fact, so the flag is omitted and the stop signal still emitted.
- `TestGenerateQuadlet_EmitsDeclaredInitRuntime` — the quadlet carries `Exec=/sbin/init`, `PodmanArgs=--systemd=always` and `StopSignal=SIGRTMIN+3`; the control (nil contract) carries none. Reverting the emission fails.
- `TestRenderDrive_RequiresRootSkipsFinalUser` — the build-side USER decision, driven through the real render: the control (no init contract) emits `USER 1000`, a root-required init does not, and an init without the flag keeps the old decision. Reverting the `generate.go` branch fails it (measured).
- `TestCapabilityInitDef_ProjectsContainerRuntimeContract` — the label projection carries `requires_root` / `systemd_mode` / `stop_signal` plus the entrypoint and management surface; a sparse-def control carries none. Dropping the three fields fails it (measured). The projection is extracted to `capabilityInitDef` so the mapping has one named, testable home.

The assembled R10 bed (the cutover's one gate) runs on the `charly` + `plugin-deploy-pod` legs; this leg's changed path is what that bed exercises.
