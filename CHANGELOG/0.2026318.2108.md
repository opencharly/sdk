# 0.2026318.2108 — fix(deploykit): reset to root before the base bootstrap — an external base ends with the image's USER

## Summary

`EmitBaseBootstrap` resets to root for an **internal** base and for a builder rootfs, but for an
**external** `base:` it emitted the bootstrap `RUN` immediately — assuming the base image left the build
as root. Every image `charly` itself builds ends with `USER <uid>` (`deploykit/generate.go` emits it for
the workload user), so composing one as `base: "ghcr.io/...:<calver>"` ran the bootstrap as uid 1000:

```
#5 0.061 /bin/sh: line 1: /etc/dnf/dnf.conf: Permission denied
#5 11.45 tar: task: Cannot open: File exists
```

The external branch now emits `USER root` **before** the bootstrap, so the base stage starts as root in
both branches. A distro base is unaffected (explicit root is a no-op); a charly-built base becomes
composable — which restores the only cheap composition path for a project that wants one candy on top of
an already-published image.

Three files:
- `deploykit/bootstrap.go` — the reset, with the measured failure in the comment.
- `deploykit/bootstrap_external_user_test.go` — the regression pin (fails on the old tree; see below).
- `deploykit/testdata/render_parity_golden.txt` — golden updated; the **entire** delta is `+USER root` and one blank line.

Refs sdk#515 (RCA + live evidence in the issue).
