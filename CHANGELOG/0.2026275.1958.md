# 0.2026275.1958 — fix(loaderkit): drop the retired version stamp from the system config layer

## Summary

`spec` #183 removed the top-level `version` field from the **closed** `#NodeDoc`, but the config stack kept merging **every** top-level key of the SYSTEM layer (`/etc/charly/charly.yml`, rendered by the charly package — never authored) into **every** project document. On a host carrying that stamp, the merged document resolves `version` as a NODE name whose value must be a struct, so **no project resolved**:

```
node "version": #NodeDoc.version: conflicting values "2026.249.2125" and {...}
                                  (mismatched types string and struct)
```

No project can fix it: the file is root-owned, and `charly migrate` (loader-independent) cannot touch it.

`readConfigStack` now drops `retiredSystemDirectives` from the **system layer** before the merge, and skips a layer the strip leaves empty. `loaderkit/config_stack.go` and its test are the only paths in the diff — **+159 / −15**.

**The strip is scoped to the system layer, and that scoping is the contract, not an implementation detail.** The system layer is package-**rendered**, so a retired directive there carries no user intent. An **authored** project that still carries `version:` keeps it: the leftover stays a hard error at the schema gate, and `charly migrate` still sees the key it exists to strip. Dropping it in the loader would silently swallow a real leftover (pinned by `TestConfigStack_AuthoredProjectVersionSurvives`).

**Two states, deliberately different:**

| system layer | result |
|---|---|
| retired stamp **plus** content (a candy node) | the stamp is dropped; the content is merged as before |
| retired stamp **only** (what the package actually renders today) | the layer contributes **nothing** — the host resolves exactly like one with no system config |

The second row is why the fix skips the emptied layer instead of merging an empty mapping: `(nil, false)` for a directory with no project is the honest post-#183 answer, not a manufactured empty project.

The stale header comment in the same file ("shipped … as a bare minimal PROJECT (a version + a charly-mcp candy node)") is corrected in the same commit (R1 — the code and its stated contract had drifted apart at #183).

Refs **opencharly/charly#754** (P0, claimed by this slug; the RCA and the live pre-fix reproduction are posted there).
