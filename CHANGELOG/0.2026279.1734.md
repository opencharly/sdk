# 0.2026279.1734 — fix(deploykit): an explicit `build:` plan step is a position marker, not a deploy step

## Summary

An explicit **`build:`** run: step — e.g. `build: all`, the ordering marker a candy
uses to force its `package.json`'s npm builder to run **before** a later install step —
was lowered by `constructOpStep` to a generic **`OpStep`**. `Op.Build` has no
`RenderOpCommand` case, so `kit.WalkPlans`'s `walkOp` returned `handled=false` and
**every `target: local` / `target: vm` deploy** hard-failed:

```
plugin-deploy-vm: walk step "Op" (candy=dsh-tui): op has no plugin-renderable verb
(an act-`plugin:` verb must route to RunHostStep): &{... Build:all ...}
```

The **image build was never affected**: `EmitTasks` renders the marker as the no-op
`# build: all (handled by builder stage)` comment, and the builder itself is emitted
from manifest detection (`compileBuilderSteps`, plan step 2) and **hoisted ahead of every
task step on BOTH the image build and the deploy plan** — so the marker carries no
deploy-time effect.

`constructOpStep` now skips a `build`-verb op (`return nil, nil`), matching the image
build's no-op semantics. `constructOpStep` is reachable ONLY via `CompileOpSteps` →
`BuildDeployPlan` (the deploy IR); the image `EmitTasks` path is untouched.

Closes #346.
