# 0.2026248.2145 — fix(vmshared): re-capture over a stale registry entry whose disk is missing

## Summary

RCA (live, check-omarchy-clone-base): the golden was deleted to force a re-capture, but the snapshot registry still held the entry (refcount 2, disk path pointing at the removed file). CreateSnapshot refused with "snapshot golden already exists" even though the disk was gone — the golden-refresh idempotency gap: a re-capture over a stale record is the operator's intent.

- CreateSnapshot: a registry entry whose external disk is MISSING (os.IsNotExist) is a stale record — drop it and proceed with the capture. A live entry (disk present) is still a hard conflict.
- B18 refinement: ONLY os.IsNotExist qualifies as stale. Any other stat failure (permission, ENOTDIR, transient I/O) must NOT delete a live entry — it falls through to the hard-conflict path.
- Unit gates: stale-entry re-capture succeeds (registry refreshed), live-entry still conflicts, non-not-exists stat error still conflicts and the entry survives.
