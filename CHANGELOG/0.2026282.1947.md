# 0.2026282.1947 — feat(kit): tell a dead assertion from a legitimate skip — classify unresolved variables (charly#865)

## Summary

A `check:` step whose variable cannot be resolved **skipped**, and a plan that had quietly stopped asserting read exactly like a green one (opencharly/charly#865). Measured in two independent places in one session — one step in one repo, six in another.

The runner could not do better, because three different situations were folded into one skip arm:

```go
// kit/planrun.go, before this PR
	if hostMissing := FilterHostVars(missing); len(hostMissing) > 0 {
		result.Status = StatusFail      // ${HOST:…} → peer unreachable
	} else {
		result.Status = StatusSkip      // ← everything else
	}
```

- a `${HOST:…}` peer that is unreachable → FAIL (correct, unchanged)
- an input that genuinely does not apply to **this run** (a deploy-scoped var under build scope, an unmounted volume) → SKIP (correct)
- **a name the author wrote that can never resolve in a `check:` in *any* run** → SKIP, which is the defect: the assertion is dead and skipping it reports it as a pass

This PR separates the third from the second.

## What changes

- **`kit/planspec.go`** — `UnresolvedClass` (`UnresolvedConditional` | `UnresolvedUnknown`) and the `unresolvedName` normaliser, now shared by `FilterHostVars` and the new path so the two cannot drift.
- **`kit/planrun.go`** — `PlanContext.ClassifyUnresolved(op, name)`, and the `missing` arm split three ways. A name the host says no mode or scope can supply, on an assert-only step, now FAILS and names the variable.
- **`kit/runner.go`** — `Runner.SetUnresolvedClassifier`, defaulting to `UnresolvedConditional`.
- **`kit/planrun_test.go`** — five tests pinning the contract in both directions.

**Why assert-only, and why the stamp.** The discriminator is *step kind × what the host can supply*, and it is exact rather than heuristic: an assert-only step's expansion env is the runner's auto-exports **by construction**, so a name nothing can supply there can never resolve. A mutating step is exempt because its scope may legitimately supply the name elsewhere — that is the skip the walk has always taken. The step kind is read from the walk's own `IntentDo` **stamp** (`StepDoMode`: `run:` → act, `check:` → assert), **not** from the resolved do-mode: the resolved mode falls back to the verb catalog, which answers for the *verb* rather than for the step the author wrote.

**Who answers, and who breaks.** The host is asked because only the host knows its own variable vocabulary. The implementor sweep for the required interface method:

```console

$ grep -rn --include=*.go 'func (.*) EffectiveEnv() map[string]string' charly/

```

**Both implementors are inside this module** — `kit.Runner`, updated here, and the test double. Charly is a *user* that passes `kit.Runner` through, as its own comment says, so **no consumer's build breaks.**

**Behaviour is unchanged without a classifier.** The default is `UnresolvedConditional` — exactly today's skip — so adopting the classifier is a deliberate cutover, not a silent change for a host that has not opted in.
